## 0.1.23 - 2026-11-18 - Editor: sprites cannot be packed into an atlas or cut from a sheet; atlas rects are written by hand

Entry: `atlas-pack`. Bump: patch.

### Added

- The Sprite Library (`Widgets/TextureEditor/`) slices a sheet into sprites, by a grid (columns x rows) or by alpha islands, with names.
- The Atlas section packs a group of sprites into `assets/atlases/<atlas>.png`. Packing is deterministic shelf packing with padding, size mode and max side. It rewrites the sprites' rects, keeps their names, and can unpack them back to single textures.
- A preview of the current atlas or of the pack plan shows the rects, names, fill ratio and size.
- The library list shows a thumbnail per sprite, its texture and an atlas badge, and filters by atlas.
- A sprite entry of `TextureLibrary.xml` can carry an optional `atlas` link: the group name, the source image and rect, and the pack settings. The link is written only when engaged. Adapt: nothing; existing files load unchanged.
- An artgen Accept into a packed sprite repacks its atlas. The `artgen_accept` answer and the panel say so.

## 0.1.22 - 2026-11-17 - Editor: the status bar does not show the GPU temperature, load and memory (or the CPU's when there is no GPU reading)

Entry: `editor-hardware-stats`. Bump: patch.

### Added

- The editor's status bar shows the GPU temperature, load and memory (`GPU 64°C 87% 9.1/12 GB`), coloured by thresholds, with the device in the tooltip; without a GPU reading it shows the CPU load and, where the OS gives it without admin rights, its temperature. Readings are polled about once a second on a worker thread (`Widgets/EditorLayout/Hardware/`); the frame never blocks and a steady frame allocates nothing.
- Readers: NVIDIA through NVML loaded at run time (Windows, Linux; no SDK at build time); macOS through IOKit (`IOAccelerator` statistics, IOHID sensors on Apple Silicon, the SMC on Intel); the CPU through `GetSystemTimes`, `/proc/stat` and hwmon, `host_statistics`. The macOS and Linux readers are not yet built on their platforms. Adapt: nothing; macOS editor builds link IOKit and CoreFoundation.

## 0.1.21 - 2026-11-17 - Art generation: a finished set cannot get more variants on a new seed, and its review sits on a separate tab

### Added

## 0.1.19 - 2026-11-17 - Art generation: Accept copies the whole 1024x1024 image (no trim to the object, no target size)

Entry: `artgen-accept-trim`. Bump: patch.

### Added

- `Widgets/ArtGen/ArtGenImage.h`: the image Accept settings (`trim`, `padding`, `maxSize`), the drawn bounds, one frame and scale for a set, premultiplied box-filter downscale, PNG read and write.
- A preset's `accept` key holds those settings (the Python service ignores it); the Generate panel edits them in Settings and beside Accept, and shows the drawn and the written size; `artgen_accept` takes an optional `image` override and answers `processing`.
- An image set keeps one frame and one scale, measured over every variant at its first Accept all and stored in the manifest as `processing`; a switch, Accept all again and Keep write through it; `artgen_enqueue` takes `frameOf: <set>` to give a replacement set the frame of an older one.

### Changed

- An accepted image is trimmed to its drawn box with 2 % padding and downscaled to at most 256 px by default, instead of copied as the generator's full frame; its `.artgen.json` gets an `accepted` record (source, crop, scale, size). Adapt: nothing for sprites already accepted; a game that wants full frames sets `"accept": {"trim": false, "maxSize": 0}` in its preset (copied byte for byte, as before).
- A set accepted before this change, or with those identity settings, keeps writing full frames. Adapt: nothing.

## 0.1.16 - 2026-11-17 - Art generation: a generated set can be judged only in the panel's grid, not on the scene where it will live

Entry: `artgen-live-alternatives`. Bump: patch.

### Added

- Live alternatives of an art set: Accept all writes a candidate of every row (the pick, or the first variant of an image row) and keeps the other variants; a pick on an accepted, live row rewrites the game's file at once (`artgen_pick` answers `switched`), and the editor reloads the sprite.
- Keep (`artgen_keep {set, job?}`, the Review's Keep and Keep all) makes a row final: its other variants are trimmed and `"kept": {seed, date}` is written into the game's `.artgen.json` provenance; `artgen_set` rows carry `accepted.kept`, `artgen_state.sets[]` carries `live` and `kept` counts.
- A row whose name a newer set accepted later is shown as replaced: a switch, a Keep and a re-accept of it are refused or skipped, with the owning set named.
- Sets are handed to the service only while its generator is ready; default set names get `-2`, `-3` when the name of that second is taken.

### Changed

- `artgen_accept_set` no longer needs a pick on every image row; its rows report `{job, as, seed, alternatives}`. Adapt: a client that relied on the refusal of an unpicked row picks before accepting.
- The `artgen` skill ends a set accepted with alternatives alive and never calls `artgen_keep`. Adapt: nothing in a game.

### Changed

## 0.1.14 - 2026-11-16 - Audio: master and bus volumes are linear gains, so a volume slider barely changes the loudness

Entry: `audio-perceptual-volume`. Bump: patch.

### Added

- `AudioManager::LevelToGain(level)`: the gain of a master or bus level (the position clamped to 0..1, NaN as 0, then cubed: 50 % is -18 dB, 20 % is -42 dB).

### Changed

- The master and bus volumes (`AudioLevel::_volume`, `SetMasterVolume`, `SetBusVolume`, `AudioConfig.xml`, the saved `audio` slot, `audio_set` / `audio_state`) are slider positions now, and the gain is their cube; a sound's own volume, a track's volume and fades stay linear. The same stored number below 1 sounds quieter than before. Adapt: nothing to change in code; a game that tuned a bus level by ear (a config default below 1) listens again and raises it (the old gain g is now the position g^(1/3)).
