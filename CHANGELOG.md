## 0.23.1 - 2026-11-25 - Perf: the 2D benchmarks run on the SDL hardware renderer and on Vulkan with a hidden window

### Added

## 0.23.0 - 2026-11-25 - Renderer: consecutive 2D quads of the same texture and state go to the backend as one batch

Entry: `render-2d-batching`. Bump: minor.

### Added

- A 2D batcher in `IRenderer`: consecutive rects and textured quads with the same texture, blend mode and view are appended to one batch and submitted once; any state change (texture, blend, clip, view, render target, clear) flushes first, so the draw order is exact. `SetBatchingEnabled(bool)` turns it off for a renderer. The SDL backend submits a batch with `SDL_RenderGeometryRaw`; on the software renderer it batches only the draws proven byte-equal and draws the rest one by one. The Vulkan backend submits a batch as one geometry draw. `GeometryVertex` has its own header `BECore/Renderer/GeometryVertex.h`, included by `IRenderer.h`. Adapt: nothing.
- `RenderCounters::primitives` counts what was asked of the renderer; `frame_stats` of the control API and the profiler overlay show it. Adapt: nothing.

### Changed

- `RenderCounters::drawCalls` (and `drawCalls` of `frame_stats`, the `draw_calls` metric of a perf set) now counts backend submissions, so it drops where draws are batched; the old meaning is `primitives`. Adapt: a test or a perf note that reads `drawCalls` as "one per sprite" reads `primitives` instead; the info-only `draw_calls` metric of a game's perf set may show a change at the next run.

## 0.20.0 - 2026-11-24 - Scene: drawing and the update events run over dense per-scene lists, not a walk of the node tree every frame

Entry: `scene-dense-update-draw`. Bump: minor.

### Added

- `IComponent::HasOnDraw()` (default true): a component that never draws returns false and stays out of the scene's draw list; the engine's non-drawing built-ins do. Adapt: nothing; a game component without `OnDraw()` may override it to return false.
- `Scene::GetDrawListBuilds()`, `IsDrawListValid()` and `GetUpdaterCount(kind)` report the scene's draw list and update lists. Adapt: nothing.

### Changed

- `SceneDrawSystem` keeps a dense draw list per scene (`SceneDrawList.h`), one entry per drawing component, rebuilt only when a node is created, removed, moved, duplicated or instantiated, a layer changes through `SetLayer()`, a component is added or removed, or editor flags change; a steady frame only draws it. Quads and sprites read their components at draw time. A layer written to the reflected field without `SetLayer()` shows in the order only after the next rebuild. Adapt: change a node's layer only through `SetLayer()`.
- `SubscribeInScene` of `SceneUpdateEvent` and `SceneFixedUpdateEvent` registers the component in its scene's update lists (`SceneUpdateList.h`); `Scene::Update()` runs them (fixed list once per fixed step due, then the frame list, last registered first, stable when one leaves) and then emits the events for plain subscribers. A component leaves on `RemoveComponent` or `RemoveChild`; a component added to a removed node never joins; an inactive scene calls none. Adapt: nothing for components that use `SubscribeInScene` through `Scene::Update()` / `SceneManager::UpdateAll()`.
- In Debug, adding or removing nodes or components and changing editor flags inside `OnDraw()` asserts. Adapt: do such edits in an update handler.

### Breaking

- `BECore/Scene/SceneRenderData.h` (`TransformData`, `QuadDrawData`, `SpriteDrawData`, the per-frame mirror in the scene registry) is removed. Adapt: read `TransformComponent`, `QuadRendererComponent` and `SpriteRendererComponent` instead.
- A hand `SceneUpdateEvent::Emit()` / `SceneFixedUpdateEvent::Emit()` no longer reaches components that subscribed with `SubscribeInScene`; plain `Subscribe` still gets it. Adapt: a test or tool that advanced time by emitting the event drives `CoreManager::GetTime().Advance(seconds)` and `SceneManager::UpdateAll()` (or `Scene::Update()`) instead.

## 0.19.0 - 2026-11-24 - JSON is read through the engine's own tape and written by JsonWriter; nlohmann leaves the engine

Entry: `json-deserializer`. Bump: minor.

### Added

- `JsonTape` and `JsonView` (`BECore/Control/JsonTape.h`, `JsonView.h`): a one-pass tokenizer into a reused buffer (no recursion, no allocation once grown, a bad text is a `JsonParseError` with its offset) and a checked, copyable read-only view over it (`Find`, items, members, typed reads, the raw text of any value); `JsonViewOps.h` (`WriteJson(JsonWriter&, JsonView)`, `WriteJsonSorted`, `JsonEquals`, `FindJsonPointer(JsonView, pointer)`), `JsonMemberMap.h`, `JsonStreamSerializer.h` (an `ISerializer` straight into a `JsonWriter`) and `Control/ControlParams.h` (`FindParam`, `GetParamString`, `GetParamInt`, `GetParamNumber`, `GetParamBool`). Adapt: nothing.
- `JsonDeserializer::Load(StringView)` / `Load(const JsonTape&)` / `Load(JsonView)`: one reader and its buffers serve many messages; the order of keys in the text does not matter. Adapt: nothing.
- `Games/GameText.h`: the text forms of the game interface (`StateText`, `ActionsText`, `ReplayStartText`, `PerformActionText`, `ResetText`, `SetStateText`) for code and tests that have no writer at hand. Adapt: nothing.
- `JsonDoubleText`: the Grisu2 double-to-text routine is the engine's own (ported, its MIT notice in `THIRD_PARTY_NOTICES.md`), so every double in an answer, file and message keeps its bytes. Adapt: nothing.

### Changed

- The control service, its handlers, the game layer, the replay file and player, the room protocol, the room client and hub, the editor panels, the console and ArtGen read through the tape and write with `JsonWriter`: no JSON tree is built per message. The bytes on the wire, in replay files and in ArtGen files are unchanged, except as the Breaking items say. Adapt: nothing.
- Of two equal keys in one object the first now counts (in `JsonEquals`, a replay line, a parameter read and a `Serialize` write); the DOM kept the last. Adapt: nothing, unless a game's client sends repeated keys.
- A recording lists the keys of `params` in the order the caller sent them (the DOM sorted them); older recordings read unchanged and the format version stays 1. A room message whose game document holds a number past a double gives the game `null` in its place instead of refusing the whole message. Adapt: nothing.

### Breaking

- `IControllableGame`: `GetState()` and `GetActions()` are removed and `WriteState` / `WriteActions` are pure virtual; `PerformAction(JsonView action, JsonWriter& outcome)` writes exactly one value (`outcome.Null()` when it has nothing to say), `Reset(JsonView)`, `SetState(JsonView)`, and `GetReplayStart()` becomes `WriteReplayStart(JsonWriter&) const`; `ControlledReset` / `ControlledAction` / `ControlledSetState` take a `JsonView` (`ControlledAction` also a `String&` for the outcome text); `ReplayMismatchJson` becomes `ReplayMismatchText` and `EXPECT_REPLAY_FINAL_STATE` takes the expected state as JSON text. Adapt: follow `Games/CLAUDE.md` "Moving a game to the view interface": read parameters with `ControlParams.h`, write with the `JsonWriter`, move the game's tests to `<Games/GameText.h>`.
- `ISeatedGame`: `Start(seed, JsonView options)`, `PerformSeatAction(seat, JsonView action)` and `bool ChooseComputerAction(int seat, JsonWriter& action) const` (true: exactly one value written). The room messages hold their game documents as compact JSON text (`CreateRoomMessage::options`, `ActionMessage::action`, `LobbySnapshot::options`, `RoomListing::options`, `ViewMessage::view` / `actions`), and `RoomClient::GetView()` / `GetActions()` are renamed `GetViewText()` / `GetActionsText()`. Adapt: the seated rows of `Games/CLAUDE.md` "Moving a game to the view interface"; `RoomServer/src/RoomServer/DemoCardGame.h` is the example.
- The nlohmann DOM is gone: `Control/Json.h`, `JsonFwd.h`, the `Json` type, `ParseJson`, `DumpJson`, `AppendJson`, `WriteJson(JsonWriter&, const Json&)`, `FindJsonMember`, `GetJsonString/Int/Number/Bool`, `JsonStringView`, `MakeJsonString`, `FindJsonPointer(const Json&, ...)`, `JsonSerializer`, `JsonDeserializer(const Json&)`, `JsonPayload::Borrowed` / `Owned`, `ControlCall::ParamsJson()`, `ControlCall::Reply(Json)`, `MakeOkResponse(id, Json)` and `ControlService::Publish(event, const Json&)`; `src/Modules/nlohmann` and the `nlohmann_json` link are removed. Adapt: read text with a `JsonTape` and `JsonView` or `JsonDeserializer::Load`; read a call's parameters from `call.Params()` with `ControlParams.h`; answer with `call.Reply([&](JsonWriter& w) {...})` or `call.ReplyObject(answer)`, publish with `Publish(event, [&](JsonWriter& w) {...})`, and build a response outside a call with `AppendOkResponse(out, id, writer)`; write with `JsonWriter` (keys in byte order where the DOM sorted them) or `JsonStreamSerializer`; `JsonPayload::Streamed` / `Text` replace `Borrowed` / `Owned`; a game that included `<nlohmann/json.hpp>` through the engine vendors its own copy.
- `tests/Common/ControlTestSupport.h`: the DOM helpers (`MakeRequest(Json)`, `CallControl`, `DomClock`, `ToJson`, the `const Json&` readers) are replaced by `MakeRequestText`, `CallControlText`, `ControlReply` and `ClockText`. Adapt: a game's tests that include it move to the text helpers.

## 0.18.0 - 2026-11-24 - The command line is read by reflection: a CommandLineDeserializer over --name=value flags

Entry: `command-line-deserializer`. Bump: minor.

### Added

- `CommandLineDeserializer` (`BECore/Application/CommandLineDeserializer.h`): an `IDeserializer` over the `--name=value` flags of a `CommandLine`, so a reflected struct is filled from the command line by its field names in kebab case, with the strict grammar of the config (`BECore/Reflection/StrictText.h`, now shared with `XmlDeserializer`); an argument near to a known flag (`--contol-port`) is a warning. `CommandLine::Find(name)` gives the first `--name` or `--name=value`. ### Changed

- The control flags are read through it over a copy of the file's `ApplicationConfig` and the new reflected `ControlFlags` (`--replay`, `--replay-exit`, `--window`, `--density`), so each flag overrides one field and an absent flag leaves the file's value; a mistyped control flag is logged as `Config 'Command line': ...`. Adapt: nothing.

### Breaking

- A boolean control flag takes a value: `--control=false`, `--headless=0`, `--manual-clock=false` were ignored (only the bare flag counted) and now switch off what the config turned on, and `--control=1` turns it on; a value that is not `true`, `false`, `1` or `0` (`--control=maybe`) was ignored and now stops the start-up with an error. Adapt: a launcher or script that passes such a flag with a value checks that the value is one of the four.
- The flag constants of `BECore/Control/ControlSettings.h` name the flag, not its prefix: `kControlPortPrefix`, `kReplayPrefix`, `kWindowPrefix`, `kDensityPrefix` are `kControlPort`, `kReplay`, `kWindow`, `kDensity` (`--control-port`, without `=`). Adapt: use the new name and `CommandLine::Find`; no game uses them today.

## 0.3.0 - 2026-11-17 - PoolString: entries are copied and hashed one by one at runtime, code constants and field names too; fixed table, no batch, two bugs

Entry: `pool-string-refactor`. Bump: minor.

### Added

- `PoolString::GetStats()` (`PoolStringStats`): strings and bytes by source (runtime, static, adopted), blocks, table capacity, load and longest probe, hits, misses, write locks, batch calls, dead entries of adopted blocks, heap-fallback blocks. A hit adds no shared write (per-thread counter slots, 64 B per thread that ever interned, never freed).
- `PoolString::InternBatch(texts, out)` (hashes every text; for outside data) and `InternBatch(texts, hashes, out)` (trusts the hashes; checked in Debug): one shared pass, one unique lock, one table growth, one allocation. `FileSystem::EnumerateFiles`, `SaveGameService::List` and `ConfigManager` use it.
- `PoolString::RegisterStatic`: inserts ready `const` entries by pointer, no hashing and no copy; the first entry of a text wins and the value is re-pointed to it.
- `PoolString::Reserve(strings, bytes)`: a hint for the table capacity and one block; a hint that cannot be right (overflow, above `kMaxReservedEntries` or the arena) is ignored.
- `PoolString::AllocateBlock(bytes)` + `AdoptBlock(block, out, options)` (`PoolString/PoolBlock.h`): a caller lays entries out in a pool-owned block and the pool validates the whole block, then links it; the token is spent on success; `PoolAdoptError` is a `CORE_ENUM`.
- The pool's memory comes from `IPoolBlockSource` (`PoolString/PoolBlockSource.h`): a reserved, bump-only virtual-memory arena on native platforms (`kDefaultReservedBytes`), the heap on wasm and as a fallback.
- `ReaderLimits::kMaxPoolStringBytes`: XML, binary and JSON readers refuse a `PoolString` value longer than it with an error before interning; the field keeps its value.
- Shared constants: `MountPoints` (`FileSystem/MountPoints.h`), `ConfigNames` (`Config/ConfigNames.h`), `TexturePaths::memory` (`Renderer/ITexture.h`), `SaveMount::point` (`Save/SaveGame.h`).
- `CI/scripts/check_pool_strings.py` with `CI/pool_strings_allowlist.txt`, run by the ctest `BagiPoolStrings`: a literal in `PoolString::Intern`/`Find` (also through `StringView{"x"}`, `"x"sv`, a ternary of literals), the same `_intern` text in two non-test files, more than two loose `_intern` in one file, a loose `_intern` in a header; `--allowlist` rows need a reason, a stale row is a finding.

### Changed

- The pool table is open addressing over `{hash, entry}` slots and grows; an entry header is 12 bytes (hash, size) with no chain pointer. `PoolString` stays one pointer (`static_assert`) and equality stays a pointer compare.
- A string longer than a block gets a block of its own; before, it was written past the end of a 128 KB page (a heap overflow reachable from a save or content file).
- `"text"_intern` constants are ready entries in the program image, registered on first use without hashing or copying; a constant no longer puts anything into the pool's blocks.
- `StaticPoolString` compared with a `PoolString` through `>`, `<=`, `>=` recursed forever; it now compares the texts.
- The process-wide pool is never destroyed, so a static destructor may still read a `PoolString` at exit.

### Breaking

- `PoolString::Intern("literal")` and `PoolString::Find("literal")` do not compile (deleted overloads for a `const char[N]`). Adapt: write `"literal"_intern` for a code constant, `PoolString::Intern(StringView(buffer))` for a runtime `char` buffer, `PoolString::Find(StringView{"literal"})` to ask whether a text was interned; a ternary of two literals becomes `c ? "a"_intern.ToPoolString() : "b"_intern.ToPoolString()`.
- `DeserializeError::path` and `errorMessage` are `String`, not `PoolString`; error texts no longer go into the pool. Adapt: drop `.ToStringView()` on them (a `String` converts to `StringView`) and write `.c_str()` for `.CStr()`.
- A `PoolString` field longer than `ReaderLimits::kMaxPoolStringBytes` (4096 bytes) is now a load error and keeps its default. Adapt: keep names, ids and keys short; a longer text belongs in a `String` field, or the game raises the constant.
- `PoolStringChain` is removed. Adapt: for a key of a name and a number use a `struct { PoolString name; int index; }` with a hash over both fields.
- The constants rules hold for a game's sources once it runs the check. Adapt: add `CI/scripts/check_pool_strings.py --root . --allowlist <the game's allowlist>` next to the engine's checks (`.claude/rules/build-project.md`), move the loose `_intern` of a file into a file-local `struct Ids { static constexpr auto name = "name"_intern; }`, and a text used in two files into one structure in a header.
