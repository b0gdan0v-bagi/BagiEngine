## 0.3.0 - 2026-11-17 - PoolString: entries are copied and hashed one by one at runtime, code constants and field names too; fixed table, no batch, two bugs

Entry: `pool-string-refactor`. Bump: minor.

### Added

- `PoolString::GetStats()` (`PoolStringStats`): strings and bytes by source (runtime, static, adopted), blocks, table capacity, load and longest probe, hits, misses, write locks, batch calls, dead entries of adopted blocks, heap-fallback blocks. A hit adds no shared write (per-thread counter slots, 64 B per thread that ever interned, never freed).
- `PoolString::InternBatch(texts, out)` (hashes every text; for outside data) and `InternBatch(texts, hashes, out)` (trusts the hashes; checked in Debug): one shared pass, one unique lock, one table growth, one allocation. `FileSystem::EnumerateFiles`, `SaveGameService::List` and `ConfigManager` use it.
- `PoolString::RegisterStatic`: inserts ready `const` entries by pointer, no hashing and no copy; the first entry of a text wins and the value is re-pointed to it.
- `PoolString::Reserve(strings, bytes)`: a hint for the table capacity and one block; a hint that cannot be right (overflow, above `kMaxReservedEntries` or the arena) is ignored.
- `PoolString::AllocateBlock(bytes)` + `AdoptBlock(block, out, options)` (`PoolString/PoolBlock.h`): a caller lays entries out in a pool-owned block and the pool validates the whole block, then links it; the token is spent on success; `PoolAdoptError` is a `CORE_ENUM`.
- The pool's memory comes from `IPoolBlockSource` (`PoolString/PoolBlockSource.h`): a reserved, bump-only virtual-memory arena on native platforms (`kDefaultReservedBytes`), the heap on wasm and as a fallback.
- `ReaderLimits::kMaxPoolStringBytes`: XML, binary and JSON readers refuse a `PoolString` value longer than it with an error before interning; the field keeps its value.
- Shared constants: `MountPoints` (`FileSystem/MountPoints.h`), `ConfigNames` (`Config/ConfigNames.h`), `TexturePaths::memory` (`Renderer/ITexture.h`), `SaveMount::point` (`Save/SaveGame.h`).
- `CI/scripts/check_pool_strings.py` with `CI/pool_strings_allowlist.txt`, run by the ctest `BagiPoolStrings`: a literal in `PoolString::Intern`/`Find` (also through `StringView{"x"}`, `"x"sv`, a ternary of literals), the same `_intern` text in two non-test files, more than two loose `_intern` in one file, a loose `_intern` in a header; `--allowlist` rows need a reason, a stale row is a finding.

### Changed

- The pool table is open addressing over `{hash, entry}` slots and grows; an entry header is 12 bytes (hash, size) with no chain pointer. `PoolString` stays one pointer (`static_assert`) and equality stays a pointer compare.
- A string longer than a block gets a block of its own; before, it was written past the end of a 128 KB page (a heap overflow reachable from a save or content file).
- `"text"_intern` constants are ready entries in the program image, registered on first use without hashing or copying; a constant no longer puts anything into the pool's blocks.
- `StaticPoolString` compared with a `PoolString` through `>`, `<=`, `>=` recursed forever; it now compares the texts.
- The process-wide pool is never destroyed, so a static destructor may still read a `PoolString` at exit.

### Breaking

- `PoolString::Intern("literal")` and `PoolString::Find("literal")` do not compile (deleted overloads for a `const char[N]`). Adapt: write `"literal"_intern` for a code constant, `PoolString::Intern(StringView(buffer))` for a runtime `char` buffer, `PoolString::Find(StringView{"literal"})` to ask whether a text was interned; a ternary of two literals becomes `c ? "a"_intern.ToPoolString() : "b"_intern.ToPoolString()`.
- `DeserializeError::path` and `errorMessage` are `String`, not `PoolString`; error texts no longer go into the pool. Adapt: drop `.ToStringView()` on them (a `String` converts to `StringView`) and write `.c_str()` for `.CStr()`.
- A `PoolString` field longer than `ReaderLimits::kMaxPoolStringBytes` (4096 bytes) is now a load error and keeps its default. Adapt: keep names, ids and keys short; a longer text belongs in a `String` field, or the game raises the constant.
- `PoolStringChain` is removed. Adapt: for a key of a name and a number use a `struct { PoolString name; int index; }` with a hash over both fields.
- The constants rules hold for a game's sources once it runs the check. Adapt: add `CI/scripts/check_pool_strings.py --root . --allowlist <the game's allowlist>` next to the engine's checks (`.claude/rules/build-project.md`), move the loose `_intern` of a file into a file-local `struct Ids { static constexpr auto name = "name"_intern; }`, and a text used in two files into one structure in a header.

## 0.2.2 - 2026-11-16 - Computed values: no formulas in data, compiled into fast typed programs for any value type

Entry: `data-values-programs`. Bump: patch.

### Added

- `Value<T>` of the kind `Program`: a field written `expr="caster.attack * (100 + ability.level * 10) / 100"` is parsed, type-checked against the context, constant-folded and compiled at load into a flat typed program (`Values/Programs/`); `Value<T>::Evaluate(context)` runs it with no allocation and no virtual call. XML, binary and JSON load and save `expr`.
- Program types: the scalars, `Vec2`, `Vec3`, `Vec4`, `IVec2`, `Quat`, `Color`, enums and `PoolString` (equality); components (`pos.y`) and constructors (`vec3(a, b, c)`), mixed pairs (`Vec3 * float`, `Quat * Vec3`), `lerp`, `clamp`, `min`, `max`, `select`, `dot`, `length`, `normalize`; a missing operator is a load error naming the file, the field and the place in the text.
- Tables: inline `at(i, e0, e1, ...)` and named `ByLevel('Name', i)` (0-based) over a `ValueTableSet` provider the game puts on the `ValueLinkScope`.
- The tree form: reflected node classes `CalcNode` (`CalcNumber`, `CalcRead`, `CalcBinary`, `CalcCall`, `CalcByLevel`, ...; `Values/Nodes/`) loaded from the key `tree` of a `Value` in the engine's factory form, compiled by the same code and saved as text.
- `CompileValue<T>` (`Programs/ProgramCompiler.h`): compile a text to a `Value<T>` from code, the entry point for `data-bindings`; `CompileOptions::fuse` turns the peephole superinstructions (`slot * k + b`, `lerp` of slots, a table over a slot) on or off.
- `CachedValue<T>`: keeps a program's last result while the version key of the levels it reads holds; `Context::IsVersioned(levels)`.
- `TypeDesc::enumBytes`: the size of an enum, part of its identity in `SameType`.
- Benchmarks of `int32_t` and `Vec3` formulas (plain C++, virtual tree, program fused and unfused, cached) in the `value-get` perf set.

### Changed

- `Context::VersionKey` also folds the address of each level's object and counter: another object at a level gives another key even when the numbers agree, and a context rebuilt each frame over the same objects gives the same key.
- `Lerp(Color)` returns 0 in every channel for a NaN `t` instead of undefined behaviour.
- `Value<T>::Reads()` of a `Program` returns the levels the program reads.

## 0.2.0 - 2026-11-16 - Assert and logger: handlers and sinks run against their configured priority; assert and log paths are not safe off the main thread

Entry: `assert-logger-handler-order`. Bump: minor.

### Added

- `IAssertHandler::Disconnect()` and `ILogSink::Disconnect()`: drop every connection of a handler or sink.
- `Logger::FlushOnMainThread()`: delivers pending lines to the sinks when called on the main thread.
- `Logger/LogTime.h`: `GetLocalLogTime()`, the one local-time helper of the sinks.

### Changed

- Assert handlers and log sinks now run in their configured priority order (lower first, equal ones in config order), as the configs and docs always said; before, the order was reversed, so `DebugBreakHandler` trapped before `LogHandler` logged.
- The log line of an assert carries its file and line and is flushed before a trap or crash.
- `AssertEvent` is safe to emit from any thread (one lock; handlers run one at a time on the failing thread); DbgHelp on Windows is serialised.
- `Logger::Fatal` / `LOG_FATAL` flush immediately only on the main thread; from a worker the line goes out at the next frame flush.
- `FileSink::Write` prints exactly the view it is given.

### Breaking

- `IAssertHandler::Initialize()` and `ILogSink::Initialize()` are now called again by the managers, after a disconnect, to fix the delivery order: an override that connects only once (behind an `_initialized` flag) ends up disconnected. Adapt: connect on every call of `Initialize()` and keep only one-time setup behind a flag of your own.
- A game whose own sinks or handlers relied on the old reversed order now sees them in config order. Adapt: check the `priority` values of the game's `LoggerConfig.xml` / `AssertHandlersConfig.xml` (lower runs first).

## 0.1.16 - 2026-11-16 - Reflection: no access by name at run time: no type registry, property paths or callable methods

Entry: `reflection-runtime-access`. Bump: patch.

### Added

- `TypeRegistry` (`BECore/Reflection/`): every reflected type (`BE_CLASS`, `BE_EVENT`) registers a `TypeInfo` at start-up, with its name, parent, fields (attributes, `TypeDesc`, offset), methods (`callable` when every parameter and the result go through `Ser::`) and a creator for a factory type. A game's types appear after its next `cmake --preset`, with no change of its own.
- Property paths (`a.b[2].c`): `GetProperty` / `SetProperty` through `IPropertyVisitor`, with type, range and `readonly` checks, and compiled paths (offset and `TypeDesc` of the fixed part).
- `MethodHandle`: a `BE_FUNCTION` method called by name, its arguments read through an `IDeserializer` and its result written through an `ISerializer`.
- `JsonSerializer` / `JsonDeserializer` (`BECore/Control/`): an interim JSON pair over the checked `Json` DOM, with a fuzz target. The allocation-free reader stays `json-deserializer`.
- Control API over named roots (`ControlRoots`; `game` is the active game): `list_types`, `describe_type`, `schema`, `get_property`, `set_property`, `call_method`, each described for `list_methods`.
- `tools/schema`: an XSD per `config/*.xml` made from the live schema, for completion and checking in VS Code. The `BagiStress` control smoke validates the engine's own config files against it.

### Changed

- The `BE_FUNCTION` marks on the widget lifecycle overrides (`IWidget::Initialize` / `Update` / `DrawScreen` / `Draw` and the same on the engine's widgets) are removed: a marked method is one that may be called from outside. Adapt: a game widget that marked its lifecycle overrides with `BE_FUNCTION` drops the mark; nothing called them by name.
