## 0.1.6 - 2026-11-16 - Todo Workers panel: the next slice of a held entry waited forever, and the CLI's start mark was not read

Entry: `panel-starting-mark`. Bump: patch.

### Changed

- Todo Workers 0.28.1 (`tools/vscode/todo-workers`): `Runs.queueStartBlock` lets a worker start when the head of its own queue is the entry (or `todo/*` branch) it holds, as `worker.py start` does: 0.28 left the next through slice and a remarks round waiting. It also holds the start while `worker.py list` shows the `starting` mark the CLI writes before its session is listed.

## 0.1.5 - 2026-11-16 - Todo Workers panel: the queue start trusted the session state alone and started a second loop in a busy worker

Entry: `panel-queue-start-guard`. Bump: patch.

### Changed

- Todo Workers 0.28 (`tools/vscode/todo-workers`): the panel starts a worker's next queued entry only when no `todo/*` branch whose entry is not in review is checked out in the game or `engine/`, no session started in the last 3 minutes, and the worker has looked free for 45 s on end (`Runs.queueStartBlock`). `worker.py list` names the newest session of `todo-w<k>`, so a live loop could hide behind a newer one that ended.

## 0.1.4 - 2026-11-16 - Reflection: no access by name at run time: no type registry, property paths or callable methods

Entry: `reflection-runtime-access`. Bump: patch.

### Added

- `TypeRegistry` (`BECore/Reflection/`): every reflected type (`BE_CLASS`, `BE_EVENT`) registers a `TypeInfo` at start-up, with its name, parent, fields (attributes, `TypeDesc`, offset), methods (`callable` when every parameter and the result go through `Ser::`) and a creator for a factory type. A game's types appear after its next `cmake --preset`, with no change of its own.
- Property paths (`a.b[2].c`): `GetProperty` / `SetProperty` through `IPropertyVisitor`, with type, range and `readonly` checks, and compiled paths (offset and `TypeDesc` of the fixed part).
- `MethodHandle`: a `BE_FUNCTION` method called by name, its arguments read through an `IDeserializer` and its result written through an `ISerializer`.
- `JsonSerializer` / `JsonDeserializer` (`BECore/Control/`): an interim JSON pair over the checked `Json` DOM, with a fuzz target. The allocation-free reader stays `json-deserializer`.
- Control API over named roots (`ControlRoots`; `game` is the active game): `list_types`, `describe_type`, `schema`, `get_property`, `set_property`, `call_method`, each described for `list_methods`.
- `tools/schema`: an XSD per `config/*.xml` made from the live schema, for completion and checking in VS Code. The `BagiStress` control smoke validates the engine's own config files against it.

### Changed

- The `BE_FUNCTION` marks on the widget lifecycle overrides (`IWidget::Initialize` / `Update` / `DrawScreen` / `Draw` and the same on the engine's widgets) are removed: a marked method is one that may be called from outside. Adapt: a game widget that marked its lifecycle overrides with `BE_FUNCTION` drops the mark; nothing called them by name.

## 0.1.3 - 2026-11-16 - No computed values in data: a field is a literal, never read from a context, for any value type

Entry: `data-values-core`. Bump: patch.

### Added

- `BECore/Values/`: `Value<T>`, a field that is a literal or a slot of a context (`Const`, `Slot`; `Program` is reserved and refused at load), `Get(const Context&)` inline with no indirect call. The value types are the trivially copyable reflected ones, `PoolString`, enums and the math types (`ValueType.h`).
- `Context` / `ContextDecl`: levels that point at reflected structs the game already has (nothing copied); a path such as `caster.position.x` is linked at load to (level, offset, type), and an unknown path or a type mismatch is a load error that names the document, the field, the path and the fields the type has.
- Content: `<damage value="12"/>` and `<damage from="caster.attack"/>`; the plain attribute `damage="12"` keeps loading, so no migration. `<context>` declares the levels in the document (list form in every format, `<context caster="UnitStats"/>` in text formats); `MakeFromConfig` opens the link scope with the config's name. XML, binary and JSON read and write `Value<T>`.
- Versions per level for caching: `Context::Set(level, object, version)`, `VersionKey`, `Value::Reads`, `ValueDependencies`.
- `IDeserializer::AttributeNames` and `IsScalarMember` (defaults keep every existing reader as it was).
- Opaque value types (`Vec2`, `Vec3`, `Color`, ...) get an identity (size and name hash) in `TypeDesc`, so `SameType` and compiled paths tell them apart.
- Benchmark `ValueBench` and the `/perf` entry `value-get` (gate off until a baseline exists).

## 0.1.1 - 2026-11-15 - Animation: a timeline cannot repeat forever or play back and forth (yoyo): no idle loops, pulses or shimmer

Entry: `timeline-repeat-yoyo`. Bump: patch.

### Added

- `Timeline::Yoyo()`: every second iteration is the exact time reversal of a forward one (clips, delays, callbacks and sub-timelines mirrored).
- `Timeline::RepeatForever()` / `IsEndless()`: an endless timeline; `TweenManager::Play` of one runs until it is cancelled (no `onComplete`, `GetProgress()` stays 0).
- `Timeline::Advance(dt)`: evaluation by the time since the last call, exact for runs of any length.
- `AnimationFrameClass` (`Interactive`, `FiniteEffect`, `DecorativeLoop`), `Timeline::SetFrameClass` / `GetFrameClass`, `TweenHandle::GetFrameClass` and `TweenManager::GetActiveCount(class)`: what keeps the frame loop awake.
