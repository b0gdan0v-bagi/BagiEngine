## 0.11.1 - 2026-11-23 - Subscriptions, event awaiters, timer links and tween waiters allocate on first use; MoveOnlyFunction heap path uncounted

Entry: `events-awaiters-inline`. Bump: patch.

### Changed

- `SubscriptionHolder` keeps two connections inside the object, an `EventAwaiter` holds its one connection, the link of a timed await comes from a pool and a tween handle keeps its first waiter inline: a subscription, a `co_await` of an event (with or without a timeout) and the first waiter of a tween no longer allocate from the heap. The price is size: `SubscriptionHolder` is 96 bytes (was 32), so `IComponent` is 128 (was 64), `IWidget` 112.
- The heap path of `MoveOnlyFunction` (a capture over its inline size) is counted under its own name in the allocation tracker.

## 0.11.0 - 2026-11-23 - IntrusivePtr and RefCounted: fix conversions, merge the atomic and non-atomic pointers, add tests

Entry: `intrusive-ptr-cleanup`. Bump: minor.

### Added

- `IntrusivePtr<T>` has `StaticPointerCast` / `DynamicPointerCast`, a hash, `swap`, `Detach()` (give up ownership without a release) and an adopt constructor; `RefCounted` asserts its count in debug builds.

### Changed

- `IntrusivePtrAtomic<T>` and `IntrusivePtrNonAtomic<T>` are deprecated aliases of the one `IntrusivePtr<T>` (the counter is the class's: `RefCounted` or `RefCountedAtomic`), and `MakeIntrusive(args...)` is a deprecated forwarder of `New<T>(args...)`; both stay for one merge. Adapt: spell `IntrusivePtr<T>` and `New<T>`.

### Breaking

- `BECore/RefCounted/Delete.h` is gone, and `RefCounted::ReleaseRef()` returns `void` (it returned whether the object was deleted). Adapt: drop the include; code that used the result of `ReleaseRef` holds an `IntrusivePtr` instead.
- Conversions between `IntrusivePtr` types compile only from a derived to a base type (implicitly) or through `StaticPointerCast` / `DynamicPointerCast`. Adapt: replace a conversion the compiler now refuses with the matching cast.
- The meta generator now sees a factory base in a reflected field of type `IntrusivePtr<Base>` too (before only under the two long names), so such a field is read and written through the factory. Adapt: a field that must stay a plain pointer field gets `BE_FIELD_ATTRS(no_factory)`; re-run `cmake --preset` to regenerate the reflection code.

## 0.10.4 - 2026-11-23 - Font atlas build allocates per glyph on the heap (19k blocks, 90 MB per ui atlas) and is rebuilt on a scene switch

Entry: `font-atlas-scratch`. Bump: patch.

### Added

- `Font::GetGlyphBox()` and `Font::RasterizeGlyphInto()` measure and draw a glyph into a caller's buffer with no heap allocation; `GlyphOutline::Kernel` and a `Dilate` into a caller's buffer do the same for outlines.

### Changed

- Building a font atlas keeps its temporaries, and stb_truetype's, in the thread's scratch arena and rasterizes straight into the page: about 8 times fewer heap allocations per atlas, the same pixels. Showing a scene again builds no atlas (a test guards it).

Entry: `room-server-alloc-trace`. Bump: patch.

### Added

- The allocation profiler keeps a size histogram per zone: `zone_allocs` answers it as `sizes`, the Chrome trace as `otherData.allocSizes`, and `tools/perf/trace_summary.py` prints the names and the sizes.
- The allocations of SDL, stb and pugixml are counted under their own names in `zone_allocs` instead of as unnamed blocks.

### Changed

## 0.10.0 - 2026-11-23 - SceneNode keeps its components and children in heap vectors: 1-2 allocations per created node (the last per-node heap allocation)

## 0.9.6 - 2026-11-23 - A text change rebuilds its layout result from scratch: ~4.5 heap allocations per layout, no capacity reuse

## 0.9.5 - 2026-11-23 - Formula and effect compile builds 15-30 heap temporaries per formula; interned programs hold heap vectors

Entry: `values-compile-scratch`. Bump: patch.

### Changed

- Compiling a formula or an effect keeps its temporaries (tokens, syntax tree, checker and lowering tables, builder code) in the thread's scratch arena: about 42 % fewer heap allocations per compile, at content load and on every editor edit of a formula.
- The program pool keeps the code and constants of interned programs in one arena of its own instead of two heap vectors per program (fewer heap blocks; the held bytes grow by the arena's first chunk).

## 0.9.0 - 2026-11-23 - Compile time: CoreManager.h includes every manager and EnTT sits in every TU through the event headers

Entry: `compile-hubs-coremanager-entt`. Bump: minor.

### Changed

- `CoreManager.h` no longer includes the header of any service: every service is held by pointer and only declared there, so a file that includes it parses none of the managers. A clean build of the engine's tests costs about 10 % less CPU.
- `FrameKind` lives in `BECore/Time/FrameKind.h`; `Time/GamePause.h` includes it, so code that took it from there is unchanged.

### Breaking

- A file that uses what a `CoreManager` getter returns must include that service's header itself, as `CoreManager.h` no longer brings it in: `GetTime()` needs `<BECore/Time/Time.h>`, `GetFileSystem()` `<BECore/FileSystem/FileSystem.h>`, `GetConfigManager()` `<BECore/Config/ConfigManager.h>`, `GetCommandLine()` `<BECore/Application/CommandLine.h>`, `GetResourceManager()` / `GetTextureLibrary()` `<BECore/Resource/...>`, `GetUIVars()` / `GetUIStrings()` / `GetUIThemes()` / `GetUIEnvironment()` `<BECore/UI/...>`, `GetTweens()` `<BECore/Animation/TweenManager.h>`, `GetControlService()` `<BECore/Control/ControlService.h>`, `GetAudio()` `<BECore/Audio/AudioManager.h>`, and so on for each getter. Code that called `IGame::Cast<T>()` and relied on `CoreManager.h` for `ClassMeta` includes `<BECore/Reflection/ClassMeta.h>`. Adapt: build the game, and for each "member access into incomplete type 'X'" add the include of X's header to that file (the getters' names and return types are unchanged).

## 0.8.4 - 2026-11-21 - Derived values keep version keys by hand: no rebuild by declared dependencies, a forgotten key is a stale screen or an allocation per frame

Entry: `data-values-reactive`. Bump: patch.

### Added

- `Derived<T>` (`BECore/Values/Derived/Derived.h`): a cached value rebuilt only when one of its declared reads moved. The reads are a `DerivedReads`: version counters (`AddSource`) and levels of a `Context` (`AddLevel`, `AddLevels`); the builder is passed to `Get`, and a hit allocates nothing. In a build with asserts the builder gets `Context::Restricted(levels)`, so reading an undeclared level fails an assert instead of leaving a stale value.
- `UIAmbient` (`BECore/UI/UIAmbient.h`): the language and the window metrics as the context levels `language` and `window` (`UIAmbient::Declare`, `UIAmbient::Fill`), fed by `UIStrings::GetLanguageView()` and `UICanvasComponent::GetWindowView()` / `GetWindowVersion()`.
- `UIStrings::GetVersionCounter()` and `UIVars::GetVersionCounter()`: the address of the version counter, for `DerivedReads::AddSource` and `Context::Set`.
- `UITextPainter::GetExpandCount()` and `UITextComponent::GetExpandCount()`: how many times the display text was expanded.
- Benchmarks `derived_*` of `ValueBench` in the perf set: the cost of a `Derived` hit.

### Changed

- `UITextPainter` keeps its expanded text as a `Derived<String>`; when a text is expanded again is unchanged (its source, a `UIVars` variable, or the string table for a text with a `{#key}`).
  Adapt: nothing; a game that keeps version keys by hand for a screen value can move it to `Derived` over its `Context` and the `UIAmbient` levels.

## 0.8.3 - 2026-11-21 - Tasks: submitting a task allocates (std::function, heap nodes); no move-only captures

Entry: `task-alloc-free`. Bump: patch.

### Added

- `ThreadPool::IsRunningInlineJob()`: on an inline pool, true while a job runs on this stack (the jobs queued by it included); always false on a worker pool.

  Adapt: nothing; a game's own `Task` coroutines take their frames from the pools without a change.
- The inline pool (single-thread build) no longer wraps each background job in a second callable.
  Adapt: nothing.

## 0.8.2 - 2026-11-20 - Loading an asset allocates field by field: no size hints in the file for one arena and exact reserves

### Changed

## 0.8.1 - 2026-11-20 - Computed values: no operations over arrays (count, any, all, sum, min, max over a reflected array)

### Added

## 0.7.2 - 2026-11-20 - Computed values: a game cannot add its own value types and operations (a 256-bit cell mask, its opcodes)

### Changed

- Program registers are 32 bytes (`kProgramRegisterBytes`) so a registered type of up to 32 bytes fits; the engine's formula results are unchanged.
  Adapt: nothing.

## 0.7.0 - 2026-11-20 - Engine containers use EASTL's default allocator: no memory tags per subsystem, no single point to route or account memory

Entry: `engine-allocator-tags`. Bump: minor.

### Added

- `BECore/Memory/MemTag.h`: memory tags (`MemTag::Core`, `UI`, `Text`, `Scene`, `Resource`, `Audio`, `Network`, `Game`). `BE_MEM_TAG(UI)` counts every allocation the thread makes until the end of the scope under that tag, whoever makes it; scopes nest and the tag is the thread's. The engine tags its own subsystem entry points and the callbacks of `IGame` (`Game`). Only with `ENGINE_PROFILER_ALLOC`; otherwise the scope costs nothing.
  Adapt: nothing; a game may tag its own coarse entry points (never inside a coroutine).

  Adapt: nothing.
- Statistics per tag: `AllocTracker::GetTagTotals()`, `FrameStats::tagAllocCount` / `tagLiveBytes`, and in the control method `frame_stats` the per-frame `tagAllocCount` / `tagLiveBytes` by tag name and a top-level `tags` list.
  Adapt: nothing; a tool that reads `frame_stats` may show the new fields.

### Breaking

  Adapt: spell the engine aliases instead of `eastl::` types; where a value of the old type is unavoidable, copy it by range (`String{view}`) or compare views (`StringView{a} == StringView{b}`).

## 0.6.12 - 2026-11-20 - Memory: no fixed-size pools for small frequent objects (nodes, events, tokens, tasks)

Entry: `memory-pools`. Bump: patch.

### Added

  Adapt: nothing; a game's own small, frequently created class may opt in after measuring it.

  Adapt: nothing; a tool that reads `frame_stats` may show the new fields.

### Changed

- `SceneNode`, `TransformComponent`, `SpriteRendererComponent`, `TweenHandle`, `UIElement` and `UITextComponent` are allocated from single-thread pools, and `CancellationToken`'s state from a concurrent pool. A class derived from a pooled one keeps using the heap (the pool is told apart by size). A class-scope `operator new` hides the global ones: a `nothrow` or aligned `new` of these types no longer compiles.
  Adapt: create and destroy these objects on the main thread, as before (the Debug build asserts it); a game class derived from them needs nothing, or `BE_POOLED_SINGLE_THREAD(Derived)` to get a pool of its own.

## 0.3.0 - 2026-11-17 - PoolString: entries are copied and hashed one by one at runtime, code constants and field names too; fixed table, no batch, two bugs

Entry: `pool-string-refactor`. Bump: minor.

### Added

- `PoolString::GetStats()` (`PoolStringStats`): strings and bytes by source (runtime, static, adopted), blocks, table capacity, load and longest probe, hits, misses, write locks, batch calls, dead entries of adopted blocks, heap-fallback blocks. A hit adds no shared write (per-thread counter slots, 64 B per thread that ever interned, never freed).
- `PoolString::InternBatch(texts, out)` (hashes every text; for outside data) and `InternBatch(texts, hashes, out)` (trusts the hashes; checked in Debug): one shared pass, one unique lock, one table growth, one allocation. `FileSystem::EnumerateFiles`, `SaveGameService::List` and `ConfigManager` use it.
- `PoolString::RegisterStatic`: inserts ready `const` entries by pointer, no hashing and no copy; the first entry of a text wins and the value is re-pointed to it.
- `PoolString::Reserve(strings, bytes)`: a hint for the table capacity and one block; a hint that cannot be right (overflow, above `kMaxReservedEntries` or the arena) is ignored.
- `PoolString::AllocateBlock(bytes)` + `AdoptBlock(block, out, options)` (`PoolString/PoolBlock.h`): a caller lays entries out in a pool-owned block and the pool validates the whole block, then links it; the token is spent on success; `PoolAdoptError` is a `CORE_ENUM`.
- The pool's memory comes from `IPoolBlockSource` (`PoolString/PoolBlockSource.h`): a reserved, bump-only virtual-memory arena on native platforms (`kDefaultReservedBytes`), the heap on wasm and as a fallback.
- `ReaderLimits::kMaxPoolStringBytes`: XML, binary and JSON readers refuse a `PoolString` value longer than it with an error before interning; the field keeps its value.
- Shared constants: `MountPoints` (`FileSystem/MountPoints.h`), `ConfigNames` (`Config/ConfigNames.h`), `TexturePaths::memory` (`Renderer/ITexture.h`), `SaveMount::point` (`Save/SaveGame.h`).
- `CI/scripts/check_pool_strings.py` with `CI/pool_strings_allowlist.txt`, run by the ctest `BagiPoolStrings`: a literal in `PoolString::Intern`/`Find` (also through `StringView{"x"}`, `"x"sv`, a ternary of literals), the same `_intern` text in two non-test files, more than two loose `_intern` in one file, a loose `_intern` in a header; `--allowlist` rows need a reason, a stale row is a finding.

### Changed

- The pool table is open addressing over `{hash, entry}` slots and grows; an entry header is 12 bytes (hash, size) with no chain pointer. `PoolString` stays one pointer (`static_assert`) and equality stays a pointer compare.
- A string longer than a block gets a block of its own; before, it was written past the end of a 128 KB page (a heap overflow reachable from a save or content file).
- `"text"_intern` constants are ready entries in the program image, registered on first use without hashing or copying; a constant no longer puts anything into the pool's blocks.
- `StaticPoolString` compared with a `PoolString` through `>`, `<=`, `>=` recursed forever; it now compares the texts.
- The process-wide pool is never destroyed, so a static destructor may still read a `PoolString` at exit.

### Breaking

- `PoolString::Intern("literal")` and `PoolString::Find("literal")` do not compile (deleted overloads for a `const char[N]`). Adapt: write `"literal"_intern` for a code constant, `PoolString::Intern(StringView(buffer))` for a runtime `char` buffer, `PoolString::Find(StringView{"literal"})` to ask whether a text was interned; a ternary of two literals becomes `c ? "a"_intern.ToPoolString() : "b"_intern.ToPoolString()`.
- `DeserializeError::path` and `errorMessage` are `String`, not `PoolString`; error texts no longer go into the pool. Adapt: drop `.ToStringView()` on them (a `String` converts to `StringView`) and write `.c_str()` for `.CStr()`.
- A `PoolString` field longer than `ReaderLimits::kMaxPoolStringBytes` (4096 bytes) is now a load error and keeps its default. Adapt: keep names, ids and keys short; a longer text belongs in a `String` field, or the game raises the constant.
- `PoolStringChain` is removed. Adapt: for a key of a name and a number use a `struct { PoolString name; int index; }` with a hash over both fields.
- The constants rules hold for a game's sources once it runs the check. Adapt: add `CI/scripts/check_pool_strings.py --root . --allowlist <the game's allowlist>` next to the engine's checks (`.claude/rules/build-project.md`), move the loose `_intern` of a file into a file-local `struct Ids { static constexpr auto name = "name"_intern; }`, and a text used in two files into one structure in a header.

## 0.1.8 - 2026-11-16 - Reflection: no access by name at run time: no type registry, property paths or callable methods

### Added

### Changed
