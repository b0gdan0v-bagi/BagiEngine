# Web Tools Guidelines

## Overview

Python tools for the browser build (entry `web-build` of the todo store; the CMake side is `cmake/BagiWeb.cmake` and the presets `web-release` / `web-debug` (threaded, the default) and `web-release-single-thread` / `web-debug-single-thread`, `.claude/rules/cmake-rules.md`; the page is `web/shell.html`). Separate processes, standard library only (Python 3.10+; `brotli` when it can be imported). Nothing here names a game apart from `BagiMatch3` as the default. The unit tests build a fake build output; the real build is checked by the browser smoke (`tests/CLAUDE.md`).

| File | Purpose |
|------|---------|
| `package.py` | `package.py <build-dir> <out-dir> [--game NAME] [--single-thread] [--app FILE]`: a web build's `<game>.html` / `.js` / `.wasm` / `.data` into a folder to serve. The page becomes `index.html`, the rest keep their names (they load each other by name); each of the four gets `name.gz`, and `name.br` when `import brotli` works; `manifest.json` is `{game, threads, files: {name: {size, sha256, gzip, brotli}}}`, `threads: false` with `--single-thread` (`serve.py` decides the isolation headers on it). Files of an earlier run that the new manifest does not list (and a stale `.br`) are deleted; other kinds are left alone. It also writes `manifest.webmanifest` (never `manifest.json`: that is the package manifest) and `icons/` (cleaned each run), listed in `manifest.json` with no `.gz` / `.br`: "The web app file". Several pages need `--game`; a missing `.js` / `.wasm`, or a `.data` the script names, is an error; the output folder must not be, hold or sit in the build folder (`PackageError`: the cleaning would delete the page) |
| `serve.py` | The static server of the Railway service. **One file that imports nothing of this repository** (the Docker image copies only it; a test checks it). `serve.py --root dist [--host H] [--port P] [--cross-origin-isolation \| --no-cross-origin-isolation] [--quiet]`; `PORT` (default 8080), `COOP_COEP=1/0`, `BASIC_AUTH_*` or the sign-in (`ACCESS.md`) from the environment; with `MATCH_STORE` also the match endpoint (`MATCH_STORE_MAX_MB`, `MATCH_LOG_VERSIONS`, `MATCH_FORWARDED_FOR`: "Match logs"). The headers and the isolation decision: "The headers of `serve.py`, and why" |
| `build_and_deploy.py` | The one command: configure and build the preset, `package.py` (with `--app <source>/web/app.json` when that file exists; its own `--app` wins), and with `--deploy` the staging and `railway up <staging> --path-as-root --service <name> --detach`. `--single-thread` adds the suffix `-single-thread` to the preset, packages `build/<preset>/bin` of that preset (`--build-dir` wins) and packages with `--single-thread`. `--dry-run` prints the commands. Programs are started by the path `shutil.which` found. Exit 2 with `run: python CI/scripts/setup_emsdk.py` when the SDK in `external/emsdk` is missing (also with `--dry-run`), when `--deploy` finds no `railway` on PATH, or when a program cannot start or the staging fails |
| `Dockerfile` | `python:3.12-slim`, `COPY serve.py` and `dist/`, `CMD ["python", "serve.py", "--root", "dist"]` with no isolation switch (the default does it), user `nobody` (the volume of the match store: "Match logs"). The Railway settings of a service are not in this folder (below, "Deploying") |
| `tests/web_smoke.py` | The browser smoke: serves a `dist/` with `serve.py` (the real isolation decision, `serve.decide_cross_origin_isolation(None, None, root)`), opens it headless in Chromium or Edge through Playwright and checks (1) the page loads, (2) a first frame that is not one flat color, (3) a click or tap changes the picture, (4) the console, (5) the backing store, (6) the web app manifest and its icons, (7) a match log piece posted by the page, (8) the save folder survives a reload. The checks, options and exit codes are in its docstring, the venv and what each check proves in `tests/CLAUDE.md` |
| `tests/` | `unittest` (`python -m unittest discover tools/web/tests` from the engine root; pytest also runs them): `test_package.py`, `test_serve.py`, `test_match_upload.py` (the match endpoint), `test_sign_in.py` (`ACCESS.md`), `test_deploy.py`, `test_setup_emsdk.py` (`CI/scripts/setup_emsdk.py`, fake runner, no SDK, no network), `test_cmake_web.py` (+ `check_bagi_web.cmake` under `cmake -P`; skipped without cmake), `test_shell.py`, `test_saves_js.py` (`web/saves.js` under node; skipped without it), `test_web_smoke.py` (the browser-free parts; its `RealBrowserTest` cases skip without Playwright or the browser), `web_fixtures.py` (a fake build output; no binary is committed) |

## The package

- **The four files are the same for both configurations:** emcc 4.0.23 writes no `<game>.worker.js`; a Worker starts from `<game>.js`.
- **The `.data` package** holds the `config/` and `assets/` of the engine, the game and the web overlay (`be_web_preload_args`); nothing unneeded is packed. SDL_image is built without TIFF and WebP on the web (`cmake/BagiEngine.cmake`).
- **`-O2` stays the default** (`BE_WEB_OPTIMIZATION`): `-Oz` saves a fraction of the download and costs run time. `-Wno-pthreads-mem-growth` is a link option on purpose (`cmake/BagiWeb.cmake`).
- **Debug** gives a `.wasm` of tens of MB; brotli at quality 11 takes minutes on it, so package it with a Python that has no `brotli`.

## The headers of `serve.py`, and why

| Rule | Why |
|------|-----|
| `Content-Type` from a table in the file (`application/wasm`, `application/octet-stream` for `.data`, `text/javascript`, `text/html; charset=utf-8`, `application/json`, `application/manifest+json` for `.webmanifest`), the file's type also for a compressed copy | A wasm streams only as `application/wasm`. Not `mimetypes`: on Windows it reads the registry and has answered `text/plain` for `.js` |
| `name.br`, then `name.gz`, by `Accept-Encoding` (q-values, `q=0` refuses, `*` allows both); `Content-Encoding`, `Vary: Accept-Encoding`, the encoded `Content-Length` | The wasm and the package are the large downloads. `name.gz` / `name.br` are never served as files (404); a file with no variant gets no `Vary` |
| Every file: `Cache-Control: no-cache` plus `ETag` (`mtime-size-encoding`); `If-None-Match` (a list, `*`, weak tags) gives 304 | A new deploy must show at once. The names are **not hashed**, so with `max-age` a browser ran the old `.js` / `.wasm` beside the new page; hashed names would need `package.py` and the loader to rewrite every reference |
| `GET /healthz` -> 200 `ok` (`no-store`) | The health check of the Railway service |
| **Access:** open, Basic or sign-in (`ACCESS.md`). Basic: with `BASIC_AUTH_USER` and `BASIC_AUTH_PASSWORD` both set, every request except `GET /healthz` needs them (401 with `WWW-Authenticate: Basic` and the isolation headers; a 401 to a method other than GET / HEAD closes the connection); one of them, an empty one, or a user with a colon: no start. The start line prints no secret | Railway puts no password on a service. Secrets are variables of the service, never files of the image or git, so the Dockerfile and staging are the same for every service |
| `..`, `%2e%2e`, `%2f`, backslash, NUL, a link out of the folder -> 404 | The path is cut into segments before the file system is touched, and the resolved path must stay below the root |
| `HEAD` works; any other method is 405 with `Allow: GET, HEAD` and `Connection: close` (the body is not read); `Server: BagiWebServe` | No Python version on the wire |
| `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` on every answer (304 and errors too). First match wins: the switch, then `COOP_COEP`, then the boolean `threads` of `manifest.json` in the root, then **on**. The start line prints the decision and its reason | A pthread wasm needs `SharedArrayBuffer`, which only a cross-origin isolated page gets: the threaded build (the default) does not start without both headers. The single-thread build needs neither and is served without them, so it works on a host that cannot send them. The headers break a page that embeds another origin without CORP. Unknown means on: a needless header costs a page that embeds nothing, a missing one a game that does not start |

## Match logs (`/matches/`)

Off unless `MATCH_STORE` names a folder (without it `/matches/...` is as it was: 405 for POST and DELETE, 404 for GET). It lets a page send a match log to its own server, piece by piece; the game side is `WebPostStart` / `WebPostPoll` (`src/Modules/SDL/CLAUDE.md`) over `window.bagiWebPost` of `web/shell.html`, a `fetch` of the page's own origin that carries its credentials (Basic or the session cookie). Behind Basic, whoever holds the password can post, read and delete every log; open, anybody can (the start line warns); with sign-in and `MATCH_COLLECT_TOKEN` the rules of `ACCESS.md` (stamp, 403, bearer). The answers carry the isolation headers.

| Request | Answers |
|---------|---------|
| `POST /matches/<id>/<index>` | 200 stored (the first write too) **or the same bytes again**; 400 bad path or body (a short fixed text, nothing of the input); 401; 409 the piece is stored with other bytes; 411 no `Content-Length` or chunked; 413 above 1 MiB (refused before the body is read); 429 + `Retry-After` the address posted too much; 507 the cap is reached or the disk failed |
| `GET /matches/` | 200 `{"matches": [{"id", "pieces"}]}` sorted by id |
| `GET\|HEAD /matches/<id>/<index>.jsonl` | 200 the file (`application/x-ndjson`, `no-store`); any other name or a missing file 404 |
| `DELETE /matches/<id>` | 200 removed, 404 not there, 400 malformed id; a piece or the list is 405 |

- **The path:** `<id>` is 32 lower-case hex digits, `<index>` decimal digits without leading zeros, nothing after; the file name is built from the validated parts only. A refusal that leaves the body unread closes the connection.
- **A piece:** UTF-8, empty or every line a JSON object ending in `\n` (a blank line is refused). Piece 0 begins with `{"event":"start","version":N,...}` with an int `N` inside `MATCH_LOG_VERSIONS` (`N` or `N-M`); an empty later piece is stored (the game's marker for a match given up). **The version range is a setting because the game owns the format:** the server must not know it, and with a store but no range every first piece is refused (400) and the start line warns.
- **Why pieces, and why 409:** a match is sent as it is played, so a tab that closes loses only the last piece, and a piece is written whole and never changed. A retry of a post whose answer was lost sends the same bytes and gets 200; other bytes for a stored index are a bug or a forgery and must not replace the first ones. Equal posts racing give two 200s: one lock serialises decide, write, delete and sweep, and the write is a temp file in the folder (`.tmp-*`, never listed or served) and `os.replace`.
- **Limits:** 1 MiB a piece; 60 posts an hour per client address (every post with a good path counts). The address is the socket peer, or with `MATCH_FORWARDED_FOR=1` the last entry of `X-Forwarded-For`, which the edge of Railway is expected to append (**not checked** against Railway; the first entry is the client's own claim, and a client that reaches the server directly would dodge the limit if it were trusted); `MATCH_STORE_MAX_MB` (default 1024) caps all pieces together; a match whose newest piece is older than 90 days (`MATCH_RETENTION_SECONDS`) goes at start and every hour, with stale temp files and empty folders.
- **What is stored:** the bytes of the pieces in `<store>/<id>/<index>.jsonl`, nothing else: no address, user agent or time except the mtime of the file. The access log skips `/matches/` lines and never prints a body or an id; the rate table lives in memory only.
- **The start:** the line prints `match store: <folder>` or `off`. A folder that cannot be written stops the server ("match store is not writable"), so a wrong volume is loud, not silent.

**The volume on Railway (the owner does it; nothing is deployed by the loop).** `railway volume add --service <name>` with a mount path such as `/data`, then `railway variables --service <name> --set MATCH_STORE=/data/matches --set MATCH_LOG_VERSIONS=1-5 --set MATCH_FORWARDED_FOR=1` (the range is the game's format). The image runs as `nobody` and a Railway volume is mounted root-owned, so the first start stops with "match store is not writable" (the Dockerfile cannot prepare the folder: the mount hides it). Railway's remedy is `RAILWAY_RUN_UID=0` as a service variable, which runs the process as root: **not checked from this machine**, and it widens what a hole in `serve.py` could do. Without `MATCH_STORE` nothing changes.

## The web app file

`<source>/web/app.json` belongs to the game (the root of the project that runs `build_and_deploy.py`; the engine itself has none and needs none). All keys optional: `name`, `short_name`, `orientation` (`any` default, `landscape`, `portrait`), `background_color`, `theme_color` (`#rrggbb`; default `#101114`), `icons` (`[{"src": PNG path relative to app.json, "sizes", "purpose"}]`). Defaults: the name is the game stem; with no icons `package.py` generates flat `theme_color` PNGs of 192 and 512, because Chrome treats a page without icons as not installable (it would open a tab with the bars). A bad file, a missing or non-PNG icon, or one outside the folder of the file (`..`) is a `PackageError`. The manifest says `display: fullscreen` (fallback `standalone`), `start_url`, `scope` and `id` `./`. The page links it with `crossorigin="use-credentials"`: a closed service uses Basic auth, and a manifest request without credentials would get 401.

## The page and the isolation

**Decided (slice 2 of `web-build`): threaded is the default, and the headers follow it.** The signal is `threads` in `manifest.json`, written by `package.py`, not a guess from file names; the image needs no switch.

The shell cannot know whether its build is threaded, so `be_web_configure_target` writes a copy of `web/shell.html` into the build folder (`be_web_generate_shell`: `configure_file(@ONLY)`, `@BAGI_WEB_THREADS@` = `1` or `0`); `--shell-file` names the copy. The threaded copy first tests `window.crossOriginIsolated` and `SharedArrayBuffer`; when either is missing it shows "This page needs cross-origin isolation" with the two headers named (plus a secure-context sentence when `window.isSecureContext` is false: plain `http://` from a host that is not `localhost`) and does **not** start the module (a pthread wasm without `SharedArrayBuffer` fails with a cryptic error). The HTML minifier folds the comparison, so the single-thread page has no test at all. `check_bagi_web.cmake` checks both generated copies.

The other messages of the shell: "WebGL is not available" (after `kWebGLReloads` reloads; the module is not started), "The game could not be loaded" / "The game stopped" (`Module.onAbort`, a page error, and an `unhandledrejection` handler, because emcc's package loader is an async function nobody awaits, so a `.data` that fails to download is only a rejected promise), "The game has ended" after Quit (`-sEXIT_RUNTIME=1`, `emscripten_cancel_main_loop()` then `Finish()`; emsdk 4.0.23 calls `Module.onExit` with **no status**).

**Fullscreen and the home-screen app.** The page names no game. It links `manifest.webmanifest` and `icons/apple-touch-icon.png` (both relative: its only references), the apple / `mobile-web-app-capable` meta tags and `theme-color`. A toggle button (top right, off the safe area, takes its own touches) is shown when `document.fullscreenEnabled` (or the `webkit` form) is true and the page is not an installed app (`navigator.standalone`, `display-mode` read once at start: it also matches after the page itself went fullscreen). On a coarse pointer the first touch `pointerup` asks for fullscreen once per load; `?fullscreen=0` turns that off. Once fullscreen starts the shell calls `screen.orientation.lock` with the manifest's `orientation` (unless `any`), errors ignored. Three degradations, none stops the game: no API (iOS Safari: the home-screen app is the way), refused (a plain page), installed (the manifest does it). The code runs in a `try` after the WebGL test and every promise has a rejection handler, or `unhandledrejection` would show "could not be loaded". The download bar counts decoded bytes against the compressed `Content-Length`, so a total the count has passed stops driving the bar.

## Saves

`/bagi/saves` is kept in the site's IndexedDB by `web/saves.js` (`--pre-js`, `-lidbfs.js`, `-sEXPORTED_RUNTIME_METHODS=FS`: `be_web_link_options`); the contract and limits are in `web/CLAUDE.md`. Smoke check (8) reloads a written file and starts the page with IndexedDB failing.

## Deploying

`build_and_deploy.py` works from the root of a project that has the web presets (the engine, or a game that carries it as `engine/`; `--source-dir` names another). It needs the Emscripten SDK (`python CI/scripts/setup_emsdk.py` installs it into `external/emsdk` once per checkout, about 2 GB; the presets find it), and for `--deploy` the Railway CLI logged in (`railway login`, `railway link`), or `RAILWAY_TOKEN`; the script reads and writes no secret. Defaults: the page in `<source>/build/<preset>/bin` (the single-thread presets have their own binary dir: their libraries are built without `-pthread` and must not meet the threaded ones), the package in `<source>/dist` (in the engine's `.gitignore`; a game adds it to its own), the staging in `<source>/build/web-deploy`. The staging holds `Dockerfile`, `serve.py` and a fresh copy of `dist/`; `railway up` gets it with `--path-as-root`, so it never uploads a linked parent such as the engine root.

By hand: `cmake --preset web-release`, `cmake --build --preset web-release --target BagiMatch3`, `package.py build/web-release/bin dist`, `serve.py --root dist` (http://localhost:8080). Single-thread: the preset `web-release-single-thread`, `package.py build/web-release-single-thread/bin dist-single --single-thread`, `serve.py --root dist-single`. A threaded page from a host that is not `localhost` over plain `http://` is not a secure context and never isolated, whatever the server sends: use `localhost` or https. The Railway service is made once (`railway add --service bagi-web`, a domain, `railway link`); its settings (Dockerfile, `/healthz`) are the game's Railway IaC partial (BagiMahjong: `web/.railway/railway.ts`). To close it: `railway variables --service <name> --set BASIC_AUTH_USER=<user> --set BASIC_AUTH_PASSWORD=<password>` and redeploy (the server reads them at start). Nothing is deployed by the tests or by the loop.

**The `.data` package and relinks.** The content is packed into `<game>.data` at **link time**. `be_web_configure_target` lists every content file in `LINK_DEPENDS` (globbed with `CONFIGURE_DEPENDS`) and, per folder, a stamp `web-content/<target>_bagi_<layer>_<folder>.txt` with the sorted file list (`be_web_content_inputs`, written with `file(CONFIGURE)`, so only when the list changes). An edit relinks because the file is newer than the package; an added or deleted file because the stamp changes (a deleted file alone leaves no trace, and the `--preload-file` line does not change). The relink is the price of editing content; the globs run at the start of every build.

## Tests

`python -m unittest discover tools/web/tests` from the engine root (in a game: from `engine/`). `test_serve.py` starts the server on port 0 of 127.0.0.1 in a thread, and one test starts `serve.py` as a program with `PORT=0`, as the Dockerfile's `CMD` does. `test_deploy.py` hands a fake runner to `build_and_deploy.run`: no `railway`, `docker`, `cmake` or emsdk. The real `brotli` is tested only when installed. `docker build` of the staged folder is a manual check.
