# Rendering Module Guidelines

## Layer Responsibilities

- `BECore/Renderer` owns the engine-level abstractions: `IRenderer`, `ITexture`, `IRenderTarget`, `RendererManager`, and for 3D the generic GPU interface `Gpu/` and the renderer above it `Render3D/` (see "Generic GPU interface and 3D").
- Backend modules provide the implementations: `SDL` (`SDLRendererBackend`, `SDLTexture`) and `Vulkan` (`VulkanRendererBackend`, `VulkanTexture`, `VulkanRenderTarget`, swapchain and pipelines).
- Scene components (`QuadRendererComponent`, `SpriteRendererComponent`) consume the abstractions, not backend types.
- The backend is chosen at startup by the `renderer` attribute of `config/ApplicationConfig.xml` (`SDLRendererBackend` or `VulkanRendererBackend`); `IRenderer` is a `FACTORY_BASE`, so a new backend is just another registered `IRenderer`.
- `IRenderTarget` is an offscreen target shown as an ImGui image (the viewport). Obtain it from `IRenderer::CreateRenderTarget()`; do not assume a backend behind `GetImGuiTextureId()`.

## Output size and view transform

- `IRenderer::GetOutputWidth()` / `GetOutputHeight()` are the pixel size of the target being drawn into (the back buffer, or the offscreen target between `SetRenderTarget()` and `UnsetRenderTarget()`); they are 0 before the first pass opens.
- `IRenderer::SetViewTransform()` sets a `ViewTransform` (scale and offset, identity by default) that `DrawFilledRect()` and `DrawTexture()` apply to their destination rect. It is state of the interface, so both backends apply it the same way (`GetViewTransform().ToOutput(x, y, w, h)`) and a new backend must do the same. `Scene::Draw()` sets it around its draw pass and resets it, so a scene with a view size fits any output (`src/Modules/BECore/Scene/CLAUDE.md`, "View size"). Only the destination is mapped: source rects and UVs are untouched.

## Drawing primitives

- **Tint:** `DrawTexture(texture, src, x, y, w, h, tint)` multiplies the texel by `tint` (white leaves it, the alpha of the tint fades it). It is the virtual one; the six-argument overload is a non-virtual helper that forwards with white, so a backend adds `using IRenderer::DrawTexture;` next to its override (the override hides the helper otherwise). The method is not `BE_FUNCTION`: the generated method table takes `&IRenderer::DrawTexture`, which an overloaded name makes ambiguous. A backend must not leave a tint on a shared texture: SDL sets the color and alpha modulation on every draw.
- **Alpha:** with the default blend mode (`Alpha`) `DrawFilledRect()`, `DrawTexture()` and `DrawGeometry()` blend straight alpha over the target in both backends (`CreateTexture()` in the SDL backend makes textures with `SDL_BLENDMODE_BLEND`, which each textured draw then sets again; see "Blend state").
- **Blend state:** `IRenderer::SetBlendMode()` / `GetBlendMode()` (`BlendMode`: `Alpha` straight alpha over the target, the default; `Add` `src*a + dst`; `Multiply` `src*dst + dst*(1-a)`) is state of the interface like the view transform: every primitive (`DrawFilledRect`, `DrawTexture`, `DrawGeometry` and so the transformed draws) obeys it on SDL (Vulkan does not implement it yet and draws straight alpha, see "Cross-Backend Compatibility"). Whoever sets another mode puts the previous one back with `ScopedBlendMode` (RAII, in `IRenderer.h`), so text, UI, RmlUi and ImGui never see a leaked mode. `SDLRendererBackend` maps the mode to `SDL_BLENDMODE_BLEND` / `SDL_BLENDMODE_ADD` / `SDL_BLENDMODE_MUL` (`ToSDLBlendMode()`) and sets it on **every** draw: `SDL_SetRenderDrawBlendMode` for a rect and for an untextured geometry draw, `SDL_SetTextureBlendMode` on the texture for a textured draw. The texture is shared, so a draw must not inherit the mode of an earlier one (the same rule as the tint). SDL's `MUL` is `src*dst + dst*(1-a)`: white with alpha 255 and black with alpha 0 both leave the target as it is (`SDLCaptureTest`); the alpha of a non-black color matters.
- **Opacity:** `IRenderer::SetOpacity()` / `GetOpacity()` (0 to 1, default 1, a NaN is 1, the range is cut) is state of the interface like the blend mode, and `ScopedOpacity(renderer, factor)` (RAII, `IRenderer.h`) sets `previous * factor` and puts `previous` back, so a subtree inside a subtree draws with the product. It is a **per-draw alpha multiply** (Unity's `CanvasGroup`), not an offscreen composite of the group: children that overlap inside a faded group blend through each other (an `SDLRenderTarget` exists, but the group is not drawn into one, and a Vulkan target cannot open in the middle of a pass, so an exact composite is a backend entry of its own). The rule is written once, in the protected `ApplyOpacity(const Color&)` (alpha times opacity, rounded; opacity 1 returns the colour untouched), and each backend calls it **once per primitive**: SDL for the rect colour, the tint of `DrawTexture()` and of the rotated branch of `DrawTransformedTexture()` (its identity branch calls `DrawTexture()`, so it does not apply it itself) and the vertex colours of `DrawGeometry()`; Vulkan the same for the rect, the texture tint and the vertex colours, so it fades like SDL. `DrawTransformedRect()` and the default `DrawTransformedTexture()` go through `DrawGeometry()` and are faded there, once. `RecordingRenderer` records the colour after the opacity. `Clear()`, the view transform and the clip are not touched.
- **`DrawTransformedRect()` / `DrawTransformedTexture()`:** `DrawTransform` (`Renderer/DrawTransform.h`) is a `rotation` in degrees, clockwise on the screen (y points down), a pivot `pivotX` / `pivotY` that is an **absolute point in the units of the call**, and `flipX` / `flipY`, which mirror the picture about its own center by swapping the UVs (independent of the rotation). Both draws are virtual, not pure and not `BE_FUNCTION`. The default of an identity transform (`IsIdentity()`: no rotation, no flip) is `DrawFilledRect()` / `DrawTexture()` unchanged; otherwise it turns the four corners (`MakeTransformedQuad()`, pure, order top-left, top-right, bottom-left, bottom-right) and calls `DrawGeometry(texture, 4 vertices, {0,1,2,2,1,3}, 0, 0)` with the UVs of the source rect over the texture size (the whole texture when the rect is null or empty; a texture without size draws nothing), the tint or color as the vertex color. So the view transform, the clip and the blend state come from `DrawGeometry()`, and a backend with `DrawGeometry()` needs no code for them. With batching on ("Batching") the same corners and UVs are appended to the batch instead, by the same code, so the two forms give the same quad. `SDLRendererBackend` overrides `DrawTransformedTexture()` (the textured geometry default is wrong on its software renderer, see "Software rasterizer" under "Cross-Backend Compatibility"): an identity transform is `DrawTexture()`, otherwise `SDL_RenderTextureRotated` with the destination rect mapped by the view transform, the center `(pivot - destination origin) * view scale`, the angle `rotation` and the flip flags (the flip is applied before the turn, as in the default), the source rect, the blend mode and the tint set as in `DrawTexture()`. The view transform is a uniform scale and an offset, so the angle is not changed by it. `DrawTransformedRect()` keeps the geometry default on both backends.
- **`BeginFrame(color)` and `Clear(color)`:** `BeginFrame(color)` is the back buffer's colour for the frame; `Application::RunFrame` calls it once, right after `NewFrameEvent` and before any widget (SDL fills the back buffer at once, Vulkan keeps the colour and opens the swapchain pass at the first draw, so an offscreen target may be drawn first). `Clear(color)` names the colour the next **offscreen** pass starts with; call it before `SetRenderTarget()`. Vulkan takes it for the pass that opens next and then goes back to opaque black, so the viewport's clear does not tint the back buffer; SDL remembers it for the next `SetRenderTarget()` (which clears its target with it, then opaque black), and fills the back buffer at once only outside a frame (before `BeginFrame` or after the present).
- **Clip:** `PushClipRect(rect)` / `PopClipRect()` keep a stack on the interface. The rect is in **output pixels, after the view transform** (a scene transform does not move it; code that has a rect in scene units maps it with `GetViewTransform().ToOutput(...)` first). Pushed rects nest: each entry is already intersected with the one below. A push that leaves nothing gives an empty clip (`IsClipEmpty()`), and both backends then skip every draw. A backend reads `GetClipRect()`: SDL applies it in `OnClipRectChanged()`, Vulkan resolves it into the scissor of each draw (`ResolveScissor()`, cut to the extent). An unbalanced push leaks into the next frame, so pair them at the call site.
- **`DrawGeometry(texture, vertices, indices, translateX, translateY)`:** indexed triangles (`GeometryVertex`: position, straight-alpha `Color`, UV 0 to 1), the primitive of a library that brings its own layout (RmlUi, `src/Modules/RmlUiHost/CLAUDE.md`). Each position is moved by the translation, then by the view transform; the draw obeys the clip; the texture is optional (without one the vertex colors are the fill). Not `BE_FUNCTION` (spans). It is virtual and not pure: the default logs once and draws nothing, for a backend without the primitive (both real backends have it). `SDLRendererBackend` uses `SDL_RenderGeometryRaw`; `VulkanRendererBackend` has a pipeline and a vertex buffer per frame in flight of its own (`src/Modules/Vulkan/CLAUDE.md`, "Geometry"). In both, an index past the vertices is logged and nothing is drawn. `IRenderer::GetGeometryDetail()` (`GeometryDetail`: `Full` by default, `Reduced` on the SDL software renderer only, where each blended triangle costs a surface and a blit) tells a generator of geometry (`UIBoxMesh` shadows, `.claude/rules/ui-shapes.md`) how many triangles to spend; a backend whose cost does not follow the triangle count keeps `Full`. `RenderProbeComponent` draws two geometry quads for a look at both (and the turned textures of the transformed draws, which are geometry on Vulkan). `DrawGeometry()` is never batched: it flushes the open batch first, so the order stays the caller's. `RecordingRenderer` records it as `DrawKind::Geometry` with the vertices in output pixels.
- **`CreateTexture(rgba, width, height)`:** a texture from pixels (RGBA8, red first, straight alpha, rows from the top, copied). It returns an empty pointer for a zero size or when the backend fails. Main thread only, like every GPU call; never inside `LoadAsync`. Vulkan textures are destroyed only when the GPU is idle (`VulkanTexture`).
- **`GetId()` and `WaitIdle()`:** `IRenderer::GetId()` is unique for the life of the process (a renderer allocated at the address of a dead one has another id); whoever keeps GPU objects of a renderer, such as the glyph atlases, remembers it and drops them when it changes. `WaitIdle()` blocks until the GPU has finished what was submitted (Vulkan: `vkDeviceWaitIdle`; the SDL default does nothing): call it before freeing textures that a frame in flight may use, and free them **before** the renderer is destroyed (`Application::Cleanup()` clears the glyph atlases before it emits `ApplicationCleanUpEvent`; the event channel calls an event's handlers in the reverse order of their subscription, so a handler subscribed earlier than the renderer's would run after its `Destroy()`).
- A test that needs a renderer uses `RecordingRenderer` (`tests/Common/RecordingRenderer.h`): it records the calls in output pixels with the clip and the blend mode in effect (`DrawCall::blend`; the default transformed draws appear as `DrawKind::Geometry`, or as the plain kind for an identity transform), reports a settable output size and keeps the pixels of the textures it makes. `RenderProbeComponent` is the debug component that draws every primitive for a look at both backends: the textures (plain, tinted, half alpha, turned 30 degrees, turned and mirrored), translucent rects, the clips, the geometry quads, and two cells split into a straight-alpha half and an additive or a multiply half (on Vulkan the halves look alike: the fallback).

## Batching

`IRenderer` gathers quads into batches for every backend (`RenderBatch.h`; `SetBatchingEnabled()`, off by default; a backend turns it on where the result is exact and implements `SubmitBatch(const RenderBatch&)` and, for a texture it cannot draw, `CanDrawTexture()`). `DrawFilledRect()`, `DrawTexture()`, `DrawTransformedRect()` and `DrawTransformedTexture()` (rotated or flipped included) call the protected `BatchRect()`, `BatchTexture()` and the transformed forms after their own checks. The quad is appended in **output pixels**: the view transform and the opacity are applied once there, the tint is the vertex colour, the UVs are those of the source rect (one place computes them, shared with the immediate default). Order is never changed: a batch holds consecutive draws only. `Flush()` times each `SubmitBatch()` as `FrameStage::Submit` (not under a counters pause); immediate draws are not in it.

- **The key** of an open batch is the texture and the blend mode. A quad with another key, or a batch of `kMaxBatchQuads`, submits the open batch first. The batch holds its texture by `IntrusivePtr`, so a texture released before the flush cannot dangle.
- **Flushed by** (`Flush()`): `PushClipRect` / `PopClipRect` (before the stack changes, so a batch always belongs to one clip and a backend may apply it at once, as SDL, or at submit time, as Vulkan), `PauseCounters` / `ResumeCounters`, `DrawGeometry()` and any draw a backend does not batch, `Clear`, `BeginFrame`, `EndFrame`, `Present`, the target calls, the capture and the ImGui render of a backend (it calls `Flush()` before anything native), disabling batching and the end of `SceneDrawSystem::Run`. `Destroy()` drops the open batch. A backend that does something natively calls `Flush()` first.
- **Counters:** a quad counts as a primitive when appended, the flush counts one submission (below).
- **SDL:** a GPU driver batches everything (one `SDL_RenderGeometryRaw`). The software renderer batches only the classes `SDLBatchCaptureTest` proved byte-equal to the immediate draw (whole-pixel opaque, additive and multiplied rects, transformed rects); **no textured quad** there, because of the two traps of "Software rasterizer" (`src/Modules/SDL/CLAUDE.md`, "Batching"). So the headless `stress-sprites` run is not batched.
- **Vulkan:** one geometry draw per batch, the clip as the scissor of the flush (`src/Modules/Vulkan/CLAUDE.md`, "Geometry"). No capture exists there; `tools/stress/qa/vulkan_look.py` pictures are the check.
- `RecordingRenderer` batches when asked (`SetBatchingEnabled(true)`, off by default so older tests are unchanged) and records a batch as `DrawKind::Batch` in the same list as the other draws, which shows the true order (`tests/BECore/RendererBatchTest.cpp`).

## Draw counters

`IRenderer` counts primitives, backend submissions, triangles and texture switches for the frame statistics (`RenderCounters`, `TakeRenderCounters()` once per frame in `Application::RunFrame`). `drawCalls` is what reached the backend, `primitives` what the scene asked for: they are equal for an unbatched renderer and `drawCalls` is lower by the batching. A backend that does not batch a primitive calls the protected `CountDraw(texture, triangles)` (both counts) **once per primitive it really submits, after its early returns** (no pass, an empty clip, a texture of another backend, a bad index): a dropped draw is not counted. A batched quad is counted by `CountPrimitive()` when it is appended and the flush counts one `CountSubmission(texture)` for the whole batch. Only the primitives count: `DrawFilledRect`, `DrawTexture`, `DrawGeometry` (its whole triangles) and a backend's own `DrawTransformedTexture`; the defaults of the transformed draws go through the batch or `DrawGeometry`, so nothing is counted twice. A texture switch is a textured submission whose texture differs from the textured submission before it (untextured ones in between do not count). `ScopedRenderCountersPause` hides the draws of the profiler's own overlay and flushes at both ends. `RecordingRenderer` counts like a backend. ImGui draws through its own backend and is reported by `ImGuiWidget` as named counters of the frame statistics.

## Texture Pipeline

- Texture loading goes through dedicated `IResourceLoader` classes (`SDLTextureLoader`, `VulkanTextureLoader`), so it follows `src/Modules/BECore/Resource/CLAUDE.md`. Textures from pixels in memory come from `IRenderer::CreateTexture()` instead and are not cached by path.
- Keep texture lifetime and ownership behind `ITexture`. Do not expose backend handles in scene/component public APIs (`GetNativeHandle()` is for backend code).
- Named sprites come from `TextureLibrary` (`config/TextureLibrary.xml`): name → texture path + source rect.
- The aspect of a sprite is the scene's business, not the backends': `SceneDrawSystem` fits the node's rect with `FitSpriteRect()` (`fit="Contain"`, in scene units, before the view transform) from the fields of the node's components and passes the result to `DrawTexture()` (or `DrawTransformedTexture()` for a rotated or flipped node, about the node's pivot), so a backend only ever sees a destination rect and a source rect. `SpriteRendererComponent::SetTexture()` gives a sprite a texture from pixels (`CreateTexture()`), which is how a test makes one draw.
- **Culling is the scene's too:** `SceneDrawSystem` makes no call for a quad or a sprite whose node rect (with a rotation: a square about the pivot that holds every turn of it) lies wholly outside `GetOutputWidth()` x `GetOutputHeight()` grown by a pixel, so such a draw is not counted. It tests the output, not the view (the letterbox bars are drawn), culls nothing while the output has no size, and never culls an `OnDraw()`: a component that draws itself drops its own off-screen work.

## Serialization and Components

- Texture-related component fields must be serialization-friendly and stable: sprite id / path / source rect, never a backend runtime handle (see `SpriteRendererComponent`).
- Serialize the data needed to rebuild the texture state, not transient backend objects.

## Cross-Backend Compatibility

- Define new renderer-facing behavior at the `IRenderer` / `ITexture` level first, then implement it in both backends where supported.
- If a backend cannot support a feature, document the fallback explicitly (skip draw, placeholder, or warning). `IRenderer::RequestCapture()` is an example: it is not pure, the default answers with an error, `SDLRendererBackend` reads its pixels back at the present and `VulkanRendererBackend` keeps the default (`src/Modules/Vulkan/CLAUDE.md`, "No capture").
- **Blend modes:** `SDLRendererBackend` implements `Alpha`, `Add` and `Multiply` (also on the headless software renderer, `SDLCaptureTest`). `VulkanRendererBackend` draws every primitive with straight alpha whatever `GetBlendMode()` says and logs one warning per backend (`WarnIfBlendModeIgnored()`) the first time a draw arrives with another mode; no blend pipeline exists yet (`src/Modules/Vulkan/CLAUDE.md`, "No blend modes"). That is a gap, not a policy: Vulkan is the planned GPU backend of the engine's own renderer ("Generic GPU interface and 3D"), and the entries `renderer-backends` and `render-3d` bring it level with SDL, blend modes included. `DrawTransformedRect()` / `DrawTransformedTexture()` need nothing from a backend: the defaults run on any backend with `DrawGeometry()`, which is what Vulkan uses for both and SDL for the rect. SDL draws a transformed texture natively (`SDL_RenderTextureRotated`, see "Drawing primitives"), so rotation and flip look the same on SDL and Vulkan, and only the blend differs.
- **Particles:** `ParticleEmitterComponent` draws one `DrawGeometry` batch per emitter under `ScopedBlendMode(effect.blend)` (`BECore/Particles/CLAUDE.md`), so on Vulkan an `Add` effect shows as straight alpha until the blend gap above is closed.
- **Direction (open, entry `renderer-backends`):** each 2D primitive is written once per backend today (quads are batched above the backends, "Batching"; the scene still makes one `IRenderer` call per quad or sprite). The planned shape is a thin backend (a batch of textured, colored triangles with a blend mode, clip, render targets, textures, present, capture) with rects, sprites, rotation, flip, text and sorting written once above it, as the 2D subset of `IGpuDevice`; it waits for the first backend that implements `IGpuDevice` (the Vulkan slice of `render-3d`). SDL3 GPU follows as a third backend and the browser gets its own (`web-3d-backend`), so a new 2D feature is added to `IRenderer` as above until then.
- **Software rasterizer (headless SDL):** a textured `SDL_RenderGeometryRaw` goes through two paths that are wrong for a picture. (1) The triangle path turns UVs into whole texel numbers and `SDL_SW_BlitTriangle` spreads a texture of n texels over the numbers 0 to n-1 and rounds down (`SDL_triangle.c`, "interpolates up to the max values included, so reduce by 1"): the texture is shrunk by (n-1)/n, the last row and column show only at the far edge, and a 2 by 2 texture shows one texel everywhere (an 8 by 8 block edge moves from 1/2 to 4/7 of the width). (2) `SDL_SW_RenderGeometryRaw` takes two triangles that form an upright rectangle for a plain blit with flips only, and a quad turned by exactly 90 or 270 degrees is such a rectangle: it comes out stretched and flipped instead of turned (other angles are fine; 180 is right by luck). That is why the SDL backend draws a transformed texture with `SDL_RenderTextureRotated` and not through `DrawGeometry()`. A textured `DrawGeometry()` from a library (RmlUi) still takes the geometry path and has effect (1) there; its quads are not turned, so (2) does not arise. A pixel test samples well inside the blocks of its texture (`SDLCaptureTest`); an untextured geometry draw has neither problem.
- ImGui reaches the backend through `RenderEvents::ImGui*Event`, not direct calls (see `src/Modules/SDL/CLAUDE.md`).

## Generic GPU interface and 3D

Status: the interface and the 3D renderer exist; **no backend implements `IGpuDevice` yet** (slice 2 of the entry `render-3d`). The planned backends are Vulkan and SDL3 GPU under this one renderer; the gaps of the Vulkan backend today (blend modes, capture) are closed by `renderer-backends` / `render-3d`. Conventions of the math: `src/Modules/BECore/Math/CLAUDE.md`.

- **Layering:** one engine renderer above (`Renderer/Render3D/`: `Renderer3D`, `Scene3D` of a `Camera3D`, a `DirectionalLight`, an `Ambient` and `MeshInstance`s), the generic interface under it (`Renderer/Gpu/`), backends below that only carry out descriptions. No GPU handle or shader language appears above the device; the 2D calls of `IRenderer` are unchanged.
- **`IGpuDevice`** (main thread, between `BeginFrame()` and `EndFrame()`): resources are `RefCounted` (`IGpuBuffer`, `IGpuPipeline`, `IGpuDepthTexture`; textures stay `ITexture`), then `BeginPass(PassDesc)` .. `EndPass()` with `SetPipeline`, buffers, `SetTexture`, `SetConstants`, `DrawIndexed`. A backend must: apply the rules of `GpuValidation.h`; create a **pipeline from its description** (`PipelineDesc`, a `ShaderId` naming a shader of the build) and refuse a shader it lacks; support a **depth attachment** (`Depth32Float`; a pipeline made for depth is not bound in a pass without it); keep two **constant slots**, `Frame` (0) and `Draw` (1), each at most `kMaxConstantsBytes` (128, the Vulkan push-constant minimum) and a multiple of 16 (push constants for one slot and a uniform ring for the other is fine); front faces counter-clockwise, depth 0 to 1, Y up (Vulkan flips with the viewport).
- **`IRenderer::GetGpuDevice()`** is null by default; `RequireGpuDevice(renderer)` gives the device or the error with the renderer's name and `GetNoGpuDeviceReason()`, which the 3D caller logs once (`LOG_ERROR`) instead of drawing a blank screen. `SDLRendererBackend` answers "no 3D": its renderer has no depth buffer and no shaders. The browser likewise until `web-3d-backend`.
- **The 3D pass comes first:** `Renderer3D::Render(renderer, scene, PassDesc)` opens a pass with its own depth attachment (the size of the target, cleared to 1), draws, ends it; the 2D scene and the UI follow in a pass the caller opens with `PassLoadOp::Load`. It keeps the lit pipeline (`Lit3D`), the depth texture and a white 1 x 1 texture of the last device (`Reset()` before the renderer dies). `FrameConstants` (112 bytes) and `DrawConstants` (80) go to the device as they are, colors linear; the shader mirrors `LambertTerm()`.
- **Tests:** `RecordingGpuDevice` (`tests/Common/RecordingGpuDevice.h`) records the commands, the constants as bytes and the buffers, and rejects a call that breaks a rule into `errors`; `RecordingRenderer::SetGpuDevice()` gives a renderer a device. Pixels are not tested here.
- **Shader tool: Slang** (decision of `render-3d`). One source gives SPIR-V (Vulkan, SDL3 GPU), MSL (Metal), WGSL (browser) and GLSL, where GLSL + `glslc` + `spirv-cross` would need a second language for Metal. The build step (slice 2) compiles `.slang` at build time into headers like `compile_shader` in `Vulkan/CMakeLists.txt`. Checked with `slangc` on a vertex + fragment file (constant buffers, a texture, a sampler): all four targets compile, one command per entry point (`slangc lit.slang -target <spirv|metal|wgsl|glsl> -entry vsMain -stage vertex -o lit.vert.<ext>`, `-o` after its `-entry`). Caveats: `[[vk::push_constant]]` is a push constant in SPIR-V and GLSL and `buffer(0)` in Metal, but WGSL gets a `var<uniform>` **without** `@group/@binding`, so the slot 0 declaration is `[[vk::binding(0, 0)]]` under a macro for WGSL; Draw is `[[vk::binding(0, 1)]]`, texture and sampler `[[vk::binding(0|1, 2)]]`. `Mat4` bytes read as columns by default (`m[0][1]` is float 4 in SPIR-V and MSL; `-matrix-layout-column-major` is the same output, pass it for clarity). `-target glsl` is `#version 450` with no ES profile, so WebGL is not served: the browser takes WGSL (`web-3d-backend`).

## Error Handling

- Validate resource loading and creation paths; log failures with enough context to trace the asset and the component.
- Avoid silent render failures: log a warning/error and apply a predictable fallback.
