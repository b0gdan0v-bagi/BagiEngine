# Rendering Module Guidelines

## Layer Responsibilities

- `BECore/Renderer` owns the engine-level abstractions: `IRenderer`, `ITexture`, `IRenderTarget`, `RendererManager`.
- Backend modules provide the implementations: `SDL` (`SDLRendererBackend`, `SDLTexture`) and `Vulkan` (`VulkanRendererBackend`, `VulkanTexture`, `VulkanRenderTarget`, swapchain and pipelines).
- Scene components (`QuadRendererComponent`, `SpriteRendererComponent`) consume the abstractions, not backend types.
- The backend is chosen at startup by the `renderer` attribute of `config/ApplicationConfig.xml` (`SDLRendererBackend` or `VulkanRendererBackend`); `IRenderer` is a `FACTORY_BASE`, so a new backend is just another registered `IRenderer`.
- `IRenderTarget` is an offscreen target shown as an ImGui image (the viewport). Obtain it from `IRenderer::CreateRenderTarget()`; do not assume a backend behind `GetImGuiTextureId()`.

## Output size and view transform

- `IRenderer::GetOutputWidth()` / `GetOutputHeight()` are the pixel size of the target being drawn into (the back buffer, or the offscreen target between `SetRenderTarget()` and `UnsetRenderTarget()`); they are 0 before the first pass opens.
- `IRenderer::SetViewTransform()` sets a `ViewTransform` (scale and offset, identity by default) that `DrawFilledRect()` and `DrawTexture()` apply to their destination rect. It is state of the interface, so both backends apply it the same way (`GetViewTransform().ToOutput(x, y, w, h)`) and a new backend must do the same. `Scene::Draw()` sets it around its draw pass and resets it, so a scene with a view size fits any output (`src/Modules/BECore/Scene/CLAUDE.md`, "View size"). Only the destination is mapped: source rects and UVs are untouched.

## Drawing primitives

- **Tint:** `DrawTexture(texture, src, x, y, w, h, tint)` multiplies the texel by `tint` (white leaves it, the alpha of the tint fades it). It is the virtual one; the six-argument overload is a non-virtual helper that forwards with white, so a backend adds `using IRenderer::DrawTexture;` next to its override (the override hides the helper otherwise). The method is not `BE_FUNCTION`: the generated method table takes `&IRenderer::DrawTexture`, which an overloaded name makes ambiguous. A backend must not leave a tint on a shared texture: SDL sets the color and alpha modulation on every draw.
- **Alpha:** with the default blend mode (`Alpha`) `DrawFilledRect()`, `DrawTexture()` and `DrawGeometry()` blend straight alpha over the target in both backends (`CreateTexture()` in the SDL backend makes textures with `SDL_BLENDMODE_BLEND`, which each textured draw then sets again; see "Blend state").
- **Blend state:** `IRenderer::SetBlendMode()` / `GetBlendMode()` (`BlendMode`: `Alpha` straight alpha over the target, the default; `Add` `src*a + dst`; `Multiply` `src*dst + dst*(1-a)`) is state of the interface like the view transform: every primitive (`DrawFilledRect`, `DrawTexture`, `DrawGeometry` and so the transformed draws) obeys it on SDL (Vulkan draws straight alpha, see "Cross-Backend Compatibility"). Whoever sets another mode puts the previous one back with `ScopedBlendMode` (RAII, in `IRenderer.h`), so text, UI, RmlUi and ImGui never see a leaked mode. `SDLRendererBackend` maps the mode to `SDL_BLENDMODE_BLEND` / `SDL_BLENDMODE_ADD` / `SDL_BLENDMODE_MUL` (`ToSDLBlendMode()`) and sets it on **every** draw: `SDL_SetRenderDrawBlendMode` for a rect and for an untextured geometry draw, `SDL_SetTextureBlendMode` on the texture for a textured draw. The texture is shared, so a draw must not inherit the mode of an earlier one (the same rule as the tint). SDL's `MUL` is `src*dst + dst*(1-a)`: white with alpha 255 and black with alpha 0 both leave the target as it is (`SDLCaptureTest`); the alpha of a non-black color matters.
- **`DrawTransformedRect()` / `DrawTransformedTexture()`:** `DrawTransform` (`Renderer/DrawTransform.h`) is a `rotation` in degrees, clockwise on the screen (y points down), a pivot `pivotX` / `pivotY` that is an **absolute point in the units of the call**, and `flipX` / `flipY`, which mirror the picture about its own center by swapping the UVs (independent of the rotation). Both draws are virtual, not pure and not `BE_FUNCTION`. The default of an identity transform (`IsIdentity()`: no rotation, no flip) is `DrawFilledRect()` / `DrawTexture()` unchanged; otherwise it turns the four corners (`MakeTransformedQuad()`, pure, order top-left, top-right, bottom-left, bottom-right) and calls `DrawGeometry(texture, 4 vertices, {0,1,2,2,1,3}, 0, 0)` with the UVs of the source rect over the texture size (the whole texture when the rect is null or empty; a texture without size draws nothing), the tint or color as the vertex color. So the view transform, the clip and the blend state come from `DrawGeometry()`, and a backend with `DrawGeometry()` needs no code for them. `SDLRendererBackend` overrides `DrawTransformedTexture()` (the textured geometry default is wrong on its software renderer, see "Software rasterizer" under "Cross-Backend Compatibility"): an identity transform is `DrawTexture()`, otherwise `SDL_RenderTextureRotated` with the destination rect mapped by the view transform, the center `(pivot - destination origin) * view scale`, the angle `rotation` and the flip flags (the flip is applied before the turn, as in the default), the source rect, the blend mode and the tint set as in `DrawTexture()`. The view transform is a uniform scale and an offset, so the angle is not changed by it. `DrawTransformedRect()` keeps the geometry default on both backends.
- **Clip:** `PushClipRect(rect)` / `PopClipRect()` keep a stack on the interface. The rect is in **output pixels, after the view transform** (a scene transform does not move it; code that has a rect in scene units maps it with `GetViewTransform().ToOutput(...)` first). Pushed rects nest: each entry is already intersected with the one below. A push that leaves nothing gives an empty clip (`IsClipEmpty()`), and both backends then skip every draw. A backend reads `GetClipRect()`: SDL applies it in `OnClipRectChanged()`, Vulkan resolves it into the scissor of each draw (`ResolveScissor()`, cut to the extent). An unbalanced push leaks into the next frame, so pair them at the call site.
- **`DrawGeometry(texture, vertices, indices, translateX, translateY)`:** indexed triangles (`GeometryVertex`: position, straight-alpha `Color`, UV 0 to 1), the primitive of a library that brings its own layout (RmlUi, `src/Modules/RmlUiHost/CLAUDE.md`). Each position is moved by the translation, then by the view transform; the draw obeys the clip; the texture is optional (without one the vertex colors are the fill). Not `BE_FUNCTION` (spans). It is virtual and not pure: the default logs once and draws nothing, for a backend without the primitive (both real backends have it). `SDLRendererBackend` uses `SDL_RenderGeometryRaw`; `VulkanRendererBackend` has a pipeline and a vertex buffer per frame in flight of its own (`src/Modules/Vulkan/CLAUDE.md`, "Geometry"). In both, an index past the vertices is logged and nothing is drawn. `RenderProbeComponent` draws two geometry quads for a look at both (and the turned textures of the transformed draws, which are geometry on Vulkan). `RecordingRenderer` records it as `DrawKind::Geometry` with the vertices in output pixels.
- **`CreateTexture(rgba, width, height)`:** a texture from pixels (RGBA8, red first, straight alpha, rows from the top, copied). It returns an empty pointer for a zero size or when the backend fails. Main thread only, like every GPU call; never inside `LoadAsync`. Vulkan textures are destroyed only when the GPU is idle (`VulkanTexture`).
- **`GetId()` and `WaitIdle()`:** `IRenderer::GetId()` is unique for the life of the process (a renderer allocated at the address of a dead one has another id); whoever keeps GPU objects of a renderer, such as the glyph atlases, remembers it and drops them when it changes. `WaitIdle()` blocks until the GPU has finished what was submitted (Vulkan: `vkDeviceWaitIdle`; the SDL default does nothing): call it before freeing textures that a frame in flight may use, and free them **before** the renderer is destroyed (`Application::Cleanup()` clears the glyph atlases before it emits `ApplicationCleanUpEvent`; EnTT calls an event's handlers in the reverse order of their subscription, so a handler subscribed earlier than the renderer's would run after its `Destroy()`).
- A test that needs a renderer uses `RecordingRenderer` (`tests/Common/RecordingRenderer.h`): it records the calls in output pixels with the clip and the blend mode in effect (`DrawCall::blend`; the default transformed draws appear as `DrawKind::Geometry`, or as the plain kind for an identity transform), reports a settable output size and keeps the pixels of the textures it makes. `RenderProbeComponent` is the debug component that draws every primitive for a look at both backends: the textures (plain, tinted, half alpha, turned 30 degrees, turned and mirrored), translucent rects, the clips, the geometry quads, and two cells split into a straight-alpha half and an additive or a multiply half (on Vulkan the halves look alike: the fallback).

## Draw counters

`IRenderer` counts draw calls, triangles and texture switches for the frame statistics (`RenderCounters`, `TakeRenderCounters()` once per frame in `Application::RunFrame`). A backend calls the protected `CountDraw(texture, triangles)` **once per primitive it really submits, after its early returns** (no pass, an empty clip, a texture of another backend, a bad index): a dropped draw is not counted. Only the primitives count: `DrawFilledRect`, `DrawTexture`, `DrawGeometry` (its whole triangles) and a backend's own `DrawTransformedTexture` (SDL's rotated draw; its identity branch goes through `DrawTexture` and is counted there). The defaults of `DrawTransformedRect` / `DrawTransformedTexture` go through `DrawGeometry`, so nothing is counted twice. A texture switch is a textured draw whose texture differs from the textured draw before it (untextured draws in between do not count). `ScopedRenderCountersPause` hides the draws of the profiler's own overlay. `RecordingRenderer` counts like a backend. ImGui draws through its own backend and is reported by `ImGuiWidget` as named counters of the frame statistics.

## Texture Pipeline

- Texture loading goes through dedicated `IResourceLoader` classes (`SDLTextureLoader`, `VulkanTextureLoader`), so it follows `src/Modules/BECore/Resource/CLAUDE.md`. Textures from pixels in memory come from `IRenderer::CreateTexture()` instead and are not cached by path.
- Keep texture lifetime and ownership behind `ITexture`. Do not expose backend handles in scene/component public APIs (`GetNativeHandle()` is for backend code).
- Named sprites come from `TextureLibrary` (`config/TextureLibrary.xml`): name → texture path + source rect.
- The aspect of a sprite is the scene's business, not the backends': `SceneDrawSystem` fits the node's rect with `FitSpriteRect()` (`fit="Contain"`, in scene units, before the view transform) from the registry copy of the component's fields (`SpriteDrawData`, `TransformData`) and passes the result to `DrawTexture()` (or `DrawTransformedTexture()` for a rotated or flipped node, about the node's pivot), so a backend only ever sees a destination rect and a source rect. `SpriteRendererComponent::SetTexture()` gives a sprite a texture from pixels (`CreateTexture()`), which is how a test makes one draw.

## Serialization and Components

- Texture-related component fields must be serialization-friendly and stable: sprite id / path / source rect, never a backend runtime handle (see `SpriteRendererComponent`).
- Serialize the data needed to rebuild the texture state, not transient backend objects.

## Cross-Backend Compatibility

- Define new renderer-facing behavior at the `IRenderer` / `ITexture` level first, then implement it in both backends where supported.
- If a backend cannot support a feature, document the fallback explicitly (skip draw, placeholder, or warning). `IRenderer::RequestCapture()` is an example: it is not pure, the default answers with an error, `SDLRendererBackend` reads its pixels back at the present and `VulkanRendererBackend` keeps the default (`src/Modules/Vulkan/CLAUDE.md`, "No capture").
- **Blend modes:** `SDLRendererBackend` implements `Alpha`, `Add` and `Multiply` (also on the headless software renderer, `SDLCaptureTest`). `VulkanRendererBackend` draws every primitive with straight alpha whatever `GetBlendMode()` says and logs one warning per backend (`WarnIfBlendModeIgnored()`) the first time a draw arrives with another mode; no pipeline was added (`src/Modules/Vulkan/CLAUDE.md`, "No blend modes"). The decision on the backends (the entry `renderer-backends`: SDL is the main backend, Vulkan stays at its feature level) comes first. `DrawTransformedRect()` / `DrawTransformedTexture()` need nothing from a backend: the defaults run on any backend with `DrawGeometry()`, which is what Vulkan uses for both and SDL for the rect. SDL draws a transformed texture natively (`SDL_RenderTextureRotated`, see "Drawing primitives"), so rotation and flip look the same on SDL and Vulkan, and only the blend differs.
- **Software rasterizer (headless SDL):** a textured `SDL_RenderGeometryRaw` goes through two paths that are wrong for a picture. (1) The triangle path turns UVs into whole texel numbers and `SDL_SW_BlitTriangle` spreads a texture of n texels over the numbers 0 to n-1 and rounds down (`SDL_triangle.c`, "interpolates up to the max values included, so reduce by 1"): the texture is shrunk by (n-1)/n, the last row and column show only at the far edge, and a 2 by 2 texture shows one texel everywhere (an 8 by 8 block edge moves from 1/2 to 4/7 of the width). (2) `SDL_SW_RenderGeometryRaw` takes two triangles that form an upright rectangle for a plain blit with flips only, and a quad turned by exactly 90 or 270 degrees is such a rectangle: it comes out stretched and flipped instead of turned (other angles are fine; 180 is right by luck). That is why the SDL backend draws a transformed texture with `SDL_RenderTextureRotated` and not through `DrawGeometry()`. A textured `DrawGeometry()` from a library (RmlUi) still takes the geometry path and has effect (1) there; its quads are not turned, so (2) does not arise. A pixel test samples well inside the blocks of its texture (`SDLCaptureTest`); an untextured geometry draw has neither problem.
- ImGui reaches the backend through `RenderEvents::ImGui*Event`, not direct calls (see `src/Modules/SDL/CLAUDE.md`).

## Vulkan specifics

Frame lifecycle, loader linking and the shader pipeline (GLSL → SPIR-V → embedded header) are in `src/Modules/Vulkan/CLAUDE.md`.

## Error Handling

- Validate resource loading and creation paths; log failures with enough context to trace the asset and the component.
- Avoid silent render failures: log a warning/error and apply a predictable fallback.
