---
name: artgen
description: Generates a game's art or sounds with the engine's art pipeline (ComfyUI through the editor's Generate panel) on a person's request, looks at the variants, and accepts the chosen one into the game (a sprite into TextureLibrary, a sound as a WAV clip) over the control API; starts ComfyUI, the editor (--editor) and the bridge when they are not running and closes what it started. Use when the user asks to generate or draw a sprite, an icon, a piece, a texture or a sound effect for the game, to make a set of them in one style, to replace a game's clip with a generated one, says "artgen", "сгенерируй спрайт", "нарисуй", "сделай звук", "сгенерируй набор"; also autonomously ("autonomously", "while I am away", "автономно", "пока меня нет").
---

# artgen

`/artgen <what to make>` ("a rook in the style of the game's pieces", "the sound of a capture", "all twelve pieces"). You make the art through the same path the person uses: the editor's Generate panel and its control API (`artgen_*`), never ComfyUI directly, so every result has its provenance and lands in the game the way an Accept by hand does. You never commit and never push.

Read first: `<engine>/src/Widgets/ArtGen/CLAUDE.md` ("The contract": every `artgen_*` method, its params and answer; "Accept", "Accept of a sound") and `<engine>/tools/artgen/CLAUDE.md` (presets, the service, the bridge) and `<engine>/tools/artgen/comfyui/CLAUDE.md` (setup, models, the health check).

Terms: `<engine>` is `engine` in a game (`.` in the engine's own repository); `<product>` is the field `Product` of `.claude/rules/build-project.md`, `<exe>` is `build/<preset>/bin/<product>` (`.exe` on Windows) with the Debug preset of that file; `<port>` is the control port (8765 is the default of `--control`); `<scratchpad>` the session's temporary folder. Commands run from the root of the repository; on Windows `python`, elsewhere `python3` (`.venv/bin/python` on macOS).

## Steps

1. **The generator.** `python <engine>/tools/artgen/comfyui_check.py --json`: exit 0 is ready (`kinds` says what it makes: `image`, `audio`, and `style` when the style models and the IP-Adapter custom node are there); exit 2 is not running: `python <engine>/tools/artgen/artgen_setup.py start` (it waits until ComfyUI answers) and remember that you started it; exit 1 is a missing model: say which. **Never run `install`** (gigabytes, licences, the audio model needs the owner's Hugging Face token): give the command (`artgen_setup.py install`, `install --audio`, `install --style`: the last one also fetches a custom node by git) and stop. A sound asked from a generator without `audio`, and a style reference asked from one without `style`, stop the same way.
2. **The editor.** Connect to `127.0.0.1:<port>` with `BagiControlClient` (`<engine>/tools/control/bagi_control_client.py`) and call `artgen_state`:
   - it answers: the person's editor is open. Work in it; the person sees your run in the Generate panel. Do not close it, do not save its scene, do not touch what the request does not name;
   - `unknown_method`: an editor in Game mode (the methods exist only after the panel was created once). Say so and stop: the person reopens it in Editor mode;
   - no connection: start your own. Build `<product>` through the `build` skill if `<exe>` is missing. Start `<exe> --editor --control --control-port=<a free port, not 8765>` in the background from the root (`--editor` opens the editor for this run; never edit `mode` of `config/ApplicationConfig.xml`) and connect until it answers (a Debug build takes several seconds). An `<exe>` that ignores `--editor` (an engine older than 0.1.12) answers `unknown_method`: rebuild it.
3. **The service.** `service.connected` false: start the bridge in the background, `python <engine>/tools/artgen/artgen_bridge.py --port <port> --exit-with-editor` (it ends with that editor), and poll `artgen_state` until `service.connected` and `service.state` is `ready`. A connected service is the panel's or the person's: never start a second bridge beside it.
4. **The preset.** `service.presets` lists the game's presets, then the engine's starters (`sprite`: one object cut out on a transparent background; `icon`; `sfx`: a short sound), each with its `kind`; a preset with an `error` is broken. Take the game's preset that fits the request (a game's style lives there: `<game root>/artgen/presets/<name>.json`, read it). When none fits, send a **draft** (the preset's content inline, `presetName` naming it) built on the closest one, and say what you changed. A preset is written to the game (`artgen_save_preset`) only when the person asks for it.
5. **Generate.** `artgen_generate {preset, subject, count, seed?}` (count 4 for a choice, 1 to remake a known seed; `artgen_busy` is a run already in work, the person's: wait for it or ask, never `artgen_cancel` a run you did not start). Poll `artgen_state` every second or two until `run.state` is `Done`, `Failed` or `Cancelled`; `run.error` is the reason of a failure. The variants are `run.variants: [{seed, path, provenance, kind}]` (files in `<game root>/artgen/out/`, git-ignored). An image takes seconds to tens of seconds on the owner's GPU, a sound about as long as an image; a run that has not moved for several minutes is reported, not waited for forever.
   - **Variations of a picture.** To redraw an existing picture (a sprite of the game, a variant you liked) instead of starting from noise, add `reference: {mode: "init", image: "assets/artgen/<sprite>.png", weight?}` (a variant's `path` under `artgen/out/` works too). `image` is read from the game root (a path that leaves it fails the run) or is an absolute path; it must be a PNG, JPEG or WebP of at most 16 MiB. `weight` is above 0 and below 1, default 0.4: higher keeps more of the picture, lower redraws more (try 0.3 for a new idea, 0.6 for a variation). A reference replaces the preset's own `reference`, which applies when the call has none. `run.reference` echoes it and each variant's provenance has a `reference` block (mode, image, hash, weight, the workflow that ran); a bad image or a preset with no way to run the mode fails the run with the reason in `run.error`. A sound takes no reference.
   - **In the style of a picture.** `reference: {mode: "style", image, weight?}` draws a **new** picture (a new subject, from noise) in the style of the image, so the shape is not copied; `image` is read as for `init`. `weight` is the adapter's strength, above 0 and below 2, default 0.8: higher follows the style harder. It needs the generator's `kinds` to list `style`; without it the run fails at once with the install command in `run.error` (hand that command to the person, step 1). A cut-out reference works: its transparent pixels are put on grey.
6. **Judge.**
   - **Images, the checks first.** A variant with an alpha has `checks` in its provenance file (`run.variants[].provenance`; a set row's is relative to the set folder): `{passed, failed: [names], metrics, thresholds}`. Read it before the picture. `passed: false`: **drop it without looking** (`failed` names: `empty`, `edge`, `pieces`, `halo`, `background`, `small`, `offCentre`; keep them for the report). `passed: true`: look. No `checks` key (no alpha: an icon) or `passed: null` (unreadable): look.
   - **Images, the eye.** Open the PNG with `Read`: the object is the asked one, one object, no text or watermark, no extra limbs or parts, and it matches the style of what the game already has (the accepted sprites in `assets/artgen/` and the atlas). With a reference, look at each variation beside its source: it should keep what the weight promises (shape, colours) and still be a new drawing, not a copy. With `style`, put the result beside the reference: the palette, the brush and the lighting carry over, the subject and the shape are the asked ones. Drop the broken ones; when none is good, generate again with other seeds or a changed prompt (at most three rounds, then show the best and say why it is not good enough; in autonomous mode, step 8).
   - **`regenerate`.** A preset's `regenerate` (`{"extra": n, "minPass": m}`) makes the service itself add up to `extra` images on the next seeds while fewer than `minPass` (default `count`) pass, so a run may hold more than `count`. `python <engine>/tools/artgen/artgen.py check <png>... [--preset <name or file> --game-root .] [--json]` runs the checks on any PNG on disk (a game's sprite, an older variant, a preset's thresholds): exit 0 all pass or have no alpha, 1 one fails or cannot be read, 2 a file or preset cannot be opened.
   - **Sounds:** you cannot hear them. Read each variant's provenance (`seconds`, `sampleRate`, `channels`, the prompt) and drop only what is plainly wrong (a length far from the asked one). The choice is the person's: give them the seeds and say to listen in the Generate panel (View → Generate Art, Play beside each).
7. **Accept.** It writes the game's files (`assets/artgen/`, `config/TextureLibrary.xml`, a clip), so accept when the request asked for the result to be put into the game; otherwise show the pick and ask.
   - An image: `artgen_accept {seed, sprite}` (a sprite name is 1 to 64 of `A-Z a-z 0-9 _ -`; an existing name is replaced, so check the library first when the person did not name it). The file is **trimmed to what is drawn and downscaled** (the preset's `accept`, else the defaults), so the answer's `width` and `height` are the written file's, not 1024; `image: {trim, padding, maxSize}` overrides it for this call. `useOnSelected: true` only when the person asked to put it on the selected node. A preset with `atlas`, or `atlas: "<group>"` in the call (`""` for none), makes the sprite a member of that atlas group and packs it: the answer's `atlas` says it (a sprite already packed in another group is refused: Unpack it in the Sprite Library first).
   - A sound: only the seed the person picked. `artgen_accept {seed, name}` writes `assets/artgen/<name>.wav`; `{seed, clip: "assets/.../x.wav"}` replaces a clip the game plays (find the clip paths in the game's sound docs or config first). `sound` overrides the processing (`maxSeconds`, `peakDb`, fades; the defaults are `ArtGenSoundSettings` in `src/Widgets/ArtGen/ArtGenSound.h`). The answer gives the length and the peak written: report them.
8. **Sets.** Many subjects in one style (the pieces of a set, the sounds of a board) are one **set**, not a loop of runs: the editor queues the jobs, runs them one at a time with one shared first seed and keeps them in `<game root>/artgen/out/<set>/` (git-ignored, the person reviews it in the panel's Set tab; "Sets" of `<engine>/src/Widgets/ArtGen/Sets/CLAUDE.md` has the rules).
   - **Queue.** `artgen_enqueue {preset, subjects, count, set?, seed?, reference?, atlas?}`: `preset` is a name or a draft (as in step 4, with `presetName`); `subjects` is one string of lines, `name: subject text` each (the name is the job's folder, file stem and the sprite or clip name of Accept all; without `name:` it is made from the subject; a `#` line and an empty one are skipped; `a cat: sitting` is one subject, the part before the first `:` is a name only when it has no space), or a list of strings and `{name, subject}`. `count` 2 to 4. **Give no `seed`**: the set draws one shared seed and records it (`artgen_state.sets[].seed`); pass `seed` only when the person asks to reproduce a look. `set` names the folder (default `<preset>-<date-time>`; an existing folder is refused as `invalid_params`). The answer is `{set, jobs, seed, serviceConnected}`. It is never `artgen_busy`: a set queued while a run or another set (the person's too) is in work waits in the line behind it; check `artgen_state` first and ask before queuing behind the person's work. `artgen_generate` is refused while a set is active. **A set of sprites of one kind (chess pieces, icons) is queued with an atlas group**: the preset has `atlas` or the call gets `atlas: "<group>"` (a name like `pieces`; a sound set takes none), and the set records it.
   - **The first sprite is the style.** To make a set look like one thing, make the first piece alone: `artgen_generate` it, judge it, `artgen_accept` it as a sprite, then queue the rest with `reference: {mode: "style", image: "assets/artgen/<first>.png"}` (`weight?` as in step 5; every job of the set runs with it, a Retry and `artgen_more` keep it). `artgen_set` and `artgen_state.sets[].reference` show it. Say in the report which sprite was the style source. A set with no reference runs as before, and a reference needs the `style` kind (step 1).
   - **Wait.** Poll `artgen_state.sets` (the row of your set: `state` `Active` or `Complete`, `jobs: {pending, running, done, failed, cancelled}`) every second or two until `Complete`; `artgen_set {set}` gives the rows (`jobs[].state`, `error`, `variants` with `file` and `provenance`). Jobs wait while no service polls: `serviceConnected` false means step 3 is not done. No job moved for several minutes: report it, do not wait for ever.
   - **Judge** each `Done` row as in step 6, checks first: the variants' `file` and `provenance` are relative to the set folder (`<game root>/artgen/out/<set>/<file>`); read the provenance JSON, then `Read` the PNGs that passed. `artgen_pick {set, job, seed}` the best that passed per row (a variant with `checks.passed` false only when the person named that seed), and keep why it beat the others for the report. A `Failed` or `Cancelled` row: `artgen_retry {set, job}` (it goes back to `Pending` and the set goes on), at most twice. A row that runs but does not fit: queue a new set of that one subject (same name) with the old set's `seed`, `count` 4, a changed subject and **`frameOf: <the old set>`** (the new object is then cut and scaled like the old rows; without it a lone row gets a frame of its own and comes out as big as a king), pick from it there, accept the old set first and the new one after it, so the better candidate is the one the game holds, and say so. The set that accepted a name last owns it: the old set's row is then *replaced by* the new set, and a pick or a Keep on it, like a repeated `artgen_accept_set` of the old set (it skips the row and lists `{job, replacedBy}`), cannot overwrite the better candidate; only the new set's row switches (the way back to the old picture is a new set). Judge each row against the others and the game's accepted sprites, so the set looks like one.
   - **Another variant per subject.** When the person asks for more choice on a finished (`Complete`) set, `artgen_more {set, count?}` (count 1 to 16, default 1; **give no `seed`**, one fresh seed is drawn for the rows): every `Done` row that is not kept gets `count` more variants appended on a new seed, and the set goes `Active` and back to `Complete` (poll as in Wait). The pick and what the game holds stay as they are, so the new variants are alternatives: judge them as above and `artgen_pick` one (on a live row it switches the game). The answer's `skipped` lists the rows left out (`kept`, `failed` and `cancelled` rows, `full` at 64 variants); `artgen_busy` means the set still runs; `artgen_more {set, jobs: [names]}` takes only those rows. A variant bigger than the frame an accepted set already fixed cannot be switched to (below).
   - **One frame and scale.** The first `artgen_accept_set` of an image set measures every variant of every row and fixes one frame (`artgen_set` shows `processing`): all files get the same size and scale, so a pawn stays smaller than a king, and a later accept, a switch or a Keep never moves it. `frameOf` is refused for an unknown set, a sound set or a set with no frame yet (`invalid_params`). A variant whose object is bigger than the fixed frame is refused (`artgen_accept_failed` "does not fit the frame of the set", nothing written): pick another variant. A set accepted before frames existed keeps writing full frames.
   - **Accept.** `artgen_accept_set {set}` only when the request asked for the result to go into the game and every row is `Done` (else `artgen_set_incomplete` names the rows). It writes a **candidate** of every row under the job's name: its pick, else the first variant (which may have failed its checks), which becomes the pick: so pick every row yourself first. The answer's `accepted` lists per row `{job, as, seed, alternatives, ...}`: the seed written and the count of other variants. With a group the rows join it unpacked and `artgen_accept_set` packs it once after the last row, answering `atlas` (`{name, texturePath, width, height, members}`): report the atlas file `assets/atlases/<group>.png` and its size; a sprite already packed in another group is refused (Unpack it first), a switch of a live row repacks, and a failed pack leaves the rows accepted (call again). It writes the sprites in one go, so the game never shows half of an old set and half of a new one, and **leaves every row's alternatives alive**: a row accepted and not kept is *live*, `artgen_set` shows `accepted.kept` false and `pick`, and `artgen_state.sets[].live` counts them. `artgen_pick {set, job, seed}` on a live row writes that variant into the game at once (the answer adds `switched`), so you may compare the candidates in the running game (`screenshot`) and flip to a better one; `artgen_accept_failed` there means the write failed and nothing changed. An `artgen_accept_failed` of `artgen_accept_set` names the row and the rows done: fix the cause and call it again (it replaces the same names). **Never call `artgen_keep`** (it is `artgen_busy` while the set runs): keeping drops the alternatives for good, and that is the person's word after they have looked at the scene in the Set tab (Keep per row, Keep all). A set of **sounds** is never picked or accepted without the person (the rule of step 6): leave the rows unpicked, list the seeds per row and say to listen in the Generate panel's Set tab (a sound set with a row unpicked is `artgen_set_incomplete`).
   - **Autonomous mode**, only when the person asks for the work to be done without them ("autonomously", "while I am away", "пока меня нет", "без вопросов"); otherwise you are interactive as above. Never stop to ask: where the text says ask, take the safe side (wait behind the person's work up to the limit, then report; never replace an existing sprite name; accept only what was asked). `N` = 3 rounds:
     - A draft built for a set adds `"regenerate": {"extra": 6}` when the preset has none; never with `checks: false`, a sound preset or changed `checks` thresholds the person did not ask for.
     - A row is **settled** at 2 variants that passed the checks and the eye (1 when only one passed in all rounds). For the others `artgen_more {set, jobs: [names]}` (no `seed`) and judge only the new variants. After round `N` a row with no variant that passed both is **unresolved**.
     - `artgen_pick` the best that passed per row. An unresolved row stays unpicked and the set is **not accepted**: `artgen_accept_set` would take its first variant, which may have failed, so never call it while a row is unresolved (the report lists them). When every row has a passing pick and the request asked for the result in the game, accept as above.
     - `Failed` / `Cancelled` rows: `artgen_retry` at most twice; one that still fails is unresolved. A single run (`artgen_generate`): `count` 4, at most `N` further runs. A sound set: only wait for `Complete`, never pick or accept, give the seeds to listen to.
     - **Push notification:** once, when the set (or run) is done and the report is ready, after step 9, with the session's push-notification tool (`PushNotification` in Claude Code): one short line in the person's language (set name, rows picked and accepted, rows waiting for the person); never one per step, in interactive mode, or with the token or a path. Without such a tool the report says it is the only notice.
9. **Finish.** If you started the editor: `quit` over the control API, wait for the process (the bridge exits with it). If you started ComfyUI: `artgen_setup.py stop`, unless the person wants to go on generating. Leave the person's editor, bridge and ComfyUI running. In autonomous mode the push notification comes after this.
10. **Report**, in the person's language, short: what was generated (preset, subject, seeds; for a set its name, folder `artgen/out/<set>/` and shared seed; per row the variants made (extra ones, rounds), the checks that failed (`failed` names), what the eye dropped, the unresolved rows, the `regenerate` you added), what was accepted where (paths, the sprite or clip name, for an image the size written, for a sound its length and peak); for a set, per subject the candidate (its seed), why it beat the others, and which rows you did not choose (the first variant took the place); that the alternatives are alive in the game and in the Set tab and that Keep is the person's; what waits for the person (sounds to listen to, a pick between two), and `git status` of what changed in the game, uncommitted: committing is the person's word.

## The example script

A session in the background while you watch its output; change the request, keep the shape. The first script is one run, the second one a set.

```python
"""python artgen-<slug>.py <port>: one run over the editor's control API; prints the variants as JSON."""

import json
import os
import sys
import time

sys.path.insert(0, "engine/tools/control")  # "tools/control" in the engine's own repository
from bagi_control_client import BagiControlClient  # noqa: E402

client = BagiControlClient("127.0.0.1", int(sys.argv[1]))
client.connect()
for _ in range(120):
    service = client.call("artgen_state")["service"]
    if service["connected"] and service["state"] == "ready":
        break
    time.sleep(0.5)
else:
    sys.exit(f"the service is not ready: {service['state']} {service['reason']}")

client.call("artgen_generate", {"preset": "sprite", "subject": "chess rook", "count": 4})
deadline = time.monotonic() + 600
while time.monotonic() < deadline:
    run = client.call("artgen_state")["run"]
    if run["state"] in ("Done", "Failed", "Cancelled"):
        break
    time.sleep(1.0)
print(json.dumps({"state": run["state"], "error": run["error"], "variants": run["variants"]}, indent=1))
client.close()
```

A set replaces the `artgen_generate` part of the first script, from `client.call("artgen_generate", ...)` through its final `print` (the connect and the readiness loop stay, and `client.close()` stays last): one call with the subjects, wait for `Complete`, print the rows with the verdict of each variant (then `Read` what passed, `artgen_pick`, accept only when asked; `artgen_keep` is never yours):

```python
subjects = ["rook: chess rook", "knight: chess knight", "bishop: chess bishop"]
queued = client.call("artgen_enqueue", {"preset": "sprite", "subjects": subjects, "count": 3, "atlas": "pieces"})
deadline = time.monotonic() + 1800
while time.monotonic() < deadline:
    row = next(s for s in client.call("artgen_state")["sets"] if s["name"] == queued["set"])
    if row["state"] == "Complete":
        break
    time.sleep(2.0)
rows = client.call("artgen_set", {"set": queued["set"]})["jobs"]
game_root = client.call("artgen_state")["gameRoot"]
set_folder = os.path.join(game_root, "artgen", "out", queued["set"])


def verdict(variant):  # None: no checks (no alpha)
    with open(os.path.join(set_folder, variant["provenance"]), encoding="utf-8") as f:
        checks = json.load(f).get("checks")
    return checks and {"passed": checks["passed"], "failed": checks.get("failed")}


print(json.dumps([{"job": r["name"], "state": r["state"], "error": r["error"],
                   "files": [[v["file"], verdict(v)] for v in r["variants"]]} for r in rows], indent=1))
```

## Forbidden

`artgen_setup.py install` or `artgen_setup {"action": "Install"}` without the owner's yes; reading, printing or writing the Hugging Face token; cancelling or replacing a run, a job or a set you did not queue (`artgen_cancel`, a pick or a retry in the person's set); `artgen_keep` (the person keeps, after looking at the scene); accepting a sound nobody listened to; in autonomous mode accepting a set while a row is unresolved or has no passing pick; picking a variant whose `checks.passed` is false unless the person named that seed; saving the scene or changing nodes beyond `useOnSelected`; editing workflows, the manifest or `ApplicationConfig.xml`; `git commit`, `git push`.
