# sync-engine

You are the **conductor** and do everything yourself, no agents. The engine repository has `main` (the showcase) and a branch per game (`games/mahjong`, `games/chess`, ...). The model (the owner's, 2026-11-14): nothing reaches `main` except through a `games/*`; a `todo/<id>` branch is never merged into `main` and never cut from it; engine work is done in the `games/*` branches (mostly `games/mahjong`); the owner syncs the triangle themself, rarely. This skill is run **only when the owner asks for it**: no other skill, `todo-loop` or `todo-merge` offers it. It merges locally and **never pushes**; engine work happens on more than one PC, so pushing and pulling is the owner's.

`/sync-engine`

Terms (those of `.claude/rules/build-project.md`, "Terms"): `<E>` is the engine repository, the same as `<engine>`: `.` in the engine repository, `engine` in a game. `<p>` is the preset the `build` skill would pick for this OS, `<E>`'s own presets (`macos-debug` on macOS); every build and test command runs from `<E>`. The read-only helper is `python3 <helper> --repo <E> ...` (`tools/sync/CLAUDE.md`: the fields of its JSON, the config keys, the exit codes); it never writes, so the skill fetches first. `<helper>` is a **copy** of `<E>/tools/sync/engine_sync.py` that step 1 makes outside the repository: after a `switch` to `main` or to a game that does not have the file yet, the original is gone. Ask the owner in Russian (AskUserQuestion) and report in Russian.

## Steps

1. **Preconditions.** Run in the **main checkout** (like `todo-merge`: a worker folder cannot switch to a branch another worktree holds): `git -C <E> rev-parse --absolute-git-dir` must equal `git -C <E> rev-parse --path-format=absolute --git-common-dir`, otherwise stop and say which folder to use. `git -C <E> status --porcelain` is empty and `git -C <E> rev-parse -q --verify MERGE_HEAD` finds nothing; otherwise stop with a message (in a game only `<E>` matters, not the game's own changes). Copy `<E>/tools/sync/engine_sync.py` to the scratchpad of the session (`<helper>`; the file has no imports of the repository). Remember the **starting branch** (`git -C <E> symbolic-ref --short -q HEAD`) or, when detached, its commit (`rev-parse HEAD`): every stop and the end switch back to it.
2. **The reminder, then the fetch.** Before any command that reads the remote, tell the owner: make sure every branch is pushed from every other PC where engine work was done. One AskUserQuestion: `Pushed, go on` / `Stop` (`Stop` ends the skill, nothing changed). Then `git -C <E> fetch origin` (the one network read: never `pull`, never `--prune`).
3. **Which `games/*` take part.** `python3 <helper> --repo <E> status --json`. Its `undecided` lists the `games/*` the owner has not decided on (the first run: `games/match3`, which moved to its own repository, and the games this PC has not seen). Ask about them in one AskUserQuestion (a question per branch: `Take part` / `Leave out`) and keep each answer in the local git config of `<E>`: `git -C <E> config --local --add engine-sync.include <branch>` or `engine-sync.exclude`. Run `status --json` again. Nothing is assumed.
4. **The state against `origin`.** Exit code 2 of `status` (`stop` in the JSON lists the branches): a participating branch is `behind` or `diverged` from its `origin`. Stop with the report (which branch, `local_ahead` / `local_behind`) and say the owner pulls or resolves it by hand; nothing was changed yet. A branch that is only `ahead` is taken as is and listed at the end (step 8). A branch with `relation: no-local` (the remote has it, this PC has no local branch) is made local: `git -C <E> branch <branch> origin/<branch>`; run `status --json` again afterwards. Exit code 1 is an error: stop with its text.
5. **The snapshot and the question.** Print one table in Russian: per `main` and `games/*` the relation to `origin`, `ahead_of_main` / `behind_main`, and the `merges` titles (the todo branches the game has that `main` has not) with the count of `commits`. **Up** candidates are the games with `own_work` (a game that only took `main` in has `sync_merges` and nothing to bring); **Down** candidates are those with `behind_main` > 0 (after Up, every game is one). Nothing for either: say so, go to step 8 (the push lines of what is ahead of `origin` are still worth printing) and end. Otherwise one AskUserQuestion call: the mode (`Up and Down` / `Up only` / `Down only` / `Stop`) and, when there are several branches, a multi-select to leave some out of this run. A branch that must be switched to (`main` for Up, a game for Down) with `held_elsewhere` true in `status` stops the run before any change, naming `worktree`.
6. **Up (`games/X` -> `main`).** `git -C <E> switch main` and `<recorded>` = `git -C <E> rev-parse main`. For each chosen Up branch, in the order of the snapshot: dry check `git -C <E> merge-tree --write-tree main <branch>`; a non-zero exit code means conflicts: report the files and back out (below). Then `git -C <E> merge --no-ff -m "Merge branch '<branch>'" -m "<the Co-Authored-By line the conversation gives>" <branch>` and note the new `HEAD` as `<last>`. If the merge fails anyway: `git -C <E> merge --abort` and back out. **Before the merges are kept**, build and test the result once (several branches: once on the final `main`), from `<E>`: `cmake --preset <p>`, `cmake --build --preset <p>` (no `--target`: every target, so `BagiStress` is built and the control smoke runs instead of skipping with 77; run it in the background, a cold build is long), `ctest --preset <p>`. A failed name is run once more alone (`ctest --preset <p> --rerun-failed`): a timing-sensitive case under load may pass. Red (a failed build, or a test that fails again): name the failing tests and back out.
   **Backing out** is the one place `reset --hard` is allowed, because the skill made those commits in this run: all three must hold, otherwise do not reset, report and stop: `git -C <E> rev-parse HEAD` equals `<last>`; `git -C <E> merge-base --is-ancestor <recorded> HEAD`; `git -C <E> merge-base --is-ancestor origin/main <recorded>` (nothing already pushed is dropped). Then `git -C <E> reset --hard <recorded>` (after a `merge --abort` when a merge was under way), switch back to the starting branch and stop **without Down**.
7. **Down (`main` -> `games/*`)**, only after Up is green or when nothing was ahead. `status --json` again (local refs only); for each chosen game with `behind_main` > 0: `git -C <E> switch <game>`, dry check `git -C <E> merge-tree --write-tree <game> main`, then `git -C <E> merge -m "Merge branch 'main' into <game>" -m "<the Co-Authored-By line>" main` (a fast-forward when the game has nothing of its own, which ignores the message). A conflict (the dry check, or the merge: then `git -C <E> merge --abort`): report the files, switch back to the starting branch and stop; the skill never resolves a game's side and does not go on to the next branch. No build for Down: a game's own build and tests are its own.
8. **The end.** `git -C <E> switch <starting branch>` (or `switch --detach <commit>`). `python3 <helper> --repo <E> pushes` prints one `git push origin <branch>` per local branch ahead of `origin`: print them as they are, say that pushing is the owner's, from this PC, and that the other PCs `git pull` after. In a game (`<E>` = `engine`): if `git status --porcelain -- engine` shows `engine` modified (the checkout stands on another commit than the pointer) and that commit is in the game's base branch `games/<area>` (`git -C engine merge-base --is-ancestor HEAD games/<area>`, `<area>` from `.claude/rules/todo-project.md`), first run `python3 engine/tools/changelog/changelog.py breaking --since pointer --repo engine` (when `engine/tools/changelog/` exists; it is read-only and never fetches) and show what it lists, so the owner sees what breaks the game before the pointer moves; then offer in one AskUserQuestion one commit `Update engine: sync <short sha>`: `git add engine` only, the Co-Authored-By line the conversation gives, on the branch the game stands on (as step 10 of `todo-merge`). A commit that is not in `games/<area>` is never offered. The pointers of the other games are left to those games: name them.
9. **Report** in Russian, short: what was merged (each `games/X` into `main`, each `main` into a game, the merge commits), whether the build and the tests ran and their result, the local branches made, what stopped the run and what the owner does, the push commands, the pointer commit, where the checkout stands now.

## Rules

- **Never:** `git push` in any form, `--force`, a `reset` outside the back-out of step 6, `git pull`, `fetch --prune`, resolving a conflict, `git submodule update`, `clean`, `stash`, `--no-verify`, `branch -D`.
- The only writes: the local config of step 3, `branch <game> origin/<game>`, `switch`, `merge` (`--no-ff` into `main`) and the one reset. No `todo/*` branch is merged, cut from `main`, switched to or deleted; the vendored zones are not touched; no file is edited.
- A dirty checkout, a branch held by another worktree, a branch behind or diverged from `origin`, a conflict, red tests: stop, report, switch back to the starting branch. Everything that is not green leaves `main` where it was.
- The skill does not offer itself and is not wired into other skills.
