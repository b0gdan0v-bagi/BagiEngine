# qa-loop

`/qa-loop [dry] [<minutes>] [<charter>]`. You are the unattended tester: for `<minutes>` (default 30) you run the seeded monkey (`tools/qa/CLAUDE.md`, "The monkey", "The loop") over the charters of the product, file what is new as `bug-<short>` entries and keep the log of the seeds you covered. A charter is a row of "Monkey" in the rules file or free text; none means the rotation. You never fix code and never commit. Interactive play by a charter is `/qa`; this skill is its unattended walk and reuses its filing (`.claude/skills/qa/SKILL.md`, step 6).

Terms as in `/qa` (`.claude/rules/qa-project.md`): `<engine>`, `<R>`, `<product>`, `<invariants>`, `<exe>`, `<scratchpad>`, `<date>`. `todo` is `python3 <engine>/tools/todo/todo.py --actor qa-loop`, `loop` is `python3 <engine>/tools/qa/bagi_monkey_loop.py`. Commands run from the root of the repository. `dry` (or `todo ping` failing) files and puts nothing into the store.

## In a worker

The skill needs a checkout of its own, so it runs in an idle worker (`worker.py list`: no session, clean, at the base), not in the owner's main checkout: `claude --bg "/qa-loop 30"` in the worker folder, or `python3 <engine>/tools/todo/worker.py run <k>` from the main checkout, which opens a session in that folder, and `/qa-loop 30` typed in it. It tests what is checked out and builds in the worker's own `build/`; it claims no entry, makes no branch and writes no file in a repository, so it meets no other loop. The worker must not run `/todo-loop` meanwhile (no `start`, no `kick`).

## Steps

1. **Rules.** Read `.claude/rules/qa-project.md`; without it say that this repository has no QA setup and stop. The charters of the loop are the rows of the table in "Monkey" whose Kinds are not `none` (each with its `Start` and `Kinds`); `<charter>` limits the loop to one row or, as free text, runs with the first row's `Start` and `Kinds`. Read "Invariants" and "Known deviations" so you know what a right answer looks like. The budget starts now: note `date +%s`.
2. **Where.** The checkout stands as it is and stays: `git status --short` must be empty (else stop and say so), and `git rev-parse --short HEAD` is the `build` of the log rows. Never switch branches or update anything.
3. **Log.** `todo plan get qa-loop-log-<product>.md --stdout > <scratchpad>/log.md` (a plan the store does not have is a new log: remove the empty file). Then `loop next-seeds --log <scratchpad>/log.md --charter "<text>" [--charter "<text>" ...] --count 5` with the charters of step 1 in the table's order: it prints `{"charter", "first", "last"}`, the charter that has no row yet, else the one walked longest ago.
4. **Build** `<product>` through the `build` skill with the preset of the field `Loop preset` of "Session", only when `<exe>` is missing or older than the sources.
5. **Sweep.** `loop sweep --exe <exe> --invariants <invariants> --charter "<text>" --first <first> --count 5 --minutes <what is left of the budget> --minutes-per-seed <the per-seed minutes of "Monkey"> --start '<the row's Start>' --kinds <the row's Kinds> --stop-after-bugs <3 minus the distinct findings of this run> --out-root <Out folder>/<date>-loop-<slug>-<first>` (no `--start` or `--kinds` for a row that has none or says all). Exit 0 clean, 1 a bug, 2 a bad option, an `--out-root` inside a repository or a start the game refused (report it, no retry loop; the bugs of the seeds before a refused one are still in `sweep.json` and go through step 6 like any other), 77 no executable. Run it in the background when the budget is above two minutes; a game process a stopped sweep leaves is yours to stop. Read `<out-root>/sweep.json` (`stopped`, and per seed `bugs`, `known`, `repros`, `drafts`, `out`). Then step 7 (not with `dry`), then the next charter (`next-seeds` again, now with the new row) while the budget lasts and fewer than 3 distinct findings are filed or matched in this run.
6. **Per bug** (a seed record with `bugs`). `python3 <engine>/tools/qa/bagi_qa.py drafts <out>` lists the drafts of the seed with their titles; read `<out>/bugs/<id>.md` and `<id>-repro.md`, and `session.jsonl` only when the draft says the reproduction is not cut. A finding in `known` is a known deviation, not a bug. A name in the record's `unshrunk` (and a lost game, `monkey.game_lost`, which is never shrunk) is not yet proved: `python3 <engine>/tools/qa/bagi_qa.py replay --exe <exe> --invariants <invariants> <out>/session.jsonl`, exit 1 means it recurs and the draft with the recording is filed, 0 drops it (say so in the report). Then, for each draft, in the `Bug area`:
   - **Duplicate check.** `todo list --all --json`; for every entry whose id starts with the `Bug id prefix` fetch `todo plan get <id>-repro.md --stdout > <scratchpad>/known/<id>-repro.md` (an entry with no such plan is skipped), then `loop dupes --repro <out>/bugs/<id>-repro.md --known <those files> <the repros filed earlier in this run>` (no file at all is fine, exit 0): exit 1 prints `DUPLICATE <file>: <finding>`. A match is handled as `/qa` step 6 handles one: open or deferred: the paragraph `**Seen again by QA (<date>):**` added to the body from `todo show <id> --json` with `todo edit <id> --body-file <file in <scratchpad>> --expected-version <version>`; in progress or review: only named in the report; closed: the new entry names it as a possible regression.
   - **No match:** `todo show` of an entry about the same thing in other words (the title and the finding name), then **file** as `/qa` step 6 does: `todo add bug-<short> --area <area> --title "<title>" --body-file <out>/bugs/bug-<short>.md`, `todo plan put bug-<short>-repro.md --entry bug-<short> --kind review --file <out>/bugs/bug-<short>-repro.md` (the kind and why: `/qa` step 6). An id that is taken (by an entry or by another seed's draft of this run) gets `-2` in the entry id and the plan name; no `--priority`, no `--stage`.
7. **Log back** (not with `dry`), after each sweep so a stopped run keeps what it covered: `loop log-add --log <scratchpad>/log.md --product <product> --sweep <out-root>/sweep.json --build <short commit>`, then `todo plan put qa-loop-log-<product>.md --entry qa-loop --kind review --file <scratchpad>/log.md` (`--kind review` for the reason `/qa` step 6 gives: the name matches no loop pattern, so the log belongs to the entry `qa-loop` and is nobody's plan). A sweep that walked no seed (`log-add` exits 2) logs nothing.
8. **Report**, short, in the user's language: the charters with their seed ranges and moves, the build, the bugs with the ids of the entries (or the drafts' paths with `dry`), what recurred as a duplicate and of which entry, what did not recur, the known deviations met, the log's plan name, the out folders, and what was not run (the budget, a charter, a refused start).

## Rules

- Never edit code, tests or content, never commit, never write inside a repository: the log, the sweeps and the scratch files are outside (`QaSession` refuses an out folder in a git work tree). The writes besides them are the entries and plans of steps 6 and 7, and none with `dry`.
- The manual clock only, headless only: `sweep` starts the game itself. Never file without a reproduction that recurred, never hide a finding behind a deviation without a reason in the rules file; one bug, one entry.
- A session that cannot start (no executable, the port taken, the game exits at once, exit 2 of a sweep) is a report with the error, not a retry loop. Never touch `.env`, a token or the entries of others beyond the paragraph of step 6.
