# Panel assets in the editor

The editor half of "panels as data": it draws a `PanelAsset` (`config/panels/<Name>Panel.xml`) on ImGui and hosts it as a widget. The format, the loader, the sources and the reads of a bound value are the pure half, `src/Modules/BECore/Widgets/PanelAssets/CLAUDE.md` (read it first). Editor only: the folder is in the `BE_WITH_EDITOR` regex of `src/CMakeLists.txt` (`.claude/rules/widgets-module.md`). The assets are the Config Editor (`config/panels/ConfigEditorPanel.xml`, `ConfigEditorPanelModel` in `Widgets/ConfigEditor/`, `Widgets/ConfigEditor/CLAUDE.md`), the File changes panel (`config/panels/FileChangesPanel.xml`, `FileChangesPanelModel` in `Widgets/FileChanges/`), the Console (`ConsolePanel.xml`, `ConsolePanelModel` and the slots in `Widgets/Console/`, `Widgets/Console/CLAUDE.md`), the Game panel (`GamePanel.xml`, `GamePanelAssetModel` in `Widgets/GamePanel/`, `Widgets/GamePanel/CLAUDE.md`) and the Profiler (`ProfilerPanel.xml`, `ProfilerPanelModel` and the slots in `Widgets/Profiler/`, `Widgets/Profiler/CLAUDE.md`), the Preferences window (`PreferencesPanel.xml`, `PreferencesPanelModel` in `Widgets/EditorLayout/`) and the editor's dialogs, which are assets of the window kind `Dialogs`: Save Layout (`EditorDialogsPanel.xml`, `EditorDialogsModel` in `Widgets/EditorLayout/`) and the Scene Editor's Add Node and Add Component (`SceneDialogsPanel.xml`, `SceneDialogsModel` in `Widgets/SceneEditor/`), and the Viewport's two toolbar rows (`ViewportToolbarPanel.xml`, a `Bar` over `ViewportToolbarModel` in `Widgets/Viewport/`), and the Sprite Library (`SpriteLibraryPanel.xml`, `SpriteLibraryPanelModel` and the slots in `Widgets/TextureEditor/`, `Widgets/TextureEditor/CLAUDE.md`).

## The interpreter

`PanelInterpreter::Prepare(asset)` once per asset change parses every binding text of the tree into a `PreparedElement` tree (parsing allocates, so no frame does it); `Draw(sources, result, slots)` walks it inside the window the caller has begun and allocates nothing in a steady frame (its reader, text scratches and visitors are members whose capacity stays). `CanDraw(element)` says whether a kind is really drawn, which the test of the shipped panels uses; keep it in step with `KindOf` when a kind is added.

- **A click is noted, then emitted.** `Draw` only puts the command and the argument of the clicked button or cell into `PanelDrawResult`; the host emits `EditorCommandEvent` after the walk, because a command may change the list that is being walked. One click per frame is kept (the last). A button has no row, so its `argument` is the literal text of the asset (empty by default) and its `width` is in em; a table's `Button` / `Selectable` cell reads `argument` from its row.
- **Ids are the asset's.** `PushID` of the element `id` around every element, and inside a table the row index and the column `id` around every cell, so the control API's lookup by name finds a control by the ids of the file (a button's own label is the last link). The window is `<title>###<asset id>`. Ids in a file are unique per asset, which the loader checks.
- **A read that fails is a `?`**, never an error: a gone source, a wrong path and a field of another kind are what a hot-reloaded asset shows while it is edited. A condition (`visible`, `enableWhen`, a popup's `open`) is a `PanelCondition` parsed once at `Prepare`; a term that cannot be read, or a text that does not parse, counts as true (`visible`, `enableWhen`), so a broken binding is seen and not hidden; an empty one is true too. Evaluating allocates nothing. `PanelField` draws the one top-level field of the bound object as the inspector does (`SingleFieldVisitor` over `ImGuiPropertyVisitor`; the visitor is reset before each field because it numbers its widgets from a counter); `PanelFields` is a `PanelField` whose object node starts open. `PanelField::label` is not drawn. **Tooltips:** wherever a control or a table cell draws its `tooltip`, the text of `tooltipBind` (a cell: the row's `tooltipField`) replaces it when it reads; it is read only while the item is hovered.
- **Child and popup.** A `PanelSection` is a `CollapsingHeader` labelled `<icon> <title>###<id>`, or with `look="Tree"` a `TreeNodeEx` of the same label whose open children are indented until its `TreePop` (and chain their ids from it); with `openBind`, for both looks, the header's open state is written to that bool whenever the field reads otherwise (a read that fails writes nothing), so a model knows whether the section is open, and the field never opens or closes the header. `PanelChild` is `BeginChild` with the asset's id (`width` / `height` in em, 0 fills the rest, optional border); a child and a popup are their own ImGui windows, so the control ids chain from them. `PanelPopup` is a modal that opens on the rising edge of its condition (true), is drawn auto-resizing while it reads true and is closed with `CloseCurrentPopup` when it reads false, so a button that clears the bool closes it one frame later (a click is emitted after the walk). The opening edge is a `mutable` flag of the prepared popup, so a popup the user closed with Esc while the bool still reads true does not open again by itself. ImGui never closes a modal on Esc, so the interpreter does it: with a `closeCommand`, Esc in the focused popup closes it and notes that command (the model clears its bool, which it must, as the popup opens again only on a rising edge); a popup with none ignores Esc. An `open` that cannot be read, does not parse or is empty leaves a popup closed, against the rule above: a broken binding must not open a modal that blocks the editor. One modal at a time. `PanelDropdown` is a button (`<icon> <text>##<id>`, or the square icon button with no text) that opens a non-modal `BeginPopup` placed under it, id `##dropdown` under the element's id; ImGui closes it on a click outside or Esc, so no model bool exists and a click inside (a button, a switch) keeps it open, except a button with `closePopup`, which calls `CloseCurrentPopup` after its click (the click is still emitted). Its `enableWhen` disables the button and, while the popup is open, what it holds; its `openCommand` is noted on the first frame the popup is open (`MenuOpenTracker`, as a menu's).
- **Controls.** `PanelCheckbox`, `PanelCombo`, `PanelNumber` and `PanelRadio` (`PanelInterpreterControls.cpp`) write the bound field through `PanelBindingWriter` the moment ImGui reports a change and emit **no command**: the model sees the new value in its next `Update`, so a model that keeps a copy of the field must read it there. A read that fails is a `?`, a write that fails is ignored. A checkbox's label is `<icon> <text>###<id>`, so a `labelBind` text that changes keeps the ImGui id (the control API finds it by the `###<id>` link); `Toggle` is a button filled with the accent while on, its label in the `style` colour (disabled while off). A combo's label is `##<id>`; with no `items` it lists the names of the enum, with `items` the value is an index when it is a number and the text of a row otherwise; an index out of range shows `?`. A row whose `separatorField` reads true is an `ImGui::Separator()` and never selectable (unreadable: an ordinary row); an index that names one shows `?`. A row whose `enableField` reads false is drawn disabled and never picked (unreadable: enabled), a row's `tooltipField` is its tooltip, `previewBind` is the closed text when it reads, and `text` is drawn after the combo as a number's. A number is a drag or, with `slider` and `min` < `max`, a slider, over a 64-bit integer or a float by the field's own kind; bounds are always clamped; the control is in the mono font with its label `##<id>` and `text` drawn after it. `decimals` and `unit` make its printf format at `Prepare` (`%.<d>f <unit>`, `%lld <unit>` over an integer; a `%` of the unit is doubled); with neither it is ImGui's default. With `input` it is an `InputScalar` (no step buttons) written only when the user presses Enter or leaves it after an edit (`IsItemDeactivatedAfterEdit`), clamped then when `min` < `max`, and its `commitCommand` noted at that moment; With `stepper` it is an `InputScalar` with - and + buttons (`step` a click, `stepFast` a Ctrl-click, which steps as a click when 0), written and clamped at every change like a drag; `step` 0 steps by one, and an integer field never steps by less than one, so a button always moves the value. A radio is `<icon> <text>###<id>`, selected while `bind == value` reads true (a condition term prepared once, so an enum compares by its name and a number by its value); a click writes `value`, a word as its index among the enum's names (looked up at the first click, then kept), and a name the enum lacks selects nothing and writes nothing. A false `enableWhen` draws the four kinds disabled (one `BeginDisabled` around the control and its text, the tooltip still shown), so they write nothing.
- **Tabs.** `PanelTabs` is `BeginTabBar` labelled `##<id>`, a `PanelTab` a `BeginTabItem` labelled `<icon> <title>###<id>` whose children are drawn only while it is the selected one, so the tab keeps its id when the title changes and the control API finds a control inside by the chain of ids.
- **Buttons.** A button with `navigable="false"` is pushed with `ImGuiItemFlags_NoNav`: a dialog that reads Space or Enter itself must not have the keyboard-nav cursor press its focused Cancel. A `fill` paints the button with the palette's accent or muted accent (`PanelDraw::ScopedButtonFill`; hover and active are the accent's) while `fillWhen` reads true; `repeat` is `ImGuiItemFlags_ButtonRepeat`, so a held button notes a click every repeat frame (the last one is emitted); an `icon` with no `text` is the square icon button, labelled `<icon>##<id>`; a `width` of `kPanelFillLineWidth` is ImGui's `-FLT_MIN`, the rest of the line.
- **Progress and text.** `PanelProgress` is `ProgressBar` of its fraction clamped to 0..1 (NaN: 0), `width` em or the line, the overlay the `textBind` text or ImGui's percentage; a fraction that cannot be read is an empty bar with `?`. A `PanelText` with an `icon` is one text `<icon> <text>`, so a wrapped or scrolled line keeps the glyph.
- **Row `align="Center"`.** The row centres its children as one group on the free width by the width they took the frame before (a `mutable` float of the prepared row), so the first frame draws at the start and a changed width follows one frame later.
- **Menus** (`PanelMenu`, `PanelMenuItem`, `PanelMenuItems`) are `BeginMenu` / `MenuItem` and draw only where a menu bar or a popup is current (`MenuBarAppending`); anywhere else they draw `?`, because the interpreter cannot see the caller's `BeginMenuBar` any other way. A menu is `<title>###<id>`, its children are drawn only while it is open, and its `openCommand` is noted on the first frame of an opening: a closed menu is not drawn, so a gap in the frame numbers (`MenuOpenTracker`) is the edge. An item is `<icon> <text>###<id>` with the chord of its command right-aligned; `PanelMenuItems` pushes the row number as an id. The chord text comes from the seam `PanelChordText` (`PanelDrawSupport.h`), which the host installs in `PanelChordTextRegistry` (the editor's `EditorChordText` caches per `HotkeyMap::Revision()`): the format knows no hotkey map, and an open menu allocates nothing in a steady frame.
- **Selected row.** A `Selectable` cell whose column names `selectedField` is drawn selected while the row's bool reads true; the label is `<text>##select`.
- **Input.** `PanelInput` and a table's `Input` cell draw `InputTextWithHint` on a member char buffer (the bound text is copied in, cut at a UTF-8 boundary when longer than the buffer, and written back through `PanelBindingWriter` on a change; a field that is not a `String` reads fine and ignores the edit). The label is `##<element or column id>`, `icon` is a prefix of the hint, `width` is in em (0 fills the line, but takes ImGui's default width with a `text`, which is drawn after the field, or with `fill` false; a multiline field too). An `Input` cell is disabled while its `enableField` reads false, a `PanelInput` while its `enableWhen` does. With `lines` it is a multiline field (`InputTextEx` with the hint) that many text lines high plus the frame padding, on the same buffer; Enter is a new line there. A bound `String` longer than `kInputBufferSize` is cut. `focus` calls `SetKeyboardFocusHere` on the frame the surrounding popup appears. Enter in a field with a `submitCommand` notes it; `commitCommand` (also of `PanelNumber`) is noted when the user lets go after an edit (`IsItemDeactivatedAfterEdit`), while the field is still written at every change, so the model's command is its "save now"; a field with both notes both on Enter and the submit wins (a click keeps one command per frame, the last).
- **Tables.** `scrollRows` N shows N rows in a scroll region (`ImGuiTableFlags_ScrollY`, rows through `ImGuiListClipper`, so a clipped row is not drawn and not found by the control API); a list that fits is a plain table. A `Button` column with a `field` is labelled with the cell's text (`<icon> <text>##<column id>`, found by its visible part). A `Checkbox` cell is `<labelField text>##<column id>` over the row's bool, written with `WriteRowBool`, disabled while `enableField` reads false; a bool that cannot be read is `?`. `maxLines` on a text is a child region of that many lines with a horizontal scrollbar, drawn without copying the text. `PanelFields` with a source alone draws the whole object.
- **Slots.** A `PanelSlot` calls the drawer registered under its name in `PanelSlots` (the global one unless the caller passes its own); an unknown name draws `?`. Each model registers its own slots (named in its folder's `CLAUDE.md`); a slot takes no arguments and draws inside the element's own id scope.

## The widget and the models

`AssetPanelWidget` (`<widget type="AssetPanelWidget" asset="FileChangesPanel"/>`) reads the asset through `PanelAssetHolder` with the real predicates (`FindEditorCommand`, `IsKnownPanelModel`), so a file that names an unknown command or model is an issue. It subscribes to `ConfigChangedEvent` and `ConfigReloadFailedEvent` of its asset: a file with issues shows a banner (error colour, three issues as `where: message`, then `and N more`, and `Could not reload: <reason>` for an unreadable file) and the **last good asset keeps being drawn below it**; a first load that failed shows the banner alone and opens the window at once.

**Title.** The window is `<title>###<asset id>`. With `titleBind` the widget reads the text through a reader of its own over its sources in `Update`, after the models' `Update` and before `Begin`, and makes the title again only when the text differs from the last one it used (a steady frame allocates nothing); an unreadable text keeps `title`, and a reload binds again. The id after `###` never changes, so the saved layout and the control API's lookup hold. ImGui keeps the window's `Name` of its first title, so a test reads `GetWindowTitle()`.

- **Window kinds.** `Docked` is a normal window; `Floating` sets `NoDocking`; `Dialogs` is a host with no visible window (one pixel, no title bar, inputs or background, drawn always, no close button, its `open` forced true), because ImGui opens a modal from a window and none of these tools has an asset window; the host's `command` is optional and never toggles it. Its popups are the only thing the user sees. A reload banner is not visible on it (the last good asset keeps working). A game that ships its own `config/WidgetsConfig.xml` lists the dialog assets itself. `Bar` is no window: see "Bars".
- **Models.** A `<source>` with a `model` is one `IPanelModel` (`CreatePanelModel` by class name, a `FACTORY_BASE`) registered in the widget's own `PanelDataSources` (the global one is its parent). A reload keeps the instance whose source name and model class did not change, so its state (such as "scanned") survives an edit of the file. **The reload is deferred**: the config event only notes it, and `Update` (or the end of the command being run) applies it, because applying the panel's own file inside a model's command (`ApplyAll` -> `ConfigChangedEvent`) could drop the model that is running. `IPanelModel::Initialize()` is an empty virtual called once after the model is registered: the place for its subscriptions, document source and slots. A model keeps `GetObject()` current; a `TypedRef` it gives is never kept past the frame. **Two hooks** serve a model with a global side effect (a switch that must be on only while the panel is): `OnOpenChanged(open)` on every change of the open flag whoever made it (the command, the close button, the asset's `open`), also `false` when the widget or the model's source goes away open and `true` for a model made while open; `EndUpdate()` after the window of each frame in which `Update` ran (the close button's `OnOpenChanged(false)` comes first), to give back what `Update` took for the draw.
- **Commands.** The asset's `command` toggles the panel; any other `EditorCommandEvent` reaches the models' `RunCommand` **only while the panel is open** (the first that returns true takes it). A command a button names must be a row of the command table (`EditorCommands.cpp`), so the palette lists it; a command with an argument does nothing without one.
- **Tests.** `AssetPanelWidget::SetConfigManager` and `SetAsset` are the seams of `PanelAssetHotReloadTest`, which runs the widget over a config folder of its own; `PanelInterpreterTest` draws in an ImGui context with no backend and finds a control by its hash chain, `GamePanelAssetTest` draws a shipped asset and finds it by label; `ConfigEditorAssetTest` draws the Config Editor asset through a real widget; `PanelAssetShippedTest` loads every file of `config/panels/` under the real predicates; the stress smoke validates the folder against the XSD.

**Bars.** An asset with `window="Bar"` (the editor's main toolbar and menu bar, the Viewport's toolbar) has no window of its own: its `Update` runs the models and keeps it registered in `PanelBarsRegistry` under the config name (`PanelBars.h`; a `Singleton`, a handle unregisters it), and the C++ window that holds the bar calls the static `PanelBarsRegistry::Draw("<config name>")` where it belongs (inside its own `BeginMenuBar`, or a child), which is the widget's `DrawBar`: it draws the elements with the interpreter and emits the click after the walk. The open flag is forced true and the asset's `command` ignored. The widget is listed **before** the window that draws it in `WidgetsConfig.xml`, so its models update first; the models' `EndUpdate` comes at the end of `DrawBar` or, when nobody drew the bar, in the next `Update`. A name nobody registered draws nothing: a game whose own `WidgetsConfig.xml` lacks the line has an empty menu bar and toolbar, or a Viewport with no toolbar. A bad reload shows as one error line above the bar. `AssetPanelWidget` sets the interpreter's chord provider from `PanelChordTextRegistry` before every draw, because the host that installs it is made after the assets.

**Editor host.** A model that needs the layout widget's per-user state (`EditorSettings`, `LayoutStore`, the layout load and save, the preferences call) asks `EditorLayoutHostRegistry` for the `IEditorLayoutHost` (`Widgets/EditorLayout/IEditorLayoutHost.h`), which `EditorLayoutWidget` registers for its lifetime; the model never holds it between calls, and a test registers a fake (`EditorLayoutHostProbe.h`). `view.preferences` is the Preferences asset's own `command`, so it toggles the window; `view.saveLayout` is handled by `EditorDialogsModel`.

A new panel is a file `config/panels/<Name>Panel.xml`, a model class when it needs data or commands, its commands in the table, and one `<widget>` line in `config/WidgetsConfig.xml`.
