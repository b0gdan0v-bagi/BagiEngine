# Pool Strings panel

The editor's view of the `PoolString` pool: the asset `config/panels/PoolStringsPanel.xml` (window `Pool Strings###PoolStrings`, hidden at start, `AssetPanelWidget` hosts it; format and interpreter: `src/Widgets/PanelAssets/CLAUDE.md`) over `PoolStringsPanelModel` and its slots. What the numbers mean (blocks, sources, dead entries, the checks): `src/Modules/BECore/PoolString/CLAUDE.md`. Editor only: the folder is in the `BE_WITH_EDITOR` regex of `src/CMakeLists.txt` (`.claude/rules/widgets-module.md`).

- **One snapshot.** `PoolStringsPanelModel` (no ImGui; the asset's source `pool`) holds one `PoolStringSnapshot` of the pool of its monitor (`CoreManager::GetPoolStringMonitor()`; `SetMonitor` is the test's seam). It is taken in the first `Update` after the panel opens and by `poolStrings.refresh`, **never by a frame itself**: `TakeSnapshot` walks the whole table. Summary, checks, blocks and contents all come from it, so they agree; the texts, block rows and check results are made when it is taken, and a later frame formats none of them. Only growth and the records are live.
- **The model never interns:** showing the pool must not grow it. Texts of the view are `String` copies.
- **Checks** list the hash collisions, then the texts held twice, up to `PoolStringsPanelLimits::kMaxCheckRows`; the rest are counted in a line. A pooled string may hold anything, so a text of a row goes through `PoolStringLine` (one line, a bounded number of bytes, no cut inside a character).
- **Contents.** The model keeps the result of `PoolStringAnalysis::Search` over the snapshot as row indices and searches again only when the snapshot, the search text, the source choice or the sort changed (a search walks every string). The controls write `search` and `sourceIndex` with no command and the model reads them in its next `Update`; the sort comes from the table's header through `SetSort`, which searches at once so that the click's frame draws the new order. `sourceItems` is All, Static, Runtime, Adopted, then the whole source names of the adopted blocks: a chosen file is found again by its name after a Refresh (the index moves when another file appears), else, and for an index outside the list, All.
- **Growth** is read from the monitor in every `Update` of the open panel: all the frames it keeps (`kFrameHistory`), the line formatted only when its sums change. Every frame that copied a runtime string is highlighted, since the panel cannot tell which frame was meant to be steady.
- **Recording** is the monitor's state, which `pool_strings` switches too: the view's `recording` follows `IsRecording()`, and only a change made by the switch is passed on. Closing the panel, destroying the model and a switch to Game mode (where no editor panel lives) **leave it on**, so the running game can be recorded; the monitor caps the records.
- **Zones.** The model holds a copy of the records (`GroupByZone`, which copies and sorts all of them), made again only when `GetRecordCounts` moved: at most once per `PoolStringsPanelLimits::kRegroupFrames` while strings keep coming, at once after a clear (from anywhere) and with a new snapshot. The counts line does not wait. **Zones are known only with `ENGINE_PROFILER_ALLOC`** (preset `macos-profile-editor`); a build without it says so and lists every record under `(no zone)`.
- **Steady frame.** With nothing new, the open panel allocates nothing and adds no pool string.
- **Slots** (`PoolStringsSlots`, a member of the model, registered in its `Initialize`) draw what the format cannot say, only the visible rows: `poolStringBlocks`, the blocks with their fill bars (a block names its file; the tooltip holds the whole source name); `poolStringContents`, the sortable list of the strings; `poolStringGrowth`, the bars of strings and of bytes per frame; and `poolStringZones`, a tree node per zone (its id is the zone, so it stays open when the order changes) over its strings. None allocates for a row. Every row of a list has one height (the clipper takes it from the first), so a cell shows one line and the tooltip a longer, still bounded, part.
- **Commands:** `view.poolStrings` (the asset's `command`, no chord), `poolStrings.refresh` and `poolStrings.clearRecords` (both run only while the panel is open).
- **Tests:** `PoolStringsPanelModelTest` (the model over an `IsolatedPool`), `PoolStringsPanelAssetTest` (the shipped file drawn in an ImGui context with no backend, a header clicked by its place since ImGui reports no item for it, and the View menu item). Not covered: the look; check it by hand.
