# Art Generation Panel

## Overview

The editor's **Generate** panel (`ArtGenWidget`, command `view.generate`, View → Generate Art): a style preset of the game and a subject become image variants, and a chosen one becomes a sprite of the game. The images come from the art generation service (`tools/artgen/`, its `CLAUDE.md`), a separate Python **client of the control API**; the editor knows neither ComfyUI nor any model. Editor only (`ArtGen` is an editor folder in `src/CMakeLists.txt`).

| File | Purpose |
|------|---------|
| `ArtGenSession.{h,cpp}` | The editor's side of the contract, no ImGui: the service's last status (with the presets and workflows), one run (request, progress, variants, end), the save of a preset, the control methods. `Singleton`: it outlives the panel |
| `ArtGenSessionSets.cpp`, `ArtGenSessionControl.h` | The same session's code for sets (the queue, the set methods; `Sets/CLAUDE.md`), and the error codes and helpers its two translation units share |
| `Reference/` | The reference picture of a run: `ArtGenReference`, its JSON and shape check, the builders, the panel's section (`Reference/CLAUDE.md`) |
| `Sets/` | Sets: a preset over a list of subjects, run as a queue of jobs; the model, the manifest on disk, the Set tab (`ArtGenSetPanel`) (`Sets/CLAUDE.md`) |
| `ArtGenPresetForm.{h,cpp}` | The preset form, no ImGui: the fields of one preset, its params as overrides of the workflow's defaults, dirty against what it was loaded with, New / Duplicate / Revert; `FormatArtGenPresetFile` (the file's key order), `CheckArtGenPresetShape` (what C++ checks before a save) |
| `ArtGenImage.{h,cpp}` | An image's processing at Accept, pure: `ArtGenImageSettings` (trim, padding, max size), `DrawnBounds`, the frame (`MakeArtGenFrame`), `ProcessArtGenImage`, the PNG read and write |
| `ArtGenAccept.{h,cpp}` | Accept, no ImGui: an image processed and written into the game's assets, the TextureLibrary entry, the reload of the sprites that use it, Use on a node (`AcceptForControl`); a sound processed and written as a WAV clip, the reload of the sources that play it (`AcceptSoundForControl`) |
| `ArtGenSound.{h,cpp}` | A sound's processing at Accept, pure: `ArtGenSoundSettings`, `ProcessArtGenSound`, their JSON, `MeasureArtGenSound`, `BuildArtGenWaveform` |
| `ArtGenLaunch.{h,cpp}` | Start the service: finds `tools/artgen/artgen_bridge.py` of the engine checkout among the content roots and starts it with `SDL_CreateProcess` (`$BAGI_PYTHON`, else `python` / `python3`) |
| `ArtGenWidget.{h,cpp}` | The ImGui panel over the session: service line, setup, the preset form; under it the tabs Generate (the run, the grid of variants, Accept) and Set |

## The contract

The service **pulls**: a request made before the service connects is not lost, and the polls are how the editor knows the service is alive (`kServiceTimeoutSeconds` silent: gone). Push events are not used (`Publish` is lost when nobody listens). Every method answers at once; a run is never a deferred call.

| Method | Caller | Params | Answer |
|--------|--------|--------|--------|
| `artgen_poll` | service, about every 0.5 s | `state` (`ready` / `not_running` / `not_installed`), `reason`, `generator`, `startedHere` (a running generator a setup action started, so Stop can end it), `presets: [{name, title, source (game / engine), kind (image / audio), preset? (the content), error?}]`, `workflows: [{name, source, kind, inputs, error?}]` | `gameRoot` (the real path of the game, where `artgen/presets/` is), `refresh: true` once after a save (look at the files now), `request: {id, preset (a name, or the preset object of a draft), presetName? (with a draft), subject, count, seed\|null, outDir?, name? (a job of a set: the folder under `<gameRoot>/artgen/out` to write into and the file stem), reference?}` once, `cancel: id` while a cancel is asked, `setup: {id, action}` once, `setupCancel: id` while a cancel of it is asked, `shutdown: true` once after Disconnect (the service exits; the editor counts it gone at once and ends its run or setup action) |
| `artgen_setup_report` | service, per event of a setup action | `id, event`: `plan` (`platform, note, root, downloadBytes, steps: [{what, dest, state, size, licence}]`), `step`, `progress` (`done, total`), `log`, `done` (`ok`, `error`) | `{stale}` |
| `artgen_progress` | service | `id, image, count, step, steps, seed` | `{stale}` |
| `artgen_image` | service, per image or sound | `id, image, count, seed, path, provenance` (real paths of the PNG or FLAC and its `.artgen.json`), `kind` (`image` when absent, `audio`) | `{stale}` |
| `artgen_done` | service, once per run | `id, status` (`ok` / `failed` / `cancelled`), `error` | `{stale}` |
| `artgen_generate` | an agent, a test | `preset` (a name, or a preset object: a draft), `presetName?`, `subject, count?` (1..16, default 4), `seed?`, `reference?` (`{mode, image, weight?}`, `Reference/CLAUDE.md`) | `{id, serviceConnected}`; `artgen_busy` while a run is in work, `invalid_params` (also a draft whose shape is not a preset) |
| `artgen_save_preset` | an agent, a test | `name, preset` | `{path}` of `<gameRoot>/artgen/presets/<name>.json`; `invalid_params` (a bad name or shape, no game root, a failed write) |
| `artgen_cancel` | an agent, a test | none (the run in work; of a set, its running job only), or `job` (+ `set`, needed when two sets have a job of that name in work), or `set` + `all: true` | `{}`; with `job` or `set` `{set, job?, state}`; `artgen_no_run`, `artgen_no_set`, `invalid_params` |
| `artgen_enqueue` | an agent, a test | `preset` (a name or a draft object), `presetName?`, `subjects` (a string of lines, or a list of strings and `{name?, subject}`), `count?`, `seed?`, `set?`, `frameOf?` (an image set that has a frame: the new set is cut by it) | `{set, jobs: [names], seed, serviceConnected}`; `invalid_params` (also a set whose folder exists, a bad `frameOf`) |
| `artgen_set` | an agent, a test | `set` | the manifest of the set plus `state` (`Active`, `Complete`); `artgen_no_set` |
| `artgen_pick` | an agent, a test | `set, job, seed` | `{set, job, pick}`; on a live row (accepted, not kept) it writes the variant into the game and adds `switched` (the acceptor's answer); `artgen_no_set`, `artgen_no_variant` (also any pick but its own on a kept row), `artgen_accept_failed` (a switch that wrote nothing, or a row another set replaced: names that set) |
| `artgen_retry` | an agent, a test | `set, job?` | `{set, retried}`; `artgen_no_set` |
| `artgen_more` | an agent, a test | `set` (not active), `count?` (1..16, default 1), `seed?`, `jobs?` (names) | `{set, seed, count, jobs: [queued], skipped: [{job, reason}]}`: the done rows that are not kept get `count` more variants on one fresh seed, appended (pick and game untouched); `reason` is `kept`, `failed`, `cancelled` or `full` (never `running`: that set is `artgen_busy`); `artgen_no_set` (also an unknown job), `artgen_busy`, `invalid_params` (also a seed that meets a variant, or nothing to run) |
| `artgen_accept` | an agent, a test | `seed` (a variant of the current run), `useOnSelected?`; an image: `sprite`, `image?` (`{trim, padding, maxSize}`, a missing key keeps the preset's); a sound: `name` or `clip`, `sound?` (`{mono, trimDb\|null, maxSeconds, sampleRate, fadeInMs, fadeOutMs, peakDb\|null}`, a missing key keeps the default) | an image: `{sprite, texturePath, png, width, height (the written file's), processing, reloadedSprites, atlas (null, or {name, texturePath, width, height, members} when a packed sprite's atlas was repacked), usedOn}`; a sound: `{clip, wav, sampleRate, channels, seconds, peakDb, reloadedSources, usedOn}`; `artgen_no_variant`, `invalid_params` (bad sound settings), `artgen_accept_failed` (a bad name or clip path, no TextureLibrary.xml, no selected node or component, a sound that trims to nothing) |
| `artgen_setup` | an agent, a test | `action`: `Plan`, `Install`, `Start`, `Stop`, or `cancel` | `{id, serviceConnected}`; `artgen_busy` while a setup or a run is in work, `artgen_no_setup` (cancel with none), `invalid_params` |
| `artgen_accept_set` | an agent, a test | `set` (every job done; a sound also picked) | `{set, accepted: [{job, as, seed, alternatives, ...the acceptor's answer}]}` (a kept row: `{job, kept: true}`, a row another set accepted later: `{job, replacedBy}`); writes each row's pick, else an image's first variant, the rest stay switchable; `artgen_no_set`, `artgen_busy` (the set is active), `artgen_set_incomplete` (names the jobs not picked, failed or cancelled), `artgen_accept_failed` (a row's file gone or a row failed: names it and the rows done) |
| `artgen_keep` | an agent, a test | `set, job?` | `{set, kept: [jobs], replaced?: [{job, by}]}`: fixes the live rows, drops their alternatives; `artgen_no_set`, `artgen_busy` (jobs to run), `invalid_params` (nothing live, or the row is replaced by a newer set), `artgen_accept_failed` |
| `artgen_state` | an agent, a test | none | `{service: {connected, polls, state, reason, generator, presets, workflows}, run: {id, state, preset, draft, subject, count, seed, reference, image, step, steps, error, cancelRequested, variants: [{seed, path, provenance, kind}]}, setup: {id, action, state, plan, current, done, total, log, error, ...}, sets: [{name, preset, kind, count, seed, state, jobs: {pending, running, done, failed, cancelled}, picked, accepted, live, kept}], gameRoot}` |

- **One run at a time.** A request is `Queued` until a poll hands it over (`Running`), then `Done`, `Failed` or `Cancelled` by `artgen_done`. A report whose `id` is not the running one is answered `{"stale": true}` and changes nothing.
- **Cancel.** A queued run is cancelled at once; a running one until the service answers `artgen_done` `cancelled` after it saw `cancel` in a poll. The images already made stay.
- **Setup actions** (`ArtGenSetup`) travel the same way and never beside a run: `RequestSetup` refuses while either is in work, and `Request` while a setup action is. The service downloads without asking, so the panel offers Install only under the plan it shows.
- The panel and `artgen_generate` go through the same `ArtGenSession::Request` (by name) or `RequestDraft` (inline). A preset the service reported broken is refused by name; a draft is checked here only for its shape, the rest by the service, which fails the run with the reason.
- **Save** (`SavePreset`, `artgen_save_preset`): the C++ side checks only the name (`IsValidSpriteName`) and the shape; the file is written atomically with the keys in the order of the docs, shown at once as the game's, and the next poll asks the service for `refresh`, whose verdict comes back as the preset's `error`. `keepVariants` starts the new run with the variants of the last one (`keptVariants`).

## Lifetime and threads

The control API cannot drop a handler and the panel is re-created at every switch of the run mode, so the session registers the methods (`RegisterControl`, once per `ControlService`, from the panel's `Initialize`) and they capture it, never the widget. Until the panel has been created once the service gets `unknown_method`. Main thread only.

## The panel

- **Tabs.** Above them, shared: the service line, setup and the preset form (the preset is what Generate and Set both use). Each tab owns its controls: **Generate** the subject, count, seed, keep-the-variants, Generate / Cancel and the run view; **Set** (`ArtGenSetPanel`) its own count and seed, Queue, the sets and the rows of the selected one with More variants, Keep and Accept all (`Sets/CLAUDE.md`, "The panel"). Generate is off while a set runs.
- **The preset form** (`ArtGenPresetForm`): the combo lists the game's presets, then the engine's starters, a broken one with its error; picking one drops unsaved edits (marked `*`). New, Duplicate (`<name>_copy`, unsaved), Save (a starter becomes the game's copy), Save as, Revert. Fields: Name, Title, Workflow, Prompt, Negative, the workflow's own inputs from the service's description (a combo where the generator offers values, else a field by the default's type; a value the preset sets has a reset button), and, for an image workflow, "Accept (image)". Generate sends a saved, unchanged preset by name and anything else as a draft.
- **Start the service** (the service line says why nothing can happen: not connected, or the generator not ready with its reason) first turns the control API on when it is off (`ApplicationEvents::StartControlServerRequestEvent`; the panel says so when it did not start), then, once it listens, runs the bridge of the engine checkout with `--port <control port> --exit-with-editor --log <editor user folder>/artgen-bridge.log` (`ArtGenLaunch`) in the background with no standard streams (an editor started from the desktop has none to hand over), through `pythonw` on Windows (no console window).
- **Set up** (`not_installed`) shows the service's plan (platform, root, each step with its size, licence and destination in the tooltip, the total); **Download and install** runs it with a progress bar and Cancel; Not now forgets it. **Start** (`not_running`) starts the local generator; **Stop ComfyUI** is there only for a generator started from the panel (`startedHere`). **Disconnect** (service connected) stops the service itself (`RequestServiceStop`).
- Thumbnails are loaded from the paths the service reported with `ResourceManager::Load` and **evicted** (`ResourceManager::Evict`) when the run is replaced or the panel dies, so generated textures do not stay cached.
- **Sounds.** A run of sound variants (`kind` audio) is a list instead of the grid: Play / Stop of each (its FLAC loaded as an `AudioClip`, played on the `Ui` bus, evicted with the run like a thumbnail), its waveform, seed, length and peak; a click on the waveform picks it. Under the pick: the processing settings, **Listen as accepted** (the processed sound made in memory), the target (a name, or **Replace a clip of the game** with its path) and Accept.
- A thumbnail is drawn over a checkerboard, so a cut-out (RGBA) variant shows its transparency. The Accept section shows what Accept will write (the file is decoded once per selection, never per frame) and edits the form's accept fields, as the Settings subsection "Accept (image)" does.
- A click selects a variant; the dice button under it puts its seed into the form (random off) for the next Generate. Thumbnails are kept by path, so a run that kept the variants loads only the new ones.

## Accept

`ArtGenSession::Accept(seed, sprite, useOnSelected, settings)` (the panel's button, with the form's accept settings, and `artgen_accept`) calls the acceptor the panel installed, `AcceptForControl`; the session test installs a fake, so the session needs no file system.

- **Files.** `ArtGenGameFile` is the one path builder the panel's text uses. The processed PNG (next section) and its `.artgen.json` (the generation's record plus `accepted`) go to `<game assets>/artgen/<sprite>.png` and `.artgen.json` (the top `assets` layer, `FileSystem::GetMountedPath`), replacing an earlier accept of the name. After Keep (`KeepForControl`, the session's Keeper) that file also holds `"kept": {seed, date}`; a later write of the name replaces the file whole, so only a kept row has it. A sprite name is 1 to 64 of `A-Z a-z 0-9 _ -` (`IsValidSpriteName`).
- **Library.** The entry `{sprite, assets/artgen/<sprite>.png, the written size}` is added or replaced and `TextureLibrary::Save` writes the game's `TextureLibrary.xml` (`StoreSpriteEntry`); an entry the library already holds is not written again, and when the save fails the entry in memory goes back to what it was. `Save` writes the whole file from the DOM: its comments and layout are not kept. A sprite in an **atlas group keeps its link** (`AcceptedSpriteEntry`: group and `pack` settings; an unpacked one only points to the new PNG). A **packed** sprite keeps its place in the atlas and its `atlas.source` becomes the new PNG (also from a cell of a sheet: the other cells keep their source), then `AcceptIntoLibrary` repacks the group with the settings it was packed with (`PackSettingsOf`) and saves again only when a member entry moved,so no Pack click is needed. A failed repack leaves the new `source` in the saved library and the old atlas file; the error says Pack in the Sprite Library finishes it. A failed second save restores the members (the atlas file is already new). A set repacks per row.
- **Reload.** The sprite's PNG path and, after a repack, the atlas path are evicted from the resource cache; then every `SpriteRendererComponent` of the active scene that names the sprite or the PNG path is reloaded, and so is every one that names another member of the repacked atlas (a UI image of a canvas is not).
- **Use on selected.** The session keeps the scene editor's primary selection (`SceneSelectionChangedEvent`; found alive in the active scene before use). The sprite goes into its `SpriteRendererComponent::_spriteId` (a node without one is refused), and `SceneEditedEvent` marks the scene unsaved.

## Accept of an image

`ArtGenImageSettings {trim, padding, maxSize}`: the form's (panel), else the call's `image` over the run's preset (a draft: own `accept` or the defaults; by name: the saved preset's). The processing is pure (`ArtGenImage`): the **drawn box** is the pixels with alpha above `kArtGenAlphaCutoff` (no alpha channel: all drawn); the **frame** is the union of the drawn boxes given, grown by `padding` percent of its longer side and clamped, scaled by `min(1, maxSize / longer side)`; the crop is averaged down over premultiplied alpha (no halo, never scaled up). A single Accept: a frame of its own. An image with nothing drawn is refused.

- **Identity** (`trim` off, `maxSize` 0): the PNG and the provenance are copied byte for byte, no `accepted` (the old Accept).
- **A set keeps one frame** (the rule and the legacy case: `Sets/CLAUDE.md`, "Accept all"): the same size and scale for every file, so a pawn stays smaller than a king. The fit of a variant in the frame is checked per row in the acceptor (`does not fit the frame of the set`). The measure over all variants is the session's `FrameMeasurer` (`MeasureFrameForControl`); with none installed an Accept all that is not identity is refused.

## Accept of a sound

`ArtGenSession::AcceptSound(seed, target, settings, useOnSelected)` (the panel and `artgen_accept` of a sound) calls `AcceptSoundForControl`.

- **Processing** (`ProcessArtGenSound`, in this order): mono (the channels averaged), trim of the silence at both ends below `trimDb`, the cut at `maxSeconds`, linear resampling to `sampleRate`, a linear fade in and out (the last frame silent), the peak brought to `peakDb`.
- **Files.** A 16-bit WAV (`EncodeWav`) at `assets/artgen/<name>.wav` or over the game's clip at `clip` (`IsValidClipPath`: `assets/.../x.wav` inside the assets; a game plays its sounds by fixed paths), written to a temporary file and renamed over the old one, in the top `assets` layer. Beside it `<file>.artgen.json`: the provenance plus `accepted` (clip, source FLAC, settings, what was written).
- **Reload.** The clip's path is evicted from the resource cache (a play by path reads the new file) and every `AudioSourceComponent` of the active scene that names it calls `ReloadClip`. Use on selected sets the clip of the node's `AudioSourceComponent` (a node without one is refused before anything is written).

## Tests

`tests/BECore/ArtGen*Test.cpp` (editor regex of `tests/CMakeLists.txt`). `ArtGenSessionTest` has a `ControlService` of its own, calls the methods as the service does, with a clock of the test and a fake acceptor, and saves into a temporary game root; the file tests write into a temporary assets folder. `ArtGenLaunchTest` really starts a stand-in script (skipped without that Python). The service side is `tools/artgen/tests/test_artgen_bridge.py` against a fake editor that answers like the session.
