# Art Generation Panel

## Overview

The editor's **Generate** panel (`ArtGenWidget`, command `view.generate`, View → Generate Art): a style preset of the game and a subject become image variants, and a chosen one becomes a sprite of the game. The editor knows neither ComfyUI nor any model: the images come from the art generation service (`tools/artgen/`, its `CLAUDE.md`), a separate Python process that is a **client of the control API**. Editor only (`ArtGen` is in the editor folders of `src/CMakeLists.txt`).

| File | Purpose |
|------|---------|
| `ArtGenSession.{h,cpp}` | The editor's side of the contract, no ImGui: the service's last status (with the presets and workflows), one run (request, progress, variants, end), the save of a preset, the control methods. `Singleton`: it outlives the panel |
| `ArtGenPresetForm.{h,cpp}` | The preset form, no ImGui: the fields of one preset, its params as overrides of the workflow's defaults, dirty against what it was loaded with, New / Duplicate / Revert; `FormatArtGenPresetFile` (the file's key order), `CheckArtGenPresetShape` (what C++ checks before a save) |
| `ArtGenAccept.{h,cpp}` | Accept, no ImGui: the variant copied into the game's assets, the TextureLibrary entry, the reload of the sprites that use it, Use on a node; `AcceptForControl` is the session's acceptor in the editor |
| `ArtGenLaunch.{h,cpp}` | Start the service: finds `tools/artgen/artgen_bridge.py` of the engine checkout among the content roots and starts it with `SDL_CreateProcess` (`$BAGI_PYTHON`, else `python` / `python3`) |
| `ArtGenWidget.{h,cpp}` | The ImGui panel over the session: service line (Start the service), setup (Set up, the plan, Install, Start, Stop), the preset form, subject, count, seed, keep the variants, Generate / Cancel, progress, the grid of variants (Use this seed), Accept |

## The contract

The service **pulls**: a request the panel makes before the service connects is not lost, and the polls are how the editor knows the service is alive (`kServiceTimeoutSeconds` without one: gone). Push events are not used (`ControlService::Publish` goes to every client and is lost when nobody listens). Every method answers at once; a run is never a deferred call (a deferred call holds back every later request).

| Method | Caller | Params | Answer |
|--------|--------|--------|--------|
| `artgen_poll` | service, about every 0.5 s | `state` (`ready` / `not_running` / `not_installed`), `reason`, `generator`, `startedHere` (a running generator a setup action started, so Stop can end it), `presets: [{name, title, source (game / engine), preset? (the content), error?}]`, `workflows: [{name, source, inputs: {name: {default, choices?}}, error?}]` (read again only when they change) | `gameRoot` (the real path of the game, where `artgen/presets/` is), `refresh: true` once after a save (look at the files now), `request: {id, preset (a name, or the preset object of a draft), presetName? (with a draft), subject, count, seed\|null}` once, `cancel: id` while a cancel is asked, `setup: {id, action}` once, `setupCancel: id` while a cancel of it is asked, `shutdown: true` once after Disconnect (the service exits; the editor counts it gone at once and ends its run or setup action) |
| `artgen_setup_report` | service, per event of a setup action | `id, event`: `plan` (`platform, note, root, downloadBytes, steps: [{what, dest, state, size, licence}]`), `step` (`what`), `progress` (`done, total` bytes), `log` (`text`), `done` (`ok`, `error`) | `{stale}` |
| `artgen_progress` | service | `id, image, count, step, steps, seed` | `{stale}` |
| `artgen_image` | service, per image | `id, image, count, seed, path, provenance` (real paths of the PNG and its `.artgen.json`) | `{stale}` |
| `artgen_done` | service, once per run | `id, status` (`ok` / `failed` / `cancelled`), `error` | `{stale}` |
| `artgen_generate` | an agent, a test | `preset` (a name, or a preset object: a draft), `presetName?`, `subject, count?` (1..16, default 4), `seed?` | `{id, serviceConnected}`; `artgen_busy` while a run is in work, `invalid_params` (also a draft whose shape is not a preset) |
| `artgen_save_preset` | an agent, a test | `name, preset` | `{path}` of `<gameRoot>/artgen/presets/<name>.json`; `invalid_params` (a bad name or shape, no game root, a failed write) |
| `artgen_cancel` | an agent, a test | none | `{}`; `artgen_no_run` |
| `artgen_accept` | an agent, a test | `seed` (a variant of the current run), `sprite`, `useOnSelected?` | `{sprite, texturePath, png, width, height, reloadedSprites, usedOn}`; `artgen_no_variant`, `artgen_accept_failed` (a bad name, no TextureLibrary.xml, no selected node, a node without a SpriteRendererComponent) |
| `artgen_setup` | an agent, a test | `action`: `Plan`, `Install`, `Start`, `Stop`, or `cancel` | `{id, serviceConnected}`; `artgen_busy` while a setup action or a run is in work, `artgen_no_setup` (cancel with none), `invalid_params` |
| `artgen_state` | an agent, a test | none | `{service: {connected, polls, state, reason, generator, presets: [{name, title, source, error?}], workflows: [{name, source, error?}]}, run: {id, state, preset, draft, subject, count, seed, image, step, steps, error, cancelRequested, variants: [{seed, path, provenance}]}, setup: {id, action, state, platform, root, downloadBytes, plan, current, done, total, log, error, cancelRequested}, gameRoot}` |

- **One run at a time.** A request is `Queued` until a poll hands it over (`Running`), then `Done`, `Failed` or `Cancelled` by `artgen_done`. A report whose `id` is not the running one is answered `{"stale": true}` and changes nothing (a late message after a new request).
- **Cancel.** A queued run is cancelled at once (the service never saw it); a running one keeps running until the service answers `artgen_done` with `cancelled` after it saw `cancel` in a poll. The images already made stay.
- **Setup actions** (`ArtGenSetup`) travel the same way and never beside a run: `RequestSetup` refuses while either is in work, and `Request` while a setup action is. An `Install` keeps the plan of the `Plan` before it on screen; the service plans again and downloads without asking, so the panel offers Install only under the plan it shows. A cancel of a queued action ends it at once, of a running install on the next poll (`Failed`, `cancelled`). `ClearSetup` forgets a plan turned down.
- The panel and `artgen_generate` go through the same `ArtGenSession::Request` (by name) or `RequestDraft` (inline). A preset the service reported broken is refused by name; a draft is checked here only for its shape, the rest (the workflow has the input) by the service, which fails the run with the reason.
- **Save** (`SavePreset`, `artgen_save_preset`): the C++ side checks only the name (`IsValidSpriteName`: a safe file name) and the shape; the file is written atomically with the keys in the order of the docs, shown at once as the game's (`source` game), and the next poll asks the service for `refresh`, whose verdict comes back as the preset's `error`. `keepVariants` starts the new run with the variants of the last one (`keptVariants` of them), so more can be made without losing the ones on screen.

## Lifetime and threads

The control API cannot drop a handler and the panel is re-created at every switch of the run mode, so the methods are registered by the session (`RegisterControl`, once per `ControlService`, from the panel's `Initialize`) and capture the session, never the widget. Until the panel has been created once (an editor that started in Game mode) the methods do not exist and the service gets `unknown_method`; it waits. Main thread only, like every handler.

## The panel

- **The preset form** (`ArtGenPresetForm`): the combo lists the game's presets, then the engine's starters (`engine`), a broken one with its error (it loads, to be fixed); picking one loads it and drops unsaved edits (the combo marks them `*`). New (on the first workflow), Duplicate (`<name>_copy`, unsaved), Save (to the Name field; a starter becomes the game's copy), Save as (a name popup), Revert. Fields: Name, Title, Workflow (the game's and the engine's), Prompt, Negative, then the workflow's own inputs from the service's description: Size when it has `width` and `height`, a combo where the generator offers values, else a field by the default's type (integer, number, text, checkbox); a value set by the preset has a reset button back to the workflow's. The service's error of the saved file shows under the form. Generate sends a saved, unchanged preset by name and anything else as a draft.
- The service line says why nothing can happen: the service not connected, or the generator not ready with its reason. A request can still be queued while the service is away.
- **Start the service** (not connected) first turns the control API on when it is off (`ApplicationEvents::StartControlServerRequestEvent`: `Application` starts the server on the default port, or a free one; the panel says so when it did not start), then, once it listens, runs the bridge of the engine checkout with `--port <control port> --exit-with-editor --log <editor user folder>/artgen-bridge.log` (`ArtGenLaunch`): in the background, with no standard streams (an editor started from the desktop has none to hand over, and SDL fails duplicating them), through `pythonw` on Windows so no console window opens; it ends with this editor; the line says "starting" until its first poll, then, after `kBridgeStartSeconds` without one, gives the command to run by hand and see why. A build without the engine checkout (no script among the roots) says so.
- **Set up** (`not_installed`) asks the service for the plan and shows it: the platform, the root, every step with its size (its licence and destination in the tooltip), the total; **Download and install** runs it with the current step, a progress bar and Cancel; Not now forgets it. Next to it the alternative, a generator on another machine (`comfyui-remote-via-todo`, not there yet). **Start** (`not_running`) and the stop button beside "Service ready" start and stop the local generator; **Stop ComfyUI** is there only for a generator started from the panel (`startedHere`), a ComfyUI started by hand gets a line saying to close its window, and the line under it says what an action did. **Disconnect**, beside the service line while the service is connected, stops the service itself (`RequestServiceStop`); Start the service runs it again.
- Thumbnails are loaded from the paths the service reported with `ResourceManager::Load` (an absolute path resolves as itself) and **evicted** (`ResourceManager::Evict`) when the run is replaced or the panel dies, so the generated textures do not stay in the cache until the editor closes.
- A thumbnail is drawn over a checkerboard, so a cut-out (RGBA) variant shows its transparency; Accept copies the PNG as it is, alpha included.
- A click selects a variant (the frame and its seed); the dice button under it puts its seed into the form (random off) for the next Generate. Thumbnails are kept by path, so a run that kept the variants loads only the new ones.

## Accept

`ArtGenSession::Accept(seed, sprite, useOnSelected)` (the panel's button and `artgen_accept`) calls the acceptor the panel installed, `AcceptForControl`; the session test installs a fake, so the session needs no file system.

- **Files.** The PNG and its `.artgen.json` are copied to `<game assets>/artgen/<sprite>.png` and `.artgen.json` (the top `assets` layer, `FileSystem::GetMountedPath`), replacing an earlier accept of the name. A sprite name is 1 to 64 of `A-Z a-z 0-9 _ -` (`IsValidSpriteName`), so it is also a safe file name.
- **Library.** The entry `{sprite, assets/artgen/<sprite>.png, the whole image}` is added or replaced and `TextureLibrary::Save` writes the game's `TextureLibrary.xml`; when that fails (no such file) the entry in memory goes back to what it was. `Save` writes the whole file from the DOM, so its comments and layout are not kept.
- **Reload.** The path is evicted from the resource cache, then every `SpriteRendererComponent` of the active scene that names the sprite or the path is reloaded, so the new picture shows at once (a UI image of a canvas is not reloaded).
- **Use on selected.** The panel keeps the scene editor's primary selection in the session (`SceneSelectionChangedEvent`; held and found alive in the active scene before use). The sprite goes into its `SpriteRendererComponent::_spriteId` (a node without one is refused), and `SceneEditedEvent` tells the scene editor the scene is unsaved.

## Tests

`tests/BECore/ArtGenSessionTest.cpp` (editor regex of `tests/CMakeLists.txt`): a `ControlService` of its own, the methods called as the service calls them, a clock of the test, a fake acceptor; the save into a temporary game root. `ArtGenPresetFormTest.cpp`: load, dirty, revert, new, duplicate, a workflow change, the file's text, the shape check. `ArtGenAcceptTest.cpp`: sprite names, the PNG size, the copy into a temporary assets folder. `ArtGenLaunchTest.cpp`: the bridge found among content roots, its arguments, a real start of a stand-in script in the background (skipped without that Python). The service side is `tools/artgen/tests/test_artgen_bridge.py` against a fake editor that answers like the session.
