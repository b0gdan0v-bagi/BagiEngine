# Game panel

The editor's panel over the active game. Editor only: the folder is in the `BE_WITH_EDITOR` regex of `src/CMakeLists.txt` (`.claude/rules/widgets-module.md`).

- **Knows no game.** It reaches the game only through `GameManager::GetActive()`, `IGame::AsControllable()` (`src/Modules/Games/CLAUDE.md`) and the reflection registry, so every game gets it with no code of its own. A game shows more here by marking fields `BE_REFLECT_FIELD` and methods `BE_FUNCTION`, the same surface as `get_property` / `call_method` of the control API.
- **Model and glue.** `GamePanelModel` (no ImGui, tested alone in `GamePanelModelTest` with the fakes of `GameControlTest.h`) holds the state text, the actions with their labels, the filter and the methods, and makes the calls. `GamePanelWidget` draws them and owns the text buffers.
- **What it shows.** The name and the state version; the last result (green, or red with `code: message`); Actions, each element of `ActionsText()` (`Games/GameText.h`) a button that passes it to `PerformActionText` as is (the list is still a `Json` here, read from that text until the editor's readers move to the tape), labelled in the Console's syntax (`set_count count=50`, `FormatGameActionLabel`); Fields, the game's own `AcceptPropertyVisitor` through `ImGuiPropertyVisitor`, so `readonly`, `range` and `tooltip` work as in the inspector; Methods, a button per `BE_FUNCTION` (nearest type wins a name) with an argument field typed like the Console's parameters (`ParseConsoleParams`: `name=value ...` or a JSON object), run through `CallMethod`; State, the indented JSON, collapsed at start. Reset is `ResetText` with `{}`, or `IGame::Reset()` for a game that is not controllable.
- **Not the control API's guard.** A method call here is the developer's own text, so a `PoolString` parameter is allowed; the control API refuses it to a client (`BECore/Reflection/CLAUDE.md`, "Reflection methods").
- **Zero allocations in a steady frame:** `Sync()` compares the game pointer and `GetStateVersion()` and rebuilds the texts and lists only when one moved (a change by a control client or by the game itself shows the same way); a click is applied after the list is drawn, never inside the walk. A field edited in Fields that does not move the state version leaves the State text as it was until the next change.
- **Command:** `view.game` (`Ctrl+Shift+G`, rebindable), also in the View menu; hidden at start.
