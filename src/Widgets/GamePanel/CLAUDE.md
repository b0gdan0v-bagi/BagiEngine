# Game panel

The editor's panel over the active game: an asset (`config/panels/GamePanel.xml`, the format and the interpreter are `src/Widgets/PanelAssets/CLAUDE.md`) over two models and the pure `GamePanelModel`. Editor only: the folder is in the `BE_WITH_EDITOR` regex of `src/CMakeLists.txt` (`.claude/rules/widgets-module.md`). There is no widget of its own: `WidgetsConfig.xml` lists `<widget type="AssetPanelWidget" asset="GamePanel"/>`.

- **Knows no game.** It reaches the game only through `GameManager::GetActive()`, `IGame::AsControllable()` (`src/Modules/Games/CLAUDE.md`) and the reflection registry, so every game gets it with no code of its own. A game shows more here by marking fields `BE_REFLECT_FIELD` and methods `BE_FUNCTION`, the same surface as `get_property` / `call_method` of the control API.
- **`GamePanelModel`** (no ImGui, tested alone in `GamePanelModelTest` with the fakes of `GameControlTest.h`) holds the state text, the actions with their labels, the filter and the methods, and makes the calls: each element of `ActionsText()` (`Games/GameText.h`) is kept as text and passed to `PerformActionText` as it is, labelled in the Console's syntax (`FormatGameActionLabel`); a method is a `BE_FUNCTION` (nearest type wins a name) called with `name=value ...` or a JSON object (`ParseConsoleParams`) through `CallMethod`, the result shown as the text of the `result` member the `JsonStreamSerializer` wrote (keys in the order the method wrote them, not sorted as `call_method` of the control API does); Reset is `ResetText` with `{}`, or `IGame::Reset()` for a game that is not controllable. `GetVersion()` grows with every rebuild, filter change and result.
- **`GamePanelAssetModel`** (the source `panel`) is the reflected `GamePanelView` over it: bools for every condition (the format has no AND), the texts, the `actions` rows (`label`, `index` into the model's full list) and the `methods` rows (`signature`, `callable`, `hasParams`, `arguments`, `index`). `Update()` follows the active game, hands the view's `filter` (written by the panel's input) to `SetFilter`, and rebuilds the view only when the model's version moved. `ActiveGameSourceModel` (the source `game`) gives `TypedRef::Of(*GameManager::GetActive())` at every read for `PanelFields bind="game"` (empty with no game), so a switched game is followed and the fields are drawn by `ImGuiPropertyVisitor` as the inspector draws them (`readonly`, `range`, `tooltip` work). `SetGame` on both models is the seam of the tests (no `GameManager`).
- **Commands** (rows of `EditorCommands.cpp`, run by the model only while the panel is open): `gamePanel.reset`, `gamePanel.perform` and `gamePanel.call` take the `index` of a row as text, so the model reads its own current list and a stale or foreign index does nothing; `gamePanel.copyState` is the one ImGui call (`SetClipboardText`). A command first syncs with the active game again: the game may have changed since `Update`.
- **Typed arguments survive a rebuild.** The `arguments` of a method row are what the user typed; the rows are made again only when the game or its method count changes, not on a state change.
- **Not the control API's guard.** A method call here is the developer's own text, so a `PoolString` parameter is allowed; the control API refuses it to a client (`BECore/Reflection/CLAUDE.md`, "Reflection methods").
- **Zero allocations in a steady frame:** `Sync` compares the game pointer and `GetStateVersion()` and the model's version is compared with the view's, so nothing is rebuilt while nothing moved (a change by a control client or by the game itself shows the same way); a click is applied after the walk, never inside it. A field edited in Fields that does not move the state version leaves the State text as it was until the next change.
- **The look is the asset's.** The ids of the controls (`gameActionFilter`, `gameReset`, `gameStateCopy`) are what `tools/stress/tests/stress_smoke.py` and `tools/qa` find; the game icon is part of the view's `gameName` because a text of the format has no icon. `view.game` (`Ctrl+Shift+G`, rebindable, also in the View menu) is the asset's `command`; hidden at start. Tests: `GamePanelAssetModelTest`, and `GamePanelAssetTest`, which draws the shipped file over both models and finds the controls by the labels of `ImGuiItemIndex`.
