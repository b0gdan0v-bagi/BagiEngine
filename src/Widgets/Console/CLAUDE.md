# Console panel

The editor's log viewer and command line. Editor only: the folder is in the `BE_WITH_EDITOR` regex of `src/CMakeLists.txt` (`.claude/rules/widgets-module.md`), so a build without the editor has neither the panel nor its tests.

- **Where the lines live.** In the `LogHistorySink` of `LoggerManager` (`BECore/Logger/CLAUDE.md`, "The history"), not in the widget: widgets are destroyed and created at a mode switch, the history is not, so the panel shows the same lines after it. `ConsoleWidget::Initialize` finds the sink with `GetSink<LogHistorySink>()`. A game that ships its own `LoggerConfig.xml` has to add the sink entry; without it the panel says so and draws nothing else.
- **Model and glue.** `ConsoleLogView` (no ImGui, tested alone) turns a `LogHistory`, a `ConsoleLogFilter` and the pause flag into `GetRows()`, indices for `LogHistory::At`, and rebuilds them only when the history's `GetVersion()`, the filter's `revision` or the pause changed. Whoever changes a filter field bumps `revision`. `ConsoleWidget` draws the toolbar, the rows, the output area and the command line, and owns the filter and the pause.
- **Pause** freezes the list at the sequence the history had when it began; the history goes on behind it, and resuming lists what came. A line the history drops while paused leaves the rows too (a row is an index).
- **Category** is the module folder of the line's `file` (`LogCategoryOfFile`), since a log call has none of its own; the combo offers the categories the history has seen.
- **Zero allocations in a steady frame:** rows and the title are made again only on a change (`FormatConsoleTitle` when the number of errors or warnings moved; `###Console` keeps the window id), labels are built in stack buffers, the message is drawn straight from the record.
- **Colours** come from `GetImGuiPalette()`; Fatal is drawn as an error. The right-click menu of a line has "Copy line" and "Open file".
- **Command:** `view.console` (`Ctrl+Shift+L`), also in the View menu; the panel is hidden at start. It is not read from the raw SDL event like the Profiler's chord, so it can be rebound.
- **Open at the line.** A double click on a row whose site is openable, or "Open file" in its menu, runs `LaunchEditor` (`EditorLauncher`, no ImGui). The command is the preference `externalEditor`, set in Preferences ("Open files with"): a template such as `code -g {file}:{line}`, split on blanks, `{file}` and `{line}` replaced **inside** an argument after the split, so a path with spaces, quotes or `;` stays one argument; double quotes keep an argument together. The program is started by `SDL_CreateProcess` with an argument array, never through `cmd` or `sh -c`, so a launcher that is a `.cmd` (VS Code on Windows) needs `cmd /c code -g {file}:{line}`. An empty template, or one that does not parse, gives the system opener of the file's `file://` URL, without the line. `IsSiteOpenable` (absolute path that exists, cached per `__FILE__` pointer) decides whether a row is clickable; a failure to start is one `LOG_WARNING`.
- **Command line.** `ConsoleCommandLine` (`ParseConsoleCommand`, `CompleteConsoleCommand`, no ImGui) and `ConsoleSession` (`ConsoleOutput`, `ConsoleCommandHistory`, `Submit`) are tested alone. Syntax: `method`, `method {"a":1}` or `method key=value ...` (a value is JSON when it parses, else the text; quotes and balanced brackets keep a value together). Tab completes the method and then the parameter names from `ControlService::GetMethods()` descriptions (`DescribeMethod`; a method without one still runs, only its parameters are not offered; the JSON form completes only the method). Up and Down walk the history. `Submit` posts to `CoreManager::GetControlService()`; the answer, also a deferred one (`step`), is printed in the output area when it arrives. That area is not the log: it is bounded (200 lines, a long line is cut) and lives in the widget. The reply holds only the `RefCountedAtomic` `ConsoleOutput`, so a session gone before it arrives costs nothing.
- **History** is the preference `consoleHistory` (the last 64 commands that parsed): the widget takes it from the first `EditorPreferencesChangedEvent` only and reports each command with `ConsoleCommandSubmittedEvent`; `EditorLayoutWidget` stores and saves it.
- **Tests:** `ConsoleLogViewTest` (filters, rebuilds, pause, a dropped oldest, the title), `EditorLauncherTest` (the argument list, the URL, `IsSiteOpenable`; no test starts a process), `ConsoleCommandLineTest` (parsing, completion, the session against a `ControlService` of its own, the history). The ImGui drawing is not covered; look at it by hand in an editor build.
