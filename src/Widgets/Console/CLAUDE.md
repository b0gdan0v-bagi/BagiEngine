# Console panel

The editor's log viewer and command line, the asset `config/panels/ConsolePanel.xml` (window `Console###Console`, hidden at start, `AssetPanelWidget` hosts it; format and interpreter: `src/Widgets/PanelAssets/CLAUDE.md`) over `ConsolePanelModel` and three slots. Editor only: the folder is in the `BE_WITH_EDITOR` regex of `src/CMakeLists.txt` (`.claude/rules/widgets-module.md`), so a build without the editor has neither the panel nor its tests.

- **Where the lines live.** In the `LogHistorySink` of `LoggerManager` (`BECore/Logger/CLAUDE.md`, "The history"), not in the panel: widgets are destroyed and created at a mode switch, the history is not, so the panel shows the same lines after it. The model finds the sink with `GetSink<LogHistorySink>()` in `Update`. A game that ships its own `LoggerConfig.xml` has to add the sink entry; without it the panel says so (`hasHistory` false hides the toolbar and the rows; the output area and the command line stay).
- **Model and glue.** `ConsoleLogView` (no ImGui, tested alone) turns a `LogHistory`, a `ConsoleLogFilter` and the pause flag into `GetRows()`, indices for `LogHistory::At`, and rebuilds them only when the history's `GetVersion()`, the filter's `revision` or the pause changed. Whoever changes a filter field bumps `revision`. The filter and the pause are the model's.
- **`ConsolePanelModel`** (no ImGui, `IPanelModel`; the asset's source `console`) holds what the toolbar shows and does, plus the session, the external editor and the history preference. Its reflected `ConsolePanelView` is written by the panel's controls with no command (the four level toggles, `category` as an index into `categories` whose first entry is `All`, `filterText`) and read by the model in its next `Update`, which turns them into the `ConsoleLogFilter` (text cut at `kMaxConsoleFilterLength` on a UTF-8 boundary; `revision` bumped only on a real change) and updates the `ConsoleLogView`. The labels with the counts, the category list, `lost` and the title (`FormatConsoleTitle` gives the text, the id after `###` is the window's) are made again only when what they show moved. The model subscribes and registers the slots in `Initialize`, which `AssetPanelWidget` calls when it makes the model (in its own `Initialize`, so before `EditorLayoutWidget`'s first `Update` sends the preferences). The asset's controls are `PanelCheckbox look="Toggle"` (labels from the model's `*Label` fields), a `PanelCombo` over `categories`, a `PanelInput`, Pause / Resume (two buttons shown by `paused` and `!paused`, both `console.pause`), Clear (`console.clear`) and the lost counter (`visible="console.lost > 0"`); the window title is `titleBind="console.title"`. `SetHistory` is the seam of the tests. A level toggle has one static tooltip, not "Hide / Show these lines" by its state.
- **Slots.** `ConsoleSlots` (ImGui; a member of the model) draws what the format cannot say: `consoleRows` (the clipper, the right-click menu, the double click, scroll to the bottom while not paused), `consoleOutput` and `consoleCommandLine` (Tab and history callbacks). The rows slot takes the height the output area and the command line need (`GetFooterHeight`) off its own, so the three share the candidates of the last Tab and the method list here, not in the model. The command line's "Clear output" button empties the session directly, as `console.clearOutput` does.
- **Pause** freezes the list at the sequence the history had when it began; the history goes on behind it, and resuming lists what came. A line the history drops while paused leaves the rows too (a row is an index).
- **Category** is the module folder of the line's `file` (`LogCategoryOfFile`), since a log call has none of its own; the combo offers the categories the history has seen.
- **Zero allocations in a steady frame:** rows and the title are made again only on a change (`FormatConsoleTitle` when the number of errors or warnings moved; the id after `###` is the asset's, added by `AssetPanelWidget`), labels are built in stack buffers, the message is drawn straight from the record.
- **Colours** come from `GetImGuiPalette()`; Fatal is drawn as an error. The right-click menu of a line has "Copy line" and "Open file".
- **Commands:** `view.console` (`Ctrl+Shift+L`; the asset's `command`, which toggles the window), also in the View menu; the panel is hidden at start; it is not read from the raw SDL event like the Profiler's chord, so it can be rebound. `console.pause`, `console.clear` and `console.clearOutput` are rows of the table (no chord, the palette lists them) that the model runs only while the panel is open.
- **Open at the line.** A double click on a row whose site is openable, or "Open file" in its menu, runs `LaunchEditor` (`EditorLauncher`, no ImGui). The command is the preference `externalEditor`, set in Preferences ("Open files with"): a template such as `code -g {file}:{line}`, split on blanks, `{file}` and `{line}` replaced **inside** an argument after the split, so a path with spaces, quotes or `;` stays one argument; double quotes keep an argument together. The program is started by `SDL_CreateProcess` with an argument array, never through `cmd` or `sh -c`, so a launcher that is a `.cmd` (VS Code on Windows) needs `cmd /c code -g {file}:{line}`. An empty template, or one that does not parse, gives the system opener of the file's `file://` URL, without the line. `IsSiteOpenable` (absolute path that exists, cached per `__FILE__` pointer) decides whether a row is clickable; a failure to start is one `LOG_WARNING`.
- **Command line.** `ConsoleCommandLine` (`ParseConsoleCommand`, `CompleteConsoleCommand`, no ImGui) and `ConsoleSession` (`ConsoleOutput`, `ConsoleCommandHistory`, `Submit`) are tested alone. Syntax: `method`, `method {"a":1}` or `method key=value ...` (a value is JSON when it parses, else the text; quotes and balanced brackets keep a value together). The parameters are the compact text of the object (`ConsoleCommand::params`, keys sorted), written with `JsonWriter` and read over a `JsonTape`, so the rules of the tape hold: of a repeated key in the brace form the first counts (the `key=value` form refuses a repeat), and a number beyond a double (`1e999`) is refused in the brace form (`number overflow`) and is a text in the `key=value` form. `Submit` writes the request with the text as it is; the answer is read through a tape and `result` is printed as the raw text the service wrote. Tab completes the method and then the parameter names from `ControlService::GetMethods()` descriptions (`DescribeMethod`; a method without one still runs, only its parameters are not offered; the JSON form completes only the method). Up and Down walk the history. `Submit` posts to `CoreManager::GetControlService()`; the answer, also a deferred one (`step`), is printed in the output area when it arrives. That area is not the log: it is bounded (200 lines, a long line is cut) and lives in the model's session. The reply holds only the `RefCountedAtomic` `ConsoleOutput`, so a session gone before it arrives costs nothing.
- **History** is the preference `consoleHistory` (the last 64 commands that parsed): the model takes it from the first `EditorPreferencesChangedEvent` only and reports each command with `ConsoleCommandSubmittedEvent`; `EditorLayoutWidget` stores and saves it.
- **Tests:** `ConsoleLogViewTest` (filters, rebuilds, pause, a dropped oldest, the title), `ConsolePanelModelTest` (the model over a history of its own), `ConsolePanelAssetTest` (the shipped file drawn over the model and the slots in an ImGui context with no backend: toggles, combo, filter, Pause, Clear and the lost counter found by their labels), `EditorLauncherTest` (the argument list, the URL, `IsSiteOpenable`; no test starts a process), `ConsoleCommandLineTest` (parsing, completion, the session against a `ControlService` of its own, the history). What the tests do not cover: the look (colours, the toolbar being wider than the default 720 px window), the right-click menu and the double click on a row, and Tab completion in the real input; look at them by hand in an editor build.
