# Vulkan Module Guidelines

## Overview

`VulkanModule` is the second renderer backend: `VulkanRendererBackend` implements `IRenderer` (see `.claude/rules/rendering-module.md` for the rules shared with SDL). It is selected by `renderer="VulkanRendererBackend"` in `config/ApplicationConfig.xml`; the window itself still comes from `SDLMainWindow` (`SDL_WINDOW_VULKAN` in `config/SDLWindowConfig.xml`). Links `BECoreModule`, `EventsModule`, `SDLModule` and `Vulkan::Headers`; every game executable links it with `WHOLE_ARCHIVE` (`be_add_game_executable`).

## Components (`src/CoreVulkan/`)

| Class | Role |
|-------|------|
| `VulkanRendererBackend` | `IRenderer`: frame lifecycle, command buffers, per-frame sync (`kMaxFramesInFlight = 2`), ImGui backend. `GetOutputWidth/Height()` is the extent of the open pass (swapchain or offscreen target), and the swapchain extent follows the window (rebuilt in `AcquireFrame()`, see "Frame lifecycle"); `DrawFilledRect` / `DrawTexture` apply `IRenderer::GetViewTransform()` to the rect on the CPU, so the shaders always get output pixels (with batching on they append a quad to the `IRenderer` batch, see "Geometry"; the rect and texture pipelines draw only with it off); `ResolveScissor()` turns the clip stack into the scissor of each draw (whole extent when unclipped, draw skipped when the clip is empty); `CreateTexture()` goes through `VulkanTextureUpload`; `WaitIdle()` is `vkDeviceWaitIdle` (a no-op once the device is destroyed) |
| `VulkanDevice` | Instance, GPU pick, logical device. Two-step init: `InitializeInstance()`, then `InitializeDevice(surface)` (the surface needs the instance). Memory-type lookup and single-time command helpers (`BeginSingleTimeCommands` gives a null handle and `EndSingleTimeCommands` gives `false` after a logged failure, and the upload then fails the texture; no `vkQueueWaitIdle` after a failed submit) |
| `VulkanSwapchain` | Swapchain, image views, framebuffers and the render pass. `AcquireNextImage` / `Present` return a `SwapchainStatus` (`CORE_ENUM`: `Ok`, `Suboptimal`, `OutOfDate`, `Failed`, made by `ClassifyResult`). `Recreate(device, surface, pixelWidth, pixelHeight)` builds a new swapchain from the old one (`oldSwapchain`) and destroys the old objects only after the new ones exist; it returns a `SwapchainRecreateResult` (`CORE_ENUM`, `Done`, `ZeroExtent`, `Failed`): `ZeroExtent` (minimized) touches nothing and `Failed` is logged. The caller does `vkDeviceWaitIdle` first. The **render pass is created once and kept**: the rect, texture and geometry pipelines and ImGui's pipeline were built against it, so a recreated swapchain must have the same image format (`ChooseSurfaceFormat` prefers the current one); a surface that no longer offers it makes `Recreate` fail with a logged error. `VulkanRendererBackend` calls it (below) |
| `VulkanSwapchainPolicy.h` | The decisions around the swapchain as pure, header-only functions: `ClassifyResult`, `ActionAfter(stage, status)` (what a frame does about the result of an acquire or a present), `IsMinimized`, `NeedsRecreate` (compares the window's pixel size with the size last *asked* for, not the extent the surface gave back, so a fixed other extent does not rebuild every frame), `ChooseExtent`, `ChooseSurfaceFormat`, `ChoosePresentMode(modes, uncapped)` (MAILBOX else FIFO; `IRenderer::SetUncapped(true)`, set by `--hidden-window`, takes IMMEDIATE first), `PresentModeName`, `IsSrgbFormat` / `ChooseImGuiColorMode` / `ImGuiViewportFormat` ("ImGui colour"), and the enums `SwapchainStatus`, `SwapchainStage`, `SwapchainAction`, `SwapchainRecreateResult` and `ImGuiColorMode` (`CORE_ENUM`). `VulkanSwapchainPolicyTest` runs without a device |
| `VulkanFramePolicy.h` | What a frame does about the result of its own calls (`vkWaitForFences`, begin and end of the command buffer, `vkResetFences`, `vkQueueSubmit`) as pure, header-only functions: `StepAfter(VkResult)` gives a `FrameStep` (`CORE_ENUM`: `Proceed`, `Skip`, `DeviceLost`), `IsNewFailure` decides what is logged, and `kFenceTimeoutNs` is the finite wait for a slot's fence. Tested by `VulkanFramePolicyTest` the same way as the swapchain policy |
| `VulkanPipelineState` | `CreatePipeline2D(device, renderPass, layout, vertexStage, fragmentStage, vertexInput)`: the one place that makes the shader modules and the state of every 2D pipeline (rect, texture, geometry): triangle list, dynamic viewport and scissor, no culling, one sample, no depth, one blend attachment. A pipeline passes only its stages (`VulkanShaderStage`: SPIR-V and the specialization of the stage), vertex input and layout. Colour blends as straight alpha, alpha as "over" (`ONE`, `ONE_MINUS_SRC_ALPHA`), so a translucent draw into an offscreen target, which `ImGui::Image` samples with blending, leaves no hole; on the opaque swapchain alpha is not seen |
| `VulkanRectPipeline`, `VulkanTexturePipeline` | Graphics pipelines for `DrawFilledRect` and `DrawTexture`. Both take the scissor of the draw as a parameter. The texture pipeline's push constants are 56 bytes: `dstRect`, `srcUV`, `tint` (vec4, multiplied with the texel in `texture.frag.glsl`), `screenSize`; the vertex and fragment shaders declare the same block. The texture pipeline also owns the one linear clamp-to-edge sampler every texture set uses, and the descriptor pools: `kSetsPerPool` sets each, a full pool (`OUT_OF_POOL_MEMORY`, `FRAGMENTED_POOL`) is followed by a new one, and `AllocateDescriptorSet` returns the pool with the set |
| `VulkanGeometryPipeline`, `VulkanGeometryBuffer` | `DrawGeometry()`: a pipeline that reads a vertex and an index buffer (20-byte vertex: position in output pixels, `R8G8B8A8_UNORM` color, UV; `uint32` indices; push constant `screenSize`), and the memory it reads from. The pipeline uses the texture pipeline's descriptor set layout, so any `VulkanTexture` binds to it, and its fragment shader multiplies the texel by the vertex color. `VulkanGeometryBuffer` keeps a list of host-visible, coherent, persistently mapped buffers (1 MiB each, bigger for a bigger draw) **per frame in flight**: `Allocate()` hands out a piece, the backend rewinds the slot in `AcquireFrame()` right after it has waited on that slot's fence, and a full buffer is followed by a new one instead of being resized, so a recorded draw never points at memory that moved |
| `VulkanTextureUpload` | Pixels in memory to a `VulkanTexture` (staging buffer, device-local image, view, descriptor set, one single-time command buffer). Shared by `VulkanTextureLoader` (pixels decoded from a file) and `CreateTexture()`; main thread only |
| `VulkanTexture` | `ITexture`: image + memory + view + descriptor set (set 0), freed to the pool it came from. Destroy it only when the GPU is idle; it has no sampler of its own |
| `VulkanTextureLoader` | `IResourceLoader` for `.bmp .png .jpg .jpeg`; `CanLoad` is true **only while the active renderer is the Vulkan backend** (`SDLTextureLoader` does the mirror check). It decodes and converts the file, `VulkanTextureUpload` uploads. Pixels are uploaded as `SDL_PIXELFORMAT_RGBA32` (bytes R,G,B,A) to match `VK_FORMAT_R8G8B8A8_SRGB`; the packed `RGBA8888` would swap the channels on little-endian |
| `VulkanRenderTarget` | `IRenderTarget`: offscreen target, initialised with the `VulkanDevice` (its `FindMemoryType`); `GetImGuiTextureId()` is a `VkDescriptorSet` from `ImGui_ImplVulkan_AddTexture` |

## Frame lifecycle

Driven by events, not by direct calls:

1. `RenderEvents::NewFrameEvent` → `AcquireFrame()`: first it follows the window. It reads `SDL_GetWindowSizeInPixels`, and `NeedsRecreate(...)` compares it with the pixel size the swapchain was last created for; a `SDLEvents::WindowEvent` of type resized or pixel-size-changed, a suboptimal result and an out-of-date result mark the swapchain dirty as well, and the per-frame compare is the safety net for a driver that reports nothing (MoltenVK after a resize). A rebuild leaves the pipelines and ImGui untouched, since the render pass is kept. Then it acquires the image and opens the command buffer. The fence wait and each `AcquireNextImage` call run inside a `FrameStage::Wait` scope (carved out of `Other`; zones `Vulkan::WaitFence`, `Vulkan::AcquireImage`). This happens before any pass opens, so `ViewportWidget` can insert an offscreen pass first.
   - **Minimized** (a pixel size of zero): the frame is skipped, nothing is reset or recorded, and the thread sleeps `kMinimizedSleepMs`, so the loop does not spin.
   - **One place for the results:** `HandleSwapchainStatus(status, stage)` reads the result of every acquire and present through `ActionAfter`. An out-of-date acquire signaled nothing, so the swapchain is rebuilt at once and the acquire is tried once more in the same frame (if that fails too the frame is skipped and the swapchain stays dirty). A suboptimal acquire signaled its semaphore, so the frame goes on and is submitted, and the swapchain is rebuilt at the start of the next one. A present that is out of date or suboptimal only marks it dirty (the frame was submitted). Any other result is logged (an acquire that fails this way also skips the frame).
   - **A skipped frame records nothing:** `_frameAcquired` stays false, `EndFrame()` does nothing, no pass opens, every draw and `OnImGuiRender()` are dropped, `SetRenderTarget()` returns (so a viewport draws nothing either, and `UnsetRenderTarget()` is a no-op), and `Present()` presents and advances the frame slot only after a real submit.
   - **Fixed render pass:** the new swapchain keeps the image format of the old one. If the surface no longer offers it (a move to another display) `Recreate` fails with a logged error and the frame is skipped; the next frame tries again after `kRecreateFailedSleepMs`.
   - **Semaphores:** image-available semaphores and fences are per frame slot; **render-finished semaphores are per swapchain image** (`_currentImageIndex` signals in the submit and waits in the present): a present holds its wait semaphore until that image is acquired again (`VUID-vkQueueSubmit-pSignalSemaphores-00067`). `RemakeRenderFinishedSemaphores()` makes them in `Initialize()` and after every successful `Recreate` (the count may change); on failure the frame is skipped and the swapchain stays dirty.
   - **Checked results, a fence that cannot hang:** the wait on the slot's fence is finite (`kFenceTimeoutNs`; a timeout skips the frame). The fence is **reset in `EndFrame()`, just before the submit** that signals it, never in `AcquireFrame()`, so a frame that fails before the submit leaves it signaled. `vkBeginCommandBuffer`, `vkEndCommandBuffer`, `vkResetFences` and `vkQueueSubmit` are checked (`StepAfter`); a failure is logged once per cause and streak, and `AbandonFrame()` closes the frame without a submit: the slot does not advance, the swapchain is marked dirty (it releases the held image), and after `vkDeviceWaitIdle` the slot's image-available semaphore (still signaled) and fence are made again. `VK_ERROR_DEVICE_LOST` is terminal: logged once, `_deviceLost` is set and every later frame is skipped as when minimized; only `Destroy()` is left.
2. `BeginFrame(color)` (`Application`, right after `NewFrameEvent`) only keeps the colour. The **swapchain pass opens lazily**, at the first draw, batch submit or ImGui render, at the latest in `Present()` (an empty frame clears too): `SetRenderTarget` asserts that no pass is open and the editor's viewport draws offscreen first.
3. `SetRenderTarget` / `UnsetRenderTarget` open and close an offscreen pass, which may come first. In Game run mode there is none: `SceneRenderWidget` draws into the swapchain pass in `DrawScreen()`.
4. `RenderPresentEvent` → end the pass, submit, present. An offscreen pass still open at `Present()` is logged once and closed (`UnsetRenderTarget()`): else the window freezes.

No test can create a Vulkan device, so the backend's frame code is not run by `ctest`; the decisions in it are the pure functions of `VulkanSwapchainPolicy.h` and `VulkanFramePolicy.h` (`VulkanSwapchainPolicyTest`, `VulkanFramePolicyTest`), and the behavior is checked by hand ("Checking by hand").

ImGui goes through `ImGuiInit/NewFrame/Render/ShutdownEvent` like the SDL backend. `ApplicationCleanUpEvent` calls `Destroy()`.

### Colour space

Every colour the engine hands a backend (a rect, a texture tint, a vertex colour of `DrawGeometry()`, the clear colour) is an sRGB value, as on SDL. The swapchain and the offscreen targets are sRGB attachments that encode on write, so `Initialize()` decides once (`_linearColors = IsSrgbFormat(swapchain format)`) and the rect, texture and geometry pipelines get it as the specialization constant `kLinearize` (constant 0); the clear colour is made linear on the CPU (`SrgbToLinear`). Blending happens in linear space, so translucent colours differ a little from SDL's. The swapchain pass takes the colour of `BeginFrame()`; `Clear(color)` is for the next offscreen pass, which takes it and the colour goes back to opaque black (`VulkanFramePolicy::ClearColorSlot`).

### ImGui colour

ImGui's vertex colours are sRGB values, but the swapchain is an sRGB attachment and encodes on write, so unchanged colours come out washed out. `OnImGuiInit` asks `ChooseImGuiColorMode(swapchain format)`: for an sRGB swapchain (`Linearize`) it gives the backend `shaders/imgui.vert.glsl` (`CustomShaderVertCreateInfo`), the stock vertex shader with the colour turned linear (alpha untouched, same interface, so the stock fragment shader stays). `imgui_impl_vulkan` builds **one** shader pair for the main pipeline and the floating-window pipeline, so the floating windows ask for `ImGuiViewportFormat` (`B8G8R8A8_SRGB`) through `PipelineInfoForViewports.PipelineRenderingCreateInfo` (read for the format list even with `UseDynamicRendering` off; the pointer targets `_imguiViewportFormat`, which lives as long as ImGui). Any other swapchain format (`Direct`) leaves the stock shader. Sampled `*_SRGB` textures (`ImGui::Image`) are decoded by the sampler and come out unchanged. Thin edges differ slightly from SDL (blending in linear space).

## Checking by hand

The window cannot be driven by a test. Run `BagiStress` (or a game) with `VK_INSTANCE_LAYERS=VK_LAYER_KHRONOS_validation` (see "Looking at the pixels") and read stderr:

- Maximize, restore, minimize and drag-resize (slowly and fast, both axes): the picture refills the window with no stretch, no frozen frame, no validation errors, no CPU spin while minimized, no crash on exit.
- HiDPI (the window config asks for `SDL_WINDOW_HIGH_PIXEL_DENSITY`; also move the window between a Retina and another display): the swapchain is twice the window size in units and follows the display, the picture is sharp; a click on a board cell, a canvas button and, in a game with a view size, a tile hits the right target, also at the edges of the window.
- Editor mode (Ctrl+Shift+E, Debug build): a docked panel and a floating window show the same `ImGuiTheme` colours (a screenshot pixel of a docked panel matches `panelBg`), a viewport picture is as bright as in the game, and on Retina panels and fonts are not doubled.

## No capture

`VulkanRendererBackend` does not implement `IRenderer::RequestCapture()`: the default answers with an error, and the `screenshot` method of the control API therefore answers `capture_failed` on this backend. A screenshot needs `--headless` (the SDL software renderer); on Vulkan the decision is the documented run of "Looking at the pixels", and a readback is its own entry (`vulkan-capture`, to be filed).

## No blend modes

`IRenderer::SetBlendMode()` (`Alpha`, `Add`, `Multiply`) is not implemented here: `DrawFilledRect()`, `DrawTexture()` and `DrawGeometry()` draw with straight alpha whatever `GetBlendMode()` says, and `WarnIfBlendModeIgnored()` logs one warning per backend, naming the mode, the first time a draw arrives with another one. The rotated and flipped draws (`DrawTransformedRect()` / `DrawTransformedTexture()`) work, since they are quads of the batch like the others. A gap, not a policy: `renderer-backends` / `render-3d` add one pipeline per mode.

## Geometry

`VulkanRendererBackend::DrawGeometry()` (indexed triangles with a color and a UV per vertex, the primitive of the RmlUi host, `src/Modules/RmlUiHost/CLAUDE.md`) writes the vertices into the frame slot's `VulkanGeometryBuffer` with the translation and the view transform applied on the CPU, so the shader gets output pixels like the others, and draws with the scissor of the clip stack. An untextured draw binds a 1 x 1 white texture made on first use (`GetWhiteTextureDescriptorSet()`, freed in `Destroy()` before the texture pipeline's descriptor pool). An index past the vertices is logged and nothing is drawn, as in the SDL backend; a trailing index or two that do not make a triangle are dropped.

**Batching.** `Initialize()` turns the `IRenderer` batcher on (`.claude/rules/rendering-module.md`, "Batching"): `DrawFilledRect()`, `DrawTexture()` and the default transformed draws append quads (output pixels, opacity applied), and `SubmitBatch()` records the batch as **one** geometry draw (`RecordGeometry()`, shared with `DrawGeometry()`) with the batch texture's descriptor set (the white one for rects). The clip is the scissor of that draw, resolved at the flush: the renderer flushes before every clip change. The pass, texture and scissor checks run at append; the transformed draws skip the pass check, so in a skipped frame a quad is counted and its batch dropped at the flush. `DrawGeometry()`, `BeginFrame()`, `EndFrame()`, `Present()`, `SetRenderTarget()`, `UnsetRenderTarget()`, the ImGui render and `WaitIdle()` flush first, so a batch never lands in another pass; `Destroy()` drops it. The order and flush points are proved on `RecordingRenderer` (`RendererBatchTest`).

## Looking at the pixels

`python3 tools/stress/qa/vulkan_look.py --exe <BagiStress> --scene rmlui --count 60 --out <dir outside the repository>` runs the game in a window (not `--headless`; needs a display) with the SDK's layers, which give a picture without code: `VK_LAYER_PATH`, `VK_INSTANCE_LAYERS=VK_LAYER_KHRONOS_validation:VK_LAYER_LUNARG_screenshot`, `VK_SCREENSHOT_FRAMES`, `VK_SCREENSHOT_DIR`. It `reset`s the scene, `step`s 40 frames, `quit`s and prints the validation lines and the `<frame>.ppm` files (`P6`, the size on separate lines); `--dry-run` shows the environment; exit 77: no SDK. Any validation line is exit 1. The `rmlui` scene reaches the descriptor-pool paths only partly (`tools/stress/src/Stress/RmlUi/CLAUDE.md`).

## Build

- **Loader:** Windows links `vulkan-1.lib` from `VULKAN_SDK` when set and present, else from `external/Vulkan-Loader/Windows/Lib`. macOS requires `external/Vulkan-Loader/macOS/lib/libvulkan.1.dylib` and fails configure without it. Linux uses the system loader. `*.dll` files are git-ignored; populate them as described in `external/Vulkan-Loader/README.md`. `VULKAN_SDK` is a per-machine cache value, override it in `CMakeUserPresets.json`.
- **Shaders:** `shaders/<name>.<stage>.glsl` → `glslc` → `.spv` → `cmake/SpvToHeader.cmake` → `<name>_<stage>_spv.h` with a `constexpr uint32_t` array in the build directory (private include path). A new shader is one `compile_shader(<stage> <name> <kVarName>)` line in `CMakeLists.txt` plus its header in the `VulkanShaders` target's `DEPENDS`. `glslc` comes from `VULKAN_SDK`, else `PATH`; do not pre-set `_GLSLC` to `""` (the search is then skipped).
- The target needs `IMGUI_VULKAN_AVAILABLE=1` consistent with `BECoreModule` because it reuses its PCH.

## Rules

- Keep Vulkan types inside this module. `BECore` headers only see `IRenderer` / `ITexture` / `IRenderTarget`; backend handles do not appear in scene or component APIs.
- A new `IRenderer` capability is added to the interface first and implemented in both backends (rendering rule).
- Add a new Vulkan class to `CoreVulkan/` and let `GLOB_RECURSE` pick it up; re-run `cmake --preset ...`.
