# SDL Module Guidelines

## Overview

SDL3 integration: window, input events and the SDL renderer backend. `Vulkan` is the alternative backend; both implement `BECore/Renderer` (`.claude/rules/rendering-module.md`: texture pipeline, serialization, fallback).

On the web (Emscripten) there is no Vulkan: the window config and the renderer come from the overlay `web/config/` (`ApplicationConfig.xml` with `SDLRendererBackend`, `SDLWindowConfig.xml` without `SDL_WINDOW_VULKAN`), the last content root of `src/main.cpp` (`BAGI_WEB_ROOT`), so it wins over the game's files of the same name. A renderer name that no backend registers (`VulkanRendererBackend` in a build without `ENGINE_WITH_VULKAN`) is a logged error of `SDL3ApplicationFabric::Create`. Details, the canvas glue and tests: "Web build" below.

## Key Components

| Component | Purpose |
|-----------|---------|
| `SDL3ApplicationFabric` | `IApplicationFabric`: takes the reflected `ApplicationConfig` (`Create(const ApplicationConfig&, const ApplicationOptions&)`) and creates the window from the config file named by `path` (an empty `path` is a logged error), the renderer named by `renderer` (default `SDLRendererBackend`, also when `renderer` is empty or the run is headless) and the events provider |
| `SDLMainWindow` | `IMainWindow` implementation; window only, the renderer is separate. `SetHeadless(true)` before `Initialize()` makes it a headless window (see "Headless and screenshots"). `GetWidth()` / `GetHeight()` read the live size in window units (`SDL_GetWindowSize`; the numbers of the config only while there is no window or SDL cannot tell, and 0 after `Destroy()`). `GetPixelDensity()`, `GetDisplayScale()` and `GetSafeArea()` read the live window (`SDL_GetWindowPixelDensity`, `SDL_GetWindowDisplayScale`, `SDL_GetWindowSafeArea`) and fall back to the neutral values of `IMainWindow` (1, 1, the whole window) when SDL fails (on the web `GetSafeArea()` is the insets of the page, `SDLWebCanvas`); see "Input and window metrics" |
| `SDLRendererBackend` | `IRenderer` implementation on the SDL renderer; owns the ImGui SDL backends. `GetOutputWidth/Height()` is `SDL_GetCurrentRenderOutputSize`; the draw calls apply `IRenderer::GetViewTransform()` to their rects; rects, textures and geometry blend with the mode of `GetBlendMode()` (`ToSDLBlendMode()`: `BLEND` / `ADD` / `MUL`, set on every draw); `DrawTransformedTexture()` is `SDL_RenderTextureRotated` (an identity transform is a plain `DrawTexture`; `.claude/rules/rendering-module.md`); `DrawTexture` sets the color and alpha modulation of the texture from the tint on every draw; the clip stack is applied through `SDL_SetRenderClipRect` in `OnClipRectChanged()` (grown to whole pixels); `CreateTexture()` makes a static `RGBA32` texture; `DrawGeometry()` is `SDL_RenderGeometryRaw` over scratch arrays that it keeps between calls (the view transform and the translation are applied to the positions on the CPU, the clip is the render clip); `RequestCapture()` reads the pixels back at the present |
| `SDLEventsProvider` / `SDLEvents.h` | SDL event polling and conversion to engine events; see "Input and window metrics" |
| `SDLScreenshot` | `EncodePng()` (scale down, PNG in memory) and `RegisterScreenshotControl()`: the `screenshot` method of the control API |
| `SDLTexture` / `SDLTextureLoader` | `ITexture` implementation and its `IResourceLoader` |
| `SDLWindowConfig` | Window settings (`config/SDLWindowConfig.xml`: size, `windowFlags`, an optional `title` the shipped files omit (the title is composed, see below); the shipped file asks for `SDL_WINDOW_HIGH_PIXEL_DENSITY`: two output pixels per unit on a Retina display, 1 on the headless dummy driver) |
| `SDLWebCanvas` | `FitWindowSize()` and `SafeAreaFromInsets()` (pure, every platform: the window size for a browser window, rounded, never below a minimum; the safe area from the four CSS insets) and, Emscripten only, `InstallWebCanvasResize()` and `GetWebSafeArea()`; see "Web build" |
| `SDLClipboard` | `SDLClipboardBackend` (`SDL_SetClipboardText` / `SDL_GetClipboardText`, installed by `SDL3ApplicationFabric::Create`; a headless run keeps it in SDL's memory) and the pure `IsPasteShortcut`. The service and its rules: `BECore/Clipboard/CLAUDE.md` |
| `SDLUtils` | Shared SDL helpers |

`IMainWindow`, `MainWindowManager` and `MainWindowAccessor` (access to the window and renderer) live in `BECore/MainWindow/`, not here.

**Window title.** `Application` calls `IMainWindow::SetTitle()` after `GameManager::Initialize()` and when the active game's name or the run mode changes, with `ComposeWindowTitle` (`BECore/MainWindow/WindowTitle.h`, pure): editor `<Game> — BagiEngine Editor`; game mode the `title` of a game's own `SDLWindowConfig.xml` (`GetConfiguredTitle()`), else the game's name, else `BagiEngine`.

## SDL3 vs SDL2 Differences

- Event types use the `SDL_EVENT_` prefix; rectangles are `SDL_FRect` (float); `SDL_Init()` returns `bool`, not `int`.

## Best Practices

- Forward declare SDL types in headers (`struct SDL_Window;`); use accessors, no raw SDL pointers kept long-term; check return values (SDL3 functions may fail).
- Do not poll SDL events outside `SDLEventsProvider`. Engine-facing code depends on `IRenderer` / `ITexture`, never on raw SDL handles.

## Headless and screenshots

`--headless` (`ApplicationOptions::headless`, set by `Application` from `ControlSettings`; `Control/CLAUDE.md`) runs a game with no window at all:

- `SDLMainWindow` sets the hint `SDL_HINT_VIDEO_DRIVER` to `dummy` before `SDL_Init` (the hint is reset on `Destroy()`, so a later window picks its driver again) and takes `SDL_WINDOW_VULKAN` out of the configured flags. The window keeps the configured size, which is also the size of the picture.
- `SDL3ApplicationFabric` ignores the `renderer` attribute and creates `SDLRendererBackend`, which asks SDL for the `software` renderer when its window is headless (the Vulkan backend needs a real surface). The texture loader follows the renderer (`SDLTextureLoader::CanLoad`), so sprites load as usual.
- The `dummy` driver with the software renderer works on macOS and on Windows 11 (`SDLCaptureTest` and the control smoke pass there); a hidden `cocoa` window with the software renderer does not (`software not available`), and the `offscreen` driver needs OpenGL.
- The Editor run mode cannot be headless (its viewport is an offscreen render target, which this backend does not implement): `Application` stops the start-up with a log line.
- A headless game has no vsync, so on the real clock it draws frames as fast as it can. Use it with `--manual-clock`.

`IRenderer::RequestCapture(callback)` is how pixels leave a renderer: `SDLRendererBackend` serves the request in `PresentFrame()` just before `SDL_RenderPresent` (`SDL_RenderReadPixels`, converted to RGBA8; after the present the back buffer is undefined) and hands a `PixelBuffer` to the callback. A newer request replaces an unserved one, whose callback gets an error. The headless run and the windowed SDL renderer both support it; `VulkanRendererBackend` does not (the default of `IRenderer` answers with an error).

The `screenshot` method (`RegisterScreenshotControl`, registered by `SDL3ApplicationFabric::Create`) asks for the capture and defers its answer by one frame of zero seconds, so on the manual clock a screenshot is a frame of its own in which nothing moves, and on the real clock it is the frame being run. It answers `{width, height, png_base64}`; `maxSize` (16 to 4096, default 1024) cuts the longer side, the proportions are kept and a picture is never enlarged. Tests: `tests/BECore/SDLCaptureTest.cpp`.

## Input and window metrics

`SDLEventsProvider::ConvertSDLEvent` turns SDL events into `SDLEvents` (`SDLEvents.h`), after emitting every one of them raw as `SDLEventWrapper` (ImGui reads those):

| SDL event | Engine event | Kept back while |
|-----------|--------------|-----------------|
| mouse button down / up, motion, wheel | `MouseButtonDownEvent`, `MouseButtonUpEvent`, `MouseMotionEvent`, `MouseWheelEvent`, **through `UIInput`** (below) | an ImGui context exists and `WantCaptureMouse` |
| key down / up | `KeyDownEvent` (key, modifiers, repeat), `KeyUpEvent`; Cmd+V (Apple) / Ctrl+V (else) also calls `Clipboard::RequestPaste()` | an ImGui context exists and `WantCaptureKeyboard` |
| text input | `TextInputEvent` (UTF-8, copied: SDL frees its string) | the same keyboard rule; SDL sends it only between `SDL_StartTextInput` and `SDL_StopTextInput`, which nothing calls yet |
| window resized, pixel size or display scale changed, moved, focus gained / lost, close requested | `WindowEvent` | |
| `SDL_EVENT_WINDOW_SAFE_AREA_CHANGED` | `SafeAreaChangedEvent` (no payload: read `IMainWindow::GetSafeArea()`) | |
| `SDL_EVENT_DISPLAY_ORIENTATION` | `DisplayOrientationChangedEvent` (display id, `SDL_DisplayOrientation`) | |

Game run mode has no ImGui context, so nothing is kept back there. Mouse positions are in output pixels, not scene units (`Scene::ScreenToSceneX/Y` maps them): SDL reports them in window units, and the provider multiplies the position of a button, motion (`x`, `y`, `xrel`, `yrel`) and wheel event (`mouse_x`, `mouse_y`; the scroll amount stays) by `IMainWindow::GetPixelDensity()` (1 with no window) before `UIInput` sees it, reading the density for every event because a window can move to another display. The raw `SDLEventWrapper` that ImGui reads stays in window units (ImGui has its own framebuffer scale), and so does the viewport-local position that `ViewportWidget` re-emits in the editor.

**`UIInput`** (`BECore/Input/UIInput.h`, `CoreManager::GetUIInput()`) is the one door for mouse input. The provider and `ViewportWidget` do not emit the mouse events themselves: they call `DispatchMouseButtonDown/Up`, `DispatchMouseMotion`, `DispatchMouseWheel`. Registered `IUIInputHandler`s (the UI canvases, `UICanvasComponent`, `BECore/UI/CLAUDE.md`) are asked first, the higher `order` first and, among equals, the later registered one; the first that answers `true` consumes the event, and only an event nobody consumed is emitted for game code. A click on a button therefore does not also hit the board under it. A handler that holds a pressed button answers `true` for the matching up and for the motion in between, wherever the pointer is. Registering or unregistering inside a handler is safe: it takes effect after the dispatch in progress, and an unregistered handler is not called again.

**While the game is paused** (`CoreManager::GetPause().IsPaused()`, which includes the manual clock) the provider drops the game-bound branches: mouse (so `UIInput` sees nothing), key and text. They are dropped, never queued, so a click made in the pause does not fire on resume. Kept: the raw `SDLEventWrapper` (ImGui, `Ctrl+Shift+E` and `Ctrl+Shift+P` read it), `QuitEvent` and the window, safe-area and orientation events (a resize re-lays the scene). `UIInput` itself is not gated: input injected by the control API (`ui_click`) works in a pause. `ViewportWidget::ForwardMouse` does the same and forgets a press that began before the pause. A canvas that took a press before the pause keeps it (pressed look, consumed hover) until the next click.

`ViewportWidget` (Editor mode) feeds the same door with viewport-local positions: down only while the image is hovered, up and motion also after the pointer leaves the image, as long as the press began there; wheel while hovered.

**Window metrics** (`IMainWindow`): `GetWidth()` / `GetHeight()` and `GetSafeArea()` are in window units, `GetPixelDensity()` is output pixels per window unit (2 on a Retina display: the shipped window config asks for the high-density mode, and both renderer backends follow the window's pixel size, the Vulkan swapchain is recreated on resize, `Vulkan/CLAUDE.md`), `GetDisplayScale()` is the user's display scale. Layout takes all three as inputs. The headless dummy driver answers 1, 1 and the whole window.

Tests: `tests/BECore/SDLEventsProviderTest.cpp` (conversions, the capture and pause rules, with the real SDL queue), `UIInputTest.cpp`, `WindowMetricsTest.cpp`.

## Web build

The browser build (`ENGINE_TARGET_WEB`, presets `web-release` / `web-debug` and their `-single-thread` variants, entry `web-build` of the todo store) uses this module with SDL3 built static (`ENGINE_STATIC_SDL`, the target `SDL3-shared` is an interface shim over `SDL3::SDL3-static`). It builds with emsdk 4.0.23 (`BagiMatch3`, SDL3 and SDL_image static from the vendored sources, no `-sUSE_...` port) and runs in headless Chromium 158 and Edge 157 (`tools/web/tests/web_smoke.py`, `tools/web/CLAUDE.md`): the menu and the board are drawn over WebGL 2 (SwiftShader), a click and a tap reach the game, the backing store follows `devicePixelRatio`; what stays unchecked is listed at the end.

- **Threads.** The default web build is threaded: `cmake/BagiEngine.cmake` sets `SDL_PTHREADS=ON` (SDL's own default for Emscripten is OFF) and `-pthread` reaches SDL and SDL_image through `CMAKE_C_FLAGS`; the single-thread presets set `SDL_PTHREADS=OFF`. SDL creates no thread of its own at start-up; the `TaskManager`'s workers are the pool of Web Workers (`TaskSystem/CLAUDE.md`, "Browser"). A threaded page needs `SharedArrayBuffer`, so it must be cross-origin isolated: `tools/web/serve.py` sends `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` for a threaded build by default (the `threads` member of `manifest.json`), and the shell of a threaded build shows a message and does not start the module when `crossOriginIsolated` is not true (`tools/web/CLAUDE.md`, "The page and the isolation").
- **Renderer.** `SDLRendererBackend` on SDL's `opengles2` driver over WebGL; there is no Vulkan. The renderer asks for vsync in a browser (`SDL_SetRenderVSync(renderer, 1)`, `#ifdef __EMSCRIPTEN__`): without it SDL sets swap interval 0 at the first frame and its Emscripten driver then runs the main loop on `setTimeout(0)` instead of `requestAnimationFrame`. The overlay `web/config/` (the last content root, `BAGI_WEB_ROOT`) makes `SDLRendererBackend` the renderer and drops `SDL_WINDOW_VULKAN`; the window asks for `SDL_WINDOW_RESIZABLE | SDL_WINDOW_HIGH_PIXEL_DENSITY` and a start size of 1280x720.
- **The page.** `web/shell.html` (`--shell-file`) has the `<canvas id="canvas">`; SDL looks for `#canvas` (`SDL_HINT_EMSCRIPTEN_CANVAS_SELECTOR` stays at its default, nothing sets it). The canvas is `100vw` x `100vh` by CSS (`100dvh` where known, so a phone's address bar does not hide the lower edge; the resize glue below reads `window.innerHeight`). The shell also shows the loading bar and messages for missing WebGL (the game is not started), an aborted module, a part that does not download and a finished game (Quit); all were looked at in a browser (`tools/web/CLAUDE.md`).
- **Canvas size.** `SDLMainWindow::Initialize` adds `SDL_WINDOW_OPENGL` (else the GLES2 renderer recreates the window, which drops every page handler of these events, ours too), then calls `InstallWebCanvasResize(window)`. It sets the window to the inner size of the page (`window.innerWidth` / `innerHeight` through `FitWindowSize`: rounded, at least 64 units) now and on every resize (`emscripten_set_resize_callback` on the window); `SDL_SetWindowSize` then sizes the canvas. SDL 3.2 cannot fill the document by itself (its resize handler skips a fullscreen window), so the glue sets the size. The window flag `SDL_WINDOW_HIGH_PIXEL_DENSITY` makes the backing store `devicePixelRatio` times larger than the window, which `SDLMainWindow::GetPixelDensity()` reports, so layout and the renderer see output pixels as on a Retina display. A change of `devicePixelRatio` alone (another display, zoom) is SDL's own handling.
- **Fullscreen of the page.** The shell asks for fullscreen on `document.documentElement` (`tools/web/CLAUDE.md`), not the canvas and not `SDL_SetWindowFullscreen`. SDL's `fullscreenchange` handler reacts to any element: it sets `SDL_WINDOW_FULLSCREEN` and sends `SDL_EVENT_WINDOW_RESIZED` with the desktop-mode size of the display without resizing the canvas (`SDL_UpdateFullscreenMode`). Our handler is registered after SDL's, runs after it and puts the page size back (`SDL_SetWindowSize` sizes the canvas whatever the flag says); the browser's own `resize` may come before the change or stale. `FitWindowToPage` skips only when `document.fullscreenElement` is a `CANVAS` (SDL's own fullscreen sizes the canvas itself), never by the flag. `orientationchange` fits too. SDL unregisters all handlers of these events when the window is destroyed.
- **Safe area.** SDL's driver answers the whole window; `InstallWebCanvasResize` reads `env(safe-area-inset-*)` through the padding of a hidden fixed element (`window.bagiSafeAreaProbe`; the shell's viewport has `viewport-fit=cover`, without it the insets are 0) at start, on resize, `fullscreenchange` and `orientationchange`, keeps the four values, and `GetSafeArea()` answers from them through `SafeAreaFromInsets` in window units (CSS pixels; a bad or negative inset is 0, one beyond the window is cut, an empty result is the whole window) with no DOM access per call. A change of the values pushes `SDL_EVENT_WINDOW_SAFE_AREA_CHANGED`, so `SafeAreaChangedEvent` comes through the usual provider (SDL sends the same event when the window size changes, so one resize can give two; the event carries no payload).
- **Input.** Mouse and touch need no code of ours: SDL 3.2 turns touches into mouse events (`SDL_HINT_TOUCH_MOUSE_EVENTS`, on by default), which go through `UIInput` in output pixels. The canvas has `touch-action: none`, so the page does not scroll or zoom under a finger. A tap reaches the game once (seen in Chromium with an emulated touch screen).
- **Tests.** `FitWindowSize` and `SafeAreaFromInsets` are covered on the desktop (`WebCanvasTest` in `tests/BECore/WebConfigTest.cpp`, together with the tests of the `web/config/` files); `tools/web/tests/test_shell.py` checks the shell by text. `SDLWebCanvas.cpp` has the Emscripten half under `#ifdef __EMSCRIPTEN__`, an empty part of the file on the desktop. EM_ASM code is stringized as written: keep it between `// clang-format off/on` (the formatter splits `===`) and put no comma outside parentheses (the macro splits its arguments there; braces and brackets do not protect it).
- **Checked in a browser** (headless Chromium and Edge, emulated touch and pixel ratio): the canvas fills the window and follows `set_viewport_size`, with a backing store of `devicePixelRatio` times that; the glue and SDL's own resize handler do not fight over the size; the loading text and the shell's messages show. **Not checked:** the glue of the fullscreen and the safe area (the Emscripten half of `SDLWebCanvas.cpp` is compiled, not run), touches and pixel ratio on a real phone, a real GPU (SwiftShader draws everything), Firefox and Safari, the loading bar over a real network.

## ImGui + SDL3

The backends are driven by events, not called from widgets. Per frame: (1) `ImGuiWidget::OnNewFrame` emits `RenderEvents::ImGuiNewFrameEvent`; (2) `SDLRendererBackend::OnImGuiNewFrame` calls `ImGui_ImplSDL3_NewFrame()` and `ImGui_ImplSDLRenderer3_NewFrame()`; (3) `ImGuiWidget` calls `ImGui::NewFrame()` and the widgets build their windows; (4) `ImGuiWidget` calls `ImGui::Render()` and emits `RenderEvents::ImGuiRenderEvent`, and `SDLRendererBackend::OnImGuiRender` calls `ImGui_ImplSDLRenderer3_RenderDrawData(...)`.

Init and shutdown use `ImGuiInitEvent` / `ImGuiShutdownEvent` the same way. `VulkanRendererBackend` subscribes to the same four events, so widget code stays backend-agnostic.

## Error Handling

Validate texture load/create results and report failures by logging/assertions. Prefer an explicit fallback (placeholder texture, skip draw, disabled component) to a silent failure. Resolve asset paths through the `FileSystem`.
