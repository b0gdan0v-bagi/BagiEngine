# RmlUiHost Module Guidelines

## Overview

The host of the vendored RmlUi (`src/Modules/RmlUi`, HTML-like `.rml` documents and CSS-like `.rcss` styles with a DOM and a layout engine of their own): the interfaces RmlUi calls, and the scene component that draws one document. It is the third candidate for authoring a UI screen (`src/Modules/BECore/UI/AuthoringDecision.md`) and is **off by default**: `-DENGINE_UI_RMLUI=ON` builds `rmlui_core` and this module, and `be_link_engine` links the module into every executable and test executable (`WHOLE_ARCHIVE`, the component registers in a static initializer). With the option off nothing here is compiled and no game or test notices. RmlUi is built with `RMLUI_FONT_ENGINE=none`: its text is drawn by `RmlUiFontEngine` over the engine's own `Font`, so nothing has to be installed.

| File | Purpose |
|------|---------|
| `RmlUiRuntime` | `Singleton`: the interfaces and the library, up while any document holds it (`Acquire()` / `Release()`). Installs the interfaces and the font engine, `Rml::Initialise()`, loads the default font of `TextConfig.xml` (`font-family: "PT Sans"` for the shipped one: the family is read from the font's name table, `Font::GetFamilyName()`). Shuts RmlUi down with the last holder and on `ApplicationCleanUpEvent`, before the renderer is destroyed (the textures belong to it) |
| `RmlUiRenderInterface` | `Rml::RenderInterface` over `IRenderer::DrawGeometry()`, `ITexture` and the clip stack. Converts the premultiplied colors and generated pixels of RmlUi to the straight alpha of `IRenderer` once, at compile / generate time. Counts what it did (`GetStats()`) |
| `RmlUiFontEngine` | `Rml::FontEngineInterface` over `BECore/Text/Font` (stb_truetype), so the library needs no FreeType. A face is a `Font` under a family (matched without regard to case), a style and a weight; a handle is a face at one pixel size with its metrics, the glyphs drawn so far and its pages (512 x 512 RGBA, white with the coverage in alpha, premultiplied, packed with `ShelfPacker`, one transparent pixel around each glyph). A page becomes a texture for each context on first use (a callback texture) and is then **sealed**: a glyph that comes later goes to a new page, so the pixels of a texture never change and geometry made earlier never goes stale (`GetVersion()` is 0). Advances are fractional with the `kern` table (as the engine's own text), each glyph lands on a whole pixel, the widths RmlUi asks for are whole pixels; `letter-spacing` and `font-kerning` are honoured (auto turns kerning off when letters are spaced). **Not done:** font effects (outline, shadow, blur, glow: logged once, drawn without), fallback faces (a font that lacks a code point draws its own fallback glyph), synthesized bold or italic (a weight or a style is another face file registered under the same family), a face index other than 0, shaping and right-to-left |
| `RmlUiSystemInterface`, `RmlUiFileInterface` | The game clock and the logger; files through `FileSystem` (virtual paths, layered like every file; a path it cannot resolve is tried as a real one, so a test can use a temporary directory). The file interface can record the `RmlUiFileStamp` (path, time of last write, size) of every file opened between `BeginRecording()` and `EndRecording()`: that is how a document knows what it is made of (hot reload) |
| `RmlUiVarsDefinition` | `UIVars` seen by a data model as the struct `vars` |
| `RmlUiDocumentComponent` | The scene component |

## The component

`<component type="RmlUiDocumentComponent" space="Screen" scaleMode="ScaleWithScreen" source="assets/ui/menu.rml"/>`. It has the fields of `UICanvasComponent` that resolve the scaler (`space`, `scaleMode`, reference size, `match`, `minScale`, `maxScale`, `useSafeArea`), `modal`, `visible`, `inputEnabled`, and `source`. `SetMarkup(text)` loads a document from a string (tests, generated screens).

- **Units.** The context is the size of the resolved rect in **output pixels**, and its density-independent pixel ratio is the canvas scale, so **`1dp` is one UI unit**, the `px` of a `UICanvasComponent` screen, and text is rasterised at its final size (no blur from scaling). Write sizes in `dp` and `%`; a `px` is a real pixel and does not follow the scaler. The context origin is the top-left of the content bounds (the safe bounds when `useSafeArea`), and the draw uses a view transform of scale 1 and that offset.
- **A screen needs `body { width: 100%; height: 100%; }`** (the body has no size in RmlUi, so a percentage in a screen would be of nothing), and a `font-family` that names a loaded face.
- **Input.** `UIInput` handler in the draw rank of the node, like a canvas. Everything under the pointer takes the event, `body` included, so a wrapper that must let clicks through says `pointer-events: none` (it is inherited: set it on `body` and `pointer-events: auto` on buttons). A press the document took is followed to its release; a drag that began elsewhere is the game's; `modal` takes everything.
- **Actions.** A `data-action="Name"` attribute on an element (or an ancestor of the clicked one; not when an element on the way has `disabled`) emits `InputEvents::ActionEvent` on click. The listener queues the action and the component emits it after RmlUi has finished with the event, because a handler may switch scenes and destroy the component (the same reason a `UICanvasComponent` clicks last).
- **UIVars.** `<body data-model="vars">` and `{{vars.score}}`. The component marks the model dirty when `UIVars::GetVersion()` changes. A game keeps calling `CoreManager::GetUIVars().Set(...)` whichever authoring path draws the screen.
- **Hot reload.** A component with a `source` notes the files its document was made of (the `.rml`, each `.rcss`, templates) and, every `hotReloadInterval` seconds of game time (`UIConfig.xml`, 0.5 by default, 0 turns it off; the draw does the polling, also while the screen is hidden), loads the document again when one of them has another write time or size. `Reload()` and `ReloadIfChanged()` are public (a tool, a test). The new document is loaded **before** the old one goes, so a file that cannot be read leaves the screen as it was (logged; the next save is tried again). A load almost never fails otherwise: RmlUi's parser takes any text for a document, so a typo shows on screen and in the log instead. Style sheets and templates are cached by RmlUi per path, so every load drops those caches first (then the list of files is complete, and a changed `.rcss` is read again). What survives a reload: the context, the `vars` data model, the component's fields, the queued actions. What does not: the old elements and with them hover, focus and scroll position. A file that is gone is not a change (an editor may save by deleting and renaming); a file that was missing at load is watched and noticed when it appears. **Not reloaded:** images (the texture cache of the engine) and fonts, and a document made with `SetMarkup()` (no files).
- **Not seen by the engine.** The document has its own DOM: the scene editor shows one component, `UILayoutValidator` and the control API's tree do not see into it. `tests/RmlUiHost/RmlUiScreensTest.cpp` replaces the validator for its three screens: the same rects as the shipped XML on every case of the size matrix, nothing outside the content, buttons over the touch size, no text that overflows its box (RmlUi's `GetScrollWidth() > GetClientWidth()`).

## What the render interface does not do

CSS `transform`, the clip mask (`overflow` with rounded corners), layers, filters (`filter`, `backdrop-filter`, `drop-shadow`), shaders (gradients, `box-shadow`). RmlUi's defaults for the optional interface methods draw nothing for them, so a document that needs them lacks them without a message. `overflow: hidden` works (a clip rect). `<img src>` loads a texture file through `ResourceManager`, not a `TextureLibrary` sprite name. `DrawGeometry` exists in both backends, so a document draws on SDL and on Vulkan; a backend that lacks it logs once and draws nothing (`.claude/rules/rendering-module.md`). Text, colored boxes with alpha, Cyrillic and `overflow: hidden` were looked at on Vulkan in a real window (`src/Modules/Vulkan/CLAUDE.md`, "Looking at the pixels"). RmlUi has no default style sheet here: a `div` is inline until a rule says `display: block` or `flex`.

## Tests (`tests/RmlUiHost/`, in `BagiEngineTests` only when the option is on)

`RmlUiFontEngineTest` (the engine on its own: family and case, handles, metrics, widths with letter spacing and kerning, control characters, the weight of a face, `ReleaseFontResources()`), `RmlUiHostTest` (geometry in output pixels, glyph quads and sealed pages, straight alpha, glyph texture, scale, a scene view, clips, hidden, clicks, hover, modal, `UIVars`, a document from a file with its `.rcss`, hot reload (a changed `.rcss` or `.rml`, an unchanged file, an unreadable one, a file that appears later, the interval and the off switch, variables and actions after a reload, markup from code), lifetime), `RmlUiScreensTest` (the three shipped screens through the size matrix, a deliberately broken screen is caught), `RmlUiSdlTest` (pixels from the software SDL renderer; set `BAGI_TEST_SCREENSHOT_DIR` to also write the PNGs), `UIAuthoringBenchmarkTest` (one screen of 1,001 elements in XML, HTML + CSS and RML; prints the table that the decision record quotes, asserts no timing). The screens of the tests are in `RmlUiScreens.h`. Run them with the presets `macos-rmlui-debug` / `macos-rmlui-release` (`cmake --preset macos-rmlui-debug`, `cmake --build --preset macos-rmlui-debug --target BagiEngineTests`, `ctest --preset macos-rmlui-debug`): each has a build directory and an output folder of its own (`build/<preset>/bin`).
