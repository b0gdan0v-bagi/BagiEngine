# PoolString: interned identifiers

`PoolString::Intern(text)` returns the one `PoolString` for a text; `Find(text)` returns it only when it was interned before and adds nothing. `StaticPoolString.h` (`"Key"_intern`, `StaticPoolString<"...">`) turns a literal into a ready entry in the program image, registered on its first use, with no hashing or copy; `PoolStringMap.h` has the hashers for maps.

## What a PoolString is

- **One pointer** to an entry (`static_assert(sizeof(PoolString) == sizeof(void*))`). Length and hash live in the entry, so `Length()`, `HashValue()` and `ToStringView()` read through the pointer and **equality is a pointer compare**. In a `consteval` context (no pool exists at compile time) equality compares the hashes.
- **Entry layout** (`Details::PoolStringEntry`): `hash` (8 bytes), `size` (4 bytes), then the text and a NUL at `offsetof(Entry, data) == 12`; the whole entry is padded to a multiple of 8. A `static_assert` pins the offset because the pool lays entries out by it. The empty text is `g_EmptyEntryStore`, built at compile time: `Intern` of an empty text (`Intern(StringView{})`) and a default `PoolString` return it, it is not in the table and not in the statistics as a string. A **code constant** is a ready entry too: `StaticPoolString<S>` has a `static constexpr` store laid out like `PoolStringEntry` (one per distinct literal, read-only data) and the first-use guard of `ToPoolString()` registers it by pointer, so `"x"_intern` costs the pool no memory. The text of a constant that was in the pool first keeps that older entry (`staticDuplicates`), so `Entry()` of a constant is not necessarily its `PoolString`: use the `PoolString`.
- **The pool never frees.** An entry lives to the end of the process, so a `PoolString` is valid forever and cheap to copy, and a text put in the pool is a permanent cost; batches and adopted blocks make loading cheaper, they do not change this. Only **names that come from data** (a content key, a type, a field, an event) go in; never text for display, a message or an error. A path that lets a client choose the text (`allowInterning` of the control API, `Reflection/CLAUDE.md`) is off by default. The readers cap one value read into a `PoolString` field (`ReaderLimits::kMaxPoolStringBytes`).

## Constants in code

- **Three ways to name a text.** `Intern(StringView)` is for names that come from data (a content key, a type, a field), never for display text. `"text"_intern` is for a constant: a ready entry, no hashing, no copy. A **named constant** is a member of a structure, `static constexpr auto name = "text"_intern;`, in an anonymous namespace of the `.cpp` (`struct Ids`), or in a header when two files need the text (`MountPoints`, `ConfigNames`, `SaveMount`, `StressNames`), so a typo is a compile error and one text has one place. A loose `_intern` is a one-off inside a function, at most two in a file; `tests/` and `tools/*/tests` are exempt from these two rules (not from the ban below). A namespace of `inline constexpr` constants (`EditorCommandIds`) counts as a structure.
- **The ban.** `PoolString::Intern` and `Find` with an array argument (a literal or a `char` buffer) are deleted templates, so `Intern("text")` does not compile; the parameter's name in the compiler's note is the hint. A deliberately runtime text or a buffer is `Intern(StringView(buf))`; a question "was it interned" is `Find(StringView{"text"})` (`"text"_intern` would intern it). A `const char*`, a `StringView` and a `String` still call the normal overload.
- **The check.** `CI/scripts/check_pool_strings.py` (ctest `BagiPoolStrings`) finds a literal in `PoolString::Intern(` / `Find(` in any spelling that still compiles (`StringView{"x"}`, `"x"sv`, a ternary of literals), the same text through `_intern` in two files, a third loose `_intern` in a file and any loose one in a header. A test file (a `tests` folder in its path) is exempt from the last three; in it `Find(StringView{"x"})` stays allowed. `CI/pool_strings_allowlist.txt` holds the exceptions, one `<rule> | <path glob or text> | <reason>` row each; a row without a reason is refused and a row that matches nothing fails, so the list only shrinks. A game runs the script from `engine/` with its own file (`--allowlist`, repeatable).

## Files

`PoolString.h` (the type, `PoolStringStats`, `PoolAdoptOptions`, the opaque `PoolAdoptError`) and `PoolBlock.h` (`PoolBlock`, `PoolAdoptResult` and the `CORE_ENUM` of `PoolAdoptError`; a caller of `AdoptBlock` includes it) and `PoolString.cpp` (wrappers over the one process-wide storage); `PoolStringEntry.h` (the entry, `PoolEntryBytes`, `ConstructPoolEntry`: the header a cook and a loader may include); `PoolEntryTable.h` (the table); `PoolStringStorage.h/.cpp` (the pool itself); `PoolBlockSource.h/.cpp` (where blocks come from); `StaticPoolString.h`, `PoolStringMap.h`.

## Storage (`PoolStringStorage.h/.cpp`)

`Details::PoolStringStorage` is the pool: the table, the blocks, the lock and the counters. `PoolString.cpp` only wraps the one process-wide instance (built by placement new into static storage, never destroyed: a static destructor elsewhere may still read a `PoolString` at exit). A test builds its own over a `CountingBlockSource` (`tests/BECore/PoolStringTestSupport.h`, `IsolatedPool`) and a small table, so growth, blocks and the failure path are checked with absolute numbers, not deltas of the shared pool. The empty text is never in the table.

- **Block source.** Blocks come from an `IPoolBlockSource`: a reserved virtual-memory arena on native platforms (`kDefaultReservedBytes` reserved, committed `kDefaultCommitChunkBytes` at a time), a heap source on wasm and when the reservation is refused (`MakeDefaultBlockSource`). The arena is **bump-only** because the pool never frees and a range that never moves or is copied keeps every entry pointer valid. A source with no more answers with an empty `PoolMemory` and the storage takes a block from the heap instead (`heapFallbackBlocks`): `Intern` never fails. The source is called under the unique lock. A future `memory-arenas` arena implements this interface; the pool does not depend on it.
- **Allocation rule (one for every path).** Entries are 8-aligned and **never cross the end of a block**. What fits the rest of the current block goes there. Otherwise a single entry of at most `kBlockBytes` starts a new standard block that becomes current (the rest of the old one is lost); a larger entry, or a batch of several new entries, gets a block of exactly its size that does not become current, so one huge string does not waste the room left for small ones. A text is at most `kPoolEntryMaxTextBytes` (the 32-bit `size`, asserted).
- **Table.** `PoolEntryTable`: open addressing over `{hash, entry}` slots, a power-of-two capacity, linear probing, an empty slot has a null entry; the stored hash lets a probe skip a slot without touching its entry. It doubles when the load would pass one half, re-placing from the stored hashes (text is not hashed again, entries do not move, so an entry pointer stays valid); `Reserve(n)` grows it once for `n` entries.
- **Locks.** One `SharedMutex`. Lookups run under the shared lock and a hit takes nothing else; everything that writes (insert, growth, a block) is under the unique lock, never on the hit path. `Intern` on a miss takes the unique lock and looks again (another thread may have inserted the text).
- **`InternBatch(texts, out)`**: one shared pass, then, if texts are missing, one unique lock, one growth of the table and one allocation for all the new strings (the distinct ones: a repeat in the batch is one miss, then hits). A batch of hits takes no unique lock. The form with `hashes` **trusts** them (`hashes[i] == GetHash(texts[i])`, `ASSERT` in Debug): a wrong one puts the text where a lookup never looks, so data from outside uses the form that hashes itself.
- **`RegisterStatic`**: puts the **pointer** of a `const` entry that lives for the whole process into the table (no hashing, copy or allocation of text; the pool never writes to it). The first entry of a text wins, whoever it was (`Intern`, another ready entry, an adopted block); each registration's `*value` is set to the winner, so a caller uses `*value` and not its own entry. The loser stays in the program image, counted in `staticDuplicates`. A batch that finds every text takes no unique lock.
- **`AllocateBlock(bytes)` / `AdoptBlock(block, usedBytes, out, options)`**: for a loader that reads a cooked string section straight into pool memory. `AllocateBlock` gives a `PoolBlock` (a move-only, non-owning token; the pool owns the memory from then on, 8-aligned, content unspecified). **A successful `AdoptBlock` spends the token** (`Data()` null): the entries are read-only for everyone from then on, so no pointer a caller took from the token may be written through. The loader lays entries one after another in the layout of `PoolStringEntry.h` and adopts. **Validation comes first, linking after**: the walk checks `usedBytes` (at most the capacity, a multiple of 8), that every header, text and NUL lie inside it, that the walk ends exactly at it, and with `verifyHashes` (default on) every hash; one bad byte refuses the whole block (`PoolAdoptError`, a `CORE_ENUM`: its name goes into a log line) and links nothing, and the block stays adoptable. A token that is empty (moved from or spent) or of another storage is refused as `NotOwned`; a refusal leaves the token as it was. The checks run outside the unique lock (they hash every text); the link takes it once. A text already in the pool, or earlier in the block, keeps its older entry and the block's entry is **dead weight** (`deadStrings`, `deadBytes`), as is an entry of the empty text. `out[i]` is the string that won, so a caller must use `out` and never keep a pointer to its own entry. With `verifyHashes` off a wrong hash is the caller's contract. No fuzz target exists yet: nothing reads untrusted bytes through `AdoptBlock` until the binary strings entry (`pool-string-binary-strings`), which adds its corpus.
- **`Reserve(strings, bytes)`** is a hint: grows the table once and takes a block of `bytes` that becomes current when the current one has less free; it limits and fails nothing. The counts may come from a file header, so a part that is not sane is **ignored** (not clamped): `strings` when the table would pass `PoolEntryTable::kMaxReservedEntries` (the sum is checked before it is formed), `bytes` above `kDefaultReservedBytes` (a block the arena could not give would come from the heap, which aborts). `AllocateBlock` has no such leniency: its size is asserted, so a loader validates a size it read.

## Loading

- **The readers (XML, binary, JSON) intern one value at a time**, with `Intern`, and do not batch. A batch needs the texts up front, and a reader does not have them: the target of a `PoolString` read is not stable until the end of the document (a generated loader reads an element into a temporary and moves it into a vector; a `PoolString` map key is read into a local and used at once), so a write deferred to the end of the document would dangle or find an empty key.
- **A batch is for a caller that holds its texts**: a directory listing (`FileSystem::EnumerateFiles`), a list of slots (`SaveGameService::List`), the stems of the config files (`ConfigManager::ScanDirectory`). Each collects its names, then makes one `InternBatch`. Names from outside use the form that hashes (the form with `hashes` is for a cook's own output).
- **The `PoolString` texts of a binary file** (a save, a cooked `.bin`) are in a pool section in the layout of a pool entry, and the reader still hashes each one itself and interns them all by one `InternBatch` at the first `PoolString` read; the hashes in the file are ignored. Reading the section straight into pool memory with `AllocateBlock` + `AdoptBlock` (the entry `pool-string-binary-strings`, next stage) is the batch of a reader that trusts a cooked file.

## Statistics

`PoolString::GetStats()` returns a `PoolStringStats`. The pool is shared by the whole process (tests, the other threads), so a test of the shared pool compares two snapshots; a test of an `IsolatedPool` reads absolute numbers.

- **Totals over all sources:** `stringCount`, `tableUsed` (distinct strings, the empty one not counted), `stringBytes` (aligned entry sizes of the linked strings; dead ones are not in it), `blockCount`, `blockBytes` (every block the pool holds, **an `AllocateBlock` block that is not adopted yet included**), `tableCapacity`, `longestProbe` (largest distance from a home slot, as of now), `hits`, `misses`, `internCalls` (`hits + misses`). An `Intern` is a miss when it inserted; the empty text and a batch's hits are hits; two threads racing for one new text are one miss and one hit. `Find` is not counted.
- **By source** `{strings, bytes, blocks, blockBytes}`: `runtime` (copied by `Intern` and `InternBatch`), `staticEntries` (registered entries that won: in the program image, so `blocks` stays 0), `adopted` (linked entries of adopted blocks; `blocks` counts a block once it is adopted).
- **Other counters:** `deadStrings`, `deadBytes` (adopted entries not linked), `staticDuplicates`, `writeLocks` (calls that took the unique lock: a miss of `Intern`, a batch with a miss left after the shared pass, `RegisterStatic` with something to insert, `AllocateBlock`, `AdoptBlock` past its checks, `Reserve`), `batchCalls`, `batchStrings`, `heapFallbackBlocks` (blocks the source did not give).
- **No shared write on a hit.** A hit is counted in a counter of the calling thread (one cache line, 64 B, per storage and thread that ever interned; its owner writes it with a plain load and store; registered once under a mutex on the thread's first call, **never freed**, so a finished thread's hits stay in the sum). Everything else is counted under the unique lock it already holds. `GetStats` sums them: the table fields come under the shared lock, the hit and batch counters under none, so the snapshot is not one instant.
