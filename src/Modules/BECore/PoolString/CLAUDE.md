# PoolString: interned identifiers

`PoolString::Intern(text)` returns the one `PoolString` for a text; `Find(text)` returns it only when it was interned before and adds nothing. `StaticPoolString.h` (`"Key"_intern`, `StaticPoolString<"...">`) interns a literal once; `PoolStringMap.h` has the hashers for maps.

## What a PoolString is

- **One pointer** to an entry (`static_assert(sizeof(PoolString) == sizeof(void*))`). Length and hash live in the entry, so `Length()`, `HashValue()` and `ToStringView()` read through the pointer and **equality is a pointer compare**. In a `consteval` context (no pool exists at compile time) equality compares the hashes.
- **Entry layout** (`Details::PoolStringEntry`): `hash` (8 bytes), `size` (4 bytes), then the text and a NUL at `offsetof(Entry, data) == 12`; the whole entry is padded to a multiple of 8. A `static_assert` pins the offset because the pool lays entries out by it. The empty text is `g_EmptyEntryStore`, built at compile time: `Intern("")` and a default `PoolString` return it, it is not in the table and not in the statistics as a string.
- **The pool never frees.** An entry lives to the end of the process, so a `PoolString` is valid forever and cheap to copy, and a text put in the pool is a permanent cost. Only **names that come from data** (a content key, a type, a field, an event) go in; never text for display, a message or an error. A path that lets a client choose the text (`allowInterning` of the control API, `Reflection/CLAUDE.md`) is off by default. The readers cap one value read into a `PoolString` field (`ReaderLimits::kMaxPoolStringBytes`).

## Storage (`PoolStringStorage.h/.cpp`)

`Details::PoolStringStorage` is the pool: the table, the blocks, the lock and the counters. `PoolString.cpp` only wraps the one process-wide instance (never destroyed: a static destructor elsewhere may still read a `PoolString` at exit). A test builds its own over a `CountingBlockSource` (`tests/BECore/PoolStringTestSupport.h`) and a small table, so growth, blocks and the failure path are checked with absolute numbers. The entry is in `PoolStringEntry.h` (`PoolEntryBytes`, `ConstructPoolEntry`), the table in `PoolEntryTable.h`.

- **Block source.** Blocks come from an `IPoolBlockSource` (`PoolBlockSource.h`): a reserved virtual-memory arena on native platforms (64 MB, committed 1 MiB at a time, bump-only: nothing is freed or moved, so a range never changes address), a heap source on wasm and when the reservation is refused. A source that has no more answers with an empty `PoolMemory` and the storage takes a block from the heap instead (`heapFallbackBlocks`): `Intern` never fails. The first block is taken on the first string.

- **Blocks.** Entries are copied into blocks of `PoolString::kBlockBytes`, aligned to 8, held by the pool and never moved or freed. **An entry never crosses the end of a block.** One that does not fit the rest of the current block starts a new standard block (the rest is lost). One larger than a standard block gets a block of exactly its size and the current block stays current, so one huge string does not waste the space left for the small ones. The length of a text is limited only by the 32-bit `size` (asserted).
- **Table.** `PoolEntryTable`: open addressing over slots `{hash, entry}`, a power-of-two capacity, linear probing, an empty slot has a null entry; the stored hash lets a probe skip a slot without touching its entry. It doubles when the load would pass one half, re-placing from the stored hashes: text is not hashed again and entries do not move, only the slots do, so an entry pointer taken out of the table stays valid.
- **Locks.** One `SharedMutex`. `Intern` looks up under the shared lock (the hit path takes nothing else) and on a miss takes the unique lock, looks again (another thread may have inserted the text), then writes the entry and inserts it, growing the table first if needed. `Find` is the shared lookup alone. `InternBatch(texts, out)` (and the form with the hashes, which the caller must get right: it trusts them) looks everything up in one shared pass, and when texts are missing takes the unique lock once, finds the distinct ones (sorted by hash), grows the table once and places them in one allocation: what fits the rest of the current block goes there, otherwise a single small entry starts a standard block and a batch of several entries (or any entry over a standard block) gets a block of exactly its size that does not become current. A text repeated in a batch is one miss and hits after it.
- **Ready entries and hints.** `RegisterStatic` puts the **pointer** of a `const` entry that lives for the whole process into the table (no hashing, copy or allocation of the text; the pool never writes to it). The first entry of a text wins, whoever it was, and each registration's `*value` is set to the winner, so a caller uses `*value` and not its own entry; the loser stays in the image, counted in `staticDuplicates`. A batch that finds every text takes no unique lock. `Reserve(strings, bytes)` is a hint: it grows the table once and takes a block of `bytes` that becomes current when the current one has less free; it limits nothing. Growth and block allocation allocate under the unique lock, never on the hit path.

## Statistics

`PoolString::GetStats()` returns a `PoolStringStats`. The pool is shared by the whole process (tests, the other threads), so a test compares two snapshots; absolute values mean nothing.

- `stringCount`, `tableUsed`: distinct strings in the table (the empty text is not one). `stringBytes`: the sum of their aligned entry sizes. `blockCount`, `blockBytes`: blocks held, standard and of their own.
- `tableCapacity`: slots. `longestProbe`: the largest distance of an entry from its home slot, as of now (growth recomputes it); a lookup of a missing text may walk one slot more.
- `runtime`: `{strings, bytes, blocks, blockBytes}` of what `Intern` copied; `writeLocks`: calls that took the unique lock; `heapFallbackBlocks`; `batchCalls`, `batchStrings` (kept in the thread's counter like the hits); `staticEntries` (`{strings, bytes}` of the registered entries that won: they are in the program image, so `blocks` stays 0) and `staticDuplicates`. `stringBytes` adds the static bytes. The other fields (`adopted`, dead counters) are 0 until those calls exist.
- `hits`, `misses`, `internCalls` (`hits + misses`): an `Intern` call is a miss when it inserted, otherwise a hit; the empty text is a hit; two threads racing for one new text are one miss and one hit. `Find` is not counted.
- **The counters add no shared write to a hit.** A hit is counted in a counter of the calling thread (one cache line each per storage, its owner writes it with a plain load and store; registered once under a mutex on the thread's first call with that storage, never freed, so a finished thread's hits stay in the sum). A miss is counted under the unique lock it already holds. `GetStats` sums them: the table fields come under the shared lock, the counters under none, so the snapshot is not one instant (counters can be a call or two off from the table fields while other threads run).
