# Programs: computed values compiled into typed code

A formula of a content file (`expr="caster.attack * 2"`) becomes a `Program`: straight-line typed instructions over registers, run by a `switch` interpreter. This folder holds the instruction set, the program and its pool, the builder and the interpreter, the text front end, the type checker and the compiler (`Values/CLAUDE.md` is the value, the context and the loading). Programs exist for `bool`, `int32_t`, `int64_t`, `float`, `double`, `Vec2`, `Vec3`, `Vec4`, `IVec2`, `Quat`, `Color`, every reflected enum and `PoolString`; any other type (`Rect`, a game's own struct) is a load error that lists these.

## The frame and the pool

Registers are `alignas(16)` objects of 16 bytes (the biggest value is `Vec4` / `Quat`; a `static_assert` holds each row type to it, so a type over 16 bytes is no row: `expr` on it is the load error that lists the types), at most 32, on the stack of `Run` and left uninitialized: an instruction reads only a register an earlier one wrote as that type. The builder hands them out like a stack (`AcquireRegister` / `ReleaseRegister`, the registers of a node's operands are the top ones), so a post-order walk of a tree needs few. A program that would need more is an error from `AcquireRegister`. **`Run` allocates nothing by construction**: it makes only stack objects and calls no container, `String` or virtual function. A program is pure and total: it writes nothing, and `select`, `&&` and `||` have computed both operands (no control flow). An `Instruction` is the opcode, the destination register, three operand registers and one 32-bit immediate (the index of a constant, or the offset of a loaded field whose level is in `a`); it is a trivially copyable 12 bytes with padding, so programs are compared and hashed field by field, never as bytes.

`ProgramPool` is process-wide and append-only, like `PoolString`: it interns by the program's code (result type and register, registers used, `reads`, instructions, constants), never by its source text, so equal formulas written differently are one program, and `Get(id)` takes no lock and returns an address that never moves (chunks that are published before an id in them is given out). `Program::Source()` is the text of the first formula that made the entry. The pool refuses a program beyond `ProgramPool::kMaxPrograms` (`Intern` returns `nullopt`) so hostile content cannot grow it without bound. `Get` loads the count with acquire in every build, so it is thread-safe on its own. `Reads()` is derived from the `LoadSlot` instructions by `Finish`: it is the mask of the levels the code loads from.

**Register images.** A value is its C++ bytes, zero-padded to 16, so equal constants are equal bytes. An enum is the `uint32_t` index of the enumerator (a `CORE_ENUM` counts 0..N-1 in declaration order), which `LoadSlot` reads from `b` bytes (`TypeDesc::enumBytes`, 1 to 8) zero-extended, a value beyond 32 bits truncated; **which enum it is lives in the checker** (`ExprType` carries the `TypeDesc`, compared with `SameType`), so two enums of different names or widths never mix and the opcode is one `Enum` row. A `PoolString` is its interned pointer: equal text is equal bytes, so `==` is a byte compare, and the pool of strings never shrinks, so a program may keep one in its constants.

## One list, one meaning

`Opcode.h` lists every typed instruction once (`BE_PROGRAM_ROWS`: operation x type, by groups of types), and the opcode enum, the interpreter's `switch`, `kHasRow` and the matrix of `ProgramInterpreterTest` are all expanded from it. An operation has a type when its C++ operator or function does (a concept in the struct, `Add<bool>` has none); `Kernels.h` ends with a `static_assert` that the rows and the concepts agree for every operation and every type, so a type that gains an operator, or a row that names an operation a type lacks, is a compile error. `ProgramOperation` names the operations apart from the type and `OpcodeOf(operation, type)` is the row lookup (`Invalid` when the type has none), so the checker keeps no table of its own. A new type is a row of `BE_PROGRAM_TYPES`, a value of `ProgramType` and rows in the groups. Operators found by concept are the engine's own: `Add` and `Sub` of the float vectors and `IVec2`, `Neg` of `Vec3`, `Vec4`, `IVec2`, and `Mul` of `Quat` by `Quat` (the Hamilton product); what the engine's types lack (`Vec2` has no `-x`, `/`, `dot`, `length`, `normalize`; nothing orders a vector) is no row. `BE_PROGRAM_MIXED_ROWS` lists the pairs of two types (`Vec3 * float`, `float * Vec3`, `Vec3 / float`, `IVec2 * int` both ways, `Quat * Vec3`); `MixedOpcodeOf` is their lookup. Equality and `select` exist for every type, `lerp` for the types with a `Lerp` (`Quat` by `Slerp`).

## Meaning of the operations

Every row has a test against a plain C++ reference (`ProgramInterpreterTest`). Operations never have undefined behaviour:

- Integer `+ - *` and `-` wrap (two's complement); `abs` of the minimum is the minimum.
- Integer `/` and `%` by zero give 0; `INT_MIN / -1` is `INT_MIN` and `INT_MIN % -1` is 0. A literal zero divisor is a load error (the checker's, not the interpreter's). `%` is for integers only.
- Floats follow IEEE (`1 / 0` is infinity, `sqrt(-1)` is NaN, a comparison with NaN is false except `!=`).
- Comparisons, `&&`, `||`, `!` give `bool`; ordering is for numbers only, logic for `bool` only.
- `min`, `max`: a NaN operand gives the other. `clamp(x, lo, hi)` is `min(max(x, lo), hi)` and `lo` when `lo > hi` (never `std::clamp`'s undefined case).
- `lerp` is `std::lerp` (exact at 0 and 1, `t` not clamped) for `float` and `double`; a vector uses the engine's `Lerp` with a `float` weight; a `Color` is lerped by the engine's `Lerp(Color)` (a NaN weight gives 0 in every channel) and a `Quat` by `Slerp`, the shortest arc. `round` goes away from zero on halves.
- Conversions between the four numbers: integer to integer keeps the low bits; integer to float rounds to nearest; float to integer truncates toward zero, saturates at the range and gives 0 for NaN; `double` to `float` rounds to nearest and gives infinity beyond the range.
- `Select` takes the condition in its first operand register, then the two values.
- `IVec2` arithmetic wraps like `int32_t` (computed through `uint32_t`). Float vectors follow IEEE; `==` of vectors is componentwise and exact, so a NaN component is unequal to itself.
- `normalize` of a zero vector is zero and of a zero `Quat` the identity (the engine's `Normalized`); `length` and `dot` are `float`. `Quat * Vec3` rotates (`Rotate`, a non-unit `Quat` scales).
- `Extract` of a `Color` channel is an `int` 0..255; `Pack` of a `Color` clamps each `int` to 0..255, of a `Quat` does not normalize.

A constant is the register image, so the builder keeps one entry for equal constants.

**Tables.** `LoadTable` (untyped, like `LoadConst`) writes entry `clamp(index, 0, count - 1)` of a run of constants to `dst`, the `int32_t` index in `a`, the first constant in `imm`, the 16-bit count in `b` and `c`. A table is consecutive, so `AddConstantRun` appends without sharing; `Finish` refuses an empty run, one outside the pool and one over `kMaxTableEntries`.

## The text of a formula

Loosest first: `||`; `&&`; `== !=`; `< <= > >=`; `+ -`; `* / %`; unary `- !`; postfix call and member. Binary operators group to the left; parentheses leave no node. A number has no suffix and no sign (a sign is the unary operator, so a literal never carries one); `a.b.c` is one `Name`, `a.b(c)` a `Call` of the name `a.b` (the checker says why that is no function), `.x` after anything but a bare name (`f(x).y`) is a `Member`. What the lexer refuses (`[`, a byte outside printable ASCII, a string with a quote or an escape) is in `ExprLexer.h`.

`PrintExpression` is the canonical text: one space around a binary operator, `, ` between arguments, every binary operand that is itself a binary in parentheses, numbers as written; parsing it gives the same tree. The limits against hostile content (`ExprLimits`: bytes of text, nesting, nodes and the **height of the tree**) are each an error that names it. The height matters because a left-nested chain `a + b + c` grows it by one per operator while no parenthesis shows it, and the checker, the lowering and the printer recurse by it: the limit keeps their frames inside the smallest secondary-thread stack. An error is `ProgramError{message, column}`, the column the 1-based byte of the token or node; the node of a binary or unary operator is at its operator.

## The type rules

`CheckExpression(ast, declaration, expected, options)` gives a `TypedExpr`: post-order nodes, each of a program type and a `Constant` (the register image), a `Slot` (`SlotRef` and the path as written) or an `Operation` (the final opcode, a conversion included). The opcode comes from `OpcodeOf(operation, type)`: **an operation exists for a type exactly when `BE_PROGRAM_ROWS` has its row**, and the error of a missing one lists the types that have it, so a type that gains a row needs no change in the checker. `ExprChecker.h` lists what it refuses; the rules a reader cannot guess:

- **No implicit conversion.** Operands of `+ - * / %`, comparisons, `min`, `max`, `clamp`, `lerp` and the two values of `select` have one type; two types are an error at the second operand that names both and the hint `float(x)` / `int(x)`. The conversions are the functions `int` (`int32_t`), `int64`, `float`, `double`; one to the operand's own type adds no node. `&&`, `||`, `!` and the condition of `select` need `bool`. The result is exactly the field's type (`SameType`): no widening of the whole formula either.
- **Literals** have no type of their own: an integer literal becomes the type of the operand beside it, else the expected type when that is a number, else `int` (`int64` when it does not fit); a float literal is `float` or `double` and an error where an integer is needed. The operands that read the context are checked first, so a literal beside one takes its type on either side; a subtree of literals beside none takes the expected number type, else `float` when it holds a float literal. A sign before a literal is part of it (`-2147483648` is an `int`). A literal that does not fit its type is an error; the argument of a conversion is read as what it spells (`double(0.1)` is exact).
- **`==` and `!=` work for every type;** ordering and arithmetic only where `OpcodeOf` has the row (`Color + Color`, `title + title`, `position < position` are errors that list the types that have it). A bare name that is no level and no function is an enumerator when the other operand of `==` / `!=`, the other value of `select` or the expected type is an enum (case-sensitive, a level of the same name wins), so `Fire == ability.element` works and a bare pair `Fire != Earth` is an unknown name.
- **Components and `Pack`.** `.x` on a vector, `Quat` or `IVec2` and `.r` on a `Color` are `Extract`; of a slot that stores the component as the program computes with it (every type but `Color`) it is a slot at the component's byte offset, so `caster.velocity.x` is one `LoadSlotFloat`. `vec2` .. `quat` and `color(r, g, b, a)` pack: an argument is a `float` (an `int` for `ivec2` and `color`), and a literal takes it.
- **Mixed pairs.** Operands of one type, or a pair of `BE_PROGRAM_MIXED_ROWS`; a literal beside a vector takes its scalar in `*` and `/` only (`v * 2`, `iv * 2`; `v + 1` is a type error). `vec3 * quat` is refused, `quat * vec3` rotates.
- **`at(i, e0, e1, ...)`** is an inline table (`kTableFunction`, no row of `kExprFunctions`: any number of arguments): `i` an `int`, every entry one type, the hint's (the operand beside it, else the field's) or the first typed entry's. The checker only types the entries (`TypedNode::entries`); the lowering refuses one that does not fold to a constant, and a constant table over a constant index folds by running its own `LoadTable`. Beside a name that reads the context a table comes second (`caster.element == at(i, Fire, Water)`): it has no type of its own. `ByLevel('Name', i)` is the same table copied from `CompileOptions::tables` (`Values/CLAUDE.md`, "Named tables"): the checker makes constant entries of the type beside it, so it waits for the typed operands as `at` does not.
- **Paths** are linked with `LinkSlot` once, against the field's own type, so its messages (`did you mean`, the fields of the type, the declared levels) are the ones shown. A path that names no field as a whole is retried as a field of a type with components plus one segment (`caster.velocity.x`); a bare unknown name lists the levels and the functions. A division or modulo by a **literal** zero is an error at the divisor. An expected type outside the program types (column 0) lists the types; the limit of 32 registers is the lowering's, not the checker's.

## Compiling

`CompileExpression(text, declaration, expected)` is parse, check, fold, lower; the answer is a `CompiledExpression` of one of three kinds, and `CompileValue<T>` makes the `Value<T>` of it (`Const`, `Slot` or `Program`). The type asked for is checked first (`CheckExpectedType`), so a field no formula can fill says so whatever the text. **Folding** runs a node whose operands are all constants through the interpreter on a one-instruction program, so the folded value is what the program would compute; there is no algebra (`a - a`, `x * 1` run), and a divisor that folds to zero is a run-time 0, not an error. A formula that folds to a constant is a `Constant` (the register image), one that is a single field a `Slot` (the path as written), so `expr="caster.attack"` loads and saves like `from`. **Lowering** is a recursive post-order walk: an operation writes into the register of its first operand and its other operands go into the registers above it, one after the other (`Pack` reads its up to four from `a` up), which are given back after the instruction, so a left-leaning chain needs two registers and a right-nested one a register per level. The 32-register limit is the lowering's error (column of the node that did not fit). The source text of the program is the text as written; the pool does not intern by it, and the slot offsets are part of the code, so one text under two declarations is two programs.

`FormatProgramError(text, error)` is `<message> (column N)`, the text around the column (a window for a long one, a byte that is not printable ASCII as `?`) and a caret line; an error without a column is the message alone.

## Fusion

`ProgramBuilder::Fuse` (the lowering calls it before `Finish` unless `CompileOptions::fuse` is false, which tests and benchmarks use) runs `Fuse` of `Peephole.h`. It writes `MulAddSlot<T>` for `LoadSlot; LoadConst k; Mul; LoadConst b; Add` over the four numbers, `LerpSlots<T>` for `LoadSlot; LoadSlot; <code of t>; Lerp` over `float` and `double` (the code of `t` stays where it is) and `LoadTableSlot` for `LoadSlot` of an `int` and `LoadTable` (`Instruction.h` has each encoding). **A fused instruction computes what the code it replaces computes, bit for bit** (`ProgramFusionTest` runs both over generated inputs: NaN, infinities, subnormals, the integer extremes): its kernel calls the unfused kernels, and `MulAddSlot` keeps the product in a variable of its own, because one expression `x * k + b` may be contracted into a fused multiply-add that rounds once. The pass reads the code, not the lowering's habits: it fuses only when every register it stops writing is dead afterwards (not read before the next write, not the result), so a program built by hand is as safe. A field that does not fit (a constant index over a byte, an offset over 16 bits) leaves the sequence unfused, never an error. `Finish` counts the levels of a fused instruction in `Reads()`. There is no `Vec3` fusion.

## Loading and its errors

`Ser::DataAccessor<Value<T>>` (`ValueAccessor.h`) compiles `expr` under the innermost `ValueLinkScope` when the field is read; the compile runs once per load, never per `Evaluate`. A formula needs a declared context even when it is all constants. A compile error is reported through `IDeserializer::ReportError` under the field's `expr` key as `column N: <message>` and ends with the document name. It is not the caret block of `FormatProgramError`: the reader cuts a report at 256 bytes and turns newlines into `?`, so the column goes first and the message is the short form (`FormatProgramError` is for tools and tests that print an error alone). A failed load leaves the field as it was and adds nothing to the pool. Every limit (text, nesting, nodes, registers) and every type error is such a load error; hostile text is an error, never a crash.
