# Programs: computed values compiled into typed code

A formula of a content file (`expr="caster.attack * 2"`) becomes a `Program`: straight-line typed instructions over registers, run by a `switch` interpreter. This folder holds the instruction set, the program and its pool, the builder and the interpreter, the text front end, the type checker and the compiler (`Values/CLAUDE.md` is the value, the context and the loading). Programs exist for `bool`, `int32_t`, `int64_t`, `float`, `double`, `Vec2`, `Vec3`, `Vec4`, `IVec2`, `Quat`, `Color`, every reflected enum and `PoolString`; any other type (`Rect`, a game's own struct) is a load error that lists these.

## The frame and the pool

Registers are `alignas(16)` objects of 16 bytes (the biggest value is `Vec4` / `Quat`; a row type bigger than 16 bytes would be a load error, a `static_assert` holds each row type to it), at most 32, on the stack of `Run` and left uninitialized: an instruction reads only a register an earlier one wrote as that type. The builder hands them out like a stack (`AcquireRegister` / `ReleaseRegister`, the registers of a node's operands are the top ones), so a post-order walk of a tree needs few. A program that would need more is an error from `AcquireRegister`. **`Run` allocates nothing by construction**: it makes only stack objects and calls no container, `String` or virtual function. A program is pure and total: it writes nothing, and `select`, `&&` and `||` have computed both operands (no control flow). An `Instruction` is the opcode, the destination register, three operand registers and one 32-bit immediate (the index of a constant, or the offset of a loaded field whose level is in `a`); it is a trivially copyable 12 bytes with padding, so programs are compared and hashed field by field, never as bytes.

`ProgramPool` is process-wide and append-only, like `PoolString`: it interns by the program's code (result type and register, registers used, `reads`, instructions, constants), never by its source text, so equal formulas written differently are one program, and `Get(id)` takes no lock and returns an address that never moves (chunks that are published before an id in them is given out). `Program::Source()` is the text of the first formula that made the entry. The pool refuses a program beyond `ProgramPool::kMaxPrograms` (`Intern` returns `nullopt`) so hostile content cannot grow it without bound. `Get` loads the count with acquire in every build, so it is thread-safe on its own. `Reads()` is derived from the `LoadSlot` instructions by `Finish`: it is the mask of the levels the code loads from.

**Register images.** A value is its C++ bytes, zero-padded to 16, so equal constants are equal bytes. An enum is the `uint32_t` index of the enumerator (a `CORE_ENUM` counts 0..N-1 in declaration order), which `LoadSlot` reads from `b` bytes (`TypeDesc::enumBytes`, 1 to 8) zero-extended, a value beyond 32 bits truncated; **which enum it is lives in the checker** (`ExprType` carries the `TypeDesc`, compared with `SameType`), so two enums never mix and the opcode is one `Enum` row. A `PoolString` is its interned pointer: equal text is equal bytes, so `==` is a byte compare, and the pool of strings never shrinks, so a program may keep one in its constants.

## One list, one meaning

`Opcode.h` lists every typed instruction once (`BE_PROGRAM_ROWS`: operation x type, by groups of types), and the opcode enum, the interpreter's `switch`, `kHasRow` and the matrix of `ProgramInterpreterTest` are all expanded from it. An operation has a type when its C++ operator or function does (a concept in the struct, `Add<bool>` has none); `Kernels.h` ends with a `static_assert` that the rows and the concepts agree for every operation and every type, so a type that gains an operator, or a row that names an operation a type lacks, is a compile error. `ProgramOperation` names the operations apart from the type and `OpcodeOf(operation, type)` is the row lookup (`Invalid` when the type has none), so the checker keeps no table of its own. A new type is a row of `BE_PROGRAM_TYPES`, a value of `ProgramType` and rows in the groups. Operators found by concept are the engine's own: `Add` and `Sub` of the float vectors and `IVec2`, `Neg` of `Vec3`, `Vec4`, `IVec2`, and `Mul` of `Quat` by `Quat` (the Hamilton product); what the engine's types lack (`Vec2` has no `-x`, `/`, `dot`, `length`, `normalize`; nothing orders a vector) is no row. `BE_PROGRAM_MIXED_ROWS` lists the pairs of two types (`Vec3 * float`, `float * Vec3`, `Vec3 / float`, `IVec2 * int` both ways, `Quat * Vec3`); `MixedOpcodeOf` is their lookup. Equality and `select` exist for every type, `lerp` for the types with a `Lerp` (`Quat` by `Slerp`).

## Meaning of the operations

Every row has a test against a plain C++ reference (`ProgramInterpreterTest`). Operations never have undefined behaviour:

- Integer `+ - *` and `-` wrap (two's complement); `abs` of the minimum is the minimum.
- Integer `/` and `%` by zero give 0; `INT_MIN / -1` is `INT_MIN` and `INT_MIN % -1` is 0. A literal zero divisor is a load error (the checker's, not the interpreter's). `%` is for integers only.
- Floats follow IEEE (`1 / 0` is infinity, `sqrt(-1)` is NaN, a comparison with NaN is false except `!=`).
- Comparisons, `&&`, `||`, `!` give `bool`; ordering is for numbers only, logic for `bool` only.
- `min`, `max`: a NaN operand gives the other. `clamp(x, lo, hi)` is `min(max(x, lo), hi)` and `lo` when `lo > hi` (never `std::clamp`'s undefined case).
- `lerp` is `std::lerp` (exact at 0 and 1, `t` not clamped) for `float` and `double`; a vector uses the engine's `Lerp` with a `float` weight; a `Color` channel is lerped by the kernel's own function (the engine's `Lerp(Color)` has undefined behaviour on a NaN channel) and a `Quat` by `Slerp`, the shortest arc. `round` goes away from zero on halves.
- Conversions between the four numbers: integer to integer keeps the low bits; integer to float rounds to nearest; float to integer truncates toward zero, saturates at the range and gives 0 for NaN; `double` to `float` rounds to nearest and gives infinity beyond the range.
- `Select` takes the condition in its first operand register, then the two values.
- `IVec2` arithmetic wraps like `int32_t` (computed through `uint32_t`). Float vectors follow IEEE; `==` of vectors is componentwise and exact, so a NaN component is unequal to itself.
- `normalize` of a zero vector is zero and of a zero `Quat` the identity (the engine's `Normalized`); `length` and `dot` are `float`. `Quat * Vec3` rotates (`Rotate`, a non-unit `Quat` scales).
- `Extract` of a `Color` channel is an `int` 0..255; `Pack` of a `Color` clamps each `int` to 0..255, of a `Quat` does not normalize.

A constant is the register image, so the builder keeps one entry for equal constants.

**Tables.** `LoadTable` (untyped, like `LoadConst`) writes entry `clamp(index, 0, count - 1)` of a run of constants to `dst`, the `int32_t` index in `a`, the first constant in `imm`, the 16-bit count in `b` and `c`. A table is consecutive, so `AddConstantRun` appends without sharing; `Finish` refuses an empty run, one outside the pool and one over `kMaxTableEntries`.

## The text of a formula

Loosest first: `||`; `&&`; `== !=`; `< <= > >=`; `+ -`; `* / %`; unary `- !`; postfix call and member. Binary operators group to the left; parentheses leave no node. Numbers are `12`, `1.5`, `.5`, `1e3` with no suffix and no sign (a sign is the unary operator, so a literal never carries one); `true` and `false` are literals, `'text'` a string: printable ASCII from space to `~`, no escapes and no `'` inside (an XML-friendly quote), `''` is the empty string; an unterminated one is an error at its opening quote. `a.b.c` is one `Name`, `a.b(c)` a `Call` of the name `a.b` (the checker says why that is no function), `.x` after anything that is not a bare name (`f(x).y`, `(a).b`) is a `Member`. `[` is refused by the lexer: a path must name a fixed field. Only ASCII is part of the language; any other byte is an error that names it (an invalid UTF-8 byte by its hex value, never copied into the message).

`PrintExpression` is the canonical text: one space around a binary operator, `, ` between arguments, every binary operand that is itself a binary in parentheses, numbers as written; parsing it gives the same tree. Limits against hostile content, each an error that names it: 4096 bytes of text, 64 levels of nesting (parentheses, call arguments, chained unary operators) and `kMaxTreeHeight` for the **height of the tree**, which a left-nested chain `a + b + c` grows by one per operator while no parenthesis shows it: the checker, the lowering and the printer recurse by it, and the limit keeps their frames (biggest under a sanitizer) inside the stack of a secondary thread, 512 nodes. An error is `ProgramError{message, column}`, the column the 1-based byte of the token or node; the node of a binary or unary operator is at its operator.

## The type rules

`CheckExpression(ast, declaration, expected)` gives a `TypedExpr`: post-order nodes, each of a program type and a `Constant` (the 16-byte register image), a `Slot` (`SlotRef` and the path as written) or an `Operation` (the final opcode, a conversion included). The opcode comes from `OpcodeOf(operation, type)`: **an operation exists for a type exactly when `BE_PROGRAM_ROWS` has its row**, and the error of a missing one lists the types that have it, so a type that gains a row needs no change in the checker.

- **No implicit conversion.** Operands of `+ - * / %`, comparisons, `min`, `max`, `clamp`, `lerp` and the two values of `select` have one type; two types are an error at the second operand that names both and the hint `float(x)` / `int(x)`. The conversions are the functions `int`, `int64`, `float`, `double` (`int` is `int32_t`); a conversion to the type the operand has adds no node. `&&`, `||`, `!` and the condition of `select` need `bool`. The result is exactly the type the field has (`SameType` of the descriptors): there is no widening of the whole formula either.
- **Literals** have no type of their own: an integer literal becomes the type of the operand beside it, else the expected type when that is a number, else `int` (`int64` when it does not fit); a float literal is `float` or `double` and an error where an integer is needed. The operands that read the context are checked first, so a literal beside one takes its type whichever side it is on; a subtree of literals beside no such operand takes the expected number type, else `float` when it holds a float literal. A sign before a literal is part of the literal (`-2147483648` is an `int`). An integer or float that does not fit its type is an error. The argument of a conversion that is a literal is read as what it spells (a float literal as `double`, so `double(0.1)` is exact).
- **Types** are `ExprType`: a `ProgramType` and, for `Enum`, the descriptor. `==` and `!=` work for every type; ordering and arithmetic only where `OpcodeOf` has the row, else the error names the operator and the type and lists the types that have it (`Color + Color`, `title + title`, `position < position`). A bare pair of enumerators with no typed operand (`Fire != Earth`) is an unknown-name error.
- **Enum and string literals.** A bare name that is no level and no function is an enumerator when the other operand of `==` / `!=`, the other value of `select` or the expected type is an enum (case-sensitive, a level of the same name wins; the operands that read the context are checked first, so `Fire == ability.element` works); an unknown one lists the enumerators with a `did you mean`. It folds to a constant index. A string literal is an interned `PoolString` constant.
- **Components and `Pack`.** `.x` on a vector, `Quat` or `IVec2` and `.r` on a `Color` are `Extract`; of a slot that stores the component as the program computes with it (every type but `Color`) it is a slot at the component's byte offset, so `caster.velocity.x` is one `LoadSlotFloat`. `vec2`, `vec3`, `vec4`, `ivec2`, `quat` and `color(r, g, b, a)` pack; an argument is a `float`, for `ivec2` and `color` an `int`, and a literal takes it (`ivec2(1.5, 2)` is the float-literal error).
- **Mixed pairs and literals beside a vector.** Operands of one type, or a pair of `BE_PROGRAM_MIXED_ROWS`; any other pair is the error that names both types and lists the pairs. An integer or float literal beside a vector takes the scalar of the pair, in `*` and `/` only (`v * 2`, `2 * v`, `iv * 2`); `v + 1` is a type error. `vec3 * quat` is refused, `quat * vec3` rotates.
- **`at(i, e0, e1, ...)`** is an inline table (`kTableFunction`, no row of `kExprFunctions`: any number of arguments): `i` an `int`, every entry one type, the hint's (the operand beside it, else the field's) or the first typed entry's. The checker only types the entries (`TypedNode::entries`); the lowering refuses one that does not fold to a constant, and a constant table over a constant index folds by running its own `LoadTable`. Beside a name that reads the context a table must come second (`caster.element == at(i, Fire, Water)`): it has no type of its own.
- **Paths** are linked with `LinkSlot` for each program type in turn, so its messages (`did you mean`, the fields of the type, the declared levels) are the ones shown; a field of a type outside the set, and a bare level or function name, say what they are. A bare unknown name lists the levels and the functions. A path that names no field as a whole is retried as a field of a type with components plus one segment (`caster.velocity.x`): where the field stores the component as the program computes with it that is a slot at the component's offset, and a `Color` channel (a byte) and `.x` of an expression are an `Extract`.
- A division or modulo by a **literal** zero is an error at the divisor; every error is `{message, column of the node}`, and an expected type outside the program types (column 0) lists the types. The limit of 32 registers is the compiler's, not the checker's.

## Compiling

`CompileExpression(text, declaration, expected)` is parse, check, fold, lower; the answer is a `CompiledExpression` of one of three kinds, and `CompileValue<T>` makes the `Value<T>` of it (`Const`, `Slot` or `Program`). The type asked for is checked first (`CheckExpectedType`), so a field no formula can fill says so whatever the text. **Folding** runs a node whose operands are all constants through the interpreter on a one-instruction program, so the folded value is what the program would compute; there is no algebra (`a - a`, `x * 1` run), and a divisor that folds to zero is a run-time 0, not an error. A formula that folds to a constant is a `Constant` (the register image), one that is a single field a `Slot` (the path as written), so `expr="caster.attack"` loads and saves like `from`. **Lowering** is a recursive post-order walk: an operation writes into the register of its first operand and its other operands go into the registers above it, one after the other (`Pack` reads its up to four from `a` up), which are given back after the instruction, so a left-leaning chain needs two registers and a right-nested one a register per level. The 32-register limit is the lowering's error (column of the node that did not fit). The source text of the program is the text as written; the pool does not intern by it, and the slot offsets are part of the code, so one text under two declarations is two programs.

`FormatProgramError(text, error)` is `<message> (column N)`, the text around the column (a window for a long one, a byte that is not printable ASCII as `?`) and a caret line; an error without a column is the message alone.

## Loading and its errors

`Ser::DataAccessor<Value<T>>` (`ValueAccessor.h`) compiles `expr` under the innermost `ValueLinkScope` when the field is read; the compile runs once per load, never per `Evaluate`. A formula needs a declared context even when it is all constants. A compile error is reported through `IDeserializer::ReportError` under the field's `expr` key as `column N: <message>` and ends with the document name. It is not the caret block of `FormatProgramError`: the reader cuts a report at 256 bytes and turns newlines into `?`, so the column goes first and the message is the short form (`FormatProgramError` is for tools and tests that print an error alone). A failed load leaves the field as it was and adds nothing to the pool. Every limit (text, nesting, nodes, registers) and every type error is such a load error; hostile text is an error, never a crash.
