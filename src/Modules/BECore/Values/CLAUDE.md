# Values: data that is a literal or a read of a context

`Value<T>` (`Value.h`) is a field type for content: `damage="12"` is a literal, `<damage from="caster.attack"/>` reads the field `attack` of an object a game put into a context. A game changes a field from `int32_t` to `Value<int32_t>` and its content keeps loading. `T` is a `ValueType` (`ValueType.h`): a number, a bool, an enum, a `PoolString`, or a small trivially copyable object (`Vec3`, `Color`, a game's own `Point`). A `String`, a list, a map, an optional and a pointer are not value types: they own memory, so a slot of them is not a plain read.

## Kinds

`ValueKind`: `Const` (the literal), `Slot` (a field of a context object), `Program` (a compiled formula: `Programs/CLAUDE.md`). The literal is a plain member beside the slot, not a union, so every `Value` is a valid literal of its type, and a `Program` is the program's id plus its text in the two fields a `Slot` uses for its offset and path, so `sizeof(Value<float>)` stays 24 and a `Value` stays trivially copyable. `Get(const Context&)` returns `const T&` into the literal or into the context object: copy out what must outlive the object. It is a branch and an addition, with no lookup and no allocation; a formula has no object to point into, so `Get` of a `Program` asserts. **`Evaluate(const Context&)` returns `T` by value for every kind** (a `Get` copy for `Const` and `Slot`, a run of the program for a `Program`: its generated function when one is bound, else the interpreter, `Programs/Native/CLAUDE.md`): write `Evaluate` where the kind is not known. `Reads()` of a program is the mask of the levels its code loads from. Two values are equal when kind, id and text are. A `Value<T>` converts implicitly from `T`.

## Context

`Context` (`Context.h`) is a fixed array of `kMaxContextLevels` pointers, one per level; each points to a reflected object of the type `ContextDecl` gives that level. Nothing is copied into it: the game writes its plain fields and a value reads them where they are. The objects and the declaration outlive the context. A null level is an `ASSERT` in `Get`, not a branch. An object of a derived type is stored at its base subobject, because the offsets are those of the declared type (`Context::Set` does it when it knows the declaration).

`ContextDecl` holds the levels, each a name and a registered `TypeInfo` (`Add(name, typeName)` checks the name against `TypeRegistry`; `Add<T>(name)` is for code).

## Paths and linking

A path is `level.property.path` (`caster.position.x`). `LinkSlot` splits the level off, compiles the rest with `CompilePath` against the level's type and turns it into `SlotRef{level, offset}` once, at load. The path must be **fully fixed**: a list element, map value, optional or pointee needs the live object and is refused (`not_fixed`). The field's type must be the type asked for under `SameType`: no numeric conversion (an `int` field into `Value<float>` is refused), because a conversion is a cost on the common path and a hidden rule in data. Every refusal is a `LinkError` whose message names the path, the field and what is wrong: the declared levels with a `did you mean`, the fields of the type, both types of a mismatch. A formula reads a list of an object through `LinkList` (a path that ends in a list field) and `LinkElementField` (a field of an element, relative to the element's type) with the same messages; the loop itself is the machine of `Programs/Lists/` (`Lists/CLAUDE.md`).

`SameType` can tell `Vec2` from `Vec3` or `Rect` from `Vec4` only because an `Opaque` descriptor carries the size and a hash of the type's name (`Reflection/CLAUDE.md`, `TypeDesc`). Without it any opaque field would link as any opaque value and `Get` would read the wrong bytes: the identity is what makes a `Slot` type safe.

## Loading

`ValueAccessor.h` is `Ser::DataAccessor<Value<T>>`; `Value.h` includes it, so a generated `.gen.hpp` that names a `Value` field sees it. Grammar: the plain attribute `damage="12"` and `<damage value="12"/>` are a `Const`; `<damage from="caster.attack"/>` is a `Slot`. An object or opaque `T` keeps its own form as the literal (`<pos x=".." y=".." z=".."/>`) and `<pos from="caster.position"/>` reads. `value` beside `from` is an error. `<damage expr="caster.attack * 2"/>` is a formula, compiled against the declaration of the scope as `from` is linked (a formula of constants only needs a declared context too); one that folds to a constant or to one field (`expr="2 * 6"`, `expr="caster.attack"`) loads as that `Const` or `Slot` and saves as such, a real program saves as `<damage expr="..."/>` with its text as written. `expr` beside `from` or `value`, or on a type no program computes, is an error. `<damage><tree type="CalcBinary" op="Mul">...</tree></damage>` is the same formula as a tree of node classes (`Nodes/CLAUDE.md`): it is built into the text it prints and compiled as `expr` is, so the same value comes out (`==`), and it saves as `expr`. `tree` beside `expr`, `from` or `value` is an error that names both; `kind="Program"` may stand beside it. An error of the tree is reported under `tree` with the node path, one of the checker with its column in the **printed** text and that text after it. A program computes `bool`, `int32_t`, `int64_t`, `float`, `double`, `Vec2`, `Vec3`, `Vec4`, `IVec2`, `Quat`, `Color`, any `CORE_ENUM` and `PoolString` (`expr` is read before the literal of an object type, so `<aim expr="caster.velocity * 2"/>` is a formula, never `<aim x= y= z=/>` with a stray key); **and every type a game registered** (`ProgramDomain`, `Programs/Domain/CLAUDE.md`: a `Value<CellMask>` takes `expr` as well, its literal keeps the object form the type's `Serialize` writes); `Rect` and an unregistered type keep `Const` and `Slot` (the registry is filled before the content loads). `tree` has no node classes for a game's operations. `kind` (`Const`, `Slot` or `Program`) is an optional key that XML and binary accept; no writer emits it. The keys `kind`, `from`, `value`, `expr` and `tree` are reserved: an object type used as a `Value<T>` literal (a game's own `Point`) cannot have an attribute of one of these names. `Save` writes a scalar `Const` as the plain attribute, so a file written before the field became a `Value` loads and saves as before: **no migration step and no `kContentVersion` bump is needed to turn a field into a `Value`**. Binary and JSON have the same shapes; an unknown `kind` is an error in every format. A formula's error is reported under the field's `expr` as `column N: <message>` and ends with the document name (the reader cuts a report at 256 bytes, so the column comes first and a long message, the list of functions of an unknown name, is shortened to keep the name). A load that fails leaves the field as it was and reports under the field's own path and line (`IDeserializer::ReportError`). `kind`, `from`, `value`, `expr` and `tree` are the known keys for strict mode and the diagnostics of `XmlDeserializer`; any other key is an unknown key those diagnostics report.

`ValueLinkScope` (RAII) says which `ContextDecl` the `from` of a load is linked against. It is a stack **per thread**: the accessor has no parameter to carry a declaration through the generated code, and two threads loading at once must never see each other's context. A `from` read where no scope has a declaration is a load error. `ValueLinkScope(const ContextDecl&)` is a declaration from code (a borrowed reference); `ValueLinkScope(StringView documentName)` is an empty scope that the document fills with its own `<context>`, and the name ends the scope's messages (`... (document 'X')`) so an error read alone names the file. `Current()` is the declaration of the **innermost scope that has one**: an empty scope opened inside a caller's scope does not hide the caller's declaration, a `<context>` shadows it for the rest of that document. `MakeFromConfig` opens the named scope (`Config/CLAUDE.md`); any other loader of a document with values opens its own, since no scene loader of the engine does yet.

## Named tables

`ByLevel('FireballDamage', ability.level)` reads a table of numbers the game supplies: `IValueTables` (`ValueTables.h`: `Find(name)`, `Names` for the error's list) on the scope (`ValueLinkScope::UseTables`; `Tables()` is the innermost scope's that has one, per thread as the declaration is), or `CompileOptions::tables` outside a document. `ValueTableSet` keeps tables in memory. **The entries are copied into the program while the formula loads**, so the provider may die and a table that changes later changes no program: reload the content. The index is plain and 0-based (`ability.level - 1` for a table whose first entry is level 1) and clamps to the ends. The result is `int`, `int64`, `float` or `double`, the type beside it or of the field, else `double`; an integer type needs whole numbers in range (the error names the table and entry). Any other type is an error: `at(i, ...)` is for them. No provider, an unknown name (with the names), an empty table and one over `kMaxTableEntries` are load errors.

## Formulas outside a file

`CompileValue<T>(text, declaration, options)` (`Programs/ProgramCompiler.h`, includable alone; the caller includes `Value.h` where it instantiates it) is what code without a document uses, for a condition (`CompileValue<bool>`) or an argument of any program type: it gives the `Value<T>` the accessor stores for `expr` (`Kind()` tells `Const`, `Slot` or `Program`), or a `ProgramError` with the column in the text. It is for load time: it allocates and adds to the pool, and the declaration is always explicit, so there is no overload without one.

## The `<context>` element

A reflected document type that declares a context has a field `ContextDecl context;` **before** its `Value` fields: a generated `Deserialize` reads fields in declaration order, and a `from` read before the declaration is the "no context is declared" error. `ContextDeclAccessor.h` (included at the bottom of `Context.h`) is its `DataAccessor`. List form, read and written by every format: `<context><level name="caster" type="UnitStats"/>...</context>`. Shorthand, text formats only (it needs `IDeserializer::AttributeNames`): `<context caster="UnitStats" cast="CastInfo"/>`, each attribute a level in document order, before the `level` children. `Save` writes the list form. A load that fails (unknown type name with the registered ones it can offer, a duplicate level, a ninth, an empty name or type, a second `<context>` in one scope, no scope open) reports through `ReportError`, leaves the field and **installs nothing**: a level's refusal is under the level's `name` or `type` key (the attribute in the shorthand), a second `<context>` and "no scope open" under the `context` key itself. An empty `<context/>` is not a refusal: it declares no level, so it shadows the declaration of a scope around it (every `from` after it is refused) and closes the scope to a later `<context>` like any other declaration. It is how a document says it reads no context. The scope keeps its own copy of what was read (`ContextDecl` is a few names and pointers), because the document object may move; a `Context` built from the document's field and the scope's copy describe the same levels.

## Versions

`Context::Set(level, object, const uint64_t* version)`: the owner of the object bumps `*version` when it changes (a `uint64_t` member the owner increments in each mutator); no pointer is version 0. `Value<T>::Reads()` is the `LevelMask` (a bit per level) of the level a `Slot` reads, empty for a `Const`; `ValueDependencies` collects the mask of a set of values. `Context::VersionKey(mask)` folds, per level, the counter's value, the count of `Set` calls and the addresses of the object and of the counter into one `uint64_t`: it differs after any one counter moved or a level was given another object or another counter, and means nothing else (compare for equality only). A context rebuilt each frame over the same objects and counters gives the same key; an object freed and another built at the same address with a counter at the same address and value is the owner's trap (it bumps the counter when it replaces an object). `IsVersioned(mask)` is true when every level of the mask has an object and a counter. **A counter must only grow**, or a change can be folded back to an earlier key. Versions are per level, not per field. `Get` has no part in it.

## Cache

`CachedValue<T>` (`CachedValue.h`, a class of its own: `Value<T>` stays trivially copyable) keeps the last result of a `Program` and the `VersionKey` of its `Reads()`; `Evaluate(context)` costs one key and one comparison when nothing changed, and a context rebuilt each frame over the same objects and counters hits. A `Const` and a `Slot` are delegated. A result that is not a `ValueType`, or comes from several values and C++, is a `Derived` (`Derived/CLAUDE.md`). It caches only when `Context::IsVersioned(Reads())`: a program that reads a level with no counter runs on every call (`Computations()` shows it; a debug build logs it once per instance); one with no `Reads()` runs once until `Invalidate` / `Reset`. Not thread-safe, not a field type (nothing is saved): the code that evaluates a content `Value<T>` owns the `CachedValue`. **It is not a speed-up for short formulas**: a hit costs a `VersionKey` (a few dependent mixes per level), and on the machine of the benchmark a hit over two levels (about 11 ns) costs as much as running the five-operation `int32_t` formula (about 9 ns) and a little less than the `Vec3` one (about 13 ns); it pays for formulas longer than about ten nanoseconds, or when the result is a costly type to rebuild.

## Benchmark

`tests/BECore/ValueBenchTest.cpp` times `Get` (plain field, `Const`, `Slot`, a chain of virtual reads) and, for an `int32_t` and a `Vec3` formula, the cases `formula_plain` (C++), `formula_tree` (hand-written virtual nodes), `formula_program` and `formula_unfused` (the interpreter: the test switches generated code off for them), `formula_native` (the same program through its generated function), `formula_run` (`Run` called directly, with no look for a bound function in `Evaluate`: against `formula_program` it is what that look costs), `formula_cached` and the `madd_*` cases of the fusible `slot * k + b`, and over a game's registered type the `mask_*` cases (below); every case's sum must equal the plain one (bit for bit for `Vec3`) and a smoke run checks the opcodes and that the generated function is bound, so a case cannot measure the same code twice. `BE_VALUE_BENCH=<n>` prints; the set of `.claude/rules/perf-project.md` (`value-get`) has a metric per line, none gating, and the baseline is the owner's. Measured on one machine (Release, other loops running): a program costs about 15 times (`int32_t` and `Vec3`) the plain C++ and about 2.3 times the virtual tree, so **the interpreter is slower than a tree of virtual nodes on a formula of five operations**; a program of one fused instruction already costs about 5 to 6 ns, so the cost sits in `Run` before the first instruction, not in the instructions. Fusion gains 1.37 times on `slot * k + b` and nothing on a formula of another shape. Generated code (`Programs/Native/CLAUDE.md`), Release, lowest of six: the formula runs 6.5 times (`int32_t`) and 6.8 times (`Vec3`) faster than the interpreter and costs about 2.3 times the plain C++; `slot * k + b` 3.7 and 3.6 times faster and 3.9 and 2.6 times the plain C++. The 32-byte registers of the domain types (`Programs/CLAUDE.md`, "The frame and the pool") cost the interpreter about 12 % on `int32_t` (`formula_program` 10.6 to 11.9 ns, measured before and after, lowest of four); `Vec3` and the generated code stayed within the noise. The look for a bound function in `Evaluate` costs 1 to 3 ns (`formula_run` 11.1 and `formula_program` 11.9 for `int32_t`, 11.7 and 15.0 for `Vec3`), not nothing: `ProgramPool::Native` and `Get` are two out-of-line calls. Over a game's registered type (`Programs/Domain/CLAUDE.md`; the toy 256-bit mask, `popcount(or_mask(and_mask(a.mask, shift(b.mask, East)), c.mask)) > 3`, five `CallDomain` instructions over three objects; Release, lowest of six, load about 7 from other loops): C++ over the mask 1.2 ns (`mask_plain`), the interpreter 27 ns (`mask_program`, 22 times; `mask_run` 26), generated code 12 ns (`mask_native`, 10 times plain, 2.2 times faster than the interpreter). **A formula over a registered type is not as fast as hand-written C++, not even as generated code**: the compiler folds the C++ into a few inlined instructions over four words, while each operation of a formula is an indirect call of a registered function (the game registers at run time, so the generated file knows only an id and cannot inline it) over 32-byte images copied through the frame, about 2.4 ns per call in generated code and 5 ns in the interpreter. Formulas with loops over lists (`list_count`, `list_any`, `list_sum`, `list_nested`, 14 tiles and 4 to 8 sets of 4 tiles; Release, lowest of three, ns per `Get`: plain C++ / interpreter / generated code): 1.3 / 47 / 9.8 for `count`, 1.4 / 68 / 9.4 for a full `any`, 0.5 / 8.4 / 2.5 when the first element answers, 1.2 / 47 / 9.8 for `sum`, 2.7 / 123 / 24 for the nested `sum` of `count`. The interpreter takes about 3.4 ns per element (about 40 times a vectorised plain loop), generated code about 0.7 ns (5 to 9 times). Use a program for data that is content and a formula the game cannot compile in; do not put one in a loop that runs per cell: a rule applied to every cell is a mask operation written in C++ and called once. The `trigger_*` cases time a script (a timer, a flag, a mask and two commands) over one cell against the same trigger in C++ (Release, lowest of three, other loops running): 4.4 ns against 46 ns, about 10 times, each with the copy of the cell and a digest of the result; a script is for content that changes per game, not a loop over a board.

## Scripts

`Effects/CLAUDE.md`: a **script** is statements that store into whole fields of writable levels (`Context::SetMutable`), branch and `emit` host commands, written as text (`cell.timer -= 1; if (...) { ... }`) and compiled with the formulas' own type rules. A field `EffectScript` loads as `<onTick script="..."/>` against the document's `<context>` and the host's `ValueLinkScope::UseWriteTargets`. Formulas stay pure; there are no loops or locals, and C++ work is a command the host handles.

## Not here

A file format for named tables (the game supplies a provider). The explanation of a value (why it is what it is): a later entry (`data-values-explain`). A screen's derived texts, lists and layouts are `Derived` (`Derived/CLAUDE.md`). No scene loader of the engine opens a scope, so a `Value` field in a component of a scene or node file needs the entry that wires them. Reading or writing a `Value` field by name through the control API treats it as an opaque value, not a leaf.
