# Values: data that is a literal or a read of a context

`Value<T>` (`Value.h`) is a field type for content: `damage="12"` is a literal, `<damage from="caster.attack"/>` reads the field `attack` of an object a game put into a context. A game changes a field from `int32_t` to `Value<int32_t>` and its content keeps loading. `T` is a `ValueType` (`ValueType.h`): a number, a bool, an enum, a `PoolString`, or a small trivially copyable object (`Vec3`, `Color`, a game's own `Point`). A `String`, a list, a map, an optional and a pointer are not value types: they own memory, so a slot of them is not a plain read.

## Kinds

`ValueKind`: `Const` (the literal), `Slot` (a field of a context object), `Program` (a compiled formula: `Programs/CLAUDE.md`). The literal is a plain member beside the slot, not a union, so every `Value` is a valid literal of its type, and a `Program` is the program's id plus its text in the two fields a `Slot` uses for its offset and path, so `sizeof(Value<float>)` stays 24 and a `Value` stays trivially copyable. `Get(const Context&)` returns `const T&` into the literal or into the context object: copy out what must outlive the object. It is a branch and an addition, with no lookup and no allocation; a formula has no object to point into, so `Get` of a `Program` asserts. **`Evaluate(const Context&)` returns `T` by value for every kind** (a `Get` copy for `Const` and `Slot`, a run of the interpreter for a `Program`): write `Evaluate` where the kind is not known. `Reads()` of a program is the mask of the levels its code loads from. Two values are equal when kind, id and text are. A `Value<T>` converts implicitly from `T`.

## Context

`Context` (`Context.h`) is a fixed array of `kMaxContextLevels` pointers, one per level; each points to a reflected object of the type `ContextDecl` gives that level. Nothing is copied into it: the game writes its plain fields and a value reads them where they are. The objects and the declaration outlive the context. A null level is an `ASSERT` in `Get`, not a branch. An object of a derived type is stored at its base subobject, because the offsets are those of the declared type (`Context::Set` does it when it knows the declaration).

`ContextDecl` holds the levels, each a name and a registered `TypeInfo` (`Add(name, typeName)` checks the name against `TypeRegistry`; `Add<T>(name)` is for code).

## Paths and linking

A path is `level.property.path` (`caster.position.x`). `LinkSlot` splits the level off, compiles the rest with `CompilePath` against the level's type and turns it into `SlotRef{level, offset}` once, at load. The path must be **fully fixed**: a list element, map value, optional or pointee needs the live object and is refused (`not_fixed`). The field's type must be the type asked for under `SameType`: no numeric conversion (an `int` field into `Value<float>` is refused), because a conversion is a cost on the common path and a hidden rule in data. Every refusal is a `LinkError` whose message names the path, the field and what is wrong: the declared levels with a `did you mean`, the fields of the type, both types of a mismatch.

`SameType` can tell `Vec2` from `Vec3` or `Rect` from `Vec4` only because an `Opaque` descriptor carries the size and a hash of the type's name (`Reflection/CLAUDE.md`, `TypeDesc`). Without it any opaque field would link as any opaque value and `Get` would read the wrong bytes: the identity is what makes a `Slot` type safe.

## Loading

`ValueAccessor.h` is `Ser::DataAccessor<Value<T>>`; `Value.h` includes it, so a generated `.gen.hpp` that names a `Value` field sees it. Grammar: the plain attribute `damage="12"` and `<damage value="12"/>` are a `Const`; `<damage from="caster.attack"/>` is a `Slot`. An object or opaque `T` keeps its own form as the literal (`<pos x=".." y=".." z=".."/>`) and `<pos from="caster.position"/>` reads. `value` beside `from` is an error. `<damage expr="caster.attack * 2"/>` is a formula, compiled against the declaration of the scope as `from` is linked (a formula of constants only needs a declared context too); one that folds to a constant or to one field (`expr="2 * 6"`, `expr="caster.attack"`) loads as that `Const` or `Slot` and saves as such, a real program saves as `<damage expr="..."/>` with its text as written. `expr` beside `from` or `value`, or on a type no program computes, is an error. `<damage><tree type="CalcBinary" op="Mul">...</tree></damage>` is the same formula as a tree of node classes (`Nodes/CLAUDE.md`): it is built into the text it prints and compiled as `expr` is, so the same value comes out (`==`), and it saves as `expr`. `tree` beside `expr`, `from` or `value` is an error that names both; `kind="Program"` may stand beside it. An error of the tree is reported under `tree` with the node path, one of the checker with its column in the **printed** text and that text after it. A program computes `bool`, `int32_t`, `int64_t`, `float`, `double`, `Vec2`, `Vec3`, `Vec4`, `IVec2`, `Quat`, `Color`, any `CORE_ENUM` and `PoolString` (`expr` is read before the literal of an object type, so `<aim expr="caster.velocity * 2"/>` is a formula, never `<aim x= y= z=/>` with a stray key); `Rect` and a game's own types keep `Const` and `Slot`. `kind` (`Const`, `Slot` or `Program`) is an optional key that XML and binary accept; no writer emits it. The keys `kind`, `from`, `value`, `expr` and `tree` are reserved: an object type used as a `Value<T>` literal (a game's own `Point`) cannot have an attribute of one of these names. `Save` writes a scalar `Const` as the plain attribute, so a file written before the field became a `Value` loads and saves as before: **no migration step and no `kContentVersion` bump is needed to turn a field into a `Value`**. Binary and JSON have the same shapes; an unknown `kind` is an error in every format. A formula's error is reported under the field's `expr` as `column N: <message>` and ends with the document name (the reader cuts a report at 256 bytes, so the column comes first). A load that fails leaves the field as it was and reports under the field's own path and line (`IDeserializer::ReportError`). `kind`, `from`, `value`, `expr` and `tree` are the known keys for strict mode and the diagnostics of `XmlDeserializer`; any other key is an unknown key those diagnostics report.

`ValueLinkScope` (RAII) says which `ContextDecl` the `from` of a load is linked against. It is a stack **per thread**: the accessor has no parameter to carry a declaration through the generated code, and two threads loading at once must never see each other's context. A `from` read where no scope has a declaration is a load error. `ValueLinkScope(const ContextDecl&)` is a declaration from code (a borrowed reference); `ValueLinkScope(StringView documentName)` is an empty scope that the document fills with its own `<context>`, and the name ends the scope's messages (`... (document 'X')`) so an error read alone names the file. `Current()` is the declaration of the **innermost scope that has one**: an empty scope opened inside a caller's scope does not hide the caller's declaration, a `<context>` shadows it for the rest of that document. `MakeFromConfig` opens the named scope (`Config/CLAUDE.md`); any other loader of a document with values opens its own, since no scene loader of the engine does yet.

## Named tables

`ByLevel('FireballDamage', ability.level)` reads a table of numbers the game supplies: `IValueTables` (`ValueTables.h`: `Find(name)`, `Names` for the error's list) on the scope (`ValueLinkScope::UseTables`; `Tables()` is the innermost scope's that has one, per thread as the declaration is), or `CompileOptions::tables` outside a document. `ValueTableSet` keeps tables in memory. **The entries are copied into the program while the formula loads**, so the provider may die and a table that changes later changes no program: reload the content. The index is plain and 0-based (`ability.level - 1` for a table whose first entry is level 1) and clamps to the ends. The result is `int`, `int64`, `float` or `double`, the type beside it or of the field, else `double`; an integer type needs whole numbers in range (the error names the table and entry). Any other type is an error: `at(i, ...)` is for them. No provider, an unknown name (with the names), an empty table and one over `kMaxTableEntries` are load errors.

## Formulas outside a file

`CompileValue<T>(text, declaration, options)` (`Programs/ProgramCompiler.h`, includable alone; the caller includes `Value.h` where it instantiates it) is what code without a document uses, for a condition (`CompileValue<bool>`) or an argument of any program type: it gives the `Value<T>` the accessor stores for `expr` (`Kind()` tells `Const`, `Slot` or `Program`), or a `ProgramError` with the column in the text. It is for load time: it allocates and adds to the pool, and the declaration is always explicit, so there is no overload without one.

## The `<context>` element

A reflected document type that declares a context has a field `ContextDecl context;` **before** its `Value` fields: a generated `Deserialize` reads fields in declaration order, and a `from` read before the declaration is the "no context is declared" error. `ContextDeclAccessor.h` (included at the bottom of `Context.h`) is its `DataAccessor`. List form, read and written by every format: `<context><level name="caster" type="UnitStats"/>...</context>`. Shorthand, text formats only (it needs `IDeserializer::AttributeNames`): `<context caster="UnitStats" cast="CastInfo"/>`, each attribute a level in document order, before the `level` children. `Save` writes the list form. A load that fails (unknown type name with the registered ones it can offer, a duplicate level, a ninth, an empty name or type, a second `<context>` in one scope, no scope open) reports through `ReportError` under the level's path, leaves the field and **installs nothing**. The scope keeps its own copy of what was read (`ContextDecl` is a few names and pointers), because the document object may move; a `Context` built from the document's field and the scope's copy describe the same levels.

## Versions

`Context::Set(level, object, const uint64_t* version)`: the owner of the object bumps `*version` when it changes (for example `TableSession::Version()`); no pointer is version 0. `Value<T>::Reads()` is the `LevelMask` (a bit per level) of the level a `Slot` reads, empty for a `Const`; `ValueDependencies` collects the mask of a set of values. `Context::VersionKey(mask)` folds, per level, the counter's value, the count of `Set` calls and the addresses of the object and of the counter into one `uint64_t`: it differs after any one counter moved or a level was given another object or another counter, and means nothing else (compare for equality only). A context rebuilt each frame over the same objects and counters gives the same key; an object freed and another built at the same address with a counter at the same address and value is the owner's trap (it bumps the counter when it replaces an object). `IsVersioned(mask)` is true when every level of the mask has an object and a counter. **A counter must only grow**, or a change can be folded back to an earlier key. Versions are per level, not per field. `Get` has no part in it.

## Cache

`CachedValue<T>` (`CachedValue.h`, a class of its own: `Value<T>` stays trivially copyable) keeps the last result of a `Program` and the `VersionKey` of its `Reads()`; `Evaluate(context)` costs one key and one comparison when nothing changed, and a context rebuilt each frame over the same objects and counters hits. A `Const` and a `Slot` are delegated. It caches only when `Context::IsVersioned(Reads())`: a program that reads a level with no counter runs on every call (`Computations()` shows it; a debug build logs it once per instance); one with no `Reads()` runs once until `Invalidate` / `Reset`. Not thread-safe, not a field type (nothing is saved): the code that evaluates a content `Value<T>` owns the `CachedValue`.

## Benchmark

`tests/BECore/ValueBenchTest.cpp` times `Get` (plain field, `Const`, `Slot`, a chain of virtual reads) and one formula as plain C++ against a compiled program; `BE_VALUE_BENCH=<n>` prints, and the set of `.claude/rules/perf-project.md` (`value-get`) runs it. The baseline is the owner's.
