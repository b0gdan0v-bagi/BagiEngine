# Memory: arenas and pools

Arena allocators for per-frame and per-task scratch data (a bump pointer over a few big blocks, freed all at once) and pools of fixed-size blocks for small objects that live and die one by one ("Pools", below). **Not a replacement of the global allocator:** `operator new` stays as it is (the vendored SDL, ImGui and stb keep `malloc`), and an arena or a pool only serves the code that asks for it.

## The registry (`ArenaStats.h`)

Every arena publishes its counters (capacity, used, peak, overflows, chunks, resets) into a static table of `ArenaStats::kMaxArenas` slots, `constinit` like `AllocTracker`: an arena on any thread claims a slot without `CoreManager`, a lock or an allocation. A full table is not an error: that arena runs uncounted.

- **Why a table and not a list of arenas:** a reader (`GetArenaStats()`, `GetArenaTotals()`) must never hold a pointer to an arena, because a thread's scratch arena ends with its thread. The reader copies numbers out of slots; a slot that is released or reused while it is copied is dropped from that snapshot (the `epoch` counter), so no entry is torn.
- **Single writer:** the arena that claimed a slot is its only writer, so the publish calls are a relaxed load and store (no read-modify-write on the bump path). Only `ArenaStatsSlot::Claim` and `Release` synchronise.
- `GetArenaStats()` allocates (a `Vector`): never on a frame path. `GetArenaTotals()` does not.
- The arena name is a string literal; the registry keeps the pointer.

## LinearArena (`LinearArena.h`)

- **Chunks:** the first chunk is a buffer the caller gives or a heap block made by the first `Allocate`; later chunks come from `::operator new` (not `malloc`, so `AllocTracker` shows the few big blocks). A request that does not fit goes to the next chunk kept from an earlier round, else to a new one of `max(chunkSize, size + alignment)` bytes.
- **Overflow:** a new chunk after the first counts one overflow and is never fatal, a full caller's buffer included (heap fallback). The lazily made first chunk is not an overflow. `Reset()` and `Rewind()` keep every chunk (a chunk is reused without a new overflow); `Release()` frees all but the first.
- **No destructors run on `Reset()`:** `Allocate<T>` is `static_assert`ed trivially destructible and returns uninitialised storage. A container on the default allocator that lives in the arena must be destroyed first.
- **Not thread-safe;** only the counters are read across threads. A zero-size request gets one byte, so addresses stay distinct.
- **Marks:** `GetMark()` / `Rewind(mark)` undo in reverse order; a mark from before `Reset()` or `Release()` asserts in Debug (a generation number) and the rewind does nothing. Nothing is allocated and nothing is registered before the first `Allocate`, so an arena can be a `constinit` object.

## Poisoning (`ArenaPoison.h`)

Memory an arena took back (`Reset`, `Rewind`) and fresh chunks are marked in one place: Debug (asserts on) fills `kFreedPattern`, an ASan build poisons the range, Release does nothing. Under ASan every byte past the bump pointer stays poisoned and an allocation unpoisons exactly its bytes (alignment gaps stay poisoned), so a pointer used after `Reset` is reported where it is read.

## Scratch arena and scopes (`ScratchArena.h`)

`ScratchArena::Get()` is the calling thread's arena, a `constinit thread_local LinearArena` and not a `CoreManager` service: it works on any thread, in a static initialiser or before the engine starts, and allocates nothing until its first `Allocate`. The thread's end frees its chunks and releases its stats slot (all scratch arenas are named `Scratch`, one entry per live thread that used it).

`ScratchScope` takes a mark and rewinds in its destructor; scopes nest like locals. **Rules:** memory of a scope must not outlive it (not returned, not stored in a longer-lived container) and must not cross to another thread; a scope ends on the thread that made it (Debug asserts). Nothing from the arena is destroyed on rewind (`LinearArena`, "No destructors").

## ArenaAllocator (`ArenaAllocator.h`)

The EASTL allocator over a `LinearArena&`, behind `ArenaVector<T>` and `ArenaString` (declared in `Types/`, which keeps `eastl::` and the arena headers out of the PCH). Another container takes it as its allocator parameter (`eastl::hash_map<K, V, Hash, Equal, ArenaAllocator>`).

- **`deallocate` does nothing,** so a vector that grows by doubling leaves every old block in the arena until `Reset()` or the scope's rewind: `reserve` first when the size is known. The container's destructor frees nothing, but a container of non-trivial elements still runs their destructors.
- **A default-constructed allocator binds to the thread's `ScratchArena`** (EASTL needs a default constructor, and builds one from a name string, which is not kept). Such a container belongs to the scope that is alive when it is made and must not cross threads; a container of a longer life takes its arena explicitly.
- **Equality is by arena.** `offset` of the aligned `allocate` is ignored (EASTL passes 0).

## Frame arena (`FrameArena.h`, `FrameAllocator.h`)

`FrameArena::Get()` is the calling thread's `LinearArena` named `Frame` (a `constinit thread_local`, like the scratch arena: any thread, no `CoreManager`, nothing allocated before the first `Allocate`), and `FrameVector<T>` takes its memory from it. It is for memory that is **handed on or kept for the rest of the frame** and given back all at once after the present. One global frame number; `Application::RunFrame` calls `FrameArena::Advance()` once per frame that ran (a held frame too, not the manual-clock idle pass), after `frameStats.EndFrame` (which reads the use of the whole frame) and the frame-end hooks.

- **Reset:** `Advance()` resets the main thread's arena at once. **Every other thread resets lazily:** `Get()` compares the frame the arena was last used in with the current number and resets first when they differ. An arena may be reset only by its owner, a pool thread cannot be reached without a lock or a hook in the pool, and a sleeping thread holds nothing it must give back (its chunks stay for its next frame). So the counters of an idle thread's arena show the last frame it worked in, and a use after the frame ended on a thread that has not called `Get()` since is caught by the stamp below, not by the poison, until its next `Get()`.
- **Stamp (Debug):** a `FrameAllocator` records the frame and the thread in its constructor, and `allocate` asserts both are still current: a `FrameVector` kept in a member and grown in a later frame, or used on another thread, trips it. Release has no stamp and no cost. `deallocate` does nothing: `reserve` first.
- **Task rule:** memory of the frame arena is valid until the end of the frame and is never kept in a member. **A task that can outlive the frame (a delayed or background task, anything `TaskManager` keeps past the call) must not use the frame arena or a `FrameVector`:** its pool thread resets its arena at the next `Get()` of a later frame, under the task's data. A task that finishes in the frame that made it may use its own thread's arena; memory made on one thread is never read by another. The stamp catches a container grown late or elsewhere; there is **no check at the capture of a task** and no hook in `TaskSystem`: a captured container is invisible to a template, and a check would cost the hot path.
- **Chunk and overflow:** `kChunkSize` is not a limit. A frame that needs more takes a further chunk, counts one overflow for it **the first time** and keeps it, so a steady frame of any size counts nothing and allocates nothing after its first frames; the constant only says how many chunks a typical screen needs. A thread that never calls `Allocate` holds no chunk and has no `Frame` entry. Read the use in the `Frame` entry of `frame_stats` `arenas` (`used` is the live number, 0 right after the reset; `peak`, `overflows`).
- **In use:** the box mesh of a `UIElement` (`UIElement::DrawBoxIn`, two `FrameVector`s handed to `DrawGeometry`). It is the biggest user: every box with a blurred shadow or glow builds a large mesh and the lists grow by doubling, so a frame holds the sum of the meshes of all the boxes of the screen; a screen with no box effect uses none. The layout and text temporaries (`UITreeLayout`, `UILayout`, `TextLayout`) die inside their call and are on the scratch arena. **Stays on the heap:** the SDL backend's `_geometry*` scratch (a member of steady capacity: nothing to give back), `TextLayoutResult` and the caches (they live across frames). `IRenderer` has no draw list: a backend submits each call at once.
- **Which arena:** `ScratchScope` for what dies inside the call and may nest (a recursion's lists are given back as it unwinds); the frame arena for memory that is returned or stored until the frame ends (it would keep every nested call's lists to the end of the frame); a heap container for what lives longer.

## Pools

For small objects made and freed one at a time (a refcounted state, a node): a freed block is the next one handed out, with no heap call and no fragmentation. **Pages** (about 16 KB, `BlockPool::kTargetPageBytes`) come from `::operator new`, so `AllocTracker` sees a few big blocks and not each object, and **are kept until the pool is destroyed**: a pool's memory follows its peak, never shrinks. Block size and alignment are fixed per pool; the block is rounded up to the alignment and to two words (the free-list link and its mark).

- **`BlockPool`** (`BlockPool.h`): an intrusive free list in front of a bump over the newest page. Not thread-safe. Nothing is allocated or registered before the first `Allocate`, so a pool can be `constinit`. `Allocate` never returns null. Debug (asserts on) fills a freed block with `ArenaPoison::kFreedPattern` except its link and mark and asserts a **double free**, a **pointer that is no block of this pool**, and a **write after free** (the pattern is checked at the next `Allocate`); an ASan build poisons freed and never-used blocks, so a use after free is reported where it happens. Release does none of it. A pool that dies with live blocks is a bug (Debug asserts).
- **`ConcurrentBlockPool`** (`ConcurrentBlockPool.h`): for objects freed on another thread than the one that made them. A central `BlockPool` under a `Mutex`, and per thread and pool a short free list (`kCacheBatch` blocks move at a time, so the lock is taken once per batch and a block freed by another thread flows back through the central list: pages do not grow in a producer-consumer pattern). The hot path takes no lock. A thread's end gives its lists back; `DrainThreadCache()` does it by hand. **Lifetime rule:** a pool may die while another thread still lists blocks of it; the list is told apart by a pool id that is never reused (also from a new pool at the same address) and dropped untouched. The lock of that decision is taken only by a pool's destructor and by a spill, never on the hot path.
- **Opt-in** (`Pooled.h`): `BE_POOLED(T)` written in the **public** section of the class body declares class-scope `operator new` / `operator delete` (and the placement form, which a class-scope `new` would hide), so `New<T>`, `new T` and the `delete this` of the RefCounted bases reach the pool with no change at a call site. `T::PooledPool()` is the pool; its name in the counters is the macro's argument. **Choose `BE_POOLED` by default** (any thread may free). `BE_POOLED_SINGLE_THREAD(T)` (`SingleThreadBlockPool.h`) is a lock-free list and fits only objects whose whole life is on one thread; Debug asserts that every call runs on the thread of the first one, Release trusts the contract. An over-aligned `T` is a `static_assert`.
- **Derived classes:** both operators are told apart by the size they get: only `size == sizeof(T)` goes to the pool, a larger derived class uses `::operator new` / `delete` (and a derived class that opts in itself gets its own pool).
- **Type pools are immortal** (a `constinit` static in an `Immortal<T>`, `Immortal.h`, whose destructor never runs; the lifetime lock of `ConcurrentBlockPool.cpp` is one too): a static destructor may free a pooled object after the pool's own destruction and would write into freed pages. The pages stay reachable from the static, so leak checkers stay quiet.
- **Counters:** `PoolStats.h` is the registry of the arenas' shape (a `constinit` table of `PoolStats::kMaxPools` slots; readers copy numbers; a full table runs that pool uncounted): `name, blockSize, live, peak, pages, pageBytes, allocations`. `GetPoolStats()` allocates; `GetPoolTotals()` does not. `AllocTracker::GetPoolStats()` forwards it; `FrameStats` takes `poolLiveBlocks` and `poolPageBytes` at `EndFrame`; `frame_stats` answers them per frame and a top-level `pools` array (`name, blockSize, live, peak, pages, allocations`). **A `BlockPool` counts on every call. A `ConcurrentBlockPool` counts on a shard per thread and publishes to the registry at every refill and spill, every `kPublishEvery` calls that hit a list, and by `DrainThreadCache()` (which publishes the pools the calling thread keeps a list for) and at a thread's end:** the registry lags by up to that many calls per thread and `peak` is the largest published `live`; `GetLiveCount()` is exact when no other thread allocates or frees during the call. A test that reads the registry drains first. **Pooled blocks are invisible to the allocation counters and to `zone_allocs`** (a block never reaches `operator new`); their pages are not: the pool counters are where pooled objects are read.
- **Cost** (`ConcurrentBlockPoolCostTest`, a `DISABLED_` benchmark in the perf set, `.claude/rules/perf-project.md`): allocate and free of a block against `new` and `delete`, on one and on four threads. Counting on one atomic that every thread adds to made four threads far slower than `new`: the shards are why it does not.
- **In use:** `BE_POOLED`: `CancellationToken::State` (the last holder may be any thread); the `TaskHandle` and the frame of every task up to 1 KiB (a bigger frame stays on the heap) come from the size classes `Task memory <size>` of `TaskSystem/TaskMemory` (`TaskSystem/CLAUDE.md`, "Memory of tasks"; not a macro: frames have many sizes). `BE_POOLED_SINGLE_THREAD`, for types of a main-thread-only contract whose Debug runs (the suites and the control smoke) never tripped the assert: `SceneNode`, `TransformComponent`, `SpriteRendererComponent`, `TweenHandle`, `UIElement`, `UITextComponent`. A scene builds tens of thousands of nodes with their components and elements, and the `entities` scene restarts tweens in nearly every frame. The derived `UIElement` classes (`UIPanel`, `UIProgressBar`, ...) have other sizes and stay on the heap; `UIStack` has the size of `UIElement` and shares its pool.
- **Left on the heap, and why:** the event queues (`EventBase<T>` is a `Vector<Derived>` per type: nothing is allocated per event); types no scene makes or that are rare (`QuadRendererComponent`, `UIInputClicker`, `UIImageComponent`, `UITooltipComponent`, `TimerLink`), because a pool keeps its pages until exit. There is no size-class macro: `UIElement` is dominated by its exact size, and no base class had its creations spread over several sizes.
- **Choosing the next type:** opt in a small refcounted type (block at most about 1 KB) that a steady scene creates about once per frame, or that one scene build or one suite run creates about 10000 times; a rarer one stays on the heap. `BE_POOLED_SINGLE_THREAD` only for a main-thread contract that a full Debug run confirms; a type made or freed on a task-pool or loader thread gets `BE_POOLED`. Read the creations from the `allocations` of `frame_stats` `pools` after a scratch opt-in, and the other sources from `zone_allocs`. A game measures its own types the same way.

## Counters

`ArenaStats` is the only source. `AllocTracker::GetArenaStats()` forwards its snapshot (a thin forwarder, so tools that already read the allocation counters find the arenas there). `FrameStats` takes `arenaUsedBytes`, `arenaPeakBytes` and `arenaOverflows` at `EndFrame`, summed over the arenas alive at that moment, the `Scratch` and `Frame` ones of every thread that used them (`GetArenaTotals`, no allocation); the overflows are the running total, not per frame. The control method `frame_stats` answers them per frame and adds a top-level `arenas` array (`name, capacity, used, peak, overflows, chunks`). The method `memory_stats` and the editor panel are the entry `editor-memory-panel`.

## Memory tags (`MemTag.h`)

`BE_MEM_TAG(UI)` counts every allocation the thread makes until the end of the scope under that `MemTag`, whoever makes it (global `operator new`, pugixml, ImGui, SDL, stb): `AllocTracker` reads the tag where it records the block (`Profiler/Alloc/CLAUDE.md`). Scopes nest, the innermost wins; a thread starts `Untagged`.

- **The tag is the thread's.** A task that runs on another thread runs under that thread's tag, not its submitter's; nothing carries a tag across threads.
- Only with `ENGINE_PROFILER_ALLOC`: otherwise `MemTagScope` is an empty object, the macro costs nothing and `GetCurrentTag()` is always `Untagged`.
- A scope allocates nothing; put it at a subsystem's coarse entry points, not in a per-element loop.
- The engine sets the tags itself at the coarse entries of `Scene` (`SceneManager`, `Scene::Update`), `UI` (the canvas layout and draw), `Text` (`TextRenderer::Draw`, `FontAtlas`), `Resource` (the initialisers and the blocking `ResourceManager::Load`) and `Game` (the callbacks of `IGame`, the scene-update step). Never in a coroutine: it resumes on another thread, whose tag it would restore wrongly. A new subsystem entry takes its tag the same way.

## EngineAllocator and ArenaAllocator: which one (`EngineAllocator.h`)

`EngineAllocator` is the allocator of the containers of `Types/` that live as long as their owner: it forwards to the global `operator new[]` / `delete[]`, so the tracker counts every block under the tag in force. It is exactly as large as `eastl::allocator` in every build (a `static_assert`): the debug name is kept only where `EASTL_NAME_ENABLED`, so the shipped build holds an empty object. Where that name exists (the profile build defines `EASTL_NAME_ENABLED`) and `ENGINE_PROFILER_ALLOC` is on, `allocate` names its block for the tracker (`Profiler/Alloc/CLAUDE.md`, "Names"). All instances are equal.

- **`ArenaAllocator` is for scratch data freed at once** (a frame's or a task's working set). An arena container never crosses its scope or its thread; anything that must outlive the scope is copied into an engine container.
- Both are EASTL allocators of different types, so a `String` and an `ArenaString` (or the two vectors) do not assign or move into each other: copy by range or `append`.
