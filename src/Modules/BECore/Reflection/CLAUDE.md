# Reflection: the type registry

How the serializers and the generator work: `.claude/rules/reflection-module.md`. This file is about what a running program can ask of the reflection by name.

## TypeDesc, TypeInfo, TypeRegistry

- **`TypeDesc`** (`TypeDesc.h`) is what a value type is, as data: kind, element and key, enum names and size (`enumBytes`, the underlying type's: two enums of one list of names over different types are two types, and a program that loads an enum field by offset needs the width), the name and hash of an object type, container traits (`resizable`, fixed capacity, `elementSize`: the stride of a list, read by `Values/Programs/Lists`). `DescribeType<T>()` is built at compile time from the same type list as `Ser::DataAccessor`; a type the accessors cannot save has none, so a reflected field of it does not compile. A type with an accessor but no `Serialize` (`UIEdges`, `UIColor`) is `Opaque`, and an `Opaque` descriptor carries `sizeof` and a hash of the compiler's spelling of the type, so `Vec2` and `Vec3` are different types to `SameType` (by name, never by address: the same in every translation unit and shared library; nothing of it is written to the schema). A new accessor shape needs its shape in `TypeDesc.h` (`TypeDescTest` holds that the two lists agree). Compare with `SameType`, never by address: an `inline constexpr` variable can exist once per shared library. An object type is named by hash only, so a recursive type (the UI tree) is no recursion in a descriptor. `interns` is true for a `PoolString` (a container says it on its element), so a guard can refuse a write or a call that would grow the pool. There is no "has a factory" flag in it: that is `TypeInfo::factoryBase`.
- **`TypeInfo`** (`TypeInfo.h`) is one reflected type: `ClassMeta`, the parent by hash and the offset of its subobject, its **own** fields (`FieldDesc`) and methods (`MethodDesc`), thunks for `AcceptPropertyVisitor` / `Serialize` / `Deserialize` on an erased pointer, and `create`. `MakeTypeInfo<T, Parent, FactoryBase>()` builds it once, in static storage, allocating nothing.
- **`TypeRegistry`** (`TypeRegistry.h`) finds a type by name or hash, lists all, answers `Bases` / `Derived` / `IsDerivedFrom` / `AllFields` (the chain walked through `parentHash`, with the parent offsets added), `FactoryBases`, `FactoryElementName(type)` (the XML element of a factory list, `FactoryTraits<Base>::elementName`; read from `FieldDesc::factoryElementName` of the fields that hold the base's pointers, because the traits are visible only in the unit of the type that owns such a field, not in a derived type's own; a base no field holds has none), and makes objects: `Create(name)` into an `OwnedObject`, `CreateAs<Base>(name)` into the typed `IntrusivePtr<Base>`.

## Rules

- **Registration is static initialization only.** The block the generator writes into every `.gen.hpp` (after the factory registration) calls `TypeRegistry::GetInstance().Register(...)` from an anonymous namespace, so a library must be linked whole, as for `AbstractFactory`: a type whose library is dropped is not registered. Reads after start-up are lock-free; `Find` during static initialization is unsupported (the order across translation units is not defined), and so is a `Register` after the first read. The parent is found by hash at the first query for the same reason.
- **A name is the simple class name.** Two classes of one name in different namespaces hash alike: the second is refused and logged (`RefusedCount()`), because `ASSERT` compiles out in Release. A test holds the count of the engine at 0; give test types distinct names.
- **A lookup never interns.** `Find(StringView)` hashes the text and compares; a client's text must not grow the `PoolString` table, which never frees (`Control/CLAUDE.md`). An unknown name allocates nothing.
- **Error texts are `String`.** `DeserializeError::path` and `errorMessage` are plain strings, never pool entries: the text of a bad value is data, and the pool never frees (`PoolString/CLAUDE.md`). For the same reason a value of a `PoolString` field over `ReaderLimits::kMaxPoolStringBytes` is an error and is not interned (`AcceptPoolStringLength`, called by every reader before `Intern`).
- **The parent is the first base only.** The generator writes `ReflectionTraits<T>::Parent` when the first base has `BE_CLASS`; a reflected base that comes second, behind an unreflected one, is not in the chain. Another base before the parent moves it: `parentOffset` is taken from `static_cast` for that. **Non-virtual bases only**: a virtual base has no fixed offset, and the registration of such a class would crash at start-up.
- **Offsets.** A field's offset comes from its member pointer on an aligned dummy address (`Detail::SubobjectOffset`): the one place that is formally not defined behaviour, because only an address is formed and nothing is read. `FieldDesc::address` is the well defined twin, and a test compares the two on live objects of every creatable engine type. Code that needs speed reads the offset; nothing else may assume it.
- **`create`** exists for a non-abstract type that registers in an `AbstractFactory`. The `OwnedObject` holds the object at the **derived** address and a release thunk of its own type, so both ref-count families of `RefCounted.h` work; `CreateAs<Base>` moves to the `Base` subobject by the chain's offsets and refuses a type that does not derive from `Base` by the registry's own chain.
- **`TypedRef`** (`TypedRef.h`) is the handle every access by name takes: the address of the **most derived** object (never of a base subobject, so the registry's offsets apply as they are), its `TypeInfo`, and `isConst`, a promise the callee keeps. `TypedRef::Of(object)` finds the derived type by the virtual `GetTypeMeta()` and moves the address back; empty when that type is not registered. It owns nothing and is not kept past the call.
- **Property paths** (`PropertyPath.h`): `name`, `a.b`, `a[2]`, `a["text key"]`, `a.b[2].c`; a name is the serialized name of a field (a parent's field is an own one), `[3]` is a sequence position and also matches an integer map key, a quoted key knows only `\"` and `\\`. Limits in `PropertyPathLimits` (path bytes, segments, key bytes, index). Client text: a bad path is an error code (`PropertyErrorCode`, the wire names of the control protocol), never an assert, nothing is interned.
- **`GetProperty` / `SetProperty`** (`PropertyAccess.h`) read and write one **leaf**: a number, bool, text or enum (a struct, list or map is `not_a_value`; an empty `Optional` is `not_found`). The value is `bool`, `int64_t`, `uint64_t`, `double` or `String` (an enum as its name); a write takes the kind that fits (the exact table is in the header: an integer into a float field is fine, a `double` into an integer field is `type_mismatch`, out of range is refused, never wrapped). `readonly` and `hidden` fields refuse a write, `hidden` can be read, `range` is checked on a numeric write. A write adds and removes no element and engages no `Optional`; a refused write changes nothing. A `PoolString` field refuses with `interning` unless `SetOptions::allowInterning`: whoever turns it on owns the limit on the text.
- **Compiled paths** (`CompiledPath.h`): the fixed part of a path (fields of the root type and of objects embedded by value) is a constant distance from the root, found once; the rest (a list element, a map value, an optional, a pair, a pointee) needs the live object and goes through `GetProperty`. `CompileProperty<T>` gives a `CompiledProperty<T>` for a fully fixed path: `Get` is an offset added to an address, with no check and no allocation. `Set` still checks `readonly`, `hidden` and `range`, because a handle outlives the code that knew what the field allows; `Mutable` does not.
- **`callable`** of a method is decided at compile time: every parameter (without `const&`) default constructible and loadable by `Ser::Load`, the result `void` or savable, and no intrusive pointer anywhere in the signature (a call makes and hands back no objects). A method that fails it is listed, never a compile error, and has no `invoke`. `PoolString` parameters stay callable and intern the text uncut; `call_method` refuses them unless the root allows interning ("Reflection methods"). `MethodDesc::invoke` reads the arguments from the current scope of an `IDeserializer`, calls `args.FinishLoad()` itself so an unknown key is a finding, and runs the method only when no error was recorded. `CallMethod` (`MethodCall.h`) wraps it with the lookup (`TypeRegistry::FindMethod`: the type's own methods first, then the parents'), the const check (a non-const method of a const `TypedRef`) and strict values with diagnostics `Error`; the arguments are keys named by the declared parameter names (`arg0`, ... when it names none), the result of a non-void method is written under `result`. Statuses (`CallStatus`): `unknown_method`, `not_callable`, `const_object`, `bad_arguments` (the errors stay in `args`); none of them changes the object. A virtual method is called virtually. `CallMethod` is for a name that arrives at run time, `InvokeMethod` (`TypeTraits.h`) for a method and arguments known at compile time.
- A fieldless `BE_EVENT` has no `serialize` / `deserialize` thunks: the generator declares them and never defines them.
- **Reader hooks for a loader that takes both shapes.** `IDeserializer::AttributeNames` appends the attribute names of the open scope in document order (only `XmlDeserializer` has any; it does not count as asking the keys); `IsScalarMember(name)` is true only in `JsonDeserializer` for a member that is neither an object nor an array, so `Value<T>` reads `"damage": 12` without a `BeginObject` that JSON refuses.
- **A game's types** appear with no change of its own: its reflection run uses the same template, so its `.gen.hpp` files register in the same registry at start-up. A template change bumps `MetadataCache.CACHE_VERSION`, which regenerates the game's files at its next `cmake --preset`.

## Reflection methods

The surface of the control API over this module (`Control/ReflectionControl`, registered by `RegisterControlBuiltins`, so every `ControlService` has it). It reaches only objects under a **root** (`ControlRoots`: `game` is the active `IGame`, resolved on every call), never a service, a widget or the renderer; a client's `root`, `path` and `method` are looked up as text and never interned.

- `get_property {root, path}` and `set_property {root, path, value}` answer `{root, path, value}`; a write answers with the value read back. A JSON `value` is a bool, an integer (`int64_t`, `uint64_t` above `INT64_MAX`), a finite number or a string; null, an array or an object is `invalid_params`. A write is `SetProperty` with `SetOptions{root.allowInterning}`.
- `call_method {root, method, arguments?}` answers `{root, method, result?}` (`result` absent for a method that returns nothing). `arguments` is an object (an absent one is empty) read by `CallMethod` under the declared parameter names, strict.
- `list_types {base?, recursive?, creatable?}` (`base` an unknown name is `unknown_type`; `recursive` default true), `describe_type {name}` (`unknown_type`) and `schema` (no params; each root with the type of what it resolves to now) answer the shapes of `SchemaExport` (below, "Schema export"); they need no root. A wrong parameter type is `invalid_params`.
- **Interning:** `allowInterning` of a root is off by default, so a client cannot grow the `PoolString` pool. A write to a `PoolString` field is `interning`; so is a call of a method that takes a `PoolString` anywhere in its parameters (`MethodInterns` walks the parameter, its element, key, alternatives and the fields of an object type, each type once), decided before the arguments are read.
- **Codes:** `invalid_params`, `unknown_root`, `no_object` (the root has no object now), `unknown_type`, the `PropertyErrorCode` names (a path over a limit is `invalid_path`), and for a call `unknown_function` (`CallStatus::unknown_method`, renamed so it is not taken for the control method of that name), `not_callable`, `const_object`, `bad_arguments`, `interning`. The message is the library's, which cuts client text.

## JSON shapes of the reflection pair

`JsonSerializer` and `JsonDeserializer` (`Control/`) are one format; `call_method` of the control API uses them (`Control/CLAUDE.md`).

- An attribute and a child are the same member. An object is a member object, an array a member array of element objects; an element that holds only `value` is that scalar (`[1,2,3]`), and the reader takes both forms. A map is an array of `{key, value}`, a variant `{index, value}` (`monostate`: the index alone), a factory element carries `type` and `enabled`.
- Integers are exact (`uint64_t` above 2^63 too), a `float` is the shortest text that reads back, a non-finite number is `null`, which the reader refuses.
- The reader is always strict: a JSON bool is the only bool, a number the only number (`3.0` and `1.5` are no integers, a string is no number, a negative is no unsigned), a string target takes only a string. A refusal is an error under the field's path and the target keeps its value; a missing key is no error. Under diagnostics an unknown key is a finding with `did you mean`. Limits are those of `ReaderLimits.h`; `StoreError` cuts the text and replaces control characters with `?`. Check `IsJsonNestedDeeperThan` on input first.
- A `SceneNode` does not round-trip: `IComponent` has no `FactoryTraits`, so no serializer writes the `type` member of a component.

## Load allocations

- An array loader reserves from the `count` that `BeginArray` gives (`DataAccessor.h`): an upper bound for a factory array (disabled and null elements count), never past the capacity of a fixed container. A hand-written loop reserves too after `BeginArray` (`TextureLibrary::Load` is the example).
- `XmlDeserializer` allocates nothing per element in the default diagnostics mode: per array it takes the element list (counted first, reserved once) and its own stacks. The `Warn` mode keeps a scope per opened node and was not measured. The DOM of pugixml is the text's own cost.
- A reader does not know the totals (new `PoolString`s, string bytes), and `PoolString::Reserve` alone removes only table growth, not the unique lock each new string takes. So no reader carries a size hint: one `PoolString::Reserve` of the exact totals saves no allocations (the `AssetLoadReserved` line of `AssetLoadAllocBenchTest`).
- Figures: `AssetLoadAllocBenchTest` (the perf benchmark `asset-load`; counts need the profile preset). None are kept in the docs.

## Schema export

`SchemaExport.h` writes the registry as JSON for the by-name methods and `tools/schema` (the XSD); every list is sorted by name (fields and parameters keep their order), so the text does not depend on the order types registered in, and no hash is written (a JSON number above 2^53 is not safe). `schema` is `{version, types, factories, roots}`. A type entry is `{name, parent, abstract, creatable, purpose, icon, factoryBase?, fields: [{name, type, attributes}], methods: [{name, const, callable, params: [{name, type}], result}]}`: its **own** fields (the chain is by `parent`; `describe_type` adds `bases`, `derived` and `allFields` with an `owner` each), `creatable` is `TypeInfo::create` (a type of a factory, not abstract), `attributes` holds only what is set. A `type` is `{kind}` with `object` (Object, Pointer), `element`, `key` (a pair's first member), `alternatives`, `values` (an enum has no name in the registry, so its values are inline), `resizable`, `capacity` where they apply. `factories` is `{base, elementName?, derived}` (`elementName` is absent for a base no reflected field holds); `roots` is `{name, type?}`, the type of the object now.
