# Reflection: the type registry

How the serializers and the generator work: `.claude/rules/reflection-module.md`. This file is what a running program can ask of the reflection by name.

## TypeDesc, TypeInfo, TypeRegistry

- **`TypeDesc`** (`TypeDesc.h`) is a value type as data: kind, element and key, enum names and width (`enumBytes`: two enums of one list of names over different underlying types are two types, and a load by offset needs the width), an object type's name and hash, container traits (`resizable`, capacity, `elementSize`, the stride `Values/Programs/Lists` reads). `DescribeType<T>()` is built at compile time from the type list of `Ser::DataAccessor`, so a field of a type with no accessor does not compile; a new accessor shape adds its shape here too (`TypeDescTest` holds the lists equal). A type with an accessor but no `Serialize` (`UIEdges`, `UIColor`) is `Opaque`, with `sizeof` and a hash of the compiler's spelling, so `Vec2` and `Vec3` differ to `SameType` (never written to the schema; `JsonPayload` is the one opaque type the schema names, as kind `any`). A `Value<T>` field is kind `Value` with `element` the descriptor of `T`, keeping the opaque size, hash and name. Compare with `SameType`, never by address: an `inline constexpr` variable can exist once per shared library. An object type is named by hash only, so a recursive type is no recursion in a descriptor. `interns` marks a `PoolString` (a container on its element), so a guard can refuse a write or a call that grows the pool. "Has a factory" is `TypeInfo::factoryBase`, not here.
- **`TypeInfo`** (`TypeInfo.h`): `ClassMeta`, the parent by hash and its subobject offset, its **own** fields (`FieldDesc`) and methods (`MethodDesc`), erased thunks for `AcceptPropertyVisitor` / `Serialize` / `Deserialize`, and `create`. `MakeTypeInfo<T, Parent, FactoryBase>()` builds it once in static storage, allocating nothing.
- **`TypeRegistry`** (`TypeRegistry.h`): a type by name or hash, `Bases` / `Derived` / `IsDerivedFrom` / `AllFields` (the chain by `parentHash`, parent offsets added), `FactoryBases`, `FactoryElementName(type)`, `Create(name)` into an `OwnedObject`, `CreateAs<Base>(name)` into an `IntrusivePtr<Base>`. The element name comes from `FieldDesc::factoryElementName` of the fields that hold the base's pointers, because `FactoryTraits<Base>` is visible only in the unit of a type that owns such a field; a base no field holds has none.

## Rules

- **Registration is static initialization only.** Every `.gen.hpp` registers its types from an anonymous namespace, so a library must be linked whole (as for `AbstractFactory`). Reads after start-up are lock-free; `Find` during static initialization and `Register` after the first read are unsupported (the order across translation units is undefined), which is also why the parent is resolved by hash at the first query.
- **A name is the simple class name.** Two classes of one name in different namespaces hash alike: the second is refused and logged (`RefusedCount()`, held at 0 for the engine by a test), because `ASSERT` compiles out in Release. Give test types distinct names.
- **A lookup never interns.** `Find(StringView)` hashes and compares: client text must not grow the `PoolString` table, which never frees; an unknown name allocates nothing.
- **Error texts are `String`**, never pool entries (`DeserializeError::path`, `errorMessage`): a bad value is data. For the same reason a `PoolString` value over `ReaderLimits::kMaxPoolStringBytes` is an error and is not interned (`AcceptPoolStringLength`, called by every reader before `Intern`).
- **The parent is the first base only**, when it has `BE_CLASS`; a reflected base behind an unreflected one is not in the chain. `parentOffset` comes from `static_cast`, so another base before the parent is fine. **Non-virtual bases only**: a virtual base has no fixed offset, and its registration would crash at start-up.
- **Offsets** come from a member pointer on a dummy address (`Detail::SubobjectOffset`), formally undefined behaviour though nothing is read; `FieldDesc::address` is the defined twin (a test compares them). Only code that needs speed reads the offset.
- **`create`** exists for a non-abstract type of an `AbstractFactory`. The `OwnedObject` holds the **derived** address and a release thunk of its own type, so both ref-count families work; `CreateAs<Base>` moves to the `Base` subobject by the chain's offsets and refuses a type the chain does not derive from `Base`.
- **`TypedRef`** (`TypedRef.h`): the address of the **most derived** object (so the registry's offsets apply as they are), its `TypeInfo`, and `isConst`, a promise the callee keeps. `TypedRef::Of(object)` goes through the virtual `GetTypeMeta()` and is empty for an unregistered type. It owns nothing; do not keep it.
- **Property paths** (`PropertyPath.h`): `a.b[2].c`, `a["text key"]`; a name is a field's serialized name (a parent's field counts as own), `[3]` is a position and also an integer map key, a quoted key knows only `\"` and `\\`. Limits in `PropertyPathLimits`. A bad path is a `PropertyErrorCode` (the wire names of the control protocol), never an assert; nothing is interned.
- **`GetProperty` / `SetProperty`** (`PropertyAccess.h`) read and write one **leaf** (number, bool, text, an enum as its name); the conversions are the header's table, out of range is refused, never wrapped. `readonly` and `hidden` refuse a write (`hidden` reads), `range` is checked. A write adds or removes no element and engages no `Optional`; a refused one changes nothing. A `PoolString` field refuses with `interning` unless `SetOptions::allowInterning`: whoever turns it on owns the limit on the text.
- **Compiled paths** (`CompiledPath.h`): the fixed part of a path (fields held by value) is an offset found once, the rest goes through `GetProperty`. `CompiledProperty<T>::Get` is that offset, no check; `Set` still checks `readonly`, `hidden` and `range`, because a handle outlives the code that knew what the field allows (`Mutable` does not).
- **`callable`** is decided at compile time: parameters (without `const&`) default constructible and loadable, the result `void` or savable, no intrusive pointer in the signature (a call makes and hands back no objects). A method that fails is listed with no `invoke`, never a compile error. `CallMethod` (`MethodCall.h`) reads the arguments strictly under the declared parameter names, with diagnostics `Error`, and runs the method only when nothing was recorded, so a failed `CallStatus` never changes the object. It is for a name known at run time; `InvokeMethod` (`TypeTraits.h`) for one known at compile time.
- A fieldless `BE_EVENT` has no `serialize` / `deserialize` thunks (declared, never defined).
- **Reader hooks for a loader that takes both shapes:** `IDeserializer::AttributeNames` lists the open scope's attributes in document order (`XmlDeserializer` only; it does not count as asking); `IsScalarMember(name)` is true only in `JsonDeserializer` for a scalar member, so `Value<T>` reads `"damage": 12` without the `BeginObject` that JSON refuses.
- **A game's types** register in the same registry with no code of their own: its reflection run uses the same template.

## Reflection methods

The control API over this module (`Control/ReflectionControl`, registered by `RegisterControlBuiltins` in every `ControlService`). It reaches only objects under a **root** (`ControlRoots`; `game` is the active `IGame`, resolved per call), never a service, a widget or the renderer; `root`, `path` and `method` are looked up as text and never interned.

- `get_property {root, path}` and `set_property {root, path, value}` answer `{root, path, value}` (a write: the value read back). `value` is a bool, an integer (`uint64_t` above `INT64_MAX`), a finite number or a string; anything else is `invalid_params`. A write is `SetProperty` with `SetOptions{root.allowInterning}`.
- `call_method {root, method, arguments?}` answers `{root, method, result?}`; `arguments` (absent is empty) is read strictly by `CallMethod` straight from the request's tape, and `result` is written by `JsonStreamSerializer`, so an object's members come in declaration order (the generated `WriteJson` sorts them).
- `list_types {base?, recursive? (default true), creatable?}`, `describe_type {name}` and `schema` need no root and answer the structs of `Control/SchemaAnswers.h` ("Schema export"); an unknown name is `unknown_type`, a wrong parameter type `invalid_params`.
- **Interning:** `allowInterning` of a root is off by default, so a client cannot grow the pool: a write to a `PoolString` field is `interning`, and so is a call of a method with a `PoolString` anywhere in its parameters (`MethodInterns` walks elements, keys, alternatives and object fields, each type once), decided before the arguments are read.
- **Codes:** `invalid_params`, `unknown_root`, `no_object` (the root has none now), `unknown_type`, the `PropertyErrorCode` names (`invalid_path` past a limit), and for a call `unknown_function` (`CallStatus::unknown_method`, renamed so it is not read as the control method of that name), `not_callable`, `const_object`, `bad_arguments`, `interning`. The message is the library's, which cuts client text.

## JSON shapes of the reflection pair

`JsonStreamSerializer` (into a `JsonWriter`, the `call_method` result) and `JsonDeserializer` (`Control/`) are one format (`Control/CLAUDE.md`).

- An attribute and a child are one member. An array is a member array of element objects; an element that holds only `value` is that scalar (`[1,2,3]`), and the reader takes both. A map is `[{key, value}]`, a variant `{index, value}` (`monostate`: the index alone). A factory element carries `type` and `enabled` when the base has `FactoryTraits` or the derived type registered in the base's `AbstractFactory` (`IComponent`), so a `SceneNode` round-trips and a cooked node file keeps its component types.
- Integers are exact (`uint64_t` too), a `float` is the shortest text that reads back, a non-finite number is `null`, which the reader refuses.
- The reader is always strict: only a JSON bool is a bool, only a number a number (`3.0` is no integer, a negative no unsigned), only a string a string. A refusal is an error under the field's path and keeps the target; a missing key is none; under diagnostics an unknown key is a finding with `did you mean`; the keys of an object may come in any order. Limits of `ReaderLimits.h`; `Load` bounds the text's size and nesting itself (`.claude/rules/json-tape.md`).

**The generated writer.** Every `BE_CLASS` and `BE_EVENT` has `WriteJson(JsonWriter&) const` (in the `.gen.hpp`): what `Serialize` saves, keys sorted by serialized name, written with no tree built. It writes no `null`: an empty `Optional` writes no member. A `BE_CLASS` also has the virtual `WriteJsonMembers(w, outer)`, the members without braces, so a class with a reflected parent merges its sorted keys with the parent's (`JsonWrite::MemberMerge` on the stack; the child wins a shared key). Which field types are written natively and which are bridged through `JsonStreamSerializer` and a scratch `String` (the same bytes, allocating) is the list of `Control/JsonWriteReflect.h`; a new `Math` type needs its overload in `JsonWriteMath.h`. A type that must write fast and has only a `Serialize` gets its own `WriteJson`. A foreign JSON value is the leaf `JsonPayload` (`Control/JsonPayload.h`, native like the `Math` types: it writes one value at the sorted place of its key; no `Serialize` form, so a struct that holds one is for `WriteJson` only).

## Load allocations

- An array loader reserves from the `count` of `BeginArray` (`DataAccessor.h`): an upper bound for a factory array, never past a fixed container's capacity. A hand-written loop reserves too (`TextureLibrary::Load`).
- `XmlDeserializer` allocates nothing per element or name in any diagnostics mode: names compare as views, an array is a counted cursor over the DOM (`count` an upper bound for the loader, comments skipped; a named array counts only its own elements and keeps the name as a view of the first one's, never the caller's argument), and `ReadAttributeView` hands out an attribute's text uncopied until the next load (the default copies into a reused member; the factory `type` is read so). `Warn` keeps its scopes' asked names in an arena the deserializer owns: a name is copied once (a caller's may be a temporary), `CloseScope` rewinds to its mark, a load resets it. The pugixml DOM is the text's own cost.
- `JsonDeserializer` reads a `JsonTape` of the text: the second `Load` of a message of the same shape allocates nothing in any diagnostics mode (reused tape, scopes and names arena; a `String` field keeps its capacity, a `PoolString` is interned straight from the text); the target's own containers must keep theirs.
- `BinaryDeserializer` allocates nothing per array or field (a cursor into the validated bytes); what a load copies and interns: "Binary Format" of the rules file. The validation's key spill and the list of texts to intern are `ArenaVector`s on a `ScratchScope` of their call; the section's texts are interned by one `InternBatch` that hashes them itself (the hashes in a file are ignored by these loads); `LoadFromContent` interns nothing, its `PoolString`s are the adopted block's (content mode: `.claude/rules/reflection-module.md`), and its bytes are the compact stream, so the validation parses the name table and the head of the section only; `poolBits` stays on the heap because the reader keeps it past `Validate` until the first `PoolString` read.
- **The writer's memory:** `BinarySerializer` owns a `LinearArena` for its two tables, the name table and the pool section (`_names`, an `ArenaHashMap<StringView, u32>`, and `_pool`, an `ArenaHashMap<StringView, PoolText>` of index and hash, both over one copy of each text, since a caller's name may be a temporary; the section entries get the `PoolString`'s own hash), scopes and index offsets; the temporaries of `GetData()` are on a `ScratchScope`. It is its own arena and not a scratch scope because the writer outlives any call and is passed by reference (`ContentCook`); an arena cannot move, so the serializer has no move constructor or assignment: construct it in place. `_buffer` stays a heap `Vector` (doubling would pile old blocks in the arena; the member says what the arena saved) and so does `_image`, the result `GetData()` returns. The bytes do not depend on the hash order: both tables are written sorted.
- No reader carries a size hint: it does not know the totals, and `PoolString::Reserve` removes only table growth, not the lock per new string (the `AssetLoadReserved` line of `AssetLoadAllocBenchTest`).

## Layout hash

`SchemaHash.h`: `ComputeLayoutHash(type name | TypeInfo)` is a 64-bit FNV-1a over the fields of a type in `Serialize` order (own and inherited): names, kinds, `resizable`, capacity, `interns`, elements, keys, alternatives, enum names and width, nested objects, and every derived type of a pointer field's base. It leaves out offsets, attributes and the compiler's spelling of an `Opaque` type, so a file cooked on one compiler loads on another; the price is that `Vec2` to `Vec3` does not move it. A type seen again contributes its name only. `CheckContentStamp` compares the `$content` hash of a cooked file with the layout of the same type in the reading program, so a file is cooked by a program that links the same types.

## Schema export

`SchemaExport.h` fills the structs of `Control/SchemaAnswers.h` (their members are the keys) for the by-name methods and `tools/schema`. Lists are sorted by name whatever the registration order (fields and parameters keep theirs), so the text does not depend on link order; no hash is written (a JSON number above 2^53 is not safe). A type entry holds its **own** fields: the chain is by `parent` (absent on a root type), and `describe_type` adds `bases`, `derived` and `allFields` with an `owner` each. An enum has no name in the registry, so its values are inline in its `type`. `roots` gives the type of each root's object now.

## Answers on the scratch arena

A control answer struct is made, written and dropped by one thread inside one call, which is what a `ScratchScope` is: `ControlService` opens one around every handler, every `done` of a deferred call, `Publish` and the envelope writers, so the reply gives its memory back with it and a repeated reply allocates nothing after the first (the arena keeps its chunks). A room server thread has the same arena and no frame.

- **Lifetime:** the struct is a local of the handler or of `done` and dies in the scope. A lambda handed to `DeferFrames` runs outside it: it captures heap data and builds the struct inside `done`, never a struct with arena members. Never make an answer a `static`, a member or a field of a pooled object: a default-constructed arena container binds to the thread's arena when it is made.
- **Field types:** `ArenaString`, `Optional<ArenaString>` and `ArenaVector<T>` (scalars, strings, reflected structs) are fields like `String` / `Vector`, with the same descriptor and the same bytes. They do not convert from `String`: fill with `ArenaString(view.data(), view.size())`, and `reserve` an `ArenaVector` from the known count (a doubling one leaves every old block in the arena until the scope ends). A text longer than the small-string buffer is what allocates, so a test of "allocates nothing" uses one.
- **`PoolString`** where the data already is one (a game's name); **`TextView`** (`Reflection/TextView.h`) where the text lives elsewhere past the write (a table's or registry's name, the client's own request text, the room wire structs: the arguments of the writer that made them): a string for every writer, `TypeKind::String`, never read back (`Load` leaves it), so no path of a root may reach it and a text the handler makes is an `ArenaString`. A bare `StringView` is no field type.
- **Stays on the heap:** a text the handler owns and moves in (a screenshot's base64; a clipboard text is a `TextView` of the held text), the `IntrusivePtr` nodes of the schema (a recursive tree, a cold method; their lists are arena and their texts are `TextView`s of the registry), `ControlError` (returned in `std::expected` across code that is no reply) and the ArtGen answers (the editor session's own data, they outlive the reply). A saved or content type (config, UI, scene, formula nodes) keeps its `String`s: no reply writes one.
