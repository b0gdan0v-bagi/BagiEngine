# Types (BECore)

The engine's names for the types it uses (`Types.h`, in the PCH): `String`, `StringView`, `FixedString<N>`, `Vector`, `SmallVector<T, N>`, `FixedVector<T, N>`, `Array`, `Span`, `HashMap`, `Map`, `HashSet`, `Set`, `FixedHashMap`, `FlatMap`, `FlatSet`, `Optional`, `UniquePtr` (+ `MakeUnique`), `Pair` (+ `MakePair`), `Variant`, `Tuple`. Each is a `using` of the EASTL type (`Optional`, `Variant` and `Tuple` of the `std::` one, which the other libraries speak), so the implementation and the allocator are chosen in one place. The owning types (`String`, `FixedString`, `Vector`, `SmallVector`, `FixedVector`, the maps and sets) take `EngineAllocator` (`Memory/CLAUDE.md`), so they are **not** the `eastl::` type of the same name: `String` is `eastl::basic_string<char, EngineAllocator>`, and one never converts into the other except by copy. The size is the same as with EASTL's allocator in every build. The headers of this folder compile alone (the PCH still has `Types.h` for the `.cpp` files): a header that spells one of these names includes `<BECore/Types/Types.h>` (`Strings.h` when it spells only the string names).

**Rule:** engine and game code spell these names, not `eastl::` or `std::`; those appear directly only in this folder and in the reflection traits (`Reflection/DataAccessor.h`, `SerializationTraits.h`, `PropertyVisitorDispatch.h`), which name templates on purpose. A line that must keep a `std::` type for a standard or third-party API says why with `//-NoStd: <why>`. **Tests follow the same rule:** they spell the aliases like the sources; a `std::` type stays only at a real boundary (gtest's printing and name generators, nlohmann, `std::filesystem`, a benchmark's `std::cout`) with `//-NoStd: <why>`; file bytes are no boundary: a test reads and writes through `TestFiles.h` or the file layer (`File/CLAUDE.md`), and `<fstream>` / `<sstream>` are not in the PCH, and in the twin tests that pin the `std::` spelling (`TypesTest`, `ReflectionAliasesTest*`), which the codemod skips. `CI/scripts/check_types.py` (ctest `BagiTypesCheck`) holds the rule: the type names and the allocating calls (`to_string`, `sto*`, `getline`, streams, `stable_sort`, `std::filesystem` iterators, `fmt::`) are one check, with a baseline of the lines other entries still own (`CI/types_baseline.txt`, shrink only).

- **`SmallVector` / `FixedVector`:** `SmallVector<T, N>` keeps N elements inside the object and then moves to the heap; `FixedVector<T, N>` never allocates and must not pass N. Pick by that, not by the size.
- **An `eastl::string` / `eastl::vector` spelled by hand** (a game's code, a test) is a different type from `String` / `Vector`: an API that takes the alias does not accept it, and `==` between the two is ambiguous. Spell the alias; compare views (`StringView{a} == StringView{b}`) where a reference of the old type is the point of a test.
- **`ArenaVector<T>` / `ArenaString`** take their memory from an arena (`Memory/CLAUDE.md`, "ArenaAllocator"); they are only declared here, a file that uses one includes `<BECore/Memory/ArenaAllocator.h>`. Other containers on an arena are spelled `eastl::...<..., ArenaAllocator>` where needed.
- **Strings as keys:** `HashMap<String, V>`, `Map<String, V>`, `FixedHashMap<String, V, N>` and `FlatMap<String, V>` use `StringHash` / `StringEqual` / `StringLess`, which are transparent over `StringView`: `find`, `contains`, `count`, `at`, `erase` take a view or a literal and make no `String`; do not write `.find(String{x})`. The hash is the one `eastl::hash<eastl::string>` gives (a test pins the iteration order), so replacing a map keeps its order. A different key type keeps its own hash; a custom hash or comparison goes in the extra template argument.
- **`FlatMap` / `FlatSet`** (a sorted vector) are for new code where the map is small, rarely changed and iterated often; the default container for a lookup stays `HashMap`.
- **Text:** `ToString(number)` (an integer's digits, a floating-point value as `{:f}` through fmt, the text `std::to_string` writes, except a NaN, which is `nan` whatever its sign; no overload for `bool` and characters) and `Format` / `AppendFormat` (`Format/Format.h`) make strings; do not build one through `std::to_string`. `StringUtils::ParseNumber<T>(text)` reads one (`from_chars`, the whole text, nullopt otherwise), not `std::sto*`.
- **The `std::` boundary:** `ToStd(StringView)` / `FromStd(std::string_view)` copy nothing; `ToStdString` / `FromStdString` make a copy and are named so. Use them at the call that meets `std::filesystem`, `nlohmann` or the like.
- **Reflection:** `String` (a string of any allocator), `FixedString`, `Vector`, `SmallVector`, `FixedVector`, `Array`, `Pair`, `HashMap`, `Map`, `FixedHashMap`, `Optional` and `Variant` are reflected as their `eastl::` forms were, with the same saved text; a `FixedString`, `FixedHashMap` or `FixedVector` that cannot overflow keeps what fits on load and reports the rest as an error of the field. `FlatMap`, `FlatSet`, `HashSet`, `Set`, `Span`, `UniquePtr` and `Tuple` are not: a field of one does not compile, and a test pins that (`.claude/rules/reflection-module.md`).
- **Sets, pairs, pointers:** `HashSet` / `Set` take the same `String` key rule as the maps; EASTL has no `Set::extract` / `merge`. `Pair` is `eastl::pair`, the `value_type` of every EASTL map; bind it with `auto [a, b]` (`std::tie(a, b) = pair` does not accept it). `MakeUnique<T>(args...)` and `MakeUnique<T[]>(n)` return a `UniquePtr`. There is no `SharedPtr` here: the engine shares through `IntrusivePtr` (`BECore/RefCounted`, the thread rule in `engine/CLAUDE.md`), so `<EASTL/shared_ptr.h>` is not in the PCH; a test that needs one shared fake takes `Common/SharedPtr.h`. `<EASTL/functional.h>` and `<functional>` stay in the PCH for `eastl::hash`, `eastl::less` and `std::invoke`: their presence is no permission for `eastl::function` or `std::function`.
- **Companions that stay `std::`:** `Variant` and `Tuple` are the standard types, so `std::visit`, `std::get`, `std::get_if`, `std::holds_alternative`, `std::monostate`, `std::apply`, `std::tie` and `std::tuple_size_v` are spelled so (as `std::nullopt` is). CTAD through an alias is not relied on: write the arguments (`Pair<float, float>{a, b}`, `Array<Format, 3>`).
- **Names:** a function, variable or member called `Span`, `Map`, `Vector` ... hides the alias in its scope (seen: a test helper `Span()`), and so does a member `Set` or `Pair` inside its class; name it `AsSpan`, `MapOf`, or spell `BECore::Set`.

Tests: `tests/BECore/TypesTest.cpp`, `tests/BECore/ReflectionAliasesTest.cpp`.
