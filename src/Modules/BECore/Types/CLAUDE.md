# Types (BECore)

The engine's names for the types it uses (`Types.h`, in the PCH): `String`, `StringView`, `FixedString<N>`, `Vector`, `SmallVector<T, N>`, `FixedVector<T, N>`, `Array`, `Span`, `HashMap`, `Map`, `HashSet`, `Set`, `FixedHashMap`, `FlatMap`, `FlatSet`, `Optional`, `UniquePtr` (+ `MakeUnique`), `SharedPtr` (+ `MakeShared`), `Pair` (+ `MakePair`), `Variant`, `Tuple`. Each is a `using` of the EASTL type (`Optional`, `Variant` and `Tuple` of the `std::` one, which the other libraries speak), so the implementation, or later an allocator, is chosen in one place.

**Rule:** engine and game code spell these names, not `eastl::` or `std::`; those appear directly only in this folder and in the reflection traits (`Reflection/DataAccessor.h`, `SerializationTraits.h`, `PropertyVisitorDispatch.h`), which name templates on purpose. A line that must keep a `std::` type for a standard or third-party API says why with `// std: <why>`.

- **`SmallVector` / `FixedVector`:** `SmallVector<T, N>` keeps N elements inside the object and then moves to the heap; `FixedVector<T, N>` never allocates and must not pass N. Pick by that, not by the size.
- **Strings as keys:** `HashMap<String, V>`, `Map<String, V>`, `FixedHashMap<String, V, N>` and `FlatMap<String, V>` use `StringHash` / `StringEqual` / `StringLess`, which are transparent over `StringView`: `find`, `contains`, `count`, `at`, `erase` take a view or a literal and make no `String`; do not write `.find(String{x})`. The hash is the one `eastl::hash<eastl::string>` gives (a test pins the iteration order), so replacing a map keeps its order. A different key type keeps its own hash; a custom hash or comparison goes in the extra template argument.
- **`FlatMap` / `FlatSet`** (a sorted vector) are for new code where the map is small, rarely changed and iterated often; the default container for a lookup stays `HashMap`.
- **Text:** `ToString(number)` (an integer's digits, a floating-point value as `std::to_string`; no overload for `bool` and characters) and `Format` / `AppendFormat` (`Format/Format.h`) make strings; do not build one through `std::to_string`.
- **The `std::` boundary:** `ToStd(StringView)` / `FromStd(std::string_view)` copy nothing; `ToStdString` / `FromStdString` make a copy and are named so. Use them at the call that meets `std::filesystem`, `nlohmann` or the like.
- **Reflection:** `String` (a string of any allocator), `FixedString`, `Vector`, `SmallVector`, `FixedVector`, `Array`, `Pair`, `HashMap`, `Map`, `FixedHashMap` and `Optional` are reflected as their `eastl::` forms were, with the same saved text. `FlatMap`, `FlatSet`, `HashSet`, `Set`, `Span`, `UniquePtr`, `SharedPtr`, `Variant` and `Tuple` are not: a field of one does not compile, and a test pins that (`.claude/rules/reflection-module.md`).
- **Sets, pairs, pointers:** `HashSet` / `Set` take the same `String` key rule as the maps; EASTL has no `Set::extract` / `merge`. `Pair` is `eastl::pair`, the `value_type` of every EASTL map; bind it with `auto [a, b]` (`std::tie(a, b) = pair` does not accept it). `MakeUnique<T>(args...)` and `MakeUnique<T[]>(n)` return a `UniquePtr`; `MakeShared<T>(args...)` returns a `SharedPtr<T>`.
- **Companions that stay `std::`:** `Variant` and `Tuple` are the standard types, so `std::visit`, `std::get`, `std::get_if`, `std::holds_alternative`, `std::monostate`, `std::apply`, `std::tie` and `std::tuple_size_v` are spelled so (as `std::nullopt` is). CTAD through an alias is not relied on: write the arguments (`Pair<float, float>{a, b}`, `Array<Format, 3>`).
- **Names:** a function, variable or member called `Span`, `Map`, `Vector` ... hides the alias in its scope (seen: a test helper `Span()`), and so does a member `Set` or `Pair` inside its class; name it `AsSpan`, `MapOf`, or spell `BECore::Set`.

Tests: `tests/BECore/TypesTest.cpp`, `tests/BECore/ReflectionAliasesTest.cpp`.
