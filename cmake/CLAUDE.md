# cmake/ — the engine setup and the build options

`BagiEngine.cmake` is the engine setup and the `be_*` functions games build on (`.claude/rules/cmake-rules.md`); `BagiPlatformOptions.cmake` the platform options; `BagiWeb.cmake` the Emscripten side. A change to any `*.cmake` needs a configure.

## Presets

| OS | Presets |
|----|---------|
| macOS | `macos-debug`, `macos-release` (Clang + Ninja); `macos-release-editor`; `macos-profile` (RelWithDebInfo with the profiler and allocation tracking, no editor: `src/Modules/BECore/Profiler/HowToProfile.md`), `macos-profile-tracy` (the same with the Tracy backend), `macos-profile-editor` (the same with the editor, for the ImGui Profiler panel), `macos-release-stats` (Release plus the light profiler with allocation counting: `HowToProfile.md`); `macos-rmlui-debug` / `-release` (`ENGINE_UI_RMLUI=ON`); `macos-asan` (Debug, Apple clang, ASan + UBSan on all code: "Sanitizers and fuzzing" below), `macos-tsan` (RelWithDebInfo with asserts and expects ON, ThreadSanitizer: the same section), `macos-coverage` (Debug, source-based coverage, ccache off: "Coverage" below), `macos-time-trace` (Debug, `-ftime-trace`, ccache off: "Compile-time measurement" below), `macos-fuzz` (Homebrew LLVM, ASan + UBSan, libFuzzer executables), `macos-fuzz-shipped` (the same in Release with asserts and expects OFF) |
| Windows | `windows-clang-{debug,release}` (default; configure and build through `python CI/scripts/vs_env.py cmake ...`), `windows-clang-profile-editor` (the Windows twin of `macos-profile-editor`: RelWithDebInfo, the profiler with allocation tracking and the editor, through `vs_env.py`), `windows-clang-release-stats` (the twin of `macos-release-stats`), `windows-clang-asan` (Debug build type with the static release CRT and a static SDL, ASan + UBSan, through `vs_env.py` like the others), `windows-msvc-{debug,release}`, `windows-msvc-release-editor`, `windows-vs2022-*`, `windows-vs2022-clangcl-*`. The MSVC builds are fallbacks (their PDBs break parallel builds now and then: `LNK1103`, `C1090`) |
| Linux | `linux-server-release` (Clang + Ninja, Release, only for the room server: no Vulkan, no tests, no editor, static SDL built with `SDL_UNIX_CONSOLE_BUILD` since the server opens no window, `no-module-scan`, `CMAKE_POSITION_INDEPENDENT_CODE=OFF` because SDL_image's `option()` would turn it ON and the executables then get `-fPIE` against a PCH made for libraries: "is pie differs in PCH file"). It builds `BagiRoomServer` in the Docker image of `tools/rooms/Dockerfile` (README.md, "Hosting the room server"); no other target, game or test is built or checked on Linux |
| Web | `web-release`, `web-debug` (threaded, the default: the task system's workers are Web Workers, the page needs cross-origin isolation, which `tools/web/serve.py` and the Docker image send), `web-release-single-thread`, `web-debug-single-thread` (needs nothing), `web-release-stats` / `web-release-single-thread-stats` (Release with the light profiler, no allocation counting). Always listed: they find the SDK in the submodule `external/emsdk` (pinned tag, about 2 GB), installed once per checkout by `python CI/scripts/setup_emsdk.py` (in a game `engine/CI/...`; `--check`); without it configure stops with "could not find toolchain file". `web-editor` is `web-debug` with the editor, the others have none. Build only, no tests. Output `build/<preset>/bin` (the page `<Game>.html`). Entry `web-build` of the todo store; the browser side: `tools/web/CLAUDE.md` |

Per-machine settings go in `CMakeUserPresets.json` (git-ignored). Without presets: `cmake -B build -G Ninja -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++`.

**Output goes under the binary dir of the build**: executables and shared libraries in `build/<preset>/bin`, static libraries in `build/<preset>/lib`, so Debug, Release and every other preset sit side by side and nothing needs deleting when you switch presets. A build without a preset gets `<-B dir>/bin`. A multi-config generator (the `windows-vs2022-*` presets) adds the configuration, `build/<preset>/bin/<Config>/`. A game that carries the engine as a submodule gets `build/<preset>/bin` in its own `build/`. Switching `BE_WITH_EDITOR` inside one preset still needs the rebuild of "The editor option".

## The editor option

`BE_WITH_EDITOR` decides whether the editor panels (`src/Widgets/{ConfigEditor,EditorLayout,SceneEditor,TextureEditor,Viewport}`) and their tests are built:

- `AUTO` (default): ON except in a single-config `Release` / `RelWithDebInfo` / `MinSizeRel`. A multi-config generator picks sources at configure time, so `AUTO` is ON there.
- `ON`: also in Release (`-DBE_WITH_EDITOR=ON`, or the `*-release-editor` presets). `OFF`: none; **a Debug build ignores `OFF`** with a configure WARNING.
- **A web build is the exception:** it has the editor only with `ON` (`web-editor`), also in Debug, so a page never carries it by accident. That page starts in Editor mode (`src/main.cpp`).
- Configure prints `Editor: ENABLED|DISABLED`. The definition `BE_WITH_EDITOR=1|0` is on every target (`kEditorBuilt` in `BECore/Application/RunMode.h`); code that needs an editor header is guarded with `#if BE_WITH_EDITOR`. ImGui and `ImGuiWidget` are in every build.
- `mode="Editor"` (or `--editor`) in a build without the editor starts in Game mode with one warning. With the editor, Ctrl+Shift+E switches modes at run time (`src/Modules/BECore/CLAUDE.md`, "Run mode").

## Web-like build on the desktop

`BagiPlatformOptions.cmake`: `ENGINE_WITH_VULKAN`, `ENGINE_WITH_REMOTE_CONTROL` (ON), `ENGINE_STATIC_SDL`, `ENGINE_SINGLE_THREAD` (OFF), `ENGINE_PROFILER_STATS` (OFF: ON forces `ENGINE_PROFILER` ON, also on the web, where `ENGINE_PROFILER_ALLOC` and `_TRACY` stay forced OFF); Emscripten forces the first three to the web values (not `ENGINE_SINGLE_THREAD`: its web default OFF is the threaded page, the `web-*-single-thread` presets set it ON) and sets `ENGINE_TARGET_WEB` / `PLATFORM_WEB`. To check the web configuration without emsdk: `cmake -S . -B build/webcheck -G "Visual Studio 17 2022" -A x64 -DENGINE_WITH_VULKAN=OFF -DENGINE_SINGLE_THREAD=ON`, then build `BagiStress BagiEngineTests` with `--config Release`; run it with `ENGINE_SINGLE_THREAD` ON and OFF (the threaded page's task system is the desktop one). It has no preset: the Visual Studio generator writes to `build/webcheck/bin/Release/`, and `build/webcheck` can be deleted after.

## Compile-time measurement

`BagiTimeTrace.cmake`: `ENGINE_TIME_TRACE` (OFF) adds `-ftime-trace` to every C/C++ compile, the vendored libraries too (Clang and clang-cl; another compiler gets a status line and nothing else). `macos-time-trace` (hidden mixin `time-trace`) is `macos-debug` with it ON and `ENGINE_CCACHE=OFF`: a ccache hit replays the object and writes no trace. Each compile leaves `<object>.json` next to its object file under `build/macos-time-trace/**/CMakeFiles/<target>.dir/`, the PCH one as `cmake_pch.hxx.json`. A game that includes the engine's presets gets the preset too.

`python3 CI/scripts/time_trace_report.py --build build/macos-time-trace [--top N] [--json] [--only tests/]` reads those traces: CPU seconds (`Total ExecuteCompiler`, the figure that holds under load; the wall time is taken with `time`), the PCH compile, the slowest TUs, the headers by **inclusive** parse time summed over TUs (a header's time contains everything it includes, so the rows overlap and are not added up; a header in the PCH is listed apart, once), the slowest template instantiations; `--only` keeps the TUs whose trace path contains the text.

**Protocol of a measurement** (slice 4 of `include-hygiene`; Apple M4 Pro, 14 cores): from `engine/`, `uptime` (write the load down), then `rm -rf build/macos-time-trace && cmake --preset macos-time-trace && time cmake --build --preset macos-time-trace --target BagiEngineTests StressTests`, then the report with `--top 30`, with `--json`, and the same with `--only tests/`. The figure that counts is the CPU total; wall time is written down and never decides (the clock moves with the load). The noise **N** is the difference of two clean builds of the same tree. **The rule:** a step is kept only if the CPU total falls by at least `max(1 % of B0, 2 x N)` against the last kept state; otherwise it is dropped (not committed) and its row below says so with the numbers. A step is **game-safe**: the game (`cmake --preset macos-debug`, `BagiMahjong MahjongTests`) builds and passes with no game file edited.

**End to end** (`macos-time-trace`, clean builds; the origin and B0 are the first of the two builds each):

## Sanitizers and fuzzing

`BagiFuzz.cmake`: `ENGINE_SANITIZE`, a `;` list of `address`, `undefined` and `thread`, puts the sanitizers on every target, vendored code included (Clang or GCC; a configure error on `cl`; on Windows the compiler is clang, and `MSVC` is also true for clang with the MSVC target, so the guard tests the compiler id), with frame pointers, and sets `BE_SANITIZED` for the code after it (the fmt rule below reads it). `undefined` is `-fsanitize=undefined,float-cast-overflow` (a float to integer conversion out of range is not in `undefined`; the engine and the vendored code run the corpus and the fuzzers clean with it) with `-fno-sanitize-recover` on both, so a finding stops the process and fails its test. `thread` is `-fsanitize=thread`. A configure error: any other value, `thread` with `address` (so also with `ENGINE_FUZZ`: the runtimes exclude each other) and `thread` on Windows (no TSan runtime). `ENGINE_FUZZ` is `address;undefined`, the same flags. `ENGINE_FUZZ_LIBFUZZER` (needs `ENGINE_FUZZ`) adds the libFuzzer instrumentation and `be_add_fuzz_executable(<Name> <Function>)`: the executable `BagiFuzz<Name>` over `BECore::Fuzz::<Function>`, all of them under the target `BagiFuzzers` (`tests/Fuzz/CLAUDE.md`). The commands are in `.claude/rules/build-project.md`, "Sanitizers", "Thread sanitizer" and "Fuzzing".

- `macos-asan` (hidden mixin `asan`: `ENGINE_SANITIZE=address;undefined`) is the ordinary Debug toolchain, Apple clang, no libFuzzer; asserts and expects stay ON. Its test preset sets `ASAN_OPTIONS` (`detect_stack_use_after_return=1`, `strict_string_checks=1`) and `UBSAN_OPTIONS` (`print_stacktrace=1`); the tests inherit them, and so does the game that `BagiStressControlSmoke` starts. The Apple ASan runtime has **no leak detector** (`detect_leaks=1` prints "not supported on this platform"), so there is no `LSAN_OPTIONS` and no leak finding on macOS.
- `macos-tsan` (hidden mixin `tsan`: `ENGINE_SANITIZE=thread`) is RelWithDebInfo so that the tests end in time, with asserts and expects ON and no editor (`BE_WITH_EDITOR=AUTO`). Its test preset sets `TSAN_OPTIONS=suppressions=` to `cmake/sanitizers/tsan.supp`, a **run-time** file under the rules of the ignore list below: a TSan report does not stop the process but fails it at its end (on macOS an abort), so the file applies and a report still fails its test. TSan does not model `std::atomic_thread_fence`: read a report on a seqlock with that in mind.
- **Suppressions of ASan and UBSan are compile-time**: `-fsanitize-ignorelist=cmake/sanitizers/ignorelist.txt`, because the runtime `UBSAN_OPTIONS=suppressions=` is not applied to a build with `-fno-sanitize-recover`. Clang only (Apple clang, LLVM): GCC has no `-fsanitize-ignorelist`, so a GCC sanitizer build gets no ignore list. A line there is a file that a vendored library owns and a check it cannot pass; the file's header says what each entry must state (library, report text, why not fixable here). An engine finding is fixed, never listed. A change to the list rebuilds everything.
- `windows-clang-asan` is `windows-clang-debug` plus the same `asan` mixin and `asan-windows-crt`, which makes the build one static world: `CMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded` (the Debug build type, asserts and expects ON, no `NDEBUG`, links the release static CRT: ASan's runtime has no debug-CRT flavour) and `ENGINE_STATIC_SDL=ON` with `SDLIMAGE_DEPS_SHARED` / `_WEBP_SHARED` / `_TIF_SHARED` OFF, so no DLL is built. With `/MD` every DLL fails to link (`duplicate symbol: malloc`) and the static runtime refuses a `/MD` object; `BagiFuzz.cmake` warns when the runtime is anything else. Its test preset sets `UBSAN_OPTIONS` and `ASAN_OPTIONS` **without** `detect_stack_use_after_return` (its 11 MB fake stack per thread runs a test with thousands of threads out of commit memory); no leak detector there either. The ignore list's glob has no `/` before `miniz.h` so that it matches the Windows source path.
- A game that includes the engine's presets gets `macos-asan` and `macos-tsan` with the same `environment`; `${fileDir}` in a test preset is the folder of the preset file (the engine's), which is how a game finds `tsan.supp`.
- Apple clang has no libFuzzer runtime, so `macos-fuzz` uses Homebrew LLVM. Its hidden mixin `fuzz` holds the compiler paths (`CMAKE_C_COMPILER`, `CMAKE_CXX_COMPILER`: the Intel prefix `/usr/local/opt/llvm` goes into a `CMakeUserPresets.json`), `CMAKE_OSX_SYSROOT=macosx` (that clang has no default SDK), `-L .../lib/c++ -Wl,-rpath,...` (linked against the system libc++ the runtime fails on `std::__1::__hash_memory`) and `-L/usr/local/lib` (Apple's linker searches it by itself for the Vulkan SDK's `libvulkan.dylib`, this clang does not). Asserts and expects stay ON in `macos-fuzz`: an assertion that an input reaches is a finding. `macos-fuzz-shipped` inherits the same mixin and sets Release, `ENGINE_ENABLE_ASSERTS=OFF` and `ENGINE_ENABLE_EXPECTS=OFF` (the flags of a shipped build, where an `ASSERT` compiles out and the code after it meets the bad input); its build folder is its own. Never put Homebrew LLVM on `PATH` for `cmake --preset`.
- Clang 21 and later (Homebrew LLVM 21; emsdk's 22 on the web) refuses `FMT_STRING()` inside the vendored fmt, so with any sanitizer (`BE_SANITIZED`) the `fmt` target is compiled as C++17 (`BagiEngine.cmake`, next to the web case).

## Coverage

`ENGINE_COVERAGE` (OFF, `BagiFuzz.cmake`, independent of the sanitizer list) compiles every target, vendored code included, with Clang's source-based coverage; a configure error for another compiler and on the web. The profile path is baked into the binaries (`<binary dir>/profraw/%m_%p.profraw`), so any run of an instrumented executable that exits (ctest, a smoke, a QA replay, by hand) leaves a profile with no environment variable; `LLVM_PROFILE_FILE` overrides it. `macos-coverage` (hidden mixin `coverage`: Debug) sets `ENGINE_CCACHE=OFF`: an object cached from another checkout would map the coverage to that checkout's sources. `CI/scripts/coverage_report.py` writes the report (commands and limits: `.claude/rules/build-project.md`, "Coverage"). A game that includes the presets gets `macos-coverage`.
