# No in-game UI: UI exists only as ImGui editor panels

**Where:** `src/Widgets/` (editor widgets), `Scene/Components/ClickableComponent.cpp` (the only clickable thing on a scene).

**What exists of stage 6.4** (found by reading the code, not by running a game): the choice group (`UISegmented`, the first slice: a radio group of `UIButton` segments bound to a `UIVars` variable, a button carries a `value` with its action and a `selected` look; a two-segment group is the toggle of a binary choice, a panel of such groups is tested on the size matrix, `UI/CLAUDE.md` "Choice panels") and, from the second slice, `UIToggle` (a labeled on/off switch; the game owns the state, a click emits the value it asks for), `UIProgressBar` (read-only, over a number range), `UISlider` (horizontal; a press and a drag emit the value under the pointer, through the new canvas hooks `UIElement::OnPress` / `OnDrag`) and the string table `UIStrings` (`{#key}` in any `text`, languages, a default language and a current one, `config/UIStrings.xml`, loaded by `CoreManager`). `ui_tree` reports the three controls, `ui_click` takes `at` (0..1; a slider is set with one click), the HTML + CSS front-end writes them (`data-widget="toggle|slider|progress"`, `data-bind` / `data-action` / `data-on` / `data-off` / `data-min` / `data-max` / `data-step`, `-be-track-color` / `-be-fill-color` / `-be-thumb-color`), and `UISettingsScreenTest` checks a settings panel (toggle, slider, progress bar, a language group) on the size matrix once per language of a table with a deliberately long one (`UI/CLAUDE.md` "Settings panels and translations").

**What is still missing:** button sounds (waits for the audio entry), a dropdown (judged not needed while four options fit a row), scrolling, focus and gamepad navigation, keyboard and gamepad activation of a button or a toggle, text input, a promotion picker for Chess, animation of the controls (plan stage 6), the debug overlay and the scene editor's tree view (stage 7; the control API methods `ui_tree` and `ui_click` exist). Also left out on purpose until a screen asks: a checkbox look for the toggle, a vertical and a range slider, text on the bar or the slider, the operating system's language as the default, remembering the language between runs, plural forms, a pseudo-localization generator. Each waits for a screen that asks for it (Mahjong is named as the first consumer). The controls, the XML front-end, `UIVars`, `UIStrings`, the validator and the first screens (the menu and HUD of Match3, the HUD of Chess) exist (`src/Modules/BECore/UI/CLAUDE.md`, `games/Match3/CLAUDE.md`, `games/Chess/CLAUDE.md`). Those screens were looked at in headless screenshots of the SDL software renderer (the text, the buttons, the HUD in the margins, the score and the status following the game); nobody has looked at them, at the selected-segment look (a fill plus a 4-unit bar, a first guess), or at the toggle, the slider and the progress bar (the switch and its thumb, a slider thumb as high as the element, the colors derived from constants: all first guesses) on Vulkan or in a real window, and the agent session cannot see a screen. No scene of the engine, Match3 or Chess uses the toggle, the slider, the progress bar or the strings yet (to look at them: `UI/CLAUDE.md`, "Trying the widgets live"); the first consumers are the Chess opponent panel (the game entry `chess-hud-opponent-panel`, which needs `UISegmented` only) and Mahjong. The words of the Chess HUD are still English literals in game code.

**A fix has to cover:**

- the manual look (owner): `BagiMatch3` and `BagiChess` in a real window on the Vulkan backend, and the editor viewport presets (the checks listed in the plan);
- the manual look of the toggle, the slider and the progress bar on Vulkan and in a real window (a scratch scene, `UI/CLAUDE.md` "Trying the widgets live");
- the rest of the control set and the tooling above (sounds, dropdown, scrolling, focus and gamepad, keyboard activation, text input), which wait for the games that need them (Mahjong).
